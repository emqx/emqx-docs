# EMQX 5.10 已知问题

## e5.10.5

| 始于版本 | 问题描述                                                     | 解决方法                                                     | 状态              |
| -------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ----------------- |
| 5.10.4   | **节点离开集群或持续宕机后，共享订阅成员不会被移除**<br />使用默认的路由表模式（`broker.routing.storage_schema = v3`）时，如果某个节点在未移除自身共享订阅成员的情况下离开集群或持续宕机，这些成员会继续保留在集群中。发往共享订阅组的消息仍可能被分发给这些成员，导致消息丢失。 | 在集群的每个节点上应用[共享订阅热补丁](https://github.com/emqx/emqx-hot-patches/tree/main/261114-stale-shared-routes)（适用于 5.10.4 和 5.10.5）。<br />或者手动移除这些成员。在一个核心节点上，列出仍拥有共享订阅成员但未运行的节点：<br />`emqx eval "lists:usort(lists:map(fun({_, _, _, P}) -> node(P) end, ets:tab2list(emqx_shared_subscription))) -- mria:running_nodes()."`<br />正在重启或暂时断连的节点也可能出现在列表中。请等待几分钟后再次运行该命令。仅移除已永久离开集群的节点所拥有的成员。清理可能恢复运行的节点会导致其订阅者无法接收共享订阅消息，直至重新订阅。<br />对于每个已永久离开集群的节点，移除其成员：<br />`emqx eval "emqx_shared_sub:purge_node('emqx@departed-node')."` | 计划于 5.10.6 修复 |

## e5.10.0

| 始于版本 | 问题描述                                                     | 解决方法                                                     | 状态              |
| -------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ----------------- |
| 5.0.0    | **集群中路由表与会话注册表可能出现不一致**<br />在集群发生网络分区恢复、节点非正常关闭或清理过程中 RPC 超时等情况后，路由表和全局会话（Channel）注册表中可能残留陈旧条目或丢失正常条目。已知表现包括：<br />- 网络分区恢复后，副本节点（Replicant）上的订阅路由可能未能完全重新同步，导致部分订阅静默丢消息，直到对应节点重启才能恢复。<br />- 网络分区恢复后，副本节点上的 Channel 可能从全局会话注册表中丢失，进而导致会话接管行为异常（重新连接的客户端无法替换其旧会话）以及 Dashboard 中客户端计数失真。<br />- 当会话所有者进程异常结束且未完成清理性注销（例如出现短暂网络分区导致注销消息无法复制，或在 down-event 清理过程中核心节点的一致性检查超时），如果同名客户端 ID 不再连接，注册表中的该条目可能永久残留。随着时间推移，这类失效条目会持续累积。<br />相关修复已在 5.10 后续补丁版本及更新的发布线中合入。详见 emqx/emqx PR [#17076](https://github.com/emqx/emqx/pull/17076)、[#17257](https://github.com/emqx/emqx/pull/17257) 与 [#17522](https://github.com/emqx/emqx/pull/17522)。 | -                                                            | 请升级至 5.10.4+、6.1.2+ 或 6.2.1+ |
