# Dashboard 用户与角色管理

EMQX Dashboard 支持多用户访问，并提供基于角色的访问控制（RBAC）。每个 Dashboard 账户都会被分配一个角色，该角色决定了账户可以查看和修改的内容。本页介绍如何通过 Dashboard 界面管理 Dashboard 用户与角色。

## 角色说明

EMQX Dashboard 内置两种角色：

| 角色 | 说明 |
|------|------|
| 管理员 | 拥有所有 Dashboard 功能和 REST API 的完整访问权限。可管理用户、模块、规则、客户端及集群的所有配置。 |
| 查看者 | 只读权限。可查看监控数据、客户端列表、订阅信息和统计数据，但无法修改任何配置。 |

:::tip
默认账户 `admin` 拥有管理员角色，且无法被删除。在生产环境部署前，请务必修改其密码。
:::

## 用户管理

本节介绍如何创建、查看、更新和删除 Dashboard 用户，以及如何修改用户密码。所有操作均需要管理员角色。

### 创建用户

1. 在左侧导航菜单中点击**通用** -> **用户**。

2. 点击**创建**。

3. 填写用户名、角色、可选备注、可选作用域以及密码。

   | 字段 | 说明 |
   |------|------|
   | 用户名 | 允许使用字母、数字、下划线和连字符。 |
   | 角色 | 管理员或查看者，默认为查看者。 |
   | 备注 | 用户的可选备注或标签。 |
   | 作用域 | 用于限制用户访问权限的可选权限类别。留空时，用户使用角色默认值。详见[基于权限类别的精细权限控制](#基于权限类别的精细权限控制)。 |
   | 密码 | 长度为 8-64 个字符，至少包含以下两种字符类型：字母、数字、特殊字符。仅支持 ASCII 字符。 |

4. 点击**确认**。

   ![create_user](./assets/create_user.png)

### 查看用户列表

在左侧导航菜单中点击**通用** -> **用户**，即可查看所有 Dashboard 用户及其角色信息。

### 更新用户

1. 在左侧导航菜单中点击**通用** -> **用户**。
2. 在用户列表中点击目标用户的**编辑**按钮。
3. 修改角色、备注或作用域后点击**确认**。

此操作不支持修改用户名或密码。如需修改密码，见[修改密码](#修改密码)。

### 删除用户

1. 在左侧导航菜单中点击**通用** -> **用户**。
2. 在用户列表中点击目标用户的**删除**按钮。
3. 在确认弹窗中点击**确认**。

::: warning 重要提示
内置的 `admin` 用户不可删除，尝试删除将返回错误。
:::

::: warning 重要提示
删除用户后，该用户的 MFA 配置将立即被清除，所有有效 Token 也会失效。该用户的所有活跃会话将被终止。
:::

### 修改密码

用户可以修改自己的密码。管理员可以修改任意用户的密码。

1. 在左侧导航菜单中点击**通用** -> **用户**。
2. 在用户列表中点击目标用户的**编辑**按钮。
3. 填写新密码后点击**确认**。

**密码规则：**
- 长度为 8 到 64 个字符
- 至少包含以下两种字符类型：字母、数字、特殊字符
- 仅支持 ASCII 字符

## 基于权限类别的精细权限控制

除了上述基于角色的访问控制，EMQX Enterprise 还支持对 Dashboard 用户进行基于权限类别的细粒度权限控制。管理员可以通过分配具体的权限类别，在角色权限的基础上进一步收窄用户的访问能力。

### 权限类别

EMQX 定义了 9 个权限类别。前 6 个类别同时适用于 API Key 与 Dashboard 用户；后 3 个类别仅适用于 Dashboard 用户，不可分配给 API Key。

| 类别 | 说明 |
|------|------|
| `banned` | 黑名单管理 |
| `rule_engine` | 规则引擎与动作 |
| `resources` | 连接器与桥接 |
| `plugins` | 插件管理 |
| `modules` | 模块配置 |
| `others` | 其他杂项端点 |
| `user_management` | 管理其他 Dashboard 账号 |
| `mfa_management` | 管理 MFA。管理员可管理其他用户的 MFA；查看者仅可在强制 MFA 锁定时豁免自己的账号。 |
| `app_management` | 管理 API Key |

### 角色与权限类别兼容性

| 角色 | 可分配的权限类别 | 角色默认值（未设置权限类别时） |
|------|--------------|---------------------------|
| 管理员 | 全部 9 个类别 | 保持升级前行为：可访问所有端点 |
| 查看者 | 6 个通用类别和 `mfa_management`。`user_management` 和 `app_management` **不允许**分配给查看者。 | 6 个通用类别：`banned`、`rule_engine`、`resources`、`plugins`、`modules`、`others`。 |

如果为管理员显式设置了 scopes，其读写操作都会被限制在所列 scope 内。查看者无论如何设置 scopes 都保持只读。对于查看者，GET 请求同样会检查 scope，对非自身资源的非 GET 请求会被拒绝。查看者不能下载备份归档（`/api/v4/data/file/*`）；查看导出列表仍然可用。用户修改自己的密码、管理自己的 MFA 以及登出等自助操作始终允许，与 scopes 设置无关。

### 为用户设置权限类别

在创建或更新 Dashboard 用户时，管理员可以选择一个或多个**作用域（Scopes）**来限制该用户的权限范围。在 API 和备份数据中，这些值存储为用户 `tags` 字段中的 `scopes` 数组：

- **不设置**（使用角色默认值）：用户保持升级前基于角色的行为。
- **空数组 `[]`**：用户被拒绝访问所有需要 scope 的端点，包括 GET 请求（自助操作仍可用）。
- **非空数组**：用户只能访问属于所列类别的端点。对于查看者，角色本身的只读限制仍然适用。

如果所选 scope 与用户角色不兼容，操作将返回错误。例如，查看者无法被分配 `user_management` 或 `app_management`。

:::tip 示例
例如，选择**模块**，表示仅允许该用户访问模块相关 API 路径。在 API 和备份数据中，该选择存储为 `scopes: ["modules"]`。修改自己的密码、管理自己的 MFA、登出等自助操作仍然可用。
:::

### 默认管理员保护

由 `dashboard.default_user.login` 配置的默认管理员账号具有额外的保护措施：

- 不可被降级为查看者角色。
- 不可设置显式的 `scopes` 字段（始终拥有全部类别）。
- 不可被删除。

这些保护机制确保集群始终拥有一个可恢复意外权限误配置的应急（break-glass）管理员账号。

## SSO 用户

当用户首次通过 SAML 单点登录（SSO）进行认证时，EMQX 会自动为其创建一个 Dashboard 账户，并分配查看者角色。

- SSO 用户的内部密码为随机生成，无法直接使用用户名和密码方式登录。
- 管理员可通过 Dashboard 用户页面修改 SSO 用户的角色。
- SAML SSO 的配置详情请参考 [SAML 2.0 单点登录](../modules/saml_sso.md)文档。

:::tip
如需为 SSO 用户授予管理员权限，可在**用户**页面编辑该用户，将其角色更改为管理员。
:::
