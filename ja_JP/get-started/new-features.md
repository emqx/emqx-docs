# 新機能

このページでは、現在のリリースでサポートされている主な新機能を紹介します。EMQXが提供するすべての機能を網羅しているわけではありませんのでご注意ください。

## EMQX 6.x シリーズ

### サブスクリプションフィルター

EMQX 6.2では、MQTT 5.0クライアント向けにサブスクリプションフィルターを導入しました。サブスクライバーはトピックフィルターの後に`?`を付けてフィルター条件を追加します。パブリッシャーはトピックに条件を含めず、通常のトピック名を使用し、評価に必要な値はMQTT 5.0のユーザープロパティで提供します。EMQXはトピックと条件の両方が一致した場合にのみメッセージを配信します。

例えば、サブスクリプション`sensor/+/temperature?location=roomA&value>25`は、ユーザープロパティ`location=roomA`かつ`value=26`で`sensor/1/temperature`にパブリッシュされたメッセージにマッチします。

#### 機能のポイント

- **一致したメッセージのみ配信**：まずメッセージのトピックをマッチングし、その後ユーザープロパティに対して条件を評価します。
- **柔軟な式**：等価比較や数値比較演算子を使用でき、複数条件は`&`で組み合わせ可能です。
- **ネットワークとクライアント負荷の軽減**：サブスクライバーの条件に合わないメッセージの配信を防ぎます。
- **後方互換性のあるオプトイン方式**：`mqtt.subscription_message_filter`で機能を制御。デフォルトは無効で、無効時は`?`をトピックフィルターの一部として扱います。
- **組み込みの可観測性**：フィルター不一致は`delivery.dropped`イベントで`subscription_filter`理由付きで報告され、`delivery.dropped.filter`メトリクスでカウントされます。

詳細は[サブスクリプションフィルターのドキュメント](../develop/subscription-filter/subscription-filter-concept.md)をご覧ください。

### MQTTストリーム

::: warning 重要なお知らせ
MQTTストリームは現在ベータ機能です。機能やインターフェースは大幅に変更される可能性があります。
:::

MQTTストリームは、EMQXに永続的で再生可能なストリーミングモデルを導入し、MQTTのリアルタイムなパブリッシュ／サブスクライブのパラダイムを拡張して耐久性のあるメッセージ保存とコンシューマー制御の再生を可能にします。

従来のMQTTの配信は一時的でサブスクライバーの接続状況に依存しますが、MQTTストリームはトピックフィルターにマッチするメッセージを名前付きの永続ストリームに連続的にキャプチャします。各ストリームは固有の名前で識別され、トピックフィルターとは独立して管理されます。

コンシューマーは`$stream/<name>`または`$stream/<name>/<topic_filter>`形式でサブスクライブします。再生開始位置はMQTT 5のサブスクリプションプロパティ`stream-offset`で指定でき、特定のタイムスタンプや`earliest`、`latest`など任意の位置から過去メッセージを再生可能です。

これにより、外部のストリーミングシステムを必要とせずに、EMQXがネイティブに過去メッセージの再生、イベントトレーシング、状態復旧をサポートします。

#### 機能のポイント

- **耐久的なメッセージストリーム**：MQTTメッセージを明示的に名前付けされたストリームに永続化し、保持ポリシーを設定可能。
- **オフセットベースの再生**：コンシューマーは`stream-offset`プロパティで再生位置を制御。
- **通常ストリームとラストバリューストリーム**：フルイベントストリームと、ラストバリューセマンティクス有効時はキーごとに最新メッセージのみを保持する圧縮ストリームをサポート。
- **キー単位の順序保証**：同一ストリームキーのメッセージは厳密にパブリッシュ順で配信。
- **MQTTネイティブ設計**：既存のMQTTパブリッシャーやクライアントの変更は不要。

MQTTストリームにより、EMQXはリアルタイムメッセージングとストリーム処理の両方に適し、アーキテクチャの複雑さを軽減し、新たなIoTやイベント駆動型アプリケーションの実現を可能にします。

詳細は[MQTTストリームのドキュメント](../develop/mqtt-stream/mqtt-stream-concept.md)をご覧ください。

### メッセージキュー

メッセージキューは、EMQX内で信頼性の高いリアルタイムMQTTパブリッシュ／サブスクライブと非同期メッセージキューイングを統合し、外部キューイングサービスの必要性を排除します。

従来のMQTTはサブスクライバーの接続状況に依存しますが、メッセージキューはサーバー側でメッセージをバッファリングし、パブリッシャーとサブスクライバーを切り離します。設定されたトピックフィルターにマッチするメッセージは名前付きキューに永続保存され、`$queue/<name>`または`$queue/<name>/<topic_filter>`形式で後から消費可能です。

各キューはトピックフィルターではなく固有の名前で明示的に識別されます。これにより、キューはフィルタリングルールとは独立して管理、監視、アクセスできます。

> メッセージキューが有効な場合、`$queue/`プレフィックスはメッセージキューのサブスクリプション用に予約され、共有サブスクリプションには使用できなくなります。

![message_queue_routing_overview](./assets/message_queue_routing_overview.png)

この機能により、MQTTはリアルタイムと遅延処理の両方に対応可能となり、KafkaやRabbitMQのような外部キューイングシステムを不要にしてIoTシステムのアーキテクチャを簡素化します。メッセージの耐久性、信頼性の高い配信、オフラインバッファリングが重要なシナリオに最適です。

#### 機能のポイント
- **名前付き永続キュー**：メッセージは明示的に名前付けされたキューに保存され、動作は設定可能。
- **切り離された配信**：パブリッシャーとサブスクライバーはサーバー側のバッファリングにより完全に切り離される。
- **オフラインストレージ**：サブスクライバーが切断されていてもメッセージは保持される。
- **ラストバリュー保持**：オプションでキーごとに最新メッセージのみを保持可能。センサーの高速変化データに最適。
- **柔軟な配信戦略**：ランダム、ラウンドロビン、最少インフライトサブスクライバーから選択可能。
- **配信保証**：永続化ストレージとQoS 1配信に対応し、データ損失を防止。

詳細は[メッセージキューのドキュメント](../develop/message-queue/message-queue-concept.md)をご覧ください。

### ネームスペース付きロールによるマルチテナンシー

EMQX 6.0.0では、[マルチテナンシー](../guides/multi-tenancy/namespace-overview.md)と大規模IoT展開におけるアクセス制御を強化するためにネームスペース付きロールを導入しました。この機能により、ユーザーは特定のネームスペースに割り当てられ、ルール、コネクター、アクションなどのリソースを自分の環境内で管理でき、他のテナントへのアクセスや影響を防ぎます。

ネームスペース付きロールは、管理者や閲覧者などの細かな権限をサポートし、ダッシュボード、API、CLIから管理可能です。これにより、チームや部門、顧客間の安全な分離を保ちながら責任の委譲が容易になります。

#### 機能のポイント
- **安全な分離**：ユーザーは割り当てられたネームスペース内のリソースのみアクセス・管理可能（例：`ns:team_a::administrator`）。
- **細かなアクセス制御**：ネームスペースユーザーはその環境のリソースにフルアクセス可能だが、クラスター全体設定はグローバル管理者権限がない限り読み取り専用。
- **運用の簡素化**：ユーザー作成時にロールを簡単に作成・割り当て可能。
- **企業向けスケーラビリティ**：マルチテナントMQTTサービス提供や内部ビジネスユニット管理に最適。

#### 追加の改善点
- **可観測性の向上**：ダッシュボードの表示はネームスペースでフィルターされ、集中管理が容易に。
- **セッショントラッキングの最適化**：ネームスペース別のセッション数は1,000未満ならオンデマンド更新、それ以上は5秒ごとに更新しパフォーマンスと精度を向上。

詳細な手順は[ネームスペース付きロールのユーザー作成](../guides/dashboard/system.md#create-a-user-with-a-namespaced-role)をご覧ください。

### 最適化されたパーシステントストレージ

EMQX 6.0.0では、パーシステントストレージの性能とスケーラビリティを大幅に改善しました。セッションデータを他のブローカーメタデータから分離することで、RAM消費を削減し、ストレージ効率を向上させ、ノードあたりの接続数を増加させています。

#### 最適化されたRocksDBパラメーター

新しい設定オプションにより、メモリと性能を細かく制御可能です：

- `durable_storage.messages.rocksdb.write_buffer_size`：シャードごとのメムテーブルサイズを制御。
- `durable_storage.messages.rocksdb.cache_size`：シャードごとのブロックキャッシュサイズを設定。
- `durable_storage.messages.rocksdb.max_open_files`：シャードごとのファイルディスクリプタ数を制限。
- `durable_storage.messages.layout.wildcard_thresholds`：ワイルドカード処理をストレージレイアウトで最適化。

#### 追加の改善点

- **効率的なシリアライズ**：デフォルトのシリアライズ形式がASN.1に変更され、ストレージサイズ削減と処理速度向上。
- **高速アクセスと低オーバーヘッド**：改善されたストレージレイアウトにより、メッセージ取得が高速化し、ディスクとメモリのオーバーヘッドを削減。

これらの改善により、EMQXは大規模で永続的なMQTTワークロードを安定した性能で処理可能になりました。

### データ統合の拡張サポート

EMQX 6.0.0はデータ統合機能をさらに強化し、MQTTデータを最新のクラウドやデータベースエコシステムとシームレスに連携してリアルタイム分析、処理、保存を可能にします。

#### 新規統合

EMQX 6.0.0で新たに追加された統合：

- **[Google BigQuery](../develop/data-integration/bigquery.md)**：大規模データウェアハウスと高度なクエリを実現し、膨大なIoTデータセットからの洞察を提供。
- **[AWS AlloyDB](../develop/data-integration/alloydb.md)**、**[CockroachDB](../develop/data-integration/cockroachdb.md)**、**[AWS Redshift](../develop/data-integration/redshift.md)**：高性能データベースへのMQTTデータストリーミングをサポートし、リアルタイム分析とスケーラブルな保存に最適。エンタープライズ向けIoT分析に適合。

#### 強化された統合

新規統合に加え、既存統合も性能、使いやすさ、クラウドネイティブ対応を向上：

- **Snowflake Snowpipe Streaming**：Snowflakeのプレビュー機能であるSnowpipe Streamingを使った低レイテンシデータ取り込みをAWSホストアカウント向けにサポート。
- **RocketMQアクション**：`key`と`tag`テンプレートのサポート追加、柔軟なメッセージルーティングとメタデータ付与のための`key_dispatch`戦略を追加。
- **AWS S3およびAWS S3 Tablesコネクター**：`access_key_id`と`secret_access_key`がオプション化され、AWSホスト環境ではEC2インスタンスメタデータサービスv2 APIから自動取得可能に。
- **RabbitMQシンク**：ヘッダーとプロパティのテンプレートカスタマイズを可能にし、RabbitMQ内でのメッセージルーティングと互換性を向上。

### その他の強化

#### 高度なLLMベースのMQTTデータ処理

EMQX 6.0.0は、OpenAIやAnthropic Claudeに加え、[Google Geminiモデル](../develop/flow-designer/gemini-node-quick-start.md)のサポートを追加し、LLMベースのデータ処理機能を強化しました。

#### LDAPサポートの強化

LDAP認可はJSON形式の拡張ACLルールをサポートし、LDAP認証はLDAPから直接ACLルールを取得可能で、クライアント側キャッシュも利用できます。

#### トレーシングの改善

最大トレース数(`trace.max_traces`)とトレースファイルサイズ(`trace.max_file_size`)の設定が可能に。`max_file_size`に達するとトレースログは停止せず新ファイルにローテートされます。

#### クラスター管理

新しい`cluster.description`設定オプションにより、EMQXダッシュボードにカスタムクラスター説明を設定・表示可能になりました。ダッシュボードでの設定方法は[ダッシュボード -> 管理 -> クラスター設定](../guides/dashboard/cluster_settings.md#cluster)をご覧ください。
