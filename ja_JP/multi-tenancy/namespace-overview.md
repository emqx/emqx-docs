# ネームスペース

EMQX 5.9.0以降、ネームスペース機能により、ユーザーはMQTTクライアントを論理的にグループ化し、単一のEMQXクラスター内でトラフィック制限を適用できます。この機能は、複数のクライアントグループ（事業部門、アプリケーション、顧客など）が同じインフラを共有しつつ、論理的に分離されたスケーラブルなデプロイメントを実現します。

::: tip 注意

この機能はEMQX 5.9ではネームスペースと呼ばれていますが、マルチテナンシー設計原則に従っています。

:::

## ネームスペースとは

EMQX Enterpriseにおけるネームスペースは、MQTTクライアントの論理的な分離とリソース管理のための仕組みです。異なるビジネスやテナントのクライアントを共有されたEMQXクラスター内で別々のネームスペースに分割し、接続、メッセージ、クォータなどの分離を実現します。

ネームスペースは、クライアントの接続メタデータ（ユーザー名やServer Name Indication（SNI）など）から抽出できる特別なクライアント属性 `tns`（テナントネームスペース）によって識別されます。

> **典型的なユースケース例**：企業内で複数の事業部門がクラスターを共有、テナントレベルのリソース分離管理、集中アクセス制御など。

### ネームスペースで実現できること

- **クライアントとメッセージの論理的分離**

  ネームスペースにより、異なるテナント間でクライアントIDやトピックスペースを分離し、論理的にクライアントを区別できます。

  ::: tip 注意

  ネームスペースを有効にしても、クライアントIDのオーバーライドやトピックプレフィックスは自動的には適用されません。これらの機能は手動で設定する必要があります。詳細は[分離メカニズム](#隔離メカニズム)をご参照ください。

  :::

- **テナントレベルのクォータと接続制御**

  ネームスペースごとに同時接続数やメッセージパブリッシュレートの制限を設定でき、公平な利用とシステムの安定性を確保します。

- **強化されたログと運用可視性**

  ログには自動的にネームスペース識別子（`tns`）が含まれ、クライアントの活動追跡や問題検出、テナント単位の診断が容易になります。

- **ネームスペースベースのリソース監視**

  ネームスペースはテナントごとの接続数やメッセージスループットなどのメトリクス収集の境界を明確にし、容量計画や運用インサイトに役立ちます。

- **管理ユーザーの分離**

  EMQX 6.0以降、ネームスペースはダッシュボード、CLI、APIユーザーにも[ネームスペース付きロール](../dashboard/system.md/#namespaced-roles)を通じて拡張されています。

  ::: warning 信頼されたデプロイメントのみ

  管理ネームスペースは、組織内のチームや事業部門を分離するなど、信頼された内部デプロイメント向けに設計されています。誤って互いの設定を変更するリスクを減らすためのものであり、強固な分離保証を提供せず、公開または信頼できないマルチテナント環境のセキュリティ境界としては適していません。

  委任管理者にネームスペーススコープのリソース管理を許可する場合は、[管理ネームスペースの運用セキュリティ](#管理ネームスペースの運用セキュリティ)をご参照ください。

  :::

  - 管理ユーザーは特定のネームスペースに限定されたロール（例：`ns:team_a::administrator`）で作成可能です。
  - ネームスペース付きユーザーは割り当てられたネームスペース内のリソースのみを閲覧・操作できます。
  - ネームスペース非対応のクラスター全体設定は閲覧は可能ですが読み取り専用で、グローバル管理者のみが変更可能です。
  - これにより、データ分離とともに安全なテナント別管理アクセスが実現します。

- **マルチテナント管理**

  システム管理者は同一クラスター内で複数のネームスペースを管理でき、各テナントは分離されたリソースとユーザー権限の自己完結型環境で運用できます。

## 管理ネームスペースの運用セキュリティ

委任されたネームスペース管理者は、コネクター、ブリッジ、アクションなどのアウトバウンドターゲットを設定可能です。追加の制御がないと、内部や機密ネットワークへの意図しないアクセスを許してしまう恐れがあります。

利用可能な場合は `rule_engine.ssrf` を有効にして、ルールエンジン管理のアウトバウンドターゲットを検証してください。さらに、ランタイムのネットワーク制御が必要な場合はEMQXホスト側でイグレス制御を追加します。

- 許可された宛先（IDプロバイダー、Webhook、コネクターバックエンドなど）へのアウトバウンドアクセスのみ許可する。
- インスタンスメタデータサービス、ループバックアドレス、リンクローカルアドレス、内部管理ネットワークへのアクセスは明示的に必要な場合を除き拒否する。代表的なメタデータエンドポイントは `100.100.100.200`、`169.254.169.253`、`169.254.169.254`、`fd00:ec2::254` など。
- 新しい統合や管理機能でアウトバウンドHTTP/TCP接続を開始する場合は、必ずファイアウォールルールを見直す。

詳細は[ルールエンジンポリシーとファイアウォールルールによるSSRF緩和](../deploy/cluster/security.md#mitigate-ssrf-with-rule-engine-policy-and-firewall-rules)をご参照ください。

## 隔離メカニズム

EMQXは高い柔軟性を持ち、ネームスペース機能導入前から様々な隔離手法をサポートしてきました。ネームスペース機能は統一されたテナント識別子フィールド（`client_attrs.tns`）を提供し、クライアントIDやトピックマウントポイントなどの設定をテナント情報に基づいて整理・管理可能にします。

ただし、隔離戦略はユーザーがビジネス要件に応じて**手動で設定**する必要があり、クライアントIDやトピックの隔離機能はシステムが自動で有効化するわけではありません。

- **クライアントIDオーバーライド**

  異なるネームスペースのクライアントが同じクライアントIDでEMQXに接続したい場合、クライアントIDオーバーライドルールを設定できます。例：

  ```
  mqtt.clientid_override = "concat([client_attrs.tns, '-', clientid])"
  ```

  このルールはクライアントIDの先頭にネームスペースを付加し、衝突を回避します。

- **マウントポイントを使ったトピック隔離**

  異なるネームスペースのクライアントが同じトピック名でパブリッシュやサブスクライブを行っても互いに影響しないよう、マウントポイントを使ってネームスペースのプレフィックスを自動付加できます。

  ```
  listener.{TYPE}.{NAME}.mountpoint = "${client_attrs.tns}/"
  ```

  この設定によりトピック名にネームスペースのプレフィックスが付加されます。

バージョン5.9時点では、ネームスペースはMQTTクライアントにのみ適用されます。ダッシュボードやREST APIはまだネームスペースによる分離をサポートしていません。EMQXは将来的に管理ネームスペースとMQTTネームスペースの統合管理を実装する予定です。詳細は[マルチテナンシーロードマップ](#マルチテナンシーロードマップ)をご覧ください。

## ネームスペースの有効化

ネームスペース機能を有効にするには、まずクライアントがどのネームスペースに属するかをEMQXに伝える必要があります。これは特別なクライアント属性 `tns`（テナントネームスペース）を設定することで行います。

### 設定ファイルによるネームスペースの有効化

`tns` 属性はクライアントの接続メタデータ（ユーザー名、SNI、その他のフィールド）から抽出可能です。

例えば、クライアントのユーザー名をネームスペース識別子として使用する場合、以下の設定を適用します。

```
mqtt.client_attrs_init = [{expression = username, set_as_attr = tns}]
```

### ダッシュボードによるネームスペースの有効化

EMQXダッシュボードからもネームスペースを有効化できます。

1. **管理** -> **MQTT設定** -> **一般**タブに移動し、**クライアント属性**セクションを探します。
2. **追加**をクリックし、以下の情報を入力します：
   - **属性**：`tns`
   - **属性式**：例えばクライアントのユーザー名をネームスペース識別子にしたい場合は `username` と入力します。その他の変数も利用可能です。属性式の詳細は[クライアント属性の設定](../client-attributes/client-attributes.md#set-client-attributes)をご参照ください。
3. **変更を保存**をクリックします。

## マルチテナンシーロードマップ

以下の機能が段階的に展開されています：

- 管理ネームスペースとMQTTネームスペースの統合
- 組み込みデータベース認証の隔離実装
- 組み込みデータベース認可の隔離実装
- 保持メッセージのクォータ隔離実装
- Prometheusメトリクスの隔離実装

::: tip 更新情報

EMQX 6.0以降、ルール、アクション、ソース、コネクターの隔離は完全に実装され、ロードマップから除外されています。

:::
