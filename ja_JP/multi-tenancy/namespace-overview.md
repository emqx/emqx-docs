# ネームスペース

EMQX 5.9.0以降、ネームスペース機能により、ユーザーはMQTTクライアントを論理的にグループ化し、単一のEMQXクラスター内でトラフィック制限を適用できます。この機能は、複数のクライアントグループ（事業部門、アプリケーション、顧客など）が同じインフラを共有しつつ、論理的に分離されたスケーラブルなデプロイメントを実現します。

::: tip 注意

この機能はEMQX 5.9ではネームスペースと呼ばれていますが、マルチテナンシー設計原則に従っています。

:::

::: warning 信頼されたデプロイメントのみ

ネームスペースは MQTT クライアントと管理ユーザーに論理的な分離を提供しますが、公開環境や信頼されないマルチテナントデプロイメントにおけるセキュリティ境界では**ありません**。組織内のチーム、事業部門、既知の顧客の分離など、信頼された内部シナリオでネームスペースを利用し、意図しないテナント間干渉のリスクを低減してください。

公開マルチテナント環境でのネームスペース利用をご検討の場合は、EMQ 営業までお問い合わせください。現時点では、このユースケースは標準ではサポートされていません。

:::

## ネームスペースとは

EMQX Enterpriseにおけるネームスペースは、MQTTクライアントの論理的分離およびリソース管理のための仕組みです。異なる事業やテナントのクライアントを共有クラスター内の別々のネームスペースに分割し、接続、メッセージ、クォータなどの分離を実現します。

ネームスペースは特別なクライアント属性 `tns`（テナントネームスペース）で識別され、クライアントの接続メタデータ（ユーザー名やServer Name Indication（SNI）など）から抽出されます。

> **典型的なユースケース**：企業内の複数事業部門がクラスターを共有、テナントレベルのリソース分離管理、集中アクセス制御など。

### ネームスペースで実現できること

- **クライアントとメッセージの論理的分離**

  ネームスペースにより、異なるテナントのクライアントIDやトピック空間を論理的に分離できます。

  ::: tip 注意

  ネームスペースを有効にしても、クライアントIDの上書きやトピックのプレフィックス付与は自動的には適用されません。これらは手動で設定する必要があります。詳細は[分離メカニズム](#隔離メカニズム)をご参照ください。

  :::

- **テナントレベルのクォータと接続制御**

  各ネームスペースごとに同時接続数やメッセージパブリッシュレートの上限を定義でき、公平な利用とシステムの安定性を確保します。

- **強化されたログと運用可視性**

  ログには自動的にネームスペース識別子（`tns`）が含まれ、クライアント活動の追跡、問題検出、テナント単位の診断が容易になります。

- **ネームスペースベースのリソース監視**

  ネームスペースごとの接続数やメッセージスループットなどのメトリクス収集に明確な境界を提供し、容量計画や運用インサイトに役立ちます。

- **管理ユーザーの分離**
  
  EMQX 6.0以降、ネームスペースはダッシュボード、CLI、APIユーザーにも[ネームスペース付きロール](../dashboard/system.md/#namespaced-roles)を通じて拡張されています。信頼モデルと必要な防護策については、本ページ冒頭の[信頼されたデプロイメントのみ](#ネームスペース)をご参照ください。

  - 管理ユーザーは特定のネームスペースに限定したロール（例：`ns:team_a::administrator`）で作成可能です。
  - ネームスペース付きユーザーは割り当てられたネームスペース内のリソースのみ閲覧・操作できます。
  - ネームスペース非対応のクラスター全体設定は閲覧のみ可能で、グローバル管理者のみ変更可能です。
  - これにより、データ分離とともにテナント固有の安全な管理アクセスが実現します。
  
- **マルチテナント管理**

  システム管理者は同一クラスター内で複数のネームスペースを管理でき、各テナントは分離されたリソースとユーザー権限の自己完結型環境で運用可能です。

## 管理ネームスペースの運用セキュリティ

委任されたネームスペース管理者は、コネクター、ブリッジ、アクションなどのアウトバウンドターゲットを設定できます。追加の制御がないと、内部や機密ネットワークへの意図しないアクセスを許してしまう恐れがあります。

利用可能な場合は `rule_engine.ssrf` を有効にして、ルールエンジン管理のアウトバウンドターゲットを検証してください。さらに、ランタイムのネットワーク制御が必要な場合はEMQXホスト側でイグレス制御を追加します：

- アイデンティティプロバイダー（IdP）、Webhook、コネクターバックエンドなど承認済み宛先へのアウトバウンドアクセスのみ許可。
- インスタンスメタデータサービス、ループバックアドレス、リンクローカルアドレス、内部管理ネットワークへのアクセスは明示的に必要な場合を除き拒否。典型的なブロック対象メタデータエンドポイントは `100.100.100.200`、`169.254.169.253`、`169.254.169.254`、`fd00:ec2::254` など。
- 新しい統合や管理機能でアウトバウンドHTTP/TCP接続を開始する場合はファイアウォールルールを必ず見直してください。

詳細は[ルールエンジンポリシーとファイアウォールルールによるSSRF緩和](../deploy/cluster/security.md#mitigate-ssrf-with-rule-engine-policy-and-firewall-rules)をご参照ください。

## 隔離メカニズム

EMQXは高い柔軟性を持ち、ネームスペース機能導入前からさまざまな隔離手法をサポートしてきました。ネームスペース機能は統一されたテナント識別子フィールド（`client_attrs.tns`）を提供し、クライアントIDやトピックマウントポイントの設定を統一的なテナント情報を中心に整理・管理可能にします。

ただし、隔離戦略はビジネス要件に応じてユーザーが**手動で設定**する必要があり、クライアントIDやトピック隔離機能が自動的に有効になるわけではありません。

- **クライアントIDの上書き**

  ::: warning 信頼されないマルチテナント環境で必須

  異なるネームスペースのクライアントが相互に信頼されていない場合（例：各ネームスペースが外部顧客や別組織を表す場合）、`mqtt.clientid_override` の設定が**必須**です。設定しないと、あるネームスペースのクライアントが別テナントのクライアントIDを使い回し、接続を切断したり、永続セッションを乗っ取ったり、サービス拒否を引き起こす可能性があります。認証はこれを防げません。セッション乗っ取りはACL適用前の接続レイヤーで発生します。

  [マウントポイントを使ったトピック隔離](#隔離メカニズム)と組み合わせて、トピックレベルでもネームスペースを跨ぐアクセスを防止してください。

  :::

  異なるネームスペースのクライアントが同じクライアントIDで接続したい場合は、クライアントID上書きルールを設定できます。例：

  ```hocon
  mqtt.clientid_override = "concat([client_attrs.tns, '-', clientid])"
  ```

  このルールはクライアントIDにネームスペースをプレフィックスとして付加し、競合を避けます。

- **マウントポイントを使ったトピック隔離**

  異なるネームスペースのクライアントが同じトピック名をパブリッシュ／サブスクライブしても影響しないように、マウントポイントでネームスペースプレフィックスを自動付与できます：

  ```
  listener.{TYPE}.{NAME}.mountpoint = "${client_attrs.tns}/"
  ```

  この設定によりトピック名にネームスペースプレフィックスが付加されます。

バージョン5.9時点では、ネームスペースはMQTTクライアントにのみ適用されます。ダッシュボードやREST APIはまだネームスペースによる分離対象ではありません。EMQXは将来的に管理ネームスペースとMQTTネームスペースの統合管理を実装予定です。詳細は[マルチテナンシーロードマップ](#マルチテナンシーロードマップ)をご覧ください。

## ネームスペースの有効化

ネームスペース機能を有効にするには、まずクライアントがどのネームスペースに属するかをEMQXに伝える必要があります。これは特別なクライアント属性 `tns`（テナントネームスペース）を設定することで行います。

### 設定ファイルによるネームスペース有効化

`tns` 属性はクライアントの接続メタデータ（ユーザー名、SNI、その他のフィールド）から抽出可能です。

例として、クライアントのユーザー名をネームスペース識別子として使う設定は以下の通りです：

```
mqtt.client_attrs_init = [{expression = username, set_as_attr = tns}]
```

### ダッシュボードによるネームスペース有効化

EMQXダッシュボードからもネームスペースを有効化できます：

1. **管理** -> **MQTT設定** -> **一般**タブに移動し、**クライアント属性**セクションを探します。
2. **追加**をクリックし、以下を入力します：
   - **属性**：`tns`
   - **属性式**：例としてクライアントのユーザー名をネームスペース識別子にしたい場合は `username` と入力します。その他の変数も使用可能です。属性式の詳細は[クライアント属性の設定](../client-attributes/client-attributes.md#set-client-attributes)をご参照ください。
3. **変更を保存**をクリックします。

## マルチテナンシーロードマップ

以下の機能が段階的に展開されています：

- 管理ネームスペースとMQTTネームスペースの統合
- 組み込みデータベース認証の分離実装
- 組み込みデータベース認可の分離実装
- 保持メッセージのクォータ分離実装
- Prometheusメトリクスの分離実装

::: tip 更新情報

EMQX 6.0以降、ルール、アクション、ソース、コネクターの分離は完全に実装されており、ロードマップには含まれていません。
:::
