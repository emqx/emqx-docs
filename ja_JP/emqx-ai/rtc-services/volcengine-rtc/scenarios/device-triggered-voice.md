# デバイス発信型音声フィードバックシナリオ

ユーザー発信の音声制御や対話型シナリオとは異なり、ここでのインタラクションはデバイス側から開始されます。デバイスが環境変化やイベントを検知すると、AIが生成した音声メッセージを能動的にトリガーし、ユーザーに再生します。これにより「人がデバイスを探す」から「デバイスが人を見つける」へと変わります。

**技術的実装**：デバイス上のセンサー（温度、煙、カメラAIなど）がイベントを検知し、MQTT経由でクラウドに報告します。AIエージェントがイベントを解析し、自然言語のアナウンスを生成します。その後、Volcano Engineの`UpdateVoiceChat` APIの`ExternalTextToSpeech`コマンドを使用し、テキストをRTCルームにプッシュしてTTS再生を行います。

**アーキテクチャ構成要素**：

- **デバイスセンサー**：環境変化を検知（標準ハードウェア）
- **EMQX**：MQTTによるイベントデータ取り込み（標準製品）
- **AIエージェント**：イベント解析とアナウンス生成（カスタム開発）
- **Volcano Engine RTC + TTS**：音声配信チャネル（標準製品）

## フローダイアグラム

![デバイス発信型音声フィードバックのフロー](./device-triggered-voice.png)

**フロー説明**：

1. デバイスセンサーがイベントを検知（例：異常温度、煙警報）
2. イベントデータをMQTT経由でクラウドに報告
3. AIエージェントがイベントを解析し、自然言語アナウンスを生成
4. `UpdateVoiceChat` APIの`ExternalTextToSpeech`コマンドを呼び出す
5. Volcano EngineがRTC経由でデバイスにTTS音声をプッシュし再生

## 代表的なシナリオ

### 産業モニタリング — リアルタイム事故警報

午前3時、工場は無人状態：

> *(温度センサーがボイラー#3の異常温度を検知)*
>  **PAシステム**：「警告！ボイラー#3の温度が285℃に達し、安全閾値を超えました。電力は自動的に削減されています。担当者は直ちに点検してください。」
>  *(当直責任者に電話も発信される)*
>
> *(異常振動検知)*
>  **システム**：「注意：モーター#5で異常振動を検知しました。ベアリングの摩耗の可能性があります。データは記録され、メンテナンスチケットが発行されました。」

即時の音声警報により点検負荷を軽減し、事故防止に寄与します。

### 子育て支援 — 安全と寄り添い

母親がキッチンで調理中、3歳児がリビングで遊んでいる状況：

> *(カメラが子供のコンセント接近を検知)*
>  **スピーカー**：「お子さま、コンセントは危ないですよ。触らないでね。代わりにブロックで遊びましょうか？」
>
> *(泣き声を検知)*
>  **スピーカー**：「どうしたの？転んだの？お母さんがすぐに行くよ。」
>  *(母親のスマホにも通知が送信される)*
>
> *(暑い日に車内温度センサーが上昇を検知し、カメラが車内に子供が一人いることを認識)*
>  **車載システム**（親のスマホに音声警告送信）：「緊急警報！車内に子供が検知されました。現在の温度は42℃で上昇中です。エアコンは自動で作動しています。直ちに車両に戻ってください！」
>  *(ハザードランプが点灯し、周囲の歩行者に注意喚起)*

デバイスが危険を能動的に検知し、保護者にタイムリーに警告します。

## 主要技術ポイント

| 項目               | 説明                                                   |
| ------------------ | ------------------------------------------------------ |
| イベント駆動       | センサーデータによるトリガー、ユーザー操作不要         |
| インテリジェント音声 | AI生成の自然言語、固定警報音ではない                   |
| 優先制御           | 重要警報は会話中でも割り込み可能                       |
| マルチチャネル     | 音声＋アプリプッシュ＋SMSによる多チャネル通知           |

## AIエージェントの柔軟性

AIエージェントは最もカスタマイズ可能なコアコンポーネントです。開発者は特定シナリオに合わせて調整可能です：

- **アナウンススタイル**：産業用の厳格な警報、子供への優しい寄り添い、医療用の専門的リマインダー
- **判断ロジック**：単一閾値ではなく複数センサーの融合判定
- **応答戦略**：緊急度に応じた通知チャネルや優先度の使い分け
- **コンテキスト認識**：履歴、時間、ユーザー習慣を踏まえたより適切なメッセージ生成

## 従来のルールベース方式との比較

| 項目             | 従来のルールベース                           | AIエージェント方式                                      |
| ---------------- | ------------------------------------------- | -------------------------------------------------------- |
| トリガー         | 固定閾値（例：温度 > 50℃）                 | 文脈推論（温度＋傾向＋環境）                             |
| メッセージ内容   | 静的テンプレート（「温度異常」など）       | 値や提案、文脈を含む動的生成                             |
| 新シナリオ対応   | 新ルールの追加が必要                        | プロンプト更新で柔軟対応                                 |
| 誤警報           | フィルタリング困難                          | 多要素解析で誤警報を低減                                 |
| 保守コスト       | ルール増加に伴い増大                        | 統一されたエージェントロジックで容易に改善可能           |
