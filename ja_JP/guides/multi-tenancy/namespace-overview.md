# Namespace

EMQX 5.9.0以降、Namespace機能により、ユーザーはMQTTクライアントを論理的にグループ化し、単一のEMQXクラスター内でトラフィック制限を適用できるようになりました。この機能は、複数のクライアントグループ（事業部門、アプリケーション、顧客など）が同じインフラを共有しつつ、論理的に分離されたスケーラブルなデプロイメントを可能にします。

::: tip 注意

この機能はEMQX 5.9ではNamespaceと呼ばれていますが、マルチテナンシー設計原則に従っています。

:::

## Namespaceとは

EMQX EnterpriseにおけるNamespaceは、MQTTクライアントの論理的分離およびリソース管理のための仕組みです。異なる事業やテナントのクライアントを共有されたEMQXクラスター内の別々のNamespaceに分割し、接続、メッセージ、クォータなどの分離を実現します。

Namespaceは特別なクライアント属性である`tns`（テナントNamespace）によって識別され、クライアントの接続メタデータ（ユーザー名やServer Name Indication（SNI）など）から抽出されます。

> **典型的なユースケース例**：企業内の複数事業部門によるクラスター共有、テナント単位のリソース分離管理、集中アクセス制御など。

### Namespaceで実現できること

- **クライアントおよびメッセージの論理的分離**

  Namespaceにより、異なるテナントのクライアントIDやトピックスペースを分離し、クライアントを論理的に区別できます。

  ::: tip 注意

  Namespaceを有効にしても、クライアントIDのオーバーライドやトピックのプレフィックス付与は自動的には適用されません。これらの機能は手動で設定する必要があります。詳細は[Isolation Mechanisms](#isolation-mechanisms)をご参照ください。

  :::

- **テナント単位のクォータおよび接続制御**

  各Namespaceごとに同時接続数やメッセージパブリッシュレートの制限を定義でき、公平な利用とシステムの安定性を確保します。

- **強化されたログおよび運用可視性**

  ログには自動的にNamespace識別子（`tns`）が含まれ、クライアントの活動追跡や問題検出、テナント単位の診断が容易になります。

- **Namespaceベースのリソース監視**

  Namespaceはテナントごとの接続数やメッセージスループットなどのメトリクス収集に明確な境界を提供し、キャパシティプランニングや運用インサイトに役立ちます。

### Isolation Mechanisms

EMQXは高い柔軟性を持ち、Namespace機能導入以前から様々な分離手法をサポートしています。Namespace機能は統一されたテナント識別フィールド（`client_attrs.tns`）を提供し、クライアントIDやトピックマウントポイントの設定を統一テナント情報に基づいて整理・管理できるようにします。

ただし、分離戦略は依然としてユーザーがビジネス要件に応じて**手動で設定**する必要があり、クライアントIDやトピックの分離機能が自動的に有効になるわけではありません。

- **クライアントIDのオーバーライド**

  異なるNamespaceのクライアントが同じクライアントIDを使ってEMQXに接続したい場合、クライアントIDオーバーライドルールを設定できます。例：

  ```
  mqtt.clientid_override = "concat([client_attrs.tns, '-', clientid])"
  ```

  このルールはNamespaceをクライアントIDのプレフィックスとして追加し、衝突を回避します。

- **マウントポイントを使ったトピック分離**

  異なるNamespaceのクライアントが同じトピック名でパブリッシュやサブスクライブを行っても互いに影響しないように、マウントポイントでNamespaceプレフィックスを自動付与できます：

  ```
  listener.{TYPE}.{NAME}.mountpoint = "${client_attrs.tns}/"
  ```

  この設定によりトピック名にNamespaceプレフィックスが付加されます。

バージョン5.9時点では、NamespaceはMQTTクライアントにのみ適用されます。ダッシュボードやREST APIはまだNamespaceによる分離がされていません。EMQXは将来的に管理用NamespaceとMQTT Namespaceの統合管理を実装する予定です。詳細は[Multi-Tenancy Roadmap](#multi-tenancy-roadmap)をご覧ください。

## Namespaceの有効化

Namespace機能を有効にするには、まずクライアントがどのNamespaceに属するかをEMQXに伝える必要があります。これは`tns`（テナントNamespace）という特別なクライアント属性を設定することで行います。

### 設定ファイルによるNamespace有効化

`tns`属性は接続メタデータ（クライアントのユーザー名、SNI、その他のフィールド）から抽出可能です。

例えば、クライアントのユーザー名をNamespace識別子として使用する場合、以下の設定を適用します：

```
mqtt.client_attrs_init = [{expression = username, set_as_attr = tns}]
```

### ダッシュボードによるNamespace有効化

EMQXダッシュボードからもNamespaceを有効化できます：

1. **管理** -> **MQTT設定** -> **一般**タブに移動し、**クライアント属性**セクションを探します。
2. **追加**をクリックし、以下を入力します：
   - **属性**：`tns`
   - **属性式**：例えばクライアントのユーザー名をNamespace識別子にしたい場合は`username`と入力します。その他の変数も使用可能です。属性式の詳細は[クライアント属性の設定](../../develop/client-attributes/client-attributes.md#set-client-attributes)をご参照ください。
3. **変更を保存**をクリックします。
