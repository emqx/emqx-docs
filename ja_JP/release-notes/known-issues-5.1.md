# EMQX 5.1 の既知の問題

## e5.1.1

- **ロールアップグレード成功後に誤ったエラーメッセージが表示される**

  ロールアップグレード後に `emqx.log` にエラーメッセージが表示される場合があります。しかし、このエラーメッセージは無害であり、アップグレードは正常に完了しています。

  コア＋レプリカントクラスターでロールアップグレードを実施すると、ログに `** ERROR ** Mnesia post_commit hook failed: error:badarg` というエラーメッセージが表示されることがあります。ただし、これらのエラーはアップグレードの成功に影響を与えず、クラスターは問題なくアップグレード可能です。

## e5.1.0

- **MongoDBブリッジUIで「Connection Pool Size」設定が重複表示される**

  MongoDBブリッジのUIにおいて、「Connection Pool Size」パラメータが重複して表示されます。2つ目の項目はMongoDB接続オプションの設定に使われるため、混乱や設定ミスの原因となります。

  > **修正バージョン:** 5.1.1

- **TimescaleDBブリッジ作成成功後もステータスが切断のままになる**

  パスワードなしログインでTimescaleDBを設定した場合、データブリッジは作成されますが切断状態のままになります。ブリッジ作成時にユーザー名を入力すると解決します。

  > **回避策:**
  > TimescaleDBのユーザー名とパスワードを設定し、正しい認証情報でデータブリッジを作成してください。

  > **修正バージョン:** 5.1.1

- **コマンドラインでリスナーを開始／停止してもダッシュボードのステータスが更新されない**

  以下のコマンドでリスナーを開始または停止しても、ダッシュボード上のリスナーステータスが更新されず、実際の状態が分かりにくくなります。

  ```
  ./bin/emqx ctl listeners stop tcp:we
  ./bin/emqx ctl listeners start tcp:we
  ```

- **プラグインの開始／停止コマンドは実行ノードのみ対象でクラスター全体には反映されない**

  以下のコマンドでプラグインを開始または停止しても、実行したノードにのみ影響し、クラスター内の他ノードには反映されません。

  ```
  ./bin/emqx ctl plugins stop emqx_plugin_template-5.0.0
  ./bin/emqx ctl plugins start emqx_plugin_template-5.0.0
  ```

  > **回避策:**
  > クラスター内の全ノードでコマンドを実行するか、ダッシュボードからプラグインを管理してください。

- **CoAPゲートウェイ接続モードで認証が必須**

  CoAPゲートウェイは認証が有効な状態でのみ接続作成を許可します。いずれかの認証方式を有効にすることで問題が解決します。

  > **回避策:**
  > 任意の認証方式を有効にし、正しい認証情報で接続を作成してください。

  > **修正バージョン:** 5.1.1

- **ダッシュボードの「Use Peer Certificate field as ClientId」オプションで `crt` を選択するとエラー発生**

  ダッシュボードの **MQTT設定** ページの **一般** タブで「Use Peer Certificate as Client ID」オプションに `crt` を選択すると、クライアントIDが文字化けして表示され、詳細表示時にエラーが発生します。

- **ファイル転送機能利用時、クラスターのレプリカノードでファイルの閲覧・ダウンロード不可**

  クラスター内でファイル転送機能を使いファイルをアップロードした場合、アップロード先のレプリカノード以外からはファイル一覧APIでアクセスできません。

  > **回避策:**
  > ファイルはアップロードしたノードからのみ閲覧・ダウンロードしてください。

  > **修正バージョン:** 5.1.1

- **ダッシュボードにリスナーポートの変更が反映されない**

  `emqx.conf` のリスナーポートを以下のように変更しても、ダッシュボード上のポート表示が更新されず、実際のポートと不一致になります。

  ```
  listeners.tcp.default {
      bind = "0.0.0.1884"
  }
  ```

  > **修正バージョン:** 5.1.1

- **「Max Connections」パラメータが「quic」または「ws」リスナーで無効**

  ダッシュボードや設定ファイルで「quic」または「ws」タイプのリスナーに対して「Max Connections」を設定しても反映されません。

- **ルールの `client.disconnected` イベント統計が不正確**

  `clean_session = false` のチャネルで `client.disconnected` イベントが2回発生し、イベント統計が正しくありません。

- **ルールアクション「republish」のペイロードにUTF-8文字を含む場合の解析問題**

  「republish」アクションで `${payload.'msg'}` をペイロードに使用すると、サブスクライブしているクライアントは実際の `${payload.msg}` の値ではなく `${payload.'msg'}` という文字列を受信します。

  > **修正バージョン:** 5.2.0

- **Oracleデータベースの「Connection Pool Size」のデフォルト値が変更不可**

  指定した値に関わらず、「Connection Pool Size」パラメータはデフォルトの8に固定されます。

  > **修正バージョン:** 5.1.1

- **サブスクライブしたトピックのQoS変更がダッシュボードに反映されない**

  CoAPクライアントがQoS 0でトピックをサブスクライブ後、QoSを1に変更しても、ダッシュボードには元のQoSが表示され、実際のQoSは0のままです。

- **ログローテーション数が10を超える設定でEMQX再起動時にログファイルが削除される**

  `rotation_number` が10より大きい値に設定されている場合、`emqx.log.11` や `emqx.log.12` など10を超える番号のログファイルがEMQX再起動時に削除されます。

- **ノードが2分以上切断されるとEMQXクラスターでスプリットブレインが発生する問題**

  EMQX 5.x のOTP25へのアップグレードにより、Erlang OTP 25で導入されたより積極的なネットワーク断片化検出方式の影響で、以前のOTP24と異なり軽微なネットワーク障害でもグローバルコンポーネントで誤ってスプリットブレイン検出が発生します。

  > **修正バージョン:** 5.2.1
