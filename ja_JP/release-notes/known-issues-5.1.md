# EMQX 5.1 の既知の問題

## e5.1.1

- **正常にローリングアップグレードした後に誤ったエラーメッセージが表示される**

  ローリングアップグレード後に `emqx.log` にエラーメッセージが表示されることがあります。しかし、このエラーメッセージは無害であり、アップグレードは正常に完了しています。

  コア＋レプリカントクラスターでローリングアップグレードを実行すると、ログに `** ERROR ** Mnesia post_commit hook failed: error:badarg` というエラーメッセージが表示される場合があります。ただし、これらのエラーはアップグレードの成功に影響を与えず、クラスターは問題なくアップグレード可能です。

## e5.1.0

- **MongoDB ブリッジ UI に「Connection Pool Size」設定が重複表示される**

  MongoDB ブリッジの UI に「Connection Pool Size」パラメータが重複して表示されます。2つ目の項目は MongoDB 接続オプションの設定に使用されるため、混乱や設定ミスの原因となります。

  > **修正バージョン:** 5.1.1

- **TimescaleDB ブリッジがパスワードなしログインで作成成功後も切断状態のままになる**

  TimescaleDB のパスワードなしログインでデータブリッジを作成すると成功するものの、切断状態のままになります。ブリッジ作成時にユーザー名を入力すると問題が解決します。

  > **回避策:**
  > TimescaleDB のユーザー名とパスワードを設定し、正しい認証情報でデータブリッジを作成してください。

  > **修正バージョン:** 5.1.1

- **コマンドラインでリスナーを開始/停止してもダッシュボードのリスナー状態が更新されない**

  以下のコマンドでリスナーを開始または停止しても、ダッシュボード上のリスナー状態が更新されず、実際の状態が分かりにくくなります。

  ```
  ./bin/emqx ctl listeners stop tcp:we
  ./bin/emqx ctl listeners start tcp:we
  ```

- **プラグインの開始/停止コマンドは実行ノードのみ影響し、クラスター全体には反映されない**

  以下のコマンドでプラグインを開始または停止しても、実行したノードにのみ影響し、クラスター内の他のノードには反映されません。

  ```
  ./bin/emqx ctl plugins stop emqx_plugin_template-5.0.0
  ./bin/emqx ctl plugins start emqx_plugin_template-5.0.0
  ```

  > **回避策:**
  > クラスター内のすべてのノードで開始/停止コマンドを実行するか、ダッシュボードからプラグインを管理してください。

- **CoAP ゲートウェイ接続モードで認証が必須**

  CoAP ゲートウェイは認証が有効な状態でのみ接続作成を許可します。いずれかの認証方式を有効にすると問題が解決します。

  > **回避策:**
  > 任意の認証方式を有効化し、正しい認証情報で接続を作成してください。

  > **修正バージョン:** 5.1.1

- **ダッシュボードの「Use Peer Certificate field as ClientId」オプションで `crt` を選択するとエラー発生**

  ダッシュボードの **MQTT 設定** ページの **一般** タブで「Use Peer Certificate as Client ID」オプションに `crt` を選択すると、クライアント ID が文字化けして表示され、詳細表示時にエラーが発生します。

- **ファイル転送機能でクラスターのレプリカノード上のファイルが閲覧・ダウンロードできない**

  クラスター内でファイル転送機能を使ってファイルをアップロードした場合、レプリカノードにアップロードされたファイルは、そのノードのファイル一覧 API からのみアクセス可能です。

  > **回避策:**
  > ファイルはアップロードしたノードからのみ閲覧およびダウンロードしてください。

  > **修正バージョン:** 5.1.1

- **ダッシュボードにリスナーポートの変更が反映されない**

  `emqx.conf` の設定ファイルでリスナーポートを以下のように変更しても、ダッシュボード上のポート表示が更新されず、表示と実際のポートが不一致になります。

  ```
  listeners.tcp.default {
      bind = "0.0.0.1884"
  }
  ```

  > **修正バージョン:** 5.1.1

- **「quic」または「ws」タイプのリスナーに対する「Max Connections」パラメータが無効**

  ダッシュボードや設定ファイルで「quic」または「ws」タイプのリスナーに対して「Max Connections」を設定しても効果がありません。

- **ルールにおける `client.disconnected` イベントの統計が不正確**

  `clean_session = false` のチャネルは `client.disconnected` イベントを2回生成し、イベント統計が正確でなくなります。

- **ルールアクション「republish」のペイロードで UTF-8 文字の解析問題**

  「republish」アクションで `${payload.'msg'}` をペイロードに使用すると、サブスクライブしているクライアントは実際の `${payload.msg}` の値ではなく `${payload.'msg'}` の文字列を受信します。

  > **修正バージョン:** 5.2.0

- **Oracle データベースの「Connection Pool Size」のデフォルト値が変更不可**

  指定した値にかかわらず、「Connection Pool Size」パラメータはデフォルトの 8 に固定されます。

  > **修正バージョン:** 5.1.1

- **サブスクライブしたトピックの QoS 更新がダッシュボードに反映されない**

  CoAP クライアントが QoS 0 のトピックをサブスクライブ後に QoS を 1 に変更しても、ダッシュボードには元の QoS が表示され、実際の QoS は 0 のままです。

- **ログローテーション番号が 10 を超えると EMQX 再起動時にログファイルが削除される**

  `rotation_number` が 10 より大きい値に設定されている場合、`emqx.log.11` や `emqx.log.12` などの番号が 10 を超えるログファイルが EMQX 再起動時に削除されます。

- **ノードが 2 分以上切断されると EMQX クラスターでスプリットブレインが発生する**

  EMQX 5.x は OTP25 へのアップグレードに伴い、Erlang OTP 25 のより積極的なネットワーク断片化検出方式の影響を受けています。OTP24 以前とは異なり、軽微なネットワーク障害でも EMQX のグローバルコンポーネントで誤ったスプリットブレイン検出が発生する可能性があります。

  > **修正バージョン:** 5.2.1
