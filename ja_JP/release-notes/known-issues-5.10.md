# EMQX 5.10 の既知の問題

## e5.10.0

| バージョン | 問題                                                         | 回避策                                                        | ステータス          |
| ----------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------- |
| 5.0.0       | **クラスターにおけるルートおよびセッションレジストリの不整合が発生する可能性**<br />ネットワークパーティションの復旧、ノードの突然のシャットダウン、またはクリーンアップ中のRPCタイムアウトなどのクラスターイベント後に、ルートテーブルおよびグローバルセッション（チャネル）レジストリに古い情報や欠落が生じる関連問題が複数あります。具体的な症状は以下の通りです。<br />- レプリカントノード上のサブスクライバーのルートがネットワークパーティション復旧後に完全に再同期されない場合があり、影響を受けたノードが再起動するまで一部のサブスクリプションがメッセージを受信しなくなることがあります。<br />- レプリカントノードが所有するチャネルがパーティション復旧後にグローバルレジストリから削除されることがあり、不正確なセッションテイクオーバー（再接続するクライアントが古いセッションを置き換えられない）やダッシュボードのクライアント数の誤表示を引き起こします。<br />- セッションの所有プロセスが正常に登録解除されずに終了した場合（例えば、登録解除のレプリケーションが妨げられた短時間のネットワーク分断後や、ダウンイベントのクリーンアップ中にコアのコンセンサスチェックがタイムアウトした場合）、グローバルセッションレジストリの行が無期限に残ることがあります。同じクライアントIDが再接続しない限り、これらの死んだ行が蓄積されます。<br />これらの修正は5.10の後続パッチリリースおよび新しいリリースラインにて適用されています。詳細はemqx/emqxのPR [#17076](https://github.com/emqx/emqx/pull/17076)、[#17257](https://github.com/emqx/emqx/pull/17257)、[#17522](https://github.com/emqx/emqx/pull/17522)をご参照ください。 | -                                                            | 5.10.4以降、6.1.2以降、または6.2.1以降にアップグレードしてください |
