# EMQX 5.10 の既知の問題

## 5.10.2

| バージョン | 問題                                                         | 回避策                                                        | ステータス                |
| ----------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------- |
| 5.1.0       | **クラスターに新しいコアノードが追加されるとレプリカントノードが起動時にハングする場合がある**<br />クラスター変更で新しいコアノードを追加する際、追加されたコアノードがレプリカントノードに必要なレプリケーション関連プロセスの起動に失敗することがあります。これにより、アップグレードまたは新規追加されたレプリカントノードが起動時にハングすることがありました。<br />Kubernetes環境では、レディネスプローブの失敗によりコントローラーがレプリカントPodを繰り返し再起動する事象が発生しました。<br />この問題は、例えば既存の2コア＋2レプリカントのクラスターに新たに2つのコアノードと2つの新しいバージョンのEMQXレプリカントを追加するアップグレードロールアウト時に典型的に発生します。 | (再)デプロイ後に1台以上のレプリカントノードが起動時にハングする場合は、新たに追加されたコアノードを1台ずつ強制的に再起動し、レプリカントの起動が完了するまで繰り返してください。 | 5.10.3、6.0.1で修正済み |
| 5.7.0       | **Cluster Linkのガベージコレクションがアクティブルートを削除する場合がある**<br />複数の独立したCluster Linkが設定され、一部のリンクが比較的長期間ダウン状態の場合、ガベージコレクション処理が誤って内部ルーティングテーブルのアクティブルートを削除することがあります。これにより、影響を受けたCluster Linkはメッセージの一部のみを転送するか、メッセージ転送を完全に停止する場合があります。 | -                                                            | 5.10.3、6.1.0で修正済み |

## 5.10.0

| バージョン | 問題                                                         | 回避策                                                        | ステータス                |
| ----------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------- |
| 5.0.0       | **クラスター内でルートおよびセッションレジストリが不整合になる場合がある**<br />ネットワークパーティションの復旧、ノードの異常シャットダウン、またはクリーンアップ中のRPCタイムアウトなどのクラスターイベント後に、ルートテーブルやグローバルセッション（チャネル）レジストリに古い情報や欠落が発生する複数の関連問題があります。具体的な症状は以下の通りです。<br />- レプリカントノード上のサブスクライバーのルートがネットワークパーティション復旧後に完全に再同期されず、一部のサブスクリプションがメッセージを受信しなくなることがあり、影響を受けたノードの再起動まで問題が続きます。<br />- レプリカントノードが所有するチャネルがパーティション復旧後にグローバルレジストリから削除され、不正なセッションテイクオーバー（再接続するクライアントが古いセッションを置き換えられない）やダッシュボード上のクライアント数の誤表示が発生します。<br />- セッションの所有プロセスがクリーンにアンレジスターされずに終了した場合（例えば短時間のネットワーク分断でアンレジスターのレプリケーションが行われなかった場合や、コアのコンセンサスチェックがダウンイベントのクリーンアップ中にタイムアウトした場合）、グローバルセッションレジストリの行が無期限に残ることがあります。同じクライアントIDが再接続しない限り、これらの不要な行が蓄積されます。<br />これらの修正は5.10の後続パッチリリースおよび新しいリリースラインで適用されています。詳細はemqx/emqxのPR [#17076](https://github.com/emqx/emqx/pull/17076)、[#17257](https://github.com/emqx/emqx/pull/17257)、[#17522](https://github.com/emqx/emqx/pull/17522)をご参照ください。 | -                                                            | 5.10.4以降、6.1.2以降、または6.2.1以降にアップグレードしてください |
