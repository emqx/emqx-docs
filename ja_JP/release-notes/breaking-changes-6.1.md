# EMQX 6.1 の互換性のない変更点

## 6.1.5

- [#18974](https://github.com/emqx/emqx/pull/18974) `mqtt.max_connect_user_properties` を追加しました。これは、CONNECT プロパティおよび Will プロパティで個別に受け入れられる MQTT v5 のユーザープロパティペアの数を制限します。デフォルトは 100 で、制限を無効にするには `infinity` に設定してください。

- [#18515](https://github.com/emqx/emqx/pull/18515) Azure Blob Storage アクションの `blob` テンプレートフィールドは、Aggregated S3 アクションの `key` フィールドと同じスキーマ検証を使用するようになり、許可されたバインディングのみが使用されることを保証します。

- [#18528](https://github.com/emqx/emqx/pull/18528) OpenTelemetry 統合のエクスポーターエンドポイントは、スキームと明示的なポートを含む有効な URL である必要があります。サポートされるスキームは `http` と `https` です。

## 6.1.2

- [#17157](https://github.com/emqx/emqx/pull/17157) 新しいルールエンジン設定 `rule_engine.limit_selects_in_namespace` を導入しました。デフォルト値は `true` です。有効にすると、ルールは自身と同じネームスペースのクライアントからパブリッシュされたメッセージにのみトリガーされます。

- [#17325](https://github.com/emqx/emqx/pull/17325) ホットアップグレードの REST API エンドポイント（`/api/v5/relup/*`）を削除しました。ホットアップグレードは現在、各ノード上の `emqx ctl relup` CLI でのみ操作可能で、ダッシュボードからは操作できません。

  対象のリリース tarball とその `.sha256` サイドカー（同じベース名、同じディレクトリ）を EMQX プロセスが読み取れる場所に配置してください。各ノードで `emqx ctl relup upgrade <TarballPath>` を実行してアップグレードを適用します。対象バージョンは tarball 内の `releases/emqx_vars`（`REL_VSN`）から読み取られます。

## 6.1.0

- [#16368](https://github.com/emqx/emqx/pull/16368) 内部の正規表現エンジンを PCRE2 にアップグレードしました。これにより、マッチング性能が向上し、より厳格な構文チェックが行われるようになりました。

  ルールエンジン SQL で `regex_match`、`regex_replace`、`regex_extract` 関数を使用している場合、これまで寛容または未定義の動作に依存していた正規表現の一部は、コンパイルできなくなったり期待通りにマッチしなくなる可能性があります。

  **主な変更点は以下の通りです：**

  - **より厳格なエスケープルール**：これまで無視されていた無効または不要なエスケープシーケンスはエラーとして扱われます。
    - **破損例**：`[\w-\.]` — 文字クラス内での `.` のエスケープは不要であり、許容されなくなりました。メタ文字のみエスケープが必要です。
    - **破損例**：有効な16進数がない `\x`（例：`\xGG`）は、リテラルの `x` として解釈されるのではなく、コンパイルエラーになります。
  - **グループ名の検証強化**：重複または空の名前付きキャプチャグループを含む正規表現は許可されなくなりました。

  **対応が必要です：** 正規表現を使用しているすべてのルールエンジン SQL 定義を見直し、検証してください。複雑なパターンについては、PCRE2 対応のテスター（多くのオンライン正規表現ツールが対応しています）で互換性を確認するか、アップグレード前にステージング環境で十分にテストしてください。
