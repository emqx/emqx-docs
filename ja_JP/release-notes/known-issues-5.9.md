# EMQX 5.9 の既知の問題

## e5.9.0

| バージョン | 問題                                                         | 回避策                                                       | ステータス                  |
| ----------- | ------------------------------------------------------------ | ------------------------------------------------------------ | --------------------------- |
| 5.0.0       | **クラスター内でルートおよびセッションレジストリが不整合になる可能性**<br />ネットワークパーティションの復旧、ノードの突然のシャットダウン、クリーンアップ中のRPCタイムアウトなどのクラスターイベント後に、ルートテーブルやグローバルセッション（チャネル）レジストリに古い情報や欠落が発生する関連問題が複数あります。具体的な症状は以下の通りです。<br />- レプリカントノード上のサブスクライバーのルートがネットワークパーティション復旧後に完全に再同期されず、影響を受けたノードが再起動するまで一部のサブスクリプションがメッセージを受信しなくなることがある。<br />- レプリカントノードが所有するチャネルがパーティション復旧後にグローバルレジストリから削除され、誤ったセッションテイクオーバー（再接続したクライアントが古いセッションを置き換えられない）やダッシュボードのクライアント数の誤表示が発生する。<br />- セッションの所有プロセスが正常に登録解除されずに終了した場合（例えば、登録解除のレプリケーションがネットワーク分断で阻害された場合や、コアのコンセンサスチェックがダウンイベントのクリーンアップ中にタイムアウトした場合）、グローバルセッションレジストリの行が無期限に残存し、同じクライアントIDが再接続しない限りこれらの死んだ行が蓄積される。<br />これらの修正は新しいリリースラインに含まれており、5.9にはバックポートされません。詳細は emqx/emqx のPR [#17076](https://github.com/emqx/emqx/pull/17076)、[#17257](https://github.com/emqx/emqx/pull/17257)、[#17522](https://github.com/emqx/emqx/pull/17522) を参照してください。 | -                                                            | 5.10.4以降、6.1.2以降、または6.2.1以降にアップグレードしてください |
| 5.0.0       | **Linuxの単調時計が逆戻りした場合のノードクラッシュ**<br />特定の仮想Linux環境では、OSが単調時計を維持できず、Erlang VMが `OS monotonic time stepped backwards!` というメッセージで終了することがあります。 | そのような環境では、`etc/vm.args` 内で `+c` フラグを `false` に設定してください。 |                             |
| 5.3.0       | **SAMLベースのSSOに関する制限**<br />EMQXダッシュボードはSAML 2.0標準に基づくシングルサインオンをサポートし、OktaやOneLoginをIDプロバイダーとして統合しています。しかし、SAMLベースのSSOは現在、証明書署名検証機構をサポートしておらず、その複雑さからAzure Entra IDとは互換性がありません。 | -                                                            |                             |
| 5.1.0       | **クラスターに新しいコアノードを追加するとレプリカントノードの起動がハングする場合がある**<br />新しいコアノードを追加するクラスター変更時に、追加されたコアがレプリカントノードに必要なレプリケーション関連プロセスの起動に失敗することがありました。これにより、アップグレードまたは新規追加されたレプリカントノードの起動がハングすることがありました。<br />Kubernetes環境では、レプリカントポッドのレディネスプローブ失敗によりコントローラーが繰り返し再起動を行う事象が発生しました。<br />この問題は、例えば既存の2コア＋2レプリカントクラスターに対し、新たに2つのコアノードと2つの新しいレプリカントを追加してEMQXの新バージョンを稼働させるアップグレードロールアウト時に発生することが多いです。 | もしレプリカントノードが（再）デプロイ後に起動でハングする場合は、新たに追加されたコアノードを1台ずつ強制的に再起動し、レプリカントの起動が完了するまで繰り返してください。 | 5.10.3、6.0.1で修正済み |
| 5.7.0       | **クラスターリンクのガベージコレクションがアクティブルートを削除する場合がある**<br />複数の独立したクラスターリンクが設定され、一部のリンクが比較的長期間ダウンしている場合、ガベージコレクション処理が誤って内部ルーティングテーブルからアクティブルートを削除することがあります。これにより、影響を受けたクラスターリンクはメッセージの一部のみを転送するか、メッセージ転送を完全に停止する可能性があります。 | -                                                        | 5.10.3、6.1.0で修正済み |
