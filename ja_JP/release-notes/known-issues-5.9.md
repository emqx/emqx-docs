# EMQX 5.9 の既知の問題

## e5.9.0

| バージョン | 問題                                                         | 回避策                                                      | ステータス                  |
| ----------- | ------------------------------------------------------------ | ------------------------------------------------------------ | --------------------------- |
| 5.0.0       | **クラスターにおけるルートおよびセッションレジストリの不整合**<br />ネットワークパーティションの回復、ノードの突然のシャットダウン、クリーンアップ中のRPCタイムアウトなどのクラスターイベント後に、ルートテーブルやグローバルセッション（チャネル）レジストリに古いエントリや欠落が発生する複数の関連問題があります。具体的な症状は以下の通りです。<br />- レプリカントノード上のサブスクライバーのルートがネットワークパーティション回復後に完全に再同期されないことがあり、影響を受けたノードの再起動まで一部のサブスクリプションがメッセージを受信しなくなる。<br />- レプリカントノードが所有するチャネルがパーティション回復後にグローバルレジストリから削除されることがあり、不正なセッションテイクオーバー（再接続したクライアントが古いセッションを置き換えられない）やダッシュボードのクライアント数の誤表示を引き起こす。<br />- セッションの所有プロセスが正常に登録解除されずに終了した場合（例えば、短時間のネットワーク分断により登録解除がレプリケートされなかった場合や、コアのコンセンサスチェックがダウンイベントのクリーンアップ中にタイムアウトした場合）、グローバルセッションレジストリの行が無期限に残り続け、同じクライアントIDが再接続しない限りこれらの死んだ行が蓄積される。<br />これらの修正は新しいリリースラインに含まれていますが、5.9にはバックポートされません。詳細はemqx/emqxのPR [#17076](https://github.com/emqx/emqx/pull/17076)、[#17257](https://github.com/emqx/emqx/pull/17257)、[#17522](https://github.com/emqx/emqx/pull/17522)を参照してください。 | -                                                            | 5.10.4以降、6.1.2以降、または6.2.1以降にアップグレードしてください |
| 5.0.0       | **Linuxの単調時計が逆戻りするとノードがクラッシュする**<br />特定の仮想Linux環境では、OSが単調時計を維持できず、Erlang VMが`OS monotonic time stepped backwards!`というメッセージとともに終了する場合があります。 | そのような環境では、`etc/vm.args`内の`+c`フラグを`false`に設定してください。 |                             |
| 5.3.0       | **SAMLベースのSSOの制限**<br />EMQXダッシュボードは、SAML 2.0標準に基づくシングルサインオンをサポートし、OktaおよびOneLoginをIDプロバイダーとして統合しています。しかし、SAMLベースのSSOは現在、証明書署名検証機構をサポートしておらず、その複雑さのためAzure Entra IDとは互換性がありません。 | -                                                            |                             |
| 5.1.0       | **新しいコアノードがクラスターに追加されるとレプリカントノードが起動時にハングする可能性がある**<br />新しいコアノードを追加するクラスター変更時に、追加されたコアがレプリカントノードに必要なレプリケーション関連プロセスの起動に失敗することがあります。これにより、アップグレードまたは新規追加されたレプリカントノードが起動時にハングすることがありました。<br />Kubernetes環境では、レプリカントポッドのレディネスプローブが失敗し、コントローラーが繰り返しポッドを再起動する原因となりました。<br />この問題は、例えば既存の2コア＋2レプリカントクラスターを拡張して2つの新しいコアノードと2つの新しいレプリカントを追加し、新しいEMQXバージョンを実行する場合のアップグレードロールアウト中に発生しやすいです。 | レプリカントノードが起動時にハングする場合は、新しく追加されたコアノードを1台ずつ強制的に再起動し、レプリカントの起動が完了するまで繰り返してください。 | 5.10.3、6.0.1で修正済み |
| 5.7.0       | **クラスターリンクのガベージコレクションがアクティブルートを削除する可能性**<br />複数の独立したクラスターリンクが設定されていて、一部のリンクが比較的長期間ダウンしている場合、ガベージコレクション処理が誤って内部ルーティングテーブルからアクティブルートを削除することがあります。これにより、影響を受けたクラスターリンクはメッセージの一部のみを転送するか、まったく転送しなくなる可能性があります。 | -                                                        | 5.10.3、6.1.0で修正済み |
