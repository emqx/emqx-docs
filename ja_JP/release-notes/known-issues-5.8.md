# EMQX 5.8 の既知の問題

## e5.8.9

| バージョン | 問題                                                         | 回避策                                                      | ステータス          |
| ----------- | ------------------------------------------------------------ | ----------------------------------------------------------- | ------------------- |
| 5.0.0       | **クラスター内でルートおよびセッションレジストリが不整合になる可能性**<br />ネットワークパーティションの復旧、ノードの突然のシャットダウン、クリーンアップ中のRPCタイムアウトなどのクラスターイベント後に、ルートテーブルやグローバルセッション（チャネル）レジストリに古いまたは欠落したエントリが残る関連問題が複数存在します。具体的な症状は以下の通りです。<br />- レプリカントノードのサブスクライバーのルートがネットワークパーティション復旧後に完全に再同期されず、影響を受けたノードの再起動まで一部のサブスクリプションがメッセージを受信しなくなる。<br />- レプリカントノードが所有するチャネルがパーティション復旧後にグローバルレジストリから削除され、セッションの誤った引き継ぎ（再接続クライアントが古いセッションを置き換えない）やダッシュボードのクライアント数の誤表示を引き起こす。<br />- セッションの所有プロセスがクリーンな登録解除なしに終了した場合（例えば、短時間のネットワーク分断により登録解除の複製が阻害された場合や、コアのコンセンサスチェックがダウンイベントのクリーンアップ中にタイムアウトした場合）、グローバルセッションレジストリの行が無期限にリークし、同じクライアントIDが再接続しない限りこれらの死んだ行が蓄積される。<br />これらの修正は新しいリリースラインに含まれており、5.8にはバックポートされません。詳細はemqx/emqxのPR [#17076](https://github.com/emqx/emqx/pull/17076)、[#17257](https://github.com/emqx/emqx/pull/17257)、[#17522](https://github.com/emqx/emqx/pull/17522)を参照してください。 | -                                                             | 5.10.4以降、6.1.2以降、または6.2.1以降にアップグレードしてください |
| 5.8.9       | **ダッシュボードからMQTTコネクターの静的クライアントIDを設定できない** | 各ノードの設定ファイルから静的クライアントIDを設定してください。 |                     |
