# EMQX バージョンライフサイクルとサポート終了（EOL）日

EMQX は、迅速に進化する SaaS プラットフォームから大規模なエンタープライズ展開まで、幅広いユーザーに対応しています。これら多様なニーズに応えるため、EMQX はイノベーション、安定性、長期メンテナンスのバランスを取った多層的なリリースおよびサポートポリシーを採用しています。

このライフサイクルポリシーは以下を目的としています：

- [EMQX Cloud](../get-started/concept.md#which-products-do-we-offer) における迅速なイノベーションを頻繁な内部アップデートでサポートすること。
- オンプレミスユーザーに対して予測可能な四半期ごとのスケジュールで新機能を提供すること。
- 指定された **Long-Term Support (LTS)** バージョンを通じてエンタープライズ顧客に長期的な安定性を提供すること。
- バージョンのサポート期間と **End-of-Life (EOL)** の明確かつ予測可能なスケジュールを保証すること。

3つの異なるリリース層（Internal、Feature、LTS）を提供することで、EMQX はユーザーが最新機能への迅速なアクセスを重視するか、長期的なプラットフォームの安定性を求めるかに応じて最適なバージョンのリリース頻度を選択できるようにしています。

## リリース層とリリース頻度

迅速なイノベーションとエンタープライズレベルの安定性のバランスを取るために、EMQX は3層のリリースモデルを採用しています。

### Internal Releases（内部リリース）

*   **頻度：** 月次。
*   **対象：** EMQX 内部チーム、EMQX Cloud、見込み顧客。
*   **目的：** EMQX 管理下の環境（例：EMQX Cloud、内部テスト、限定的なパブリックステージング）で新機能を迅速に提供・検証すること。内部リリースは選定された顧客への早期アクセスも提供し、将来のパブリック Feature Releases の基盤となります。
*   **品質保証：** 公開ダウンロードはできませんが、EMQX Cloud の基盤として使用され、完全なQAを経て本番環境対応の品質を保証しています。実験的または不安定なものではありません。
*   **サポート：** Cloud 環境向けに EMQX チームが直接メンテナンスを行います。オンプレミスの直接利用は想定していません。

### Feature Releases（パブリック版）

*   **頻度：** 四半期ごと（通常3月、6月、9月、12月）。
*   **対象：** 最新の安定機能をタイムリーに利用したいオンプレミスユーザー。
*   **目的：** 最近の内部リリースで検証された機能をパッケージ化し、一般のオンプレミス利用者に提供すること。
*   **サポート期間：** 初回リリース日から18ヶ月。

### Long-Term Support (LTS) Releases（パブリック版）

*   **頻度：** 年次（通常6月の Feature Release が LTS 指定されます）。
*   **対象：** 最大の安定性と長期計画を必要とするミッションクリティカルなエンタープライズユーザー。
*   **目的：** 高度に安定化・検証されたバージョンを長期サポート付きで提供すること。
*   **サポート期間：** 初回リリースから3年（特例として 4.4.x は5年サポート）。

この多層的リリースモデルにより、機能は内部検証を経て成熟し、オンプレミス展開においてより高い安定性と品質が保証されます。

## バージョン番号と命名規則

EMQX はセマンティックバージョニング（`MAJOR.MINOR.PATCH`、例：`5.8.1`）を基本とし、リリース層ごとに特定の命名規則を設けています。

### メジャーリリース（例：`4.0.0`、`5.0.0`、`6.0.0`）

*   非互換な変更を含む可能性がある大規模な更新を導入します。
*   メジャーバージョン間の直接的なインプレースアップグレードは一般的にサポートされません。通常は新規デプロイメントの構築と設定・データの手動移行が必要です。詳細は各メジャーバージョンの移行ガイドを参照してください。

### Internal Releases（例：`5.9.0-M3.202506`）

*   **フォーマット：** `X.Y.Z-M[1-3].YYYYMM`（例：`5.9.0-M2.202505`、`5.9.1-M3.202506`）。
*   `X.Y` は開発中の次期または現行のパブリック Feature Release のマイナーバージョンと連動することが多いです。
*   `Z` は内部イテレーションごとにインクリメントされることがあります。臨時の修正も含まれます。

### Feature Releases（例：`5.7.0`、`5.9.0`、`5.10.0`）

*   新機能、改善、バグ修正を四半期ごとに提供するパブリックマイナーリリースです。
*   同一メジャーバージョン内の過去のマイナーリリース（例：`5.x`）と後方互換性があり、クラスタのローリングアップグレードをサポートします。
*   **フォーマット：** `X.Y.0`。
*   `Y`（マイナーバージョン）は四半期ごとにインクリメントされます。
*   **命名：** `EMQX Enterprise X.Y.0`。

### LTS Releases（例：`5.8.0`）

*   年次の Feature Release のうち、Long-Term Support として指定されたリリースです。初回の LTS リリース（`X.Y.0`）は、その時点での最新かつ安定した機能セットを含みます。
*   **フォーマット：** `X.Y.0`。
*   **命名：** `EMQX Enterprise X.Y.0`。
*   LTS ステータスはドキュメントおよび公式ダウンロードページで明確に示されます。

### パッチリリース（例：`5.8.1`、`5.9.2`）

*   重要なバグ修正およびセキュリティパッチのみを含みます。
*   新機能や破壊的変更は含みません。
*   発行対象：
    *   **Feature Releases：** 初回リリース（`X.Y.0`）から18ヶ月のサポート期間内の各 Feature マイナーリリースラインは、そのラインに適用される（影響する）重要なバグ修正およびセキュリティ脆弱性パッチをパッチリリースで受け取ります。
    *   **LTS Releases：** アクティブな LTS リリースラインは、3年間のサポート期間中、そのラインに適用される（影響する）重要なバグ修正およびセキュリティパッチをパッチリリースで受け取ります。

## メンテナンスポリシー

EMQX のリリースは種類とライフサイクル段階に応じて異なるメンテナンスが行われます。

*   **Internal Release：**
    *   EMQX チームがメンテナンスを担当します。発見されたバグは通常、次回の内部イテレーションや Cloud 環境内のホットフィックスで対応されます。これらの修正は dev ブランチにマージされ、将来のパブリックリリースに反映されます。
*   **Feature Releases（パブリック）：**
    *   新機能や改善は四半期ごとの Feature マイナーリリース（例：5.9.0、5.10.0）で導入されます。18ヶ月のライフサイクル期間中、各 Feature リリースライン（例：5.9.x）は、そのラインに適用される重要なバグ修正およびセキュリティパッチをパッチリリース（例：5.9.1、5.9.2）で受け取ります。
    *   対象ユーザーは、新機能への迅速なアクセスを求め、短期間のサポートサイクルを許容できるユーザーです。
*   **Long-Term Support (LTS) Releases（パブリック）：**
    *   **初回 LTS リリース（例：5.8.0）：** 最新の安定機能セットを含んでリリースされます。
    *   **以降の LTS パッチリリース（例：5.8.1、5.8.2）：** 3年間のライフサイクル期間中、以下の更新がパッチリリースで提供されます：
        *   重要なバグ修正
        *   セキュリティ脆弱性パッチ
        *   **重要な注意点：** 最大限の安定性を確保するため、LTS バージョンのパッチリリース（X.Y.Z）では新機能の追加は行いません。
    *   対象ユーザーは、システムの安定性、予測可能性、長期サポートを厳格に求めるエンタープライズ顧客や、デプロイ後の変更を最小限に抑えたいシナリオです。
*   **パッチリリース：**
    *   例：5.10.1、5.10.2 はバグ修正およびセキュリティパッチのみを含み、新機能は含みません。
    *   まれに、メンテナンスチームの裁量で、メンテナンスモードのバージョンに対し、移行を支援するための最小限かつ非破壊的な変更を追加する場合があります。

## Business Source License (BSL) とバージョンサポート

::: tip 注意

EMQX バージョン 5.9.0 以降は Business Source License (BSL) 1.1 の下でライセンスされています。詳細は[公式発表](https://www.emqx.com/en/news/emqx-adopts-business-source-license)をご覧ください。

:::

### コミュニティユーザー

- コミュニティユーザーは、BSL 条件の下で LTS ブランチを含むすべての EMQX バージョンを利用できます。
- ソフトウェアは無保証で提供されており、利用は自己責任です。EMQX は利用に伴う問題や損害に対して責任を負いません。
- BSL の下では、指定された変更日（Change Date）後にソースコードが完全なオープンソースライセンス（例：Apache 2.0）に移行します。これにより、コミュニティは長期メンテナンスの成果を含む完全なオープンバージョンにアクセスできるようになります。
- 変更日前でも、コミュニティユーザーは該当する BSL バージョンに適用されるパッチリリース（バグ修正やセキュリティアップデート）を受け取ることがあります。

### エンタープライズ顧客

- 商用ライセンスおよびサブスクリプション契約を持つ顧客は、プレミアム機能および公式サポート（契約に定められたサービスレベル保証を含む）を受けられます。
- LTS バージョンにはエンタープライズ向けに5年間のサポートコミットメントが提供されます。これにより、コードブランチが後に BSL 条件のオープンソースライセンスに移行しても、ミッションクリティカルな展開に対する継続的なメンテナンスとサポートが保証されます。

## アップグレードパスの推奨

最新機能、パフォーマンス改善、セキュリティアップデートへのアクセスを確保するために、展開形態に応じて以下のアップグレード戦略を推奨します：

*   **EMQX Cloud：** EMQX チームが完全に管理しており、ユーザーは月次アップデートをシームレスに享受できます。
*   **オンプレミス Feature Releases：** ユーザーは四半期ごとの Feature Release 間でアップグレードし、新機能を利用できます。サポート期間内（18ヶ月以内）の Feature Release を利用し続けることが推奨されます。
*   **オンプレミス LTS Releases：** エンタープライズユーザーは、現在の LTS バージョンから次の LTS バージョンへの移行を計画し、長期サポートが途切れないように十分な重複期間を設けることが可能です。Feature Release から LTS Release へのアップグレードもサポートされています。

各リリースには詳細なアップグレードガイドと互換性に関する注意事項が含まれており、計画と実行を支援します。
