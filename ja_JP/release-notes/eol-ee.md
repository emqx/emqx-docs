# EMQX バージョンライフサイクルとサポート終了（EOL）日

EMQX は、迅速に進化する SaaS プラットフォームから大規模なエンタープライズ展開まで、幅広いユーザーに対応しています。これら多様なニーズに応えるため、EMQX はイノベーション、安定性、長期メンテナンスのバランスを取った多層的なリリースおよびサポート方針を採用しています。

本ライフサイクルポリシーは以下を目的としています：

- [EMQX Cloud](../get-started/concept.md#which-products-do-we-offer) における頻繁な内部アップデートによる迅速なイノベーションの支援
- オンプレミスユーザーに対して予測可能な四半期スケジュールでの新機能提供
- 指定された **Long-Term Support (LTS)** バージョンによるエンタープライズ顧客への長期安定性の提供
- バージョンのサポートおよび **End-of-Life (EOL)** の明確かつ予測可能なスケジュールの確保

3つの異なるリリース階層（Internal、Feature、LTS）を提供することで、EMQX はユーザーが最新機能への迅速なアクセスを重視するか、長期的なプラットフォームの安定性を重視するかに応じて最適なバージョンのリリース頻度を選択できるようにしています。

## リリース階層とリリース頻度

迅速なイノベーションとエンタープライズグレードの安定性のバランスを取るため、EMQX は3層のリリースモデルを採用しています。

### Internal リリース

*   **頻度:** 月次。
*   **対象:** EMQX 内部チーム、EMQX Cloud、および見込み顧客。
*   **目的:** EMQX 管理下の環境（EMQX Cloud、内部テスト、限定的な公開ステージングなど）で新機能を迅速に提供・検証。Internal リリースは選定された顧客への早期アクセスも提供し、将来の公開 Feature リリースの基盤となります。
*   **品質保証:** 公開ダウンロードは不可ですが、EMQX Cloud の基盤として使用され、完全なQAを経て本番環境対応の品質が保証されています。実験的または不安定なものではありません。
*   **サポート:** Cloud 環境向けに EMQX チームが直接保守。オンプレミスの顧客向け直接利用は想定していません。

### Feature リリース（公開）

*   **頻度:** 四半期ごと（通常は3月、6月、9月、12月）。
*   **対象:** 最新の安定機能をタイムリーに利用したいオンプレミスユーザー。
*   **目的:** 最近の Internal リリースで検証された機能をパッケージ化し、一般的なオンプレミス利用向けに提供。
*   **サポート期間:** 初回リリース日から18か月。

### Long-Term Support (LTS) リリース（公開）

*   **頻度:** 年次（通常は6月の Feature リリースが LTS 指定されます）。
*   **対象:** 最大の安定性と長期計画を必要とするミッションクリティカルなエンタープライズユーザー。
*   **目的:** 高い安定性と広範な検証を経たバージョンを、拡張されたサポートライフサイクルとともに提供。
*   **サポート期間:** 初回リリースから3年間（4.4.x は特例で5年間サポート）。

この階層的リリースモデルにより、機能は内部検証を経て成熟し、オンプレミス展開においてより高い安定性と品質を保証します。

## バージョン番号と命名規則

EMQX はセマンティックバージョニング（`MAJOR.MINOR.PATCH`、例：`5.8.1`）を基本とし、リリース階層ごとに特定の命名規則を設けています。

### メジャーリリース（例：`4.0.0`、`5.0.0`、`6.0.0`）

*   後方互換性のない変更を含む可能性のある大幅な更新を導入。
*   メジャーバージョン間の直接アップグレードは一般的にサポートされません。通常は新規デプロイを構築し、設定やデータを手動で移行します。詳細は各メジャーバージョンの移行ガイドを参照してください。

### Internal リリース（例：`5.9.0-M3.202506`）

*   **形式:** `X.Y.Z-M[1-3].YYYYMM`（例：`5.9.0-M2.202505`、`5.9.1-M3.202506`）。
*   `X.Y` は開発中の次期または現行の公開 Feature リリースのマイナーバージョンに対応。
*   `Z` は内部反復で増分されることがあり、アドホックな修正が含まれる場合があります。

### Feature リリース（例：`5.7.0`、`5.9.0`、`5.10.0`）

*   新機能、改善、バグ修正を四半期ごとに提供する公開マイナーリリース。
*   同一メジャーバージョン内の過去のマイナーリリース（例：`5.x`）と後方互換性があり、クラスタのローリングアップグレードをサポート。
*   **形式:** `X.Y.0`。
*   `Y`（マイナーバージョン）は四半期ごとに増分。
*   **命名:** `EMQX Enterprise X.Y.0`。

### LTS リリース（例：`5.8.0`）

*   年次の Feature リリースのうち、長期サポート対象として指定されたもの。初回 LTS リリース（`X.Y.0`）はリリース時点での最新かつ安定した機能セットを含みます。
*   **形式:** `X.Y.0`。
*   **命名:** `EMQX Enterprise X.Y.0`。
*   LTS ステータスはドキュメントおよび公式ダウンロードページで明示。

### パッチリリース（例：`5.8.1`、`5.9.2`）

*   重要なバグ修正およびセキュリティパッチのみを含む。
*   新機能や破壊的変更は含まれません。
*   発行対象：
    *   **Feature リリース:** 18か月のサポート期間内の各 Feature マイナーリリースライン（初回リリース `X.Y.0` から）に対し、そのリリースラインに影響する重要なバグ修正やセキュリティ脆弱性の修正を提供。
    *   **LTS リリース:** 3年間のサポート期間中、該当する LTS リリースラインに影響する重要なバグ修正やセキュリティパッチを提供。

## メンテナンスポリシー

EMQX のリリースは種類とライフサイクル段階に応じて異なるメンテナンスが行われます。

*   **Internal リリース:**
    *   EMQX チームが保守。発見されたバグは通常、次回の内部反復や Cloud 環境内のホットフィックスで対応されます。これらの修正は dev ブランチにマージされ、将来の公開リリースに反映されます。
*   **Feature リリース（公開）:**
    *   新機能や改善は四半期ごとの Feature マイナーリリース（例：5.9.0、5.10.0）で提供されます。18か月のライフサイクル期間中、各 Feature リリースライン（例：5.9.x）は該当する重要なバグ修正およびセキュリティパッチをパッチリリース（例：5.9.1、5.9.2）で受け取ります。
    *   対象ユーザーは、新機能への迅速なアクセスを望み、短期間のサポートサイクルを許容するユーザーです。
*   **Long-Term Support (LTS) リリース（公開）:**
    *   **初回 LTS リリース（例：5.8.0）:** 最新の安定機能セットを含んでリリース。
    *   **以降の LTS パッチリリース（例：5.8.1、5.8.2）:** 3年間のライフサイクル期間中、以下の更新を提供：
        *   重要なバグ修正
        *   セキュリティ脆弱性パッチ
        *   **重要:** 最大の安定性を確保するため、LTS のパッチリリース（X.Y.Z）は新機能を導入しません。
    *   対象ユーザーは、システムの安定性、予測可能性、長期サポートを厳格に求めるエンタープライズ顧客や、デプロイ後の変更を最小限に抑えたいシナリオです。
*   **パッチリリース:**
    *   例：5.10.1、5.10.2 はバグ修正とセキュリティパッチのみを含み、新機能は含みません。
    *   稀に、メンテナンスチームの裁量で、メンテナンスモードのバージョンに対して最小限かつ影響の少ない変更を加えることがあります。

## Business Source License (BSL) とバージョンサポート

::: tip 注意

EMQX 5.9.0 以降のバージョンは Business Source License (BSL) 1.1 の下でライセンスされています。詳細は[公式発表](https://www.emqx.com/en/news/emqx-adopts-business-source-license)をご覧ください。

:::

### コミュニティユーザー

- コミュニティユーザーは、LTS ブランチを含むすべての EMQX バージョンを BSL 条件の下で利用可能です。
- ソフトウェアは保証なしで提供され、使用は自己責任となります。EMQX は利用に起因する問題や損害について責任を負いません。
- BSL では、指定された変更日（Change Date）後に EMQX のソースコードが完全なオープンソースライセンス（例：Apache 2.0）に移行します。これにより、コミュニティは長期メンテナンスの成果を含む完全なオープンバージョンにアクセス可能になります。
- 変更日前でも、コミュニティユーザーは該当する BSL バージョンに適用されるパッチリリース（バグ修正やセキュリティ更新）を受け取ることができます。

### エンタープライズ顧客

- 商用ライセンスおよびサブスクリプションを持つ顧客は、プレミアム機能および公式サポート（契約に定められたサービスレベル保証を含む）を受けられます。
- LTS バージョンにはエンタープライズ向けとして5年間のサポートコミットメントが提供されます。これにより、コードブランチが後に BSL 条件のオープンソースライセンスに移行しても、ミッションクリティカルな展開に対する継続的なメンテナンスとサポートが保証されます。

## アップグレードパスの推奨

最新機能、パフォーマンス改善、セキュリティアップデートを確実に利用するため、展開タイプに応じた定期的なアップグレード戦略を推奨します。

*   **EMQX Cloud:** EMQX チームが完全に管理し、ユーザーは月次の更新をシームレスに享受可能。
*   **オンプレミス Feature リリース:** 四半期ごとの Feature リリース間でアップグレードし、新機能を利用可能。サポート期間内（18か月以内）の Feature リリースを利用し続けることを推奨。
*   **オンプレミス LTS リリース:** エンタープライズユーザーは現在の LTS バージョンから次の LTS バージョンへの移行を計画し、長期サポートの継続を確保。Feature リリースから LTS リリースへのアップグレードもサポート。

各リリースには詳細なアップグレードガイドと互換性情報が含まれており、計画と実行を支援します。
