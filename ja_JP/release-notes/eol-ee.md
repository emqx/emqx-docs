# EMQX バージョンライフサイクルとサポート終了（EOL）日

EMQX は、迅速に変化する SaaS プラットフォームから大規模なエンタープライズ展開まで、幅広いユーザーに対応しています。これら多様なニーズに応えるため、EMQX はイノベーション、安定性、長期メンテナンスのバランスを取った多層的なリリースおよびサポートポリシーを採用しています。

本ライフサイクルポリシーは以下を目的としています：

- [EMQX Cloud](../get-started/concept.md#which-products-do-we-offer) における頻繁な内部アップデートによる迅速なイノベーションの支援
- オンプレミスユーザーに対して予測可能な四半期スケジュールで新機能を提供
- 指定された **Long-Term Support (LTS)** バージョンを通じたエンタープライズ顧客への長期安定性の提供
- バージョンのサポート期間および **End-of-Life (EOL)** の明確かつ予測可能なスケジュールの確保

3つの異なるリリース階層（Internal、Feature、LTS）を提供することで、EMQX はユーザーが最新機能への迅速なアクセスを重視するか、長期的なプラットフォーム安定性を重視するかに応じて、最適なバージョンのリリース頻度を選択できるようにしています。

## リリース階層とリリース頻度

迅速なイノベーションとエンタープライズレベルの安定性のバランスを取るため、EMQX は3層のリリースモデルを採用しています。

### Internal リリース

*   **頻度：** 月次。
*   **対象：** EMQX 内部チーム、EMQX Cloud、および見込み顧客。
*   **目的：** EMQX が管理する環境（例：EMQX Cloud、内部テスト、限定的なパブリックステージング）で新機能を迅速に提供・検証。Internal リリースは選定された顧客への早期アクセスも提供し、将来のパブリック Feature リリースの基盤となります。
*   **品質保証：** 公開ダウンロードはできませんが、EMQX Cloud を支えるために完全なQAを経ており、実運用に耐える品質です。実験的または不安定なものではありません。
*   **サポート：** Cloud 環境向けに EMQX チームが直接メンテナンス。オンプレミス顧客向けの直接提供はありません。

### Feature リリース（パブリック）

*   **頻度：** 四半期ごと（通常は3月、6月、9月、12月）。
*   **対象：** 最新の安定機能をタイムリーに利用したいオンプレミスユーザー。
*   **目的：** 最近の Internal リリースで検証された機能をパッケージ化し、一般的なオンプレミス利用向けに提供。
*   **サポート期間：** 初回リリース日から18ヶ月。

### Long-Term Support (LTS) リリース（パブリック）

*   **頻度：** 年次（通常は6月の Feature リリースが LTS 指定されます）。
*   **対象：** 最大の安定性と長期計画を必要とするミッションクリティカルなエンタープライズユーザー。
*   **目的：** 高度に安定化され、徹底的に検証されたバージョンを長期サポート付きで提供。
*   **サポート期間：** 初回リリースから3年（4.4.x は特例で5年間サポート）。

この階層的リリースモデルにより、機能は内部検証を経て成熟し、オンプレミス展開においてより高い安定性と品質を確保しています。

## バージョン番号付けと命名規則

EMQX はセマンティックバージョニング（`MAJOR.MINOR.PATCH`、例：`5.8.1`）を基盤とし、リリース階層ごとに特定の命名規則を設けています。

### メジャーリリース（例：`4.0.0`、`5.0.0`、`6.0.0`）

*   後方互換性のない変更を含む可能性のある大幅な更新を導入。
*   メジャーバージョン間の直接のインプレースアップグレードは原則サポートされません。通常は新規デプロイを構築し、設定やデータを手動で移行します。詳細は各メジャーバージョンの移行ガイドを参照してください。

### Internal リリース（例：`5.9.0-M3.202506`）

*   **形式：** `X.Y.Z-M[1-3].YYYYMM`（例：`5.9.0-M2.202505`、`5.9.1-M3.202506`）。
*   `X.Y` は開発中の次期または現行のパブリック Feature リリースのマイナーバージョンと連動。
*   `Z` は内部の反復に応じて増分。臨時の修正も含まれることがあります。

### Feature リリース（例：`5.7.0`、`5.9.0`、`5.10.0`）

*   新機能、改善、バグ修正を四半期ごとに提供するパブリックのマイナーリリース。
*   同一メジャーバージョン内の過去のマイナーリリース（例：`5.x`）と後方互換性（APIおよび機能）を維持し、クラスターのローリングアップグレードをサポート。
*   **形式：** `X.Y.0`。
*   `Y`（マイナーバージョン）は四半期ごとに増分。
*   **命名：** `EMQX Enterprise X.Y.0`。

### LTS リリース（例：`5.8.0`）

*   年次の Feature リリースのうち、Long-Term Support として指定されたもの。初回 LTS リリース（`X.Y.0`）はリリース時点での最新かつ安定した完全検証済みの機能セットを含む。
*   **形式：** `X.Y.0`。
*   **命名：** `EMQX Enterprise X.Y.0`。
*   LTS ステータスはドキュメントおよび公式ダウンロードページで明示されます。

### パッチリリース（例：`5.8.1`、`5.9.2`）

*   重大なバグ修正およびセキュリティパッチのみを含む。
*   新機能や破壊的変更は含みません。
*   発行対象：
    *   **Feature リリース：** 初回リリース（`X.Y.0`）から18ヶ月のサポート期間中、そのマイナーリリースライン（例：`5.9.x`）に適用される重大なバグ修正およびセキュリティ脆弱性修正。
    *   **LTS リリース：** 3年間のサポート期間中、その LTS リリースラインに適用される重大なバグ修正およびセキュリティ脆弱性修正。

## メンテナンスポリシー

EMQX のリリースは種類やライフサイクル段階に応じて異なるメンテナンスが行われます。

*   **Internal リリース：**
    *   EMQX チームがメンテナンスを担当。発見されたバグは通常、次回の内部リリースや Cloud 環境内のホットフィックスで対応されます。これらの修正は dev ブランチに統合され、将来のパブリックリリースに反映されます。
*   **Feature リリース（パブリック）：**
    *   新機能や改善は四半期ごとの Feature マイナーリリース（例：5.9.0、5.10.0）で提供。18ヶ月のサポート期間中は、各 Feature リリースライン（例：5.9.x）に対し、該当する重大なバグ修正およびセキュリティパッチがパッチリリース（例：5.9.1、5.9.2）で提供されます。
    *   対象ユーザーは新機能の迅速な利用を望み、短期間のサポートサイクルを許容するユーザーです。
*   **Long-Term Support (LTS) リリース（パブリック）：**
    *   **初回 LTS リリース（例：5.8.0）：** 最新の安定機能セットでリリース。
    *   **以降の LTS パッチリリース（例：5.8.1、5.8.2）：** 3年間のライフサイクル中、以下のアップデートを提供：
        *   重大なバグ修正
        *   セキュリティ脆弱性パッチ
        *   **重要な注意点：** 最大の安定性を確保するため、LTS のパッチリリース（`X.Y.Z`）では新機能の追加は行いません。
    *   対象ユーザーはシステムの安定性、予測可能性、長期サポートを厳格に要求するエンタープライズ顧客や、展開後の変更を最小限に抑えたいシナリオです。
*   **パッチリリース：**
    *   例：5.10.1、5.10.2 はバグ修正とセキュリティパッチのみを含み、新機能は含みません。
    *   まれに、メンテナンスチームの裁量で、移行を支援するための最小限かつ影響の少ない変更がメンテナンスモードのバージョンに追加されることがあります。

## Business Source License (BSL) とバージョンサポート

::: tip 注意

EMQX バージョン 5.9.0 以降は Business Source License (BSL) 1.1 の下でライセンスされています。詳細は[公式発表](https://www.emqx.com/en/news/emqx-adopts-business-source-license)をご覧ください。

:::

### コミュニティユーザー

- コミュニティユーザーは、LTS ブランチを含むすべての EMQX バージョンを BSL 条件の下で利用できます。
- ソフトウェアは無保証で提供されており、使用は自己責任です。EMQX は使用に起因する問題や損害について一切責任を負いません。
- BSL の下では、指定された変更日以降にソースコードが完全なオープンソースライセンス（例：Apache 2.0）に移行します。これにより、コミュニティは長期メンテナンスの成果を含む完全なオープンバージョンにアクセス可能になります。
- 変更日前でも、関連する BSL バージョンに適用されるパッチリリース（バグ修正やセキュリティアップデート）を受け取ることができます。

### エンタープライズ顧客

- 商用ライセンスおよびサブスクリプション契約を持つ顧客は、プレミアム機能と公式サポート（契約に定められたサービスレベル保証を含む）を受けられます。
- LTS バージョンにはエンタープライズ向けに5年間のサポートコミットメントが提供されます。これにより、コードブランチが後に BSL 条件のオープンソースライセンスに移行しても、ミッションクリティカルな展開に対する継続的なメンテナンスとサポートが保証されます。

## アップグレードパス推奨

最新機能、パフォーマンス改善、セキュリティアップデートを確実に利用するため、展開タイプに応じて以下の定期的なアップグレード戦略を推奨します。

*   **EMQX Cloud：** EMQX チームが完全に管理し、ユーザーは月次アップデートをシームレスに享受可能。
*   **オンプレミス Feature リリース：** 四半期ごとの Feature リリース間でアップグレードし、新機能を利用可能。サポート期間内（18ヶ月以内）の Feature リリースを利用し続けることを推奨。
*   **オンプレミス LTS リリース：** エンタープライズユーザーは現在の LTS バージョンから次の LTS バージョンへの移行を計画し、長期サポートの継続を確保。Feature リリースから LTS へのアップグレードもサポート。

各リリースには詳細なアップグレードガイドと互換性情報が含まれており、計画と実行を支援します。
