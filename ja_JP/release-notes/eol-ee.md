# EMQX バージョンライフサイクルとサポート終了（EOL）日

EMQX は、迅速に変化する SaaS プラットフォームから大規模なエンタープライズ展開まで、幅広いユーザーに対応しています。これら多様なニーズに応えるため、EMQX はイノベーション、安定性、長期メンテナンスのバランスを取った多層的なリリースおよびサポートポリシーを採用しています。

本ライフサイクルポリシーは以下を目的としています：

- [EMQX Cloud](../get-started/concept.md#which-products-do-we-offer) における頻繁な内部アップデートによる迅速なイノベーションの支援
- オンプレミスユーザー向けに予測可能な四半期スケジュールで新機能を提供
- 指定された **Long-Term Support (LTS)** バージョンによるエンタープライズ顧客への長期安定性の提供
- バージョンのサポート期間および **End-of-Life (EOL)** の明確かつ予測可能なスケジュールの確保

3つの異なるリリース階層（Internal、Feature、LTS）を提供することで、EMQX はユーザーが最新機能への迅速なアクセスを重視するか、長期的なプラットフォームの安定性を重視するかに応じて最適なバージョン選択を可能にしています。

## リリース階層とリリース頻度

迅速なイノベーションとエンタープライズ品質の安定性の両立を目指し、EMQX は3層のリリースモデルを採用しています。

### Internal リリース

*   **頻度:** 月次
*   **対象:** EMQX 内部チーム、EMQX Cloud、見込み顧客
*   **目的:** EMQX が管理する環境（例：EMQX Cloud、内部テスト、限定的なパブリックステージング）で新機能を迅速に提供・検証。Internal リリースは選定された顧客への早期アクセスも提供し、将来のパブリック Feature リリースの基盤となります。
*   **品質保証:** 公開ダウンロードは不可ですが、EMQX Cloud の基盤として使用され、完全な QA を経て本番運用に耐える品質を保証。実験的または不安定なものではありません。
*   **サポート:** Cloud 環境向けに EMQX チームが直接メンテナンス。オンプレミス顧客向けの直接提供はありません。

### Feature リリース（パブリック）

*   **頻度:** 四半期ごと（通常は3月、6月、9月、12月）
*   **対象:** 最新の安定機能をタイムリーに利用したいオンプレミスユーザー
*   **目的:** 最近の Internal リリースで検証された機能をパッケージ化し、一般的なオンプレミス利用に提供
*   **サポート期間:** 初回リリース日から18ヶ月間

### Long-Term Support (LTS) リリース（パブリック）

*   **頻度:** 年次（通常は6月の Feature リリースが LTS 指定される）
*   **対象:** 最大の安定性と長期計画が求められるミッションクリティカルなエンタープライズユーザー
*   **目的:** 高度に安定化・検証されたバージョンを長期サポート付きで提供
*   **サポート期間:** 初回リリースから3年間（4.4.x は移行期間中の特例として5年間サポート）

この階層的リリースモデルにより、機能は内部検証を経て成熟し、オンプレミス展開においてより高い安定性と品質を確保しています。

## バージョン番号と命名規則

EMQX は Semantic Versioning（`MAJOR.MINOR.PATCH`、例：`5.8.1`）を基盤とし、リリース階層ごとに特定の命名規則を設けています。

### Major リリース（例：`4.0.0`、`5.0.0`、`6.0.0`）

*   後方互換性のない変更を含む可能性のある大規模な更新を導入
*   Major バージョン間の直接アップグレードは一般的にサポートされません。新規デプロイの構築と設定・データの手動移行が必要です。各 Major バージョンの移行ガイドを参照してください。

### Internal リリース（例：`5.9.0-M3.202506`）

*   **フォーマット:** `X.Y.Z-M[1-3].YYYYMM`（例：`5.9.0-M2.202505`、`5.9.1-M3.202506`）
*   `X.Y` は開発中の次期または現行のパブリック Feature リリースのマイナーバージョンと対応
*   `Z` は内部反復で増分。臨時修正が適用される場合もあります。

### Feature リリース（例：`5.7.0`、`5.9.0`、`5.10.0`）

*   新機能、改善、バグ修正を四半期ごとに提供するパブリックマイナーリリース
*   同一 Major バージョン内の過去のマイナーリリース（例：`5.x`）と後方互換性（API・機能）を保持し、ローリングクラスターアップグレードをサポート
*   **フォーマット:** `X.Y.0`
*   `Y`（マイナーバージョン）は四半期ごとに増分
*   **命名:** `EMQX Enterprise X.Y.0`

### LTS リリース（例：`5.8.0`）

*   年次の Feature リリースのうち、Long-Term Support として指定されたもの。初回 LTS リリース（`X.Y.0`）はリリース時点での最新かつ完全に検証済みの安定機能セットを含む
*   **フォーマット:** `X.Y.0`
*   **命名:** `EMQX Enterprise X.Y.0`
*   LTS ステータスはドキュメントおよび公式ダウンロードページで明示

### パッチリリース（例：`5.8.1`、`5.9.2`）

*   重大なバグ修正およびセキュリティパッチのみを含む
*   新機能や破壊的変更は含まない
*   発行対象：
    *   **Feature リリース:** 初回リリース（`X.Y.0`）から18ヶ月のサポート期間内の各 Feature マイナーリリースラインに対し、そのリリースラインに該当する重大なバグ修正・セキュリティパッチを提供
    *   **LTS リリース:** 3年間のサポート期間中、該当する LTS リリースラインに対し重大なバグ修正・セキュリティパッチを提供

## メンテナンスポリシー

EMQX のリリースは種類とライフサイクル段階に応じて異なるメンテナンスを受けます。

*   **Internal リリース:**
    *   EMQX チームが対応。発見されたバグは通常、次回の内部反復や Cloud 環境内のホットフィックスで修正され、これらは dev ブランチにマージされ将来のパブリックリリースに反映されます。
*   **Feature リリース（パブリック）:**
    *   新機能や改善は四半期ごとの Feature マイナーリリース（例：5.9.0、5.10.0）で提供。18ヶ月のライフサイクル期間中は、各 Feature リリースライン（例：5.9.x）に対し、該当する重大なバグ修正・セキュリティパッチをパッチリリース（例：5.9.1、5.9.2）で提供。
    *   対象ユーザーは新機能への迅速なアクセスを望み、短期サポートサイクルを許容するユーザー。
*   **Long-Term Support (LTS) リリース（パブリック）:**
    *   **初回 LTS リリース（例：5.8.0）:** 最新の安定機能セットを含む形でリリース。
    *   **以降の LTS パッチリリース（例：5.8.1、5.8.2）:** 3年間のライフサイクル期間中、以下の更新を提供：
        *   重大なバグ修正
        *   セキュリティ脆弱性パッチ
        *   **重要:** LTS のパッチリリース（X.Y.Z）は新機能を導入しません。
    *   対象ユーザーはシステムの安定性、予測可能性、長期サポートを厳格に求めるエンタープライズ顧客や、デプロイ後の変更を最小限に抑えたいケース。
*   **パッチリリース:**
    *   例：5.10.1、5.10.2 はバグ修正とセキュリティパッチのみ。新機能は含みません。
    *   稀に、メンテナンス中のバージョンの新バージョン移行を支援するため、メンテナンスチームの裁量で最小限かつ非破壊的な変更を加える場合があります。

## Business Source License (BSL) とバージョンサポート

::: tip 注意事項

EMQX 5.9.0 以降のバージョンは Business Source License (BSL) 1.1 の下でライセンスされています。詳細は[公式発表](https://www.emqx.com/en/news/emqx-adopts-business-source-license)をご覧ください。

:::

### コミュニティユーザー

- コミュニティユーザーは LTS ブランチを含むすべての EMQX バージョンを BSL 条件の下で利用可能です。
- ソフトウェアは無保証で提供され、使用に伴う問題や損害に対して EMQX は責任を負いません。
- BSL の変更日以降、EMQX のソースコードは Apache 2.0 などの完全なオープンソースライセンスに移行し、長期メンテナンスの成果を含む完全版がコミュニティに提供されます。
- 変更日前でも、該当する BSL バージョンに対するパッチリリース（バグ修正・セキュリティ更新）を受け取ることが可能です。

### エンタープライズ顧客

- 商用ライセンスおよびサブスクリプション契約により、プレミアム機能と公式サポート（サービスレベル保証を含む）を受けられます。
- LTS バージョンには 5 年間のサポートコミットメントが提供され、ミッションクリティカルな展開に対する継続的なメンテナンスとサポートが保証されます。コードブランチが後に BSL 条件下のオープンソースライセンスに移行してもこのサポートは継続されます。

## アップグレードパス推奨

最新機能、性能改善、セキュリティ更新へのアクセスを確保するため、展開形態に応じた定期的なアップグレード戦略を推奨します。

*   **EMQX Cloud:** EMQX チームが完全に管理し、ユーザーは月次アップデートをシームレスに享受可能。
*   **オンプレミス Feature リリース:** 四半期ごとの Feature リリース間でアップグレードし、新機能を利用。18ヶ月のサポート期間内の Feature リリースを利用し続けることが推奨されます。
*   **オンプレミス LTS リリース:** エンタープライズユーザーは現在の LTS バージョンから次の LTS への移行を計画し、長期サポートの継続を確保。Feature リリースから LTS へのアップグレードもサポートされています。

各リリースには詳細なアップグレードガイドと互換性に関する注意事項が付属し、計画と実行を支援します。
