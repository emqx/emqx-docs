# EMQX Enterprise Version 4

## e4.4.38

*リリース日: 2026-09-01*

### 強化点

- ダッシュボードユーザーに対して、カテゴリ別の細粒度な権限管理をサポートしました。

  以前は、ダッシュボードユーザーは `administrator`（全権限）と `viewer`（読み取り専用）の2つのロールのみでした。

  本リリースでは、9つのカテゴリに基づく権限モデルを導入しました：

  - 既存の6つのビジネスカテゴリ：`banned`、`rule_engine`、`resources`、`plugins`、`modules`、`others`。これらはAPIキーとダッシュボードユーザーの両方に適用されます。
  - ダッシュボードユーザーのみに適用される新規3カテゴリ：`user_management`（他のダッシュボードアカウント管理）、`mfa_management`（他ユーザーのMFA管理）、`app_management`（APIキー管理）。

  ダッシュボードユーザーの権限を絞るには、ユーザーの `tags` フィールドに `scopes` 配列を設定します。明示的な `scopes` フィールドがないユーザーはアップグレード前の動作を維持します：

  - 管理者はすべてのエンドポイントにアクセス可能。
  - ビューアーはバックアップアーカイブのダウンロードを除くすべての読み取り専用エンドポイントにアクセス可能。

  `scopes` が設定されている場合、以下のルールが適用されます：

  - 明示的な `scopes` を持つ管理者は、そのスコープに限定されて読み書き操作が可能。管理者の明示的スコープリストは強制されます。
  - ビューアーは引き続き読み取り専用。他ユーザーのリソースに対するGET以外のリクエストはスコープに関わらず拒否されます。
  - ビューアーは `user_management` または `app_management` を持てず、デフォルトのビューアースコープはこれらのカテゴリと `mfa_management` を除外します。ビューアーにおける `mfa_management` は自己のMFAロック免除のみ許可し、他ユーザーのMFA管理は不可です。
  - GETリクエストはスコープチェックされ、マッピングされていないAPIパスはスコープ制限ユーザーに対して拒否（fail-closed）されます。空のスコープリストは自己サービス（自身のパスワード、MFA、ログアウト）以外のすべてのアクセスを拒否します。
  - 自己サービスパスは `scopes` に影響されず、ビューアーは常に自身のパスワード変更、MFA管理、ログアウトが可能です。
  - ビューアーはバックアップアーカイブ（`/api/v4/data/file/*`）をダウンロードできなくなりました。バックアップにはダッシュボードユーザーパスワードハッシュ、TOTPシークレット、APIキー認証情報が含まれるためです。エクスポート一覧（`/data/export`）はビューアーに引き続き利用可能です。

  `dashboard.default_user.login` で設定されたデフォルト管理者アカウントは追加保護されており、降格不可、明示的な `scopes` 設定不可、削除不可です。

- SAML SSOバックエンドでユーザーごとの `force_mfa` オーバーライドをサポートしました。

  以前は各SAMLバックエンドの `force_mfa` フラグがすべてのユーザーに一律適用され、個別調整はできませんでした。

  本リリースでは、ダッシュボードユーザーの `tags` フィールドに内部状態 `admin_override` を追加しました。この状態は管理者が既存エンドポイントで他ユーザーのMFAを有効/無効にした際に暗黙的に管理されます。

  `admin_override` の意味は以下の通りです：

  - `admin_override = mfa_required`：バックエンドの `force_mfa` 設定に関わらず、SSOログイン時にMFAを必須とします。
  - `admin_override = mfa_exempted`：バックエンドの `force_mfa` 設定に関わらず、SSOログイン時にMFAをスキップ可能とします。
  - 未設定（デフォルト）：バックエンドの `force_mfa` 設定が適用されます。

  自己サービスによるMFA変更は `admin_override` を変更せず、元の意味を保持します。

  **ローリングアップグレード注意**：本リリースに未アップグレードの古いノードがクラスター内に存在する間は、`admin_override = mfa_required` は古いノードでは効果を持ちません。古いノードはバックエンドの `force_mfa` のみを尊重します。`admin_override = mfa_exempted` は既存の `disable_mfa` プレースホルダ経路を通じて古いノードでも効果を持ち続けます。

- `emqx_ctl log-throttling` によるログスロットリングのランタイム制御を追加しました。

  以前はグローバルスロットル制限、時間ウィンドウ、レベルは設定ファイルでのみ設定可能でした。新しい `log-throttling` コマンドグループは以下の操作をサポートします：

  - ローカルノードの現在設定を `log-throttling print`、全ノードで `log-throttling print-cluster` で確認。
  - グローバルスロットル制限、時間ウィンドウ、レベルをそれぞれ `log-throttling limit set <Limit>`、`log-throttling window set <Duration>`、`log-throttling level set <Level>` で更新。クラスタ全体適用は対応する `set-cluster` バリアントを使用。
  - 特定ログ行に独立したスロットル制限を設定可能。例：`log-throttling line-limit set '<Mod:Ln,...>' <Limit>`。例 `'emqx_channel:1551,emqx_username_quota:245' 0` は該当2行を完全にサイレント化し、他はグローバル制限を維持。クラスタ全体適用は `line-limit set-cluster` を使用。
  - 行単位のオーバーライド削除は `log-throttling line-limit del '<Mod:Ln,...>'`、クラスタ全体は `del-cluster`。

  行番号はリリース間で変動するため、行単位制限はランタイム限定で設定ファイルには永続化されません。ログ行の頻度調整に一時的に利用してください。

- デフォルトのログスロットリング設定を `50,60s` から `5,60s` に変更しました。各スロットラーは60秒間に最大5回の重複ログを許容し、それ以降はドロップ＆集約します。高頻度ログの洪水を軽減します。

- ユーザーネームクォーターモジュールは新たなノード間同期機構を採用し、クラスター性能と安定性を向上しました。

  本リリースではMnesiaレプリケーションを廃止し、ノード毎のETSテーブルと専用RPCチャネルに基づくストリーミング設計に置き換えました。これによりクラスター参加時のメモリ使用量とリソース消費を削減し、同期処理経路の過負荷保護も追加されました。非推奨の `refresh_username_tab_interval` 設定は削除されました。

- ノードの `net_ticktime` のデフォルトを120秒から60秒に短縮しました。

  高負荷時、遅延または停止したノードへのRPCチャネルが混雑・ブロックし、キューイングされたメッセージがメモリ使用量を増加させOOMを引き起こす可能性があります。

  `net_ticktime` を60秒に短縮（`vm.args` の `-kernel net_ticktime` で設定）することで、クラスターは故障ノードをより早く検知・除去可能となり、RPCリクエストのブロック時間を短縮します。

- グローバルGC機構にメモリプレッシャー検知トリガーを追加しました。

  システムメモリ使用率が高水準（`os_mon.sysmem_high_watermark`）を超え、周期的GCが無効の場合、`emqx_os_mon` がメモリアラーム発生時にトリガー信号を送出し、スムーズなグローバルGCを実行してメモリ使用量を削減します。以下の設定で制御されます：

  - `node.global_gc_mem_pressure`（デフォルト `on`）：メモリプレッシャートリガーGCの有効化。
  - `node.global_gc_mem_pressure_min_interval`（デフォルト `5m`）：トリガーGC間の最小間隔（スロットリング用）。

- クラスター内ノード間リンクの健全性をPrometheusメトリクスで報告する `emqx_erpc_probe` プラグインを追加しました。

  各ノードはクラスター内の他ノードごとに独立したプローブプロセスを起動し、`erpc_probe.probe_interval`（デフォルト1秒）間隔で `erpc:call(Peer, erlang, node, [], Timeout)`（タイムアウトは `erpc_probe.probe_timeout`、デフォルト5秒）を送信します。

  プラグインは以下のPrometheusメトリクスを公開します：

  - `emqx_erpc_probe_result_total`（カウンター）：`result` ラベル別のプローブ結果数。値は `ok`、`timeout`、`noconnection`、`system_limit`。
  - `emqx_erpc_probe_duration_seconds`（ヒストグラム）：成功したプローブの往復時間。p99レイテンシなどで遅延検知に利用可能。

  新規インストールでは `data/loaded_plugins` によりデフォルト有効化。設定ファイルは `etc/plugins/emqx_erpc_probe.conf`。設定変更後はプラグイン再起動が必要です。

  既存クラスターはアップグレード後も `data/loaded_plugins` を保持し自動有効化されません。有効化は `./bin/emqx ctl plugins load emqx_erpc_probe` 実行、または `data/loaded_plugins` に `{emqx_erpc_probe, true}.` を追記しノード再起動で可能です。

### バグ修正

- バックアップ復元時にダッシュボードユーザーの明示的なスコープと `admin_override` が失われる問題を修正。

  バックアップインポート時にダッシュボードユーザーの `tags` の拡張フィールドをそのまま保持し、明示的な `scopes` やユーザーごとの `admin_override` を復元後も維持します。これによりロールデフォルトに戻る問題を解消しました。

- バックアップ関連エンドポイント（`/api/v4/data*`）がAPIキー認証でアクセス可能だった問題を修正。

  バックアップのエクスポート/インポートはAPIキー認証では拒否され、ダッシュボードログインセッションは影響を受けません。

- APIキー更新エンドポイントで入力検証を厳格化し、不正な値を拒否するようにしました。

  不明な権限キー、真偽値でない権限値、オブジェクトでなく配列が渡された `permissions`、非真偽値の `fallback` はHTTP 400を返します。部分更新時は省略されたフィールドを文字列 `undefined` で上書きせず既存値を維持します。

- SAML SSOの依存ライブラリ `esaml` をv1.1.5にアップグレードし、SAMLレスポンスやメタデータのXMLエンティティ展開を無効化。悪意あるSAML XMLによる外部・カスタムエンティティ展開を防止しました。

- SAML SSOコールバックで不正なDEFLATE圧縮レスポンスがHTTP 500を返していた問題を修正。現在はHTTP 400を返し、Cowboyリクエストプロセスは終了しません。

- RabbitMQのルールアクションで、異なる `durable` 設定で同一のエクスチェンジを2つ宣言した際に、すべてのキューバインディングが破壊される問題を修正。

  修正前は `exchange.declare` の `durable` 設定不一致時にブリッジがエクスチェンジを削除・再宣言し、既存のキューバインディングも消失していました。修正後は `durable` またはタイプ不一致時に明確なエラーメッセージ（`PRECONDITION_FAILED`）を返し、既存エクスチェンジとバインディングは保持されます。

- ゲートウェイ接続におけるピア証明書のCN/DNフィールドの検証を追加。

  以前はTLS証明書やPROXYプロトコルv2で取得したCN/DNに制御文字が含まれても検証されず、ログインジェクションのリスクがありました。制御文字を含むフィールドは拒否し接続を切断します。

- バックアップファイル名の検証を強化し、バックアップディレクトリ外へのパス脱出を防止。

  以前は拡張子のみ検証していたため、パス区切り文字や不正文字を含むファイル名でディレクトリ外に逃げるパス・トラバーサルが可能でした。現在は合法的なベース名かつ解決後のパスがバックアップディレクトリ内に収まることを要求します。

- ノード参加時に評価ライセンスがクラスターライセンスとして選択される可能性があった問題を修正。

  評価ライセンスと正式ライセンスが共存する場合、クラスター参加時のライセンス交渉で評価ライセンスが選ばれることがありました。現在は非評価ライセンスを優先します。

- クラスター参加後、無効化されたモジュールのフックがクリアされず、モジュールが新ノード上で有効のままになる問題を修正。

  例えばRetainerモジュールがクラスターで無効化されていても、新規参加ノードでアクティブになることがありました。これによりサブスクリプション処理時にエラーが発生していました。現在は無効化されたモジュールは正しく停止され、フックもクリアされます。

- `$SYS` トピックの保持メッセージがワイルドカードサブスクリプションに配信される問題を修正。

  以前はワイルドカードフィルター（例：`#`）でサブスクライブしたクライアントに `$SYS` トピックの保持メッセージが届き、MQTT仕様違反でした。現在は `$SYS/#` のような具体的なトピックにサブスクライブしたクライアントのみに配信されます。

- 再パブリッシュルールアクションで元メッセージのMQTTプロパティが失われる問題を修正。

  以前はユーザープロパティなどのMQTTプロパティが転送時に失われていました。現在は保持されます。

- MQTTブリッジの接続関連設定の検証不足を修正。

  プールサイズが正の値でない、再接続間隔が不正などの設定が静かに適用されたり不明瞭なエラーを起こしていました。現在は検証され、不正設定は明確なエラーとなります。

- 不正な設定でリソース作成時にREST APIが `emqx_rule_engine_api` をクラッシュさせ、ルールエンジンアプリケーションがシャットダウンする問題を修正。

  例えば `bridge_mqtt` リソース作成時に必須フィールド `clientid` が欠落すると例外が発生し、APIプロセスがクラッシュしていました。現在はHTTP 400クライアントエラーを返し、APIプロセスは影響を受けません。

- 監査ログでHTTP APIパスバインディングがURLデコードされていなかった問題を修正。

  以前は監査ログにURLエンコードされたままのパスバインディングが記録され、リスト形式の値が正しく保存されないことがありました。現在はデコード・正規化されたパスバインディングが記録されます。

- ホットコンフィグインポートで不正な設定を受け入れていた問題を修正。

  現在はインポート前に検証し、不正値はエラーを返して適用されません。

- バックアップインポート後に `loaded-modules` レコードが更新されない問題を修正。

  以前はモジュール設定を含むバックアップインポート後に `data/loaded_modules` ファイルが更新されず、再起動後にインポート状態と異なるモジュールがロードされることがありました。現在はインポート後にレコードを更新します。

- Prometheusに報告されるCPU使用率メトリクスの不正確さを修正。

  以前は `cpu_sup:util` の初回呼び出しが不安定で、Prometheusが不正確な `cpu_use` と `cpu_idle` を取得していました。現在は長寿命の `emqx_os_mon` プロセス経由で収集し、正確な値を報告します。

- クラスター間で転送されるMQTTメッセージの順序が乱れる問題を修正。

  以前は同一クライアントが同一トピックに連続パブリッシュしたメッセージが、異なるノード間で順序が乱れて配信されることがありました。クロスノード転送に `gen_rpc:cast` を使用していたため、受信側で並列ワーカーがランダムに処理し順序が失われていました。現在は `gen_rpc:ordered_cast` を使用し、到着順に処理することでクライアント単位のメッセージ順序を復元します。

- `emqx_ctl listeners restart http:dashboard`（および `https:dashboard`）が `undef` エラーで失敗していた問題を修正。

  ダッシュボードリスナーの `start_listener/1` と `stop_listener/1` 関数がエクスポートされていなかったため、再起動コマンドが失敗し、リスナー停止後にポート（例：18083）が使用不可のままでした。現在は両関数をエクスポートし、期待通り停止・起動します。

- `os_mon.memsup_system_only` が有効になっていなかった回帰を修正し、多数接続時のシステムメモリ使用率取得を高速化。

  以前の修正（e4.4.34）では `os_mon.memsup_system_only = true` を `emqx.os_mon` 環境に設定していたため、`memsup` は起動時に読む `os_mon` 環境に反映されず、全プロセスを走査し続けていました。現在は `os_mon` アプリケーション環境に直接マッピングし（デフォルト `true`）、`memsup` はシステムメモリのみを取得します。

## e4.4.36

*リリース日: 2026-05-22*

### 強化点

- ノードごとのライセンス情報をPrometheusメトリクスで公開。

  `emqx_license_max_sessions`、`emqx_license_expiry_at`、`emqx_license_issued_at` の3つのメトリクスを追加。タイムスタンプはUnixエポック秒（UTC）。ライセンス未取得時は全て `0` を返します。

- RabbitMQルールアクションでデフォルト（無名）エクスチェンジをサポート。

  `exchange` パラメータは必須でなくなり、空文字 `""` がデフォルト。空の場合、ルールアクションはデフォルトのダイレクトエクスチェンジ経由でパブリッシュし、`routing_key` と同名のキューにルーティングされます。このモードではブリッジは `exchange.declare` / `exchange.delete` を実行しません。詳細は [RabbitMQ: Default Exchange](https://www.rabbitmq.com/docs/exchanges#default-exchange) を参照。

- Erlang VMのスケジューラロードコンパクションをデフォルトで無効化。

  `vm.args` に `+scl false` を設定し、スケジューラの安定性向上と負荷遷移時のメッセージレイテンシ低減を図りました。

  ただし、一部CPUトポロジーでは低負荷時にCPU使用率が増加する可能性があります。必要に応じて `+scl true` で再有効化したり、スケジューラ数削減、CPUハイパースレッディング無効化、単一NUMAノードのCPUコアバインドなどで調整可能です。

- MQTT接続ヒープメモリ制限更新時のパフォーマンスを最適化。

  ClientIDのログトレース有効化後、過剰ログによるプロセス終了を防ぐため、該当MQTT接続プロセスのヒープメモリ制限を調整します。この最適化で、設定更新時のGC誘発によるパフォーマンス低下を避けるため、`persistent_term` ではなくETSを使用します。

- Erlang分散通信ポートバッファ関連の設定項目を追加し、デフォルト値を増加。クラスター安定性を向上。

  以前のデフォルトは1460Bでしたが、ネットワークレイテンシやメッセージ量増加に対応し、RPCレイテンシを大幅に削減。設定例：

  ```hocon
  node.dist_connect_options.nodelay = false
  node.dist_connect_options.sndbuf = 1MB
  node.dist_connect_options.recbuf = 1MB
  node.dist_connect_options.buffer = 1MB
  node.dist_listen_options.nodelay = false
  node.dist_listen_options.sndbuf = 1MB
  node.dist_listen_options.recbuf = 1MB
  node.dist_listen_options.buffer = 1MB
  ```

- ホットアップグレードスクリプトのタイムアウトを5分から25分に延長。

  旧バージョンのスクリプトを使用するため、新しいデフォルトタイムアウトは本バージョンから上位へのアップグレード時にのみ有効です。

- ノード避難/リバランス機能およびクラスター分散ロック（`ekka_locker`）のマルチノード呼び出しで `rpc` を `erpc` に置換し、高負荷時の性能と安定性を向上。

- Erlang/OTPを24.3.4.17-2にアップグレード。

  Erlang/OTPの修正はホットアップグレードでは適用されず、EMQX再起動後に有効となります。

### バグ修正

- 不安定なネットワーク環境下でのEMQXクラスターの自己修復失敗を修正。

- Redis Sentinel接続で、RedisデータノードとSentinelノードに別々の認証設定を適用可能に修正。

- 一部HTTP APIでRPC自己呼び出し問題を修正。

## 4.4.25

*リリース日: 2024-09-13*

### 強化点

  `gen_tcp:send/2` の制限により、Redisクライアントプロセスの送信キューが増加すると送信性能が低下し、ボトルネックとなっていました。Redis認証/ACL、Redisプラグイン、Redisルールエンジンアクションの送信性能を改善。大量デバイス再接続時の負荷を軽減。

- 「内部DB AUTH/ACL」モジュールのACL機能を改善。

  - 1クライアントあたりのACLエントリ数制限を追加。ACL検証時に大量エントリがあるとパフォーマンス低下するため、`auth.mnesia.max_acls_for_each_login` 設定またはモジュールの `Max ACLs` パラメータで制限可能。
  - ACLテーブルの格納構造とトピックマッチングロジックを最適化し、検索・マッチング性能を向上。ACLエントリ数が多いほど効果大。
  - ACLエントリの追加・削除時にACLキャッシュをリセット。

- ルールエンジンのバッチ送信処理に過負荷保護を追加。

  バッチ送信時に外部DB応答が遅いとメッセージがバッチプロセスのメッセージキューに蓄積し、メモリ制限超過リスクあり。メッセージキューサイズが `"最大バッチサイズ" * 10`（1000未満は1000）を超えるとアクションを一定期間（デフォルト60秒）「アンロード」し、その間のメッセージは破棄。`action_olp_blocked/<RuleID>/<ActionID>` アラームを発報。

  過負荷保護対象アクション例：

  - Cassandra、ClickHouse、DolphinDB、InfluxDB、IoTDB、Lindorm、MySQL、Oracle、PostgreSQL、SQLServer、Tablestore、TDengine、GCP Pubsub

- 未定義値をデータベースに `NULL` として挿入するオプションを追加。

  ルールエンジンの各種DBアクションで `${var}` プレースホルダー使用時、変数が未定義の場合に文字列 `undefined` ではなく `NULL` を挿入可能に。

- ログスロットリングをサポート。

  異常時に大量の重複ログが発生しシステム負荷増大や有用ログの埋没を防止。`etc/logger.conf` の `log.throttling` 設定で時間ウィンドウと最大ログレートを指定可能。

  CPUコア数分のスロットラーを起動し、例：`log.throttling = 50,60s` なら各スロットラーは60秒間に同一ログ（モジュール名＋行番号）を最大50回制限。8コアなら最大400回/分程度のログ出力。ドロップ時は以下ログを出力：

  ```
  log throttled during last 60s, dropped_msg: #{{emqx_channel,1400} => #{msg => "Client ~s (Username: '~s') login failed for ~0p", count => 33}}
  ```

  デフォルトで警告以上のログレベルに有効化、設定は `50,60s`。

- HTTP/HTTPS管理インターフェースのタイムアウト設定を追加。

  `etc/plugins/emqx_management.conf` に以下設定を追加：

  - `management.listener.<Proto>.request_timeout`：TCP接続確立後、HTTPリクエスト受信なしで切断するまでの時間（デフォルト5秒）。
  - `management.listener.<Proto>.idle_timeout`：HTTPリクエスト受信後、追加リクエストなしで切断するまでのアイドルタイムアウト（デフォルト60秒）。

  `<Proto>` は `http` または `https`。

- 「再パブリッシュ」アクションのターゲットトピック検証を追加。

  非UTF-8バイナリのトピック指定は失敗。

- Redis-Clusterドライバの性能を最適化。

  Redis Clusterアクセス時のメモリフットプリントを削減。影響対象はRedis認証/ACL、Redisプラグイン、ルールエンジンのRedisアクション。
