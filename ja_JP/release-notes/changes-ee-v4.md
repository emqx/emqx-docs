# EMQX Enterprise Version 4

## e4.4.38

*リリース日: 2026-09-01*

### 強化点

- ダッシュボードユーザーはカテゴリ別の細粒度な権限管理をサポートするようになりました。

  以前は、ダッシュボードユーザーには `administrator`（全権限）と `viewer`（読み取り専用）の2つの役割のみがありました。

  本リリースでは、9つのカテゴリによる権限モデルを導入しました：

  - 既存の6つのビジネスカテゴリ：`banned`、`rule_engine`、`resources`、`plugins`、`modules`、`others`。これらはAPIキーとダッシュボードユーザーの両方に適用されます。
  - ダッシュボードユーザーのみに適用される新たな3つのカテゴリ：`user_management`（他のダッシュボードアカウント管理）、`mfa_management`（他ユーザーのMFA管理）、`app_management`（APIキー管理）。

  ダッシュボードユーザーの権限を絞るには、ユーザーの `tags` フィールドに `scopes` 配列を設定します。`scopes` フィールドが明示的にないユーザーはアップグレード前の挙動を維持します：

  - 管理者はすべてのエンドポイントにアクセス可能。
  - ビューアはバックアップアーカイブのダウンロードを除くすべての読み取り専用エンドポイントにアクセス可能。

  `scopes` が設定されている場合、以下のルールが適用されます：

  - 明示的な `scopes` を持つ管理者は、そのスコープに限定され、読み書き操作ともにスコープリストが厳格に適用されます。
  - ビューアは読み取り専用のままです。スコープに関係なく他ユーザーのリソースへの非GETリクエストは拒否されます。
  - ビューアは `user_management` や `app_management` を持てず、デフォルトのビューアスコープはこれらのカテゴリと `mfa_management` を除外します。ビューアにおける `mfa_management` は強制MFAロックからの自己免除のみを許可し、他ユーザーのMFA管理はできません。
  - GETリクエストはスコープチェックされ、スコープ制限ユーザーはマッピングされていないAPIパスは拒否されます（フェイルクローズ）。空のスコープリストは自己サービス（自身のパスワード、MFA、ログアウト）以外すべて拒否します。
  - 自己サービスパスは `scopes` に影響されず、ビューアは常に自身のパスワード変更、MFA管理、ログアウトが可能です。
  - ビューアはバックアップアーカイブ（`/api/v4/data/file/*`）のダウンロードができなくなりました。バックアップにはダッシュボードユーザーパスワードハッシュ、TOTPシークレット、APIキー認証情報が含まれるためです。エクスポート一覧（`/data/export`）はビューアに引き続き利用可能です。

  `dashboard.default_user.login` で設定されたデフォルト管理者アカウントは追加で保護されており、降格、明示的な `scopes` 設定、削除はできません。

- SAML SSOバックエンドはユーザー単位の `force_mfa` オーバーライドをサポートしました。

  以前は各SAMLバックエンドの `force_mfa` フラグが全ユーザーに一律適用され、個別調整はできませんでした。

  本リリースでは、ダッシュボードユーザーの `tags` フィールドに内部状態 `admin_override` を追加しました。管理者が既存のエンドポイントで他ユーザーのMFAを有効化/無効化すると、この状態が暗黙的に維持されます。

  `admin_override` の意味は以下の通りです：

  - `admin_override = mfa_required`：バックエンドの `force_mfa` 設定に関係なく、SSOログイン時にMFAが必須。
  - `admin_override = mfa_exempted`：バックエンドの `force_mfa` 設定に関係なく、SSOログイン時にMFAをスキップ可能。
  - 未設定（デフォルト）：バックエンドの `force_mfa` 設定が適用される。

  自己サービスによるMFA変更は `admin_override` を変更せず、元の意味を保持します。

  **ローリングアップグレード注意**：本リリースに未アップグレードの古いノードがクラスターに存在する間は、`admin_override = mfa_required` は古いノードで効果を持ちません。古いノードは引き続きバックエンドの `force_mfa` 設定のみを尊重します。`admin_override = mfa_exempted` は既存の `disable_mfa` プレースホルダ経路を通じて古いノードでも効果を持ち続けます。

- `emqx_ctl log-throttling` によるログスロットリングのランタイム制御を追加しました。

  以前はグローバルのスロットル制限、時間窓、レベルは設定ファイルでのみ設定可能でした。新しい `log-throttling` コマンドグループは以下をサポートします：

  - ローカルノードの現在設定を `log-throttling print`、クラスタ全体は `log-throttling print-cluster` で表示。
  - グローバルスロットル制限、時間窓、レベルを `log-throttling limit set <Limit>`、`log-throttling window set <Duration>`、`log-throttling level set <Level>` で更新。クラスタ全体は対応する `set-cluster` コマンドで適用。
  - 特定ログ行の独立スロットル制限を `log-throttling line-limit set '<Mod:Ln,...>' <Limit>` で設定。例：`'emqx_channel:1551,emqx_username_quota:245' 0` は該当行を完全に無効化し、他はグローバル制限を維持。クラスタ全体は `set-cluster` 版を使用。
  - 行単位のオーバーライド削除は `log-throttling line-limit del '<Mod:Ln,...>'`、クラスタ全体は `del-cluster`。

  行番号はリリース間で変動するため、行単位制限はランタイムのみで設定ファイルに永続化されません。ログ行が多すぎる・少なすぎる場合の一時調整に利用してください。

- デフォルトのログスロットリング設定を `50,60s` から `5,60s` に変更しました。各スロットラーは60秒間に最大5回の重複ログを許可し、それ以降はドロップ・集約します。これにより高頻度ログの洪水を軽減します。

- ユーザー名クォーターモジュールは新しいノード間同期機構を採用し、クラスターの性能と安定性を向上しました。

  本リリースではMnesiaレプリケーションを廃止し、ノード毎のETSテーブルと専用RPCチャネルによるストリーミング設計に置き換えました。この新機構はクラスター会員変更時のメモリ使用量とリソース消費を削減し、同期・処理経路の過負荷保護も追加します。非推奨の `refresh_username_tab_interval` 設定は削除されました。

- デフォルトノードの `net_ticktime` を120秒から60秒に短縮しました。

  高負荷時に遅いまたは停止したノードへのRPCチャネルが混雑・ブロックし、キューに溜まったメッセージがメモリ使用量を増大させOOMを引き起こす可能性があります。

  `net_ticktime` を60秒に短縮（`vm.args` の `-kernel net_ticktime` で設定）することで、クラスターは障害ノードをより早く検知・削除可能となり、RPCリクエストがブロックされる時間窓を短縮します。

- グローバルGC機構をメモリプレッシャー検知によるGCトリガーで強化しました。

  システムメモリ使用率が高水準（`os_mon.sysmem_high_watermark`）を超え、周期的GCが無効な場合、`emqx_os_mon` がメモリアラーム発生時にトリガー信号を発し、スムーズなグローバルGCを実行してメモリ使用量を削減します。以下の設定で制御可能です：

  - `node.global_gc_mem_pressure`（デフォルト `on`）：メモリプレッシャー検知GCの有効化。
  - `node.global_gc_mem_pressure_min_interval`（デフォルト `5m`）：トリガー間の最小間隔（スロットリング用）。

- ノード間ネットワークヘルスプローブプラグイン `emqx_erpc_probe` を追加しました。クラスター内ノード間リンクの健全性をPrometheusメトリクスで報告します。

  各ノードはクラスター内の他ノードごとに独立したプローブプロセスを実行し、`erpc_probe.probe_interval`（デフォルト1秒）間隔で `erpc:call(Peer, erlang, node, [], Timeout)`（タイムアウトは `erpc_probe.probe_timeout`、デフォルト5秒）を送信します。

  プラグインは以下のPrometheusメトリクスを公開します：

  - `emqx_erpc_probe_result_total`（カウンター）：`result` ラベル別のプローブ結果数。値は `ok`、`timeout`、`noconnection`、`system_limit`。
  - `emqx_erpc_probe_duration_seconds`（ヒストグラム）：成功したプローブの往復時間。p99レイテンシなどで遅延検出に利用可能。

  新規インストールでは `data/loaded_plugins` でデフォルト有効化。設定ファイルは `etc/plugins/emqx_erpc_probe.conf`。設定更新後はプラグイン再起動が必要です。

  既存クラスターはアップグレード後も旧 `data/loaded_plugins` を保持し、自動有効化されません。有効化は `./bin/emqx ctl plugins load emqx_erpc_probe` または `data/loaded_plugins` に `{emqx_erpc_probe, true}.` を追加しノード再起動で可能です。

### バグ修正

- バックアップ復元時にダッシュボードユーザーの明示的なスコープおよび `admin_override` が消失する問題を修正。

  バックアップインポート時にダッシュボードユーザーの `tags` 拡張フィールドをそのまま保持し、明示的な `scopes` やユーザー単位の `admin_override` を復元後も維持します。従来はロールのデフォルトに戻っていました。

- バックアップAPIエンドポイント（`/api/v4/data*`）がAPIキー認証情報からアクセス可能だった問題を修正。

  バックアップのエクスポート/インポートはAPIキー認証情報では拒否され、ダッシュボードログインセッションには影響ありません。

- APIキー更新エンドポイントの入力検証を厳格化し、不正な値を拒否。

  不明な権限キー、非ブール値の権限値、`permissions` にオブジェクトではなくJSON配列、非ブール値の `fallback` はHTTP 400で拒否。部分更新では未指定フィールドを文字列 `undefined` で上書きせず既存値を保持します。

- SAML SSO用 `esaml` 依存を v1.1.5 にアップグレードし、SAMLレスポンスとメタデータのXMLエンティティ展開を無効化。悪意あるSAML XMLによる外部・カスタムエンティティ展開を防止。

- SAML SSOコールバックが不正なDEFLATE圧縮レスポンスでHTTP 500を返す問題を修正。現在はHTTP 400を返し、Cowboyリクエストプロセスは終了しません。

- RabbitMQのルールアクションで、異なる `durable` 設定の同一交換機を2つのアクションが宣言した際に、交換機の再作成が全キューバインディングを破壊する問題を修正。

  修正前は `exchange.declare` の `durable` 設定不一致時にブリッジが交換機を削除・再宣言し、既存のキューバインディングも削除していました。修正後は `PRECONDITION_FAILED` エラーメッセージを返し、既存交換機とバインディングは保持されます。

- ゲートウェイ接続におけるピア証明書のCN/DNフィールド検証を追加。

  以前はTLS証明書やPROXYプロトコルv2から取得したCN/DNに制御文字が含まれていても検証されず、ログインジェクションのリスクがありました。制御文字を含むフィールドは拒否され接続を切断します。

- バックアップファイル名の検証を強化し、バックアップディレクトリ外へのパス脱出を防止。

  以前は拡張子のみチェックしていたため、パス区切り文字や不正文字を含むファイル名でバックアップディレクトリ外に逃げられていました。現在は合法的なベース名で、解決後のパスがバックアップディレクトリ内に収まる必要があります。

- ノードがクラスターに参加する際に評価ライセンスがクラスタライセンスとして選択される可能性がある問題を修正。

  以前は評価ライセンスと正式ライセンスが共存すると、評価ライセンスが選ばれることがありました。現在は非評価ライセンスを優先します。

- クラスター参加後に無効化されたモジュールのフックがクリアされず、新ノードでモジュールがアクティブになる問題を修正。

  以前はRetainerなどの無効化モジュールが新規参加ノードでアクティブのままで、サブスクリプション処理時にエラーを報告していました。現在は無効化モジュールは停止され、フックもクリアされます。

- `$SYS` トピックの保持メッセージがワイルドカードサブスクリプションに配信される問題を修正。

  MQTT仕様により、`#` や `+` で始まるフィルターは `$` で始まるトピックにマッチしてはなりません。保持メッセージは具体的なトピック（例：`$SYS/#`）にサブスクライブしたクライアントにのみ配信されます。

- 再パブリッシュルールアクションで元メッセージのMQTTプロパティが失われる問題を修正。

  以前はユーザープロパティなどのMQTTプロパティが失われていました。再パブリッシュメッセージはこれらを保持します。

- MQTTブリッジの接続関連設定の検証不足を修正。

  プールサイズが正の値でない、再接続間隔が不正などの設定が無視されたり不明瞭なエラーを起こしていました。現在は検証され、不正設定は明確なエラーとなります。

- 無効な設定でリソース作成時にREST APIが `emqx_rule_engine_api` をクラッシュさせルールエンジンアプリケーションをシャットダウンする問題を修正。

  例：`bridge_mqtt` リソースで必須フィールド `clientid` が欠落した場合、設定検証で例外が発生しAPIプロセスがクラッシュ。並行リクエスト時にルールエンジンが再起動上限に達しHTTP 500を返していました。現在は明確なHTTP 400クライアントエラーを返し、APIプロセスに影響しません。

- 監査ログでHTTP APIパスバインディングがURLデコードされず、リスト形式の値が正しく保存されない問題を修正。

  現在はデコード・正規化されたパスバインディングを記録します。

- ホットコンフィグインポートで無効設定が適用される問題を修正。

  現在はインポート前に検証し、無効値はエラーを返して適用されません。

- バックアップインポート後に `loaded-modules` レコードが更新されない問題を修正。

  以前はモジュール設定を含むバックアップインポート後に `data/loaded_modules` が更新されず、再起動後に状態がインポート時と異なることがありました。現在はインポート後にレコードを更新します。

- Prometheusに報告されるCPU使用率メトリクスの不正確さを修正。

  `cpu_sup:util` は初回呼び出し時に信頼性が低く、Prometheusの `cpu_use` と `cpu_idle` が不正確でした。現在は長時間稼働する `emqx_os_mon` プロセス経由で収集し、正確な値を報告します。

- クラスター間で転送されるMQTTメッセージの順序が乱れる問題を修正。

  同一クライアントの同一トピックへの連続パブリッシュが異なるノードのサブスクライバーに順不同で届く問題（MQTT-4.6.0-5/6違反）。以前は `gen_rpc:cast` を使用し、受信側で並列ワーカーがランダムに処理していたため順序が乱れました。現在は `gen_rpc:ordered_cast` を使用し、同一接続のキャストを到着順に処理し順序を復元します。

- `emqx_ctl listeners restart http:dashboard`（および `https:dashboard`）が `undef` エラーで失敗する問題を修正。

  ダッシュボードリスナーの `start_listener/1` と `stop_listener/1` がエクスポートされていなかったため、再起動コマンドが失敗し、リスナー停止後にポート（例：18083）が利用不可のままでした。両関数をエクスポートし、正常に停止・起動できるようにしました。

- `os_mon.memsup_system_only` が実際には有効になっておらず、多数接続時にシステムメモリ使用量取得が遅い問題を修正。

  以前は `os_mon.memsup_system_only = true` が誤って `emqx.os_mon` 環境に設定され、`memsup` は起動時に参照する `os_mon` 環境に反映されていませんでした。結果として全Erlangプロセスを走査し続け、`/nodes` と `/emqx_prometheus` の応答が遅延していました。

  本リリースでは `os_mon.memsup_system_only` を直接 `os_mon` アプリケーション環境にマッピング（デフォルト `true`）し、`memsup` はシステムメモリのみを取得します。

## e4.4.36

*リリース日: 2026-05-22*

### 強化点

- ノード毎のライセンス情報をPrometheusメトリクスで公開。

  `emqx_license_max_sessions`、`emqx_license_expiry_at`、`emqx_license_issued_at` の3つのメトリクスを追加。タイムスタンプはUnixエポック秒（UTC）。ライセンス未取得時はすべて `0` を返します。

- RabbitMQルールアクションがRabbitMQのデフォルト（無名）交換機をサポート。

  `exchange` パラメータは必須でなくなり、デフォルトは空文字列 `""`。空の場合、メッセージはデフォルトのダイレクト交換機を通じてパブリッシュされ、`routing_key` と同名のキューにルーティングされます。このモードではブリッジは `exchange.declare` / `exchange.delete` を実行しません。詳細は [RabbitMQ: Default Exchange](https://www.rabbitmq.com/docs/exchanges#default-exchange) を参照。

- Erlang VMのスケジューラ負荷圧縮をデフォルトで無効化。

  `vm.args` に `+scl false` を設定し、スケジューラの安定性向上と負荷遷移時のメッセージレイテンシ低減を図りました。

  ただし、CPUトポロジによっては低負荷時にEMQXのCPU使用率が増加する場合があります。複数NUMAノードや多数論理CPUコアの環境では、負荷圧縮を再有効化（`+scl true`）やスケジューラ数削減、CPUハイパースレッド無効化、単一NUMAノードCPUコアバインドなどで改善可能です。

- MQTT接続ヒープメモリ制限更新時の性能を最適化。

  ClientIDのログトレース有効化後、過剰ログによるプロセス終了を防ぐためヒープ制限を調整します。設定更新時に大量のMQTT接続プロセスでGCが発生し性能低下するため、`persistent_term` ではなくETSを使用してヒープ制限を管理します。

- Erlang分散通信ポートバッファ関連設定を追加し、デフォルト値を増加。クラスター安定性を向上。

  従来のデフォルトバッファサイズは1460Bでしたが、本リリースでは1MBに増加し、高レイテンシや大容量メッセージに対応。RPCレイテンシを大幅に低減します。設定例：

  ```hocon
  node.dist_connect_options.nodelay = false
  node.dist_connect_options.sndbuf = 1MB
  node.dist_connect_options.recbuf = 1MB
  node.dist_connect_options.buffer = 1MB
  node.dist_listen_options.nodelay = false
  node.dist_listen_options.sndbuf = 1MB
  node.dist_listen_options.recbuf = 1MB
  node.dist_listen_options.buffer = 1MB
  ```

- ホットアップグレードスクリプトのタイムアウトを5分から25分に延長。

  ホットアップグレードは旧バージョンのスクリプトを使用するため、新デフォルトタイムアウトは本バージョンから新バージョンへのアップグレード時にのみ適用されます。

- ノード避難/リバランス機能およびクラスター分散ロック（`ekka_locker`）のマルチノード呼び出しにおいて、`rpc` を `erpc` に置換し、高負荷時の性能と安定性を向上。

- Erlang/OTPを24.3.4.17-2にアップグレード。

  Erlang/OTPの修正はホットアップグレードでは適用されず、EMQX再起動後に有効となります。

### バグ修正

- 不安定なネットワーク環境下でのEMQXクラスターの自己修復失敗を修正。

- Redis Sentinel接続において、RedisデータノードとSentinelノードで別々の認証設定が可能に。

- 一部HTTP APIのRPC自己呼び出し問題を修正。

*リリース日: 2025-01-23*

### 強化点

  1. ローカルでプレフィックスツリーとルーティングレコードを更新しSUBACK応答。
  2. ルーティング情報を非同期で他ノードに伝播し、各ノードがプレフィックスツリーを更新。

## 4.4.25

*リリース日: 2024-09-13*

### 強化点

- MQTTユーザー名のセッション数制限モジュールを導入。

  ダッシュボードの **Modules** → **Username Quota** で設定可能。ホワイトリストに登録されたユーザー名は制限対象外。

  MQTTブリッジングで制限を回避するにはホワイトリスト利用が必須。

- MQTT 3.1.1プロトコルでCONNECTメッセージに不正なWill QoS値が含まれる場合のエラーログを改善。

- Redis送信性能を改善。

  `gen_tcp:send/2` の制限により、Redisクライアントプロセスの送信キューが増加すると送信性能が低下し、Redisクライアントがボトルネックになる問題を改善。Redis認証/ACL、Redisプラグイン、Redisルールエンジンリソースに効果。大量デバイス再接続時の負荷軽減。

- SysKeeper送信性能を改善。

  `gen_tcp:send/2` の制限により、`emqx_bridge_sysk_forward` プロセスの送信キュー増加で送信性能が低下しボトルネックになる問題を改善。

- ログトレースの単一ファイルサイズ上限を512MBから1GBに拡大。

- 内蔵DB AUTH/ACLモジュールのACL機能を改善。

  - 単一クライアントのACLエントリ数制限を設定可能に。

    パブリッシュ・サブスクライブ時にACL検証でクライアントのACLエントリを走査するため、多数エントリは性能低下要因。`auth.mnesia.max_acls_for_each_login` またはモジュールの `Max ACLs` パラメータで制限可能。

  - 内蔵ACLモジュールの検索・マッチング性能を改善。

    ACLテーブルの格納構造とトピックマッチングロジックを最適化し、単一クライアントのACLエントリ数が多いほど効果が顕著。

  - ACLエントリの追加・削除時にACLキャッシュをリセット。

- ルールエンジンのバッチ送信処理に過負荷保護を追加。

  バッチ送信有効時、外部DB応答遅延でメッセージがバッチ処理のメッセージキューに蓄積し、メモリ制限超過リスク。メッセージキューサイズが `"最大バッチサイズ" * 10`（1000未満は1000）を超えるとアクションを一定期間（デフォルト60秒）「アンロード」し、以降のメッセージは破棄し `action_olp_blocked/<RuleID>/<ActionID>` アラームを発生。

  対象アクション：

  - Cassandra、ClickHouse、DolphinDB、InfluxDB、IoTDB、Lindorm、MySQL、Oracle Database、PostgreSQL、SQLServer、Tablestore、TDengine、GCP Pubsub

- 未定義値をデータベースに `NULL` として挿入するオプションを追加。

  ルールエンジンの各種DBアクションで `${var}` プレースホルダー使用時、未定義変数が文字列 `undefined` として挿入される問題を解消。新オプション `Insert Undefined Values as NULL` を有効化すると `NULL` 挿入。

  対応アクション：

  - Cassandra、ClickHouse、DolphinDB、MySQL、Oracle Database、PostgreSQL、SQLServer、TDengine

- ログスロットリングをサポート。

  異常時に大量の類似ログが生成されシステム負荷増大や有用ログの埋没を防止。`etc/logger.conf` の `log.throttling` 設定で時間窓と最大ログレートを指定可能。

  効率化のためCPUコア数分のスロットラーを起動。例：`log.throttling = 50,60s` は各スロットラーが60秒間に最大50回の同一ログ（モジュール名と行番号で判定）を許可。8コアなら1分間に50〜400ログ。ログドロップ時は以下ログを出力：

  ```
  log throttled during last 60s, dropped_msg: #{{emqx_channel,1400} => #{msg => "Client ~s (Username: '~s') login failed for ~0p", count => 33}}
  ```

  デフォルトで警告以上ログに有効、設定値は `50,60s`。

- HTTP/HTTPS管理インターフェースのタイムアウト設定を追加。

  `etc/plugins/emqx_management.conf` に以下設定を追加：

  - `management.listener.<Proto>.request_timeout`：TCP接続確立後、HTTPリクエスト未受信で切断するまでの秒数（デフォルト5秒）。
  - `management.listener.<Proto>.idle_timeout`：接続で少なくとも1回リクエスト受信後、次のリクエストが一定時間来なければ切断（デフォルト60秒）。

  `<Proto>` は `http` または `https`。

- 「再パブリッシュ」アクションのターゲットトピック検証を追加。

  UTF-8非対応バイナリトピックの場合、アクションは失敗。

- Redis-Clusterドライバーの性能を最適化。

  Redis Clusterアクセス時のEMQXのメモリフットプリントを削減。対象はRedis認証/ACL、Redisプラグイン、ルールエンジンのRedisアクション。

### バグ修正

- Kafkaサーバーの最大メッセージサイズ超過時にKafka Producerがブロックする問題を修正。

  以前は単一メッセージがKafkaサーバーの `message.max.bytes` を超えると、ルールエンジン内のKafka Producer送信キューがブロックされ、以降のメッセージがキャッシュ上限までバッファされていました。現在はルールエンジンKafkaリソースの `Max Batch Bytes` を超える単一メッセージは破棄し、キューブロックを防止。

- 一部状況で「リソースダウン」アラームが解除できない問題を修正。

- Willメッセージトリガールールの `timestamp` フィールド値が誤っていた問題を修正。

  ルールトリガー時刻ではなくクライアント接続時刻が設定されていました。

- Kafkaアクションで `username` を `Message Key` に設定した際、ユーザー名がないと送信失敗する問題を修正。

  ユーザー名なしメッセージは文字列 `undefined` をキーとして使用。

- プロセス異常終了時に `$events/client_disconnected` イベントがトリガーされない問題を修正。

- DynamoDBアクションで `clientid` を `Hash Key` に設定した場合に送信失敗する問題を修正。

- ノード再起動後に共有サブスクリプションのスティッキーストラテジーがランダムに退化する可能性を修正。

## 4.4.24

*リリース日: 2024-04-16*

### 強化点

- `/load_rebalance/availability_check` を認証不要のパブリックAPIに変更。ロードバランサー設定を簡素化し、ブローカー過負荷を防止するためAPIを軽量化。

- 負荷再分散/避難の待機ヘルスチェックフェーズをよりグレースフルに。

  避難対象ノードへの接続は禁止しません。このフェーズではロードバランサーがノードを不健康と判断しているか不明で、禁止すると再接続試行が多数失敗する恐れがあります。

- HTTP APIのアイドルタイムアウトが短すぎる問題を改善。

  以前は5秒に設定され、5秒間リクエストがないとTCP接続を切断。現在は60秒に延長。

- 一部設定項目の説明を改善。

  - Webhookリソース・アクションの `Base URL` と `Path` パラメータ説明を改善。
  - ホットコンフィグのWS/WSSリスナーの `idle_timeout` 設定説明を強化。
  - オフラインメッセージ関連アクションの `Max Returned Count` 詳細説明を改善。
  - ClickHouseリソースの英語パラメータ `Key` を `Password` に名称変更。
  - HStreamDBアクションの `PartitionKey` を `Partition Key` に名称変更。
  - Retainerモジュールの `Maximum Retained Message Size` 詳細説明を `0B` から `0` に更新。
  - Retainerモジュールの `Message Interception` を `Intercept Empty Messages` に改名し説明を改善。

- 一部設定値の範囲・妥当性チェックを追加。

  - `mqtt.max_topic_levels`、`mqtt.max_packet_size`、`keepalive_backoff` は非負値必須。
  - SSLリスナー起動時に `verify_peer`、`fail_if_no_peer_cert`、`cacertfile` の依存関係をチェック。以前はSSLクライアント接続時のみチェック。
  - リスナー設定の `acceptors`、`max_connections`、`max_conn_rate`、`active_n` は非負値必須。
  - RabbitMQリソースの `Heartbeat Interval` と `Automatic Reconnection Interval` は正しい時間長文字列必須。
  - GB/T 32960 と JT/T808 リスナーで重複ポートチェックを追加。
  - GB/T 32960 と JT/T808 ゲートウェイ設定の一部パラメータ値検証を追加。

- ログフォーマットを最適化し、ダッシュボードの表示問題を修正。

  - ルールエンジンのレート値が長い浮動小数点数で表示される問題を小数点以下2桁に修正。
  - システムリソース使用率アラートのCPU使用率を小数点以下2桁に修正。
  - ログから `mfa` などのデバッグフィールドを削除。

- ルールエンジンがユーザー定義SQL関数をサポート。

  例：ユーザーカスタムプラグインに `emqx_rule_funcs1` モジュールの `func` 関数がある場合、

  ```SQL
  SELECT emqx_rule_funcs1.func() FROM "t/#"
  ```

  のように使用可能。モジュール名は `emqx_rule_funcs` または `EmqxRuleFuncs` で始まる必要あり。
