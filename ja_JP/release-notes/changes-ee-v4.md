# EMQX Enterprise Version 4

## e4.4.38

*リリース日: 2026-09-01*

### 強化点

- ダッシュボードユーザーに対して、カテゴリ別の細粒度な権限管理をサポートしました。

  以前は、ダッシュボードユーザーには `administrator`（全権限）と `viewer`（読み取り専用）の2つのロールのみがありました。

  本リリースでは、9つのカテゴリによる権限モデルを導入しました：

  - 既存の6つのビジネスカテゴリ：`banned`、`rule_engine`、`resources`、`plugins`、`modules`、`others`。これらはAPIキーとダッシュボードユーザーの両方に適用されます。
  - ダッシュボードユーザーのみに適用される3つの新カテゴリ：`user_management`（他のダッシュボードアカウント管理）、`mfa_management`（他ユーザーのMFA管理）、`app_management`（APIキー管理）。

  ダッシュボードユーザーの権限を絞るには、ユーザーの `tags` フィールドに `scopes` 配列を設定します。`scopes` が明示されていないユーザーはアップグレード前の動作を維持します：

  - 管理者はすべてのエンドポイントにアクセス可能。
  - ビューアーはバックアップアーカイブのダウンロードを除くすべての読み取り専用エンドポイントにアクセス可能。

  `scopes` が設定されている場合、以下のルールが適用されます：

  - 明示的な `scopes` を持つ管理者ユーザーは、そのスコープに限定され、読み書き操作ともにスコープリストが厳格に適用されます。
  - ビューアーは引き続き読み取り専用で、他ユーザーのリソースに対する非GETリクエストはスコープに関係なく拒否されます。
  - ビューアーは `user_management` と `app_management` を持てず、デフォルトのビューアースコープはこれらと `mfa_management` を除外しています。ビューアーにおける `mfa_management` は自己の強制MFAロック解除のみ許可し、他ユーザーのMFA管理はできません。
  - GETリクエストはスコープチェックされ、マッピングされていないAPIパスはスコープ制限ユーザーに対して拒否されます（フェイルクローズ）。空のスコープリストは自己サービス以外のすべてのアクセスを拒否します（自己パスワード変更、自己MFA管理、ログアウトは除く）。
  - 自己サービスパスは `scopes` の影響を受けず、ビューアーは常に自身のパスワード変更、MFA管理、ログアウトが可能です。
  - ビューアーはバックアップアーカイブ（`/api/v4/data/file/*`）をダウンロードできなくなりました。バックアップにはダッシュボードユーザーのパスワードハッシュ、TOTPシークレット、APIキー認証情報が含まれるためです。エクスポート一覧（`/data/export`）はビューアーも利用可能です。

  `dashboard.default_user.login` で設定されたデフォルト管理者アカウントは追加保護されており、降格不可、明示的な `scopes` 設定不可、削除不可です。

- SAML SSOバックエンドでユーザーごとの `force_mfa` オーバーライドをサポートしました。

  以前は、各SAMLバックエンドの `force_mfa` フラグはすべてのユーザーに一律適用され、個別調整はできませんでした。

  本リリースでは、ダッシュボードユーザーの `tags` フィールドに内部状態 `admin_override` を追加しました。管理者が既存のエンドポイントを使って他ユーザーのMFAを有効化・無効化すると、この状態が暗黙的に維持されます。

  `admin_override` の意味は以下の通りです：

  - `admin_override = mfa_required`：バックエンドの `force_mfa` 設定に関わらず、SSOログイン時にMFAを必須とします。
  - `admin_override = mfa_exempted`：バックエンドの `force_mfa` 設定に関わらず、SSOログイン時にMFAをスキップ可能とします。
  - 未設定（デフォルト）：バックエンドの `force_mfa` 設定が適用されます。

  自己サービスによるMFA変更は `admin_override` を変更せず、元の意味を保持します。

  **ローリングアップグレード注意**：本リリースに未アップグレードの古いノードがクラスターに残っている間は、`admin_override = mfa_required` は古いノードで効果を発揮しません。古いノードは引き続きバックエンドの `force_mfa` 設定のみを尊重します。一方、`admin_override = mfa_exempted` は既存の `disable_mfa` プレースホルダ経路を通じて古いノードでも有効です。

- `emqx_ctl log-throttling` によるログスロットリングのランタイム制御を追加しました。

  以前は、グローバルのスロットル制限、時間ウィンドウ、レベルは設定ファイルでのみ指定可能でした。新しい `log-throttling` コマンドグループは以下の操作をサポートします：

  - ローカルノードの現在設定を `log-throttling print`、全ノードで `log-throttling print-cluster` で確認。
  - グローバル制限、時間ウィンドウ、レベルをそれぞれ `log-throttling limit set <Limit>`、`log-throttling window set <Duration>`、`log-throttling level set <Level>` で更新。全ノード適用は対応する `set-cluster` コマンドを使用。
  - 特定ログ行の独立した制限を `log-throttling line-limit set '<Mod:Ln,...>' <Limit>` で設定。例：`'emqx_channel:1551,emqx_username_quota:245' 0` は該当行を完全にサイレンスし、他行はグローバル制限を維持。全ノード適用は `set-cluster` バリアントを使用。
  - 行単位のオーバーライド削除は `log-throttling line-limit del '<Mod:Ln,...>'`、全ノード削除は `del-cluster` を使用。

  行番号はリリース間で変動するため、行単位制限はランタイムのみで設定ファイルに永続化されません。ログ行の頻度調整に一時的に使用してください。

- デフォルトのログスロットリング設定を `50,60s` から `5,60s` に変更しました。各スロットラーは60秒間に最大5回の重複ログを許可し、それ以降はドロップ・集約します。これにより高頻度ログの氾濫を抑制します。

- ユーザー名クォーターモジュールで新しいノード間同期機構を採用し、クラスターのパフォーマンスと安定性を向上しました。

  Mnesiaレプリケーションを廃止し、ノードごとのETSテーブルと専用RPCチャネルによるストリーミング設計に置き換えました。これにより、クラスター参加時のメモリ使用量とリソース消費が削減され、同期・処理経路の過負荷保護が追加されました。廃止された `refresh_username_tab_interval` 設定は削除されました。

- ノードの `net_ticktime` のデフォルトを120秒から60秒に短縮しました。

  高負荷時に遅いまたは停止したノードへのRPCチャネルが輻輳・ブロックし、キューイングされたメッセージがメモリ使用量を増加させOOMを引き起こす問題を軽減します。`vm.args` の `-kernel net_ticktime` で設定可能です。これにより、クラスターは障害ノードをより速く検出・除去でき、RPCリクエストのブロック時間を短縮します。

- メモリプレッシャー検知によるグローバルGCを強化しました。

  システムメモリ使用率が高水準（`os_mon.sysmem_high_watermark`）を超え、周期的GCが無効の場合に、`emqx_os_mon` がメモリアラーム発生時にトリガー信号を発し、スムーズなグローバルGCを実行してメモリ使用量を削減します。以下の設定で制御可能です：

  - `node.global_gc_mem_pressure`（デフォルト `on`）：メモリプレッシャー検知グローバルGCの有効化。
  - `node.global_gc_mem_pressure_min_interval`（デフォルト `5m`）：連続トリガー間の最小間隔（スロットリング用）。

- クラスター内ノード間のネットワークヘルスプローブプラグイン `emqx_erpc_probe` を追加しました。クラスター内ノード間リンクの健全性をPrometheusメトリクスで報告します。

  各ノードはクラスター内の他ノードごとに独立したプローブプロセスを実行し、`erpc_probe.probe_interval`（デフォルト1秒）間隔で `erpc:call(Peer, erlang, node, [], Timeout)` を送信し、タイムアウトは `erpc_probe.probe_timeout`（デフォルト5秒）で設定します。

  プラグインは以下のPrometheusメトリクスを公開します：

  - `emqx_erpc_probe_result_total`（カウンター）：`result` ラベル別のプローブ結果数。値は `ok`、`timeout`、`noconnection`、`system_limit`。
  - `emqx_erpc_probe_duration_seconds`（ヒストグラム）：成功したプローブの往復時間を計測し、タイムアウト前の遅延検出に利用可能（例：p99レイテンシ）。

  新規インストールでは `data/loaded_plugins` によりデフォルトで有効化されます。設定ファイルは `etc/plugins/emqx_erpc_probe.conf` にあり、更新後はプラグイン再起動が必要です。

  既存クラスターのアップグレードでは `data/loaded_plugins` を保持するため自動有効化されません。有効化するには `./bin/emqx ctl plugins load emqx_erpc_probe` を実行するか、`{emqx_erpc_probe, true}.` を `data/loaded_plugins` に追加しノードを再起動してください。

### バグ修正

- バックアップ復元時にダッシュボードユーザーの明示的なスコープと `admin_override` が消失する問題を修正しました。

  バックアップインポート時にダッシュボードユーザーの `tags` の拡張フィールドをそのまま保持するようにしました。明示的な `scopes` やユーザーごとの `admin_override` を持つユーザーは復元後も保持され、ロールデフォルトに戻りません。

- バックアップエンドポイント（`/api/v4/data*`）がAPIキー認証情報からアクセス可能だった問題を修正しました。

  バックアップのエクスポート・インポートはAPIキー認証情報では拒否され、ダッシュボードログインセッションは影響を受けません。

- APIキー更新エンドポイントの入力検証を厳格化し、不正な値を拒否するようにしました。

  不明な権限キー、真偽値以外の権限値、オブジェクトが期待される `permissions` にJSON配列が渡された場合、非真偽値の `fallback` などでHTTP 400を返します。部分更新では省略されたフィールドを文字列 `undefined` で上書きせず既存値を保持します。

- SAML SSOの依存ライブラリ `esaml` をv1.1.5にアップグレードし、SAMLレスポンスおよびメタデータ解析時のXMLエンティティ展開を無効化、悪意あるSAML XMLによる外部・カスタムエンティティ展開を防止しました。

- SAML SSOコールバックでDEFLATE圧縮レスポンスの不正なものに対しHTTP 500を返していた問題を修正し、HTTP 400を返してCowboyリクエストプロセスを終了しないようにしました。

- RabbitMQのルールアクションで同じエクスチェンジを異なる `durable` 設定で2つ宣言した際に、キューのバインディングが全て消失するバグを修正しました。

  修正前は `exchange.declare` の `durable` 設定が既存と異なる場合、ブリッジがエクスチェンジを削除して再宣言し、既存のキューバインディングも削除されていました。修正後は `durable` またはタイプ不一致の場合は明確なエラーメッセージ（`PRECONDITION_FAILED`）を返し、既存のエクスチェンジとバインディングは保持されます。

- ゲートウェイ接続におけるピア証明書のCN/DNフィールドの検証を追加しました。

  以前はTLS証明書やPROXYプロトコルv2から取得したCN/DNに制御文字が含まれていても検証されず、ログインジェクションのリスクがありました。不正な制御文字を含むフィールドは拒否され接続を切断します。

- バックアップファイル名の検証を強化し、バックアップディレクトリ外へのパス脱出を防止しました。

  以前は拡張子のみチェックしていたため、パス区切り文字や不正文字を含む名前でバックアップディレクトリ外にファイルを作成できました。現在は合法的なベースネームかつ解決後のパスがバックアップディレクトリ内に収まることを要求します。

- クラスター参加時に評価ライセンスがクラスタライセンスとして選択される可能性があった問題を修正しました。

  評価ライセンスと正式ライセンスが共存する場合、交渉で評価ライセンスが選ばれることがありました。現在は常に非評価ライセンスを優先します。

- ノードがクラスターに参加した後、無効化されたモジュールのフックがクリアされず、モジュールがアクティブなままになる問題を修正しました。

  以前はRetainerなどの無効化されたモジュールが新規参加ノードでアクティブなままになり、サブスクリプション処理時にエラーが発生していました。現在はノード参加時に無効化されたモジュールは正しく停止され、フックもクリアされます。

- `$SYS` トピックの保持メッセージがワイルドカードサブスクライブに配信されていた問題を修正しました。

  MQTT仕様により、`#` や `+` で始まるフィルターは `$` で始まるトピックにマッチしてはいけません。現在は `$SYS/#` のような具体的なトピックにサブスクライブしているクライアントのみに配信されます。

- 再パブリッシュルールアクションで元メッセージのMQTTプロパティが失われていた問題を修正しました。

  以前はユーザープロパティなどが再パブリッシュ時に消失していました。現在はプロパティを保持します。

- MQTTブリッジの接続関連設定のバリデーション不足を修正しました。

  プールサイズが正の整数でない、再接続間隔が不正などの設定が静かに適用されるか不明瞭なエラーを発生させていました。現在はバリデーションを追加し、不正設定は明確なエラーとなります。

- 無効な設定でリソースを作成した際にREST APIが `emqx_rule_engine_api` をクラッシュさせ、ルールエンジンアプリケーションがシャットダウンする問題を修正しました。

  例えば `bridge_mqtt` リソースの必須フィールド `clientid` が欠落した場合、設定検証で例外が発生しAPIプロセスがクラッシュしていました。現在はHTTP 400でクライアントエラーを返し、APIプロセスは影響を受けません。

- 監査ログに記録されるHTTP APIパスのバインディングがURLデコードされていなかった問題を修正しました。

  以前はエンコード済みのまま記録され、リスト形式の値が正しく保存されないことがありました。現在はデコード・正規化されたパスバインディングを記録します。

- ホットコンフィグインポートで無効な設定を受け入れていた問題を修正しました。

  現在はインポート前に設定を検証し、無効な値はエラーを返して適用されません。

- バックアップインポート後に `loaded-modules` レコードが更新されなかった問題を修正しました。

  以前はモジュール設定を含むバックアップインポート後に `data/loaded_modules` ファイルが更新されず、再起動後のモジュール状態がインポート状態と異なることがありました。現在はインポート後にレコードを更新します。

- Prometheusに報告されるCPU使用率メトリクスの不正確さを修正しました。

  `cpu_sup:util` は初回呼び出し時に信頼性が低いため、`emqx_os_mon` の長寿命プロセス経由で収集するように変更し、正確な値を報告します。

- クラスター内ノード間で転送されるMQTTメッセージの順序が乱れていた問題を修正しました。

  同一クライアントが同一トピックに連続パブリッシュしたメッセージが、異なるノード接続のサブスクライバーに順序通り届かないことがありました。クロスノード転送は `gen_rpc:cast` を使用しており、受信側で並列ワーカーにより順序が乱れていました。現在は `gen_rpc:ordered_cast` を使用し、到着順に処理して順序を保持します。

- `emqx_ctl listeners restart http:dashboard`（および `https:dashboard`）が `undef` で失敗していた問題を修正しました。

  ダッシュボードリスナーの `start_listener/1` と `stop_listener/1` 関数がエクスポートされていなかったため、再起動コマンドが失敗していました。現在は両関数をエクスポートし、リスナーの停止・起動が正常に行われます。

- `os_mon.memsup_system_only` が実際には有効になっておらず、大量接続時にシステムメモリ使用量取得が遅かった問題を修正しました。

  以前の修正（e4.4.34）では `emqx.os_mon` アプリケーション環境に設定しており、`memsup` が起動時に参照する `os_mon` アプリケーション環境に反映されていませんでした。現在は `os_mon` アプリケーション環境に直接マッピングし、`memsup` がシステムメモリのみを監視するようにしました。

## e4.4.36

*リリース日: 2026-05-22*

### 強化点

- ノードごとのライセンス情報をPrometheusメトリクスで公開しました。

  `emqx_license_max_sessions`、`emqx_license_expiry_at`、`emqx_license_issued_at` の3つのメトリクスを追加。タイムスタンプはUnixエポック秒（UTC）。ライセンス未取得時は全て `0` を返します。

- RabbitMQルールアクションでRabbitMQのデフォルト（名前なし）エクスチェンジをサポートしました。

  `exchange` パラメータは必須でなくなり、空文字列 `""` がデフォルトです。空の場合、デフォルトのダイレクトエクスチェンジ経由でパブリッシュし、`routing_key` と同名のキューにルーティングされます。このモードではブリッジは `exchange.declare`/`exchange.delete` を実行しません。詳細は [RabbitMQ: Default Exchange](https://www.rabbitmq.com/docs/exchanges#default-exchange) を参照してください。

- Erlang VMのスケジューラロードコンパクションをデフォルトで無効化しました。

  `vm.args` に `+scl false` を設定し、スケジューラの安定性向上と負荷遷移時のメッセージレイテンシ低減を図りました。

  ただし、CPUトポロジーによっては低負荷時のCPU使用率が上昇する場合があります。複数NUMAノードや論理CPUコアが多い環境では、`+scl true` に戻す、スケジューラ数を減らす、ハイパースレッディングを無効化する、単一NUMAノードのCPUコアにバインドする等の対策が有効です。

- MQTT接続ヒープメモリ制限更新時のパフォーマンスを最適化しました。

  ClientIDのログトレース有効化後、過剰ログによるプロセス終了を防ぐためヒープ制限を調整します。設定更新時のGC発生による性能低下を避けるため、`persistent_term` の代わりにETSを使用するようにしました。

- Erlang分散通信ポートバッファ関連の設定項目を追加し、デフォルト値を増加してクラスター安定性を向上しました。

  以前はデフォルト1460Bでしたが、1MBに拡大し高レイテンシ・大容量メッセージに対応、RPCレイテンシ削減とクラスター安定化を実現しています。設定例：

  ```hocon
  node.dist_connect_options.nodelay = false
  node.dist_connect_options.sndbuf = 1MB
  node.dist_connect_options.recbuf = 1MB
  node.dist_connect_options.buffer = 1MB
  node.dist_listen_options.nodelay = false
  node.dist_listen_options.sndbuf = 1MB
  node.dist_listen_options.recbuf = 1MB
  node.dist_listen_options.buffer = 1MB
  ```

- ホットアップグレードスクリプトのタイムアウトを5分から25分に延長しました。

  旧バージョンのスクリプトを使用するため、新規タイムアウトは本バージョンから新バージョンへのアップグレード時にのみ有効です。

- ノード避難／リバランス機能およびクラスター分散ロック（`ekka_locker`）のマルチノード呼び出しで `rpc` から `erpc` に置き換え、性能と高並行時の安定性を向上しました。

- Erlang/OTPを24.3.4.17-2にアップグレードしました。

  Erlang/OTPの修正はホットアップグレードで反映されず、EMQX再起動後に有効となります。

### バグ修正

- 不安定なネットワーク環境下でのEMQXクラスターの自己修復失敗を修正しました。

## 4.4.25

*リリース日: 2024-09-13*

### 強化点

- 単一MQTTユーザー名のセッション数を制限するユーザー名クォーターモジュールを導入しました。

  ダッシュボードの **Modules** → **Username Quota** で設定可能。ホワイトリストに登録されたユーザー名はクォータ制限を受けません。

  MQTTブリッジングではホワイトリストの利用が必須です。

- MQTT 3.1.1プロトコルのCONNECTメッセージで不正なWill QoS値を持つ場合のエラーログを改善しました。

- Redisへのメッセージ送信性能を改善しました。

  `gen_tcp:send/2` の制限によりRedisクライアントの送信キューが増加すると送信性能が低下し、ボトルネックとなっていました。Redis認証/ACL、プラグイン、ルールエンジンのRedisリソースで改善し、大量デバイス再接続時の負荷を軽減します。

- SysKeeperへのメッセージ送信性能を改善しました。

  `gen_tcp:send/2` の制限により `emqx_bridge_sysk_forward` の送信キュー増加で性能低下していました。高負荷時のボトルネックを解消します。

- 単一ログトレースファイルのサイズ上限を512MBから1GBに拡大しました。

- 「Internal DB AUTH/ACL」モジュールのACL機能を改善しました。

  - 単一クライアントのACLエントリ数制限を設定可能にしました。

    多数のACLエントリがあるとパブリッシュ・サブスクライブ時の性能が低下するため、`auth.mnesia.max_acls_for_each_login` またはモジュールの `Max ACLs` パラメータで制限可能です。

  - ACLテーブルの格納構造とトピックマッチングロジックを最適化し、検索・マッチング性能を向上しました。ACLエントリ数が多いほど効果が大きいです。

  - ACLエントリの追加・削除時にACLキャッシュをリセットします。

- ルールエンジンのバッチ送信処理に過負荷保護を追加しました。

  バッチ送信時に外部DB応答が遅いとメッセージがバッチプロセスに蓄積し、メモリ制限超過リスクがありました。メッセージキューサイズが `"最大バッチサイズ" * 10`（1000未満は1000）を超えるとアクションを一定時間（デフォルト60秒）「アンロード」し、その間のメッセージは破棄、`action_olp_blocked/<RuleID>/<ActionID>` アラームを発報します。

  対象アクション：

  - Cassandra、ClickHouse、DolphinDB、InfluxDB、IoTDB、Lindorm、MySQL、Oracle Database、PostgreSQL、SQLServer、Tablestore、TDengine、GCP Pubsub

- 未定義値をデータベースに `NULL` として挿入するオプションを追加しました。

  ルールエンジンの各種DBアクションで `${var}` プレースホルダーを使う際、未定義変数が文字列 `"undefined"` として挿入されていました。新オプション `Insert Undefined Values as NULL` を有効にすると `NULL` として挿入します。

  対象アクション：

  - Cassandra、ClickHouse、DolphinDB、MySQL、Oracle Database、PostgreSQL、SQLServer、TDengine

- ログスロットリングをサポートしました。

  異常時に大量の類似ログが発生しシステム負荷増大や有用ログ埋没を招く問題を緩和します。`etc/logger.conf` の `log.throttling` で時間ウィンドウと最大ログレートを設定可能です。

  効率化のためCPUコア数分のスロットラーを起動し、例えば `log.throttling = 50,60s` なら各スロットラーは60秒間に同一ログ（モジュール名＋行番号）を最大50回まで許可。8コアなら最大400回/分となります。ログがドロップされると以下のようなログを出力します。

  ```
  log throttled during last 60s, dropped_msg: #{{emqx_channel,1400} => #{msg => "Client ~s (Username: '~s') login failed for ~0p", count => 33}}
  ```

  デフォルトで警告以上のログレベルに対して有効、設定は `50,60s`。

- HTTP/HTTPS管理インターフェースのタイムアウト設定を追加しました。

  `etc/plugins/emqx_management.conf` に以下を追加：

  - `management.listener.<Proto>.request_timeout`：TCP接続確立後、HTTPリクエスト未受信で切断するまでの時間（デフォルト5秒）
  - `management.listener.<Proto>.idle_timeout`：接続上で1回以上HTTPリクエスト受信後、次のリクエスト未受信で切断するまでのアイドルタイムアウト（デフォルト60秒）

  `<Proto>` は `http` または `https`。

- 「再パブリッシュ」アクションのターゲットトピック検証を追加しました。

  UTF-8エンコードされていないバイナリトピックの場合、アクションは失敗します。

- Redis-Clusterドライバの性能を最適化しました。

  Redis Clusterアクセス時のメモリ使用量を削減し、以下機能が恩恵を受けます：

  - Redis認証/ACL
  - Redisプラグイン
  - ルールエンジンのRedisアクション

### バグ修正

- Kafkaサーバーの最大メッセージサイズ制限を超えるメッセージ送信でKafkaプロデューサーがブロックされる問題を修正しました。

  クライアントがユーザー名を提供しない場合、Kafkaプロデューサーは文字列 `"undefined"` をキーに使用します。

  バッファ内メッセージ数が `message_accumulation_size` に達するか、時間が `message_accumulation_interval` に達するとバッファ内メッセージを一括送信します。`message_accumulation_size=0` でバッファリング機能を無効化します。

- SQL Serverリソースに `auto_reconnect` オプションを追加しました。

  接続断時に自動再接続可能に。無効化は `auto_reconnect = false`。

- RabbitMQリソースにTLS接続を追加しました。

- GCP PubSubアクションで属性定義とオーダリングキーをサポートしました。

### バグ修正

- ルールエンジンの `mongo_date()` 関数がダッシュボードでテストできなかった問題を修正しました。

- 4.4.19へのホットアップグレード後にルールエンジンのRabbitMQアクションで送信失敗する問題を修正しました。

## 4.4.19

*リリース日: 2023-06-27*

### 強化点

- MQTT/TCPおよびMQTT/SSLリスナーでTCPキープアライブをサポートしました。

  新設定 `zone.<zone-name>.tcp_keepalive = Idle,Interval,Probes` でTCPレイヤのキープアライブを有効化し時間パラメータを指定可能。LinuxとMacOSのみ有効です。

- Proxy Protocol関連のエラーログを改善しました。

  改善前ログ例：

  ```
  2023-04-20T14:56:51.671735+08:00 [error] supervisor: 'esockd_connection_sup - <0.2537.0>', errorContext: connection_shutdown, reason: {invalid_proxy_info,<<"f\n">>}, offender: [{pid,<0.3192.0>},{name,connection},{mfargs,{...}}]

  2023-04-20T14:57:01.348275+08:00 [error] supervisor: 'esockd_connection_sup - <0.2537.0>', errorContext: connection_shutdown, reason: {proxy_proto_timeout,5000}, offender: [{pid,<0.3194.0>},{name,connection},{mfargs,{...}}]
  ```

  改善後ログ例：

  ```
  2023-04-20T18:07:06.180134+08:00 [error] [esockd_proxy_protocol] The listener 127.0.0.1:8883 is working in proxy protocol mode, but received invalid proxy_protocol header, raw_bytes=<<"f\n">>

  2023-04-20T18:10:17.205436+08:00 [error] [esockd_proxy_protocol] The listener 127.0.0.1:8883 is working in proxy protocol mode, but timed out while waiting for proxy_protocol header
  ```

- TLSリスナーで部分証明書チェーン検証を可能にする機能を追加しました。

  設定は `listeners.conf` の `listener.ssl.external.partial_chain` を参照。

- TLSリスナーでクライアント証明書の拡張キー使用法検証を追加しました。

  設定は `listeners.conf` の `listener.ssl.external.verify_peer_ext_key_usage` を参照。

- HTTP API `/api/v4/nodes` のレスポンスに `live_connections` フィールドを追加しました。

  従来の `connections` は切断済みでも永続セッションがあればカウントしていましたが、`live_connections` は切断されていないMQTT接続中のクライアント数を示します。

- ルールエンジンに3つの乱数SQL関数を追加しました。

  - `random()`：0以上1未満の乱数生成。
  - `uuid_v4()`：ハイフン付きのUUIDバージョン4文字列生成。
  - `uuid_v4_no_hyphen()`：ハイフンなしのUUIDバージョン4文字列生成。

- `mqtt.max_clientid_len` 設定に数値範囲検証（23〜65535）を追加しました。

- プラグイン `emqx_gcp_device` を追加しました。

  Google IoT Coreからの移行を簡素化し、デバイス設定・認証情報のインポート、Google IoT Core互換MQTT認証、デバイス管理APIを提供します。

- RabbitMQアクションで動的ルーティングキーをサポートしました。

  `${key}` 形式の変数を利用可能。

- DynamoDBリソースのデフォルトポートを追加しました。

  URLにポート指定がない場合はHTTPは80、HTTPSは443をデフォルトとします。

### バグ修正

- Kafkaアクションで単一メッセージがKafkaサーバーの最大メッセージサイズを超えた場合にKafkaプロデューサーがブロックされる問題を修正しました。

- 一部状況で「リソースダウン」アラームがクリアされない問題を修正しました。

- Willメッセージトリガーのルールで `timestamp` フィールド値が誤っていた問題を修正しました。

- Kafkaアクションで `username` をメッセージキーに設定した場合に送信失敗する問題を修正しました。

- ルールエンジンがプロセス異常終了時に `$events/client_disconnected` イベントを発火しなかった問題を修正しました。

- DynamoDBアクションで `clientid` をハッシュキーに設定した場合に送信失敗する問題を修正しました。

- ノード再起動後に共有サブスクリプションのスティッキー戦略がランダムに劣化する問題を修正しました。
