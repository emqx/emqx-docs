# EMQX Enterprise Version 6

## 6.2.3

*リリース日: 2026-08-21*

EMQX 6.2.3 へのアップグレード前に、破壊的変更および既知の問題を必ずご確認ください。

### 強化点

#### アクセス制御

- [#17813](https://github.com/emqx/emqx/pull/17813) ダッシュボードのユーザーおよび API キーのエンドポイントで、特権スコープ（`system`、`user_management`、`api_key_management`、`sso_management`）とその他のスコープが混在するスコープリストを拒否するようになりました。これら4つの特権スコープは管理者相当の権限を持つため、制限付きスコープと組み合わせてもアカウントを意味のある形で制限できません。アカウントに管理者相当の権限を持たせる場合は特権スコープのみのリストを、それ以外は非特権スコープのみのリストを使用してください。既存の混在スコープを持つレコードは次回の更新まで動作しますが、次回の更新時には分割が必要です。
- [#17980](https://github.com/emqx/emqx/pull/17980) 強化されたセキュリティプロファイルにおいて、EMQX はサーバー起動によるサブスクライブに対してトピック検証、認可、MQTT機能チェック、クライアントサブスクライブフックを適用するようになりました。
- [#18002](https://github.com/emqx/emqx/pull/18002) 強化されたセキュリティプロファイルで、SAMLレスポンスおよびアサーションの署名検証をデフォルトで有効化しました。
- [#18296](https://github.com/emqx/emqx/pull/18296) 認証器の `precondition` 式（および Variform 式が許される場所）で使用可能な新関数 `is_jwt(value)` を追加しました。これは値が構造的に JWT（JWSコンパクト形式）である場合にのみ true を返し、署名検証は行いません。これにより、非JWTパスワードを提示するクライアントに対して JWT 認証器をスキップでき、特に強化セキュリティプロファイルで有用です。

#### マルチテナンシー

- [#17732](https://github.com/emqx/emqx/pull/17732) APIキーの作成および更新エンドポイントに `namespace` フィールドを追加しました。オペレーターはもはや `role` 文字列内にネームスペースをエンコードする必要がありません（既存の `ns:<namespace>::<role>` 形式は引き続き有効です）。両方の形式が提供された場合は一致している必要があります。
- [#17855](https://github.com/emqx/emqx/pull/17855) ネームスペーススコープのダッシュボード管理者は、自身のネームスペース内で API キーの作成、一覧表示、読み取り、更新、削除が可能になりました。グローバル API キーや他のネームスペースのキーは作成できず、他のネームスペースの API キーは非表示となります。

#### データ統合

- [#17933](https://github.com/emqx/emqx/pull/17933) RabbitMQ コネクターがマルチノードの `servers` リスト（例：`rmq1:5672,rmq2:5672`）をサポートし、接続時のフェイルオーバーとプール開始オフセットのローテーションを提供します。`servers` 未設定時は従来の `server`/`port` 設定が有効です。
- [#17944](https://github.com/emqx/emqx/pull/17944) HTTP コネクターおよび HTTP 認証・認可に OAuth2 クライアントクレデンシャル認証を追加しました。有効時、EMQX は設定されたトークンエンドポイントからアクセストークンを取得・更新し、アウトバウンドリクエストに Bearer 認証ヘッダーとして付加します。

  トークン取得失敗時はコネクタのヘルスチェックが `disconnected` を報告します。OAuth2 を有効にしつつ `Authorization` ヘッダーを指定した設定は拒否されます。

  クライアントIDとクライアントシークレットはトークンリクエストボディのフォームフィールドとして送信され、HTTP Basic `Authorization` ヘッダーでの送信はサポートされません。

- [#18014](https://github.com/emqx/emqx/pull/18014) Datalayers Arrow Flight コネクターで準備済みステートメントの自動再構築を有効化しました。サーバーが準備済みステートメントを失った場合（例：再起動後）、クライアントが自動的に再作成し書き込み操作を再試行するため、書き込み失敗を回避します。
- [#18042](https://github.com/emqx/emqx/pull/18042) DynamoDB コネクターに AWS IAM ロール認証情報サポートを追加しました。アクセスキーIDとシークレットアクセスキーが省略された場合、EMQX は ECS タスクロールまたは EC2 インスタンスメタデータから一時的な認証情報を取得し、有効期限前に更新します。
- [#18081](https://github.com/emqx/emqx/pull/18081) Snowflake Streaming アクションのレジリエンスを向上しました。特にチャネルの内部状態が同期外になった場合、失敗した行をリトライし、手動介入なしにチャネルの再オープンを試みます。
- [#18085](https://github.com/emqx/emqx/pull/18085) Kafka、Confluent、Azure Event Hubs プロデューサーの新設定を追加しました：

  - `max_batch_age`（アクション）：プロデューサーバッファに一定期間以上滞留したメッセージを送信せず破棄し、`dropped.expired` メトリクスにカウントします。デフォルトは `infinity`（破棄なし）。
  - `max_retries`（アクション）：指定回数のリトライ失敗後にメッセージバッチを破棄し、`failed` メトリクスにカウントします。リトライカウンターは Kafka が明示的にエラーコードを返した場合のみ増加し、接続喪失後の再送では増加しません。デフォルトは `infinity`（無限リトライ）。
  - `reconnect_delay`（アクション）：接続喪失後の再接続までの遅延。デフォルトは `2s`（従来はハードコード）。
  - `request_timeout`（コネクター）：Kafka からの応答待機時間。これを超えると接続は古いとみなされ再確立されます。デフォルトは `30s`。

  Kafka クライアントライブラリのアップグレード（wolff 4.2.1）により、メモリモードバッファの `max_linger_time` サポートが復活。小規模バッチは `max_linger_time` まで待機しメッセージ集約を促進、フルバッチは遅延なく送信されます。

- [#18110](https://github.com/emqx/emqx/pull/18110) スキーマレジストリで JSON Schema drafts 2019-09 および 2020-12 をサポートしました。
- [#18137](https://github.com/emqx/emqx/pull/18137) GCP Pub/Sub プロデューサー・コンシューマーが完全修飾トピックパス（`projects/<project-id>/topics/<topic-name>`）をトピック設定で受け入れるようになりました。これにより、サービスアカウントのプロジェクトとは異なる GCP プロジェクトのトピックにパブリッシュまたはコンシューム可能です。ベアトピック名は従来通りサービスアカウントのプロジェクトに解決されます。コンシューマーはサブスクリプションをサービスアカウントのプロジェクトに作成し、トピック参照のみ別プロジェクトを指すことが可能です。

#### ルールエンジン

- [#18253](https://github.com/emqx/emqx/pull/18253) ルールエンジンSQLに新関数 `map_to_range(value, min, max)` と `hash_to_range(value, min, max)` を追加しました。値またはそのハッシュを指定範囲の整数にマッピングし、シャーディングやバケット分割に有用です。例：トピックのセグメントからシャードインデックスを算出し、大規模デバイス群を複数ルールに分散可能です。
- [#18306](https://github.com/emqx/emqx/pull/18306) LZ4 Frame 圧縮・解凍用のルール関数 `lz4_compress` と `lz4_uncompress` を追加しました。

#### プラグイン

- [#18012](https://github.com/emqx/emqx/pull/18012) EMQX REST API 経由の同期 MQTT リクエスト/レスポンスフロー用プラグイン `emqx_sync_request` を追加しました。ノードローカルの CLI 診断機能としてリクエストカウンターや現在の保留状態も提供します。
- [#18353](https://github.com/emqx/emqx/pull/18353) ルールSQL用の名前付きマッピングテーブルを提供する新プラグイン `emqx_maptabs` を追加しました。

  テーブルは JSON ファイルから初期化され、メモリ上に保持され高速にルールエンジンのホットパスから参照可能です。`maptab_lookup(Table, Key)`、`maptab_lookup(Table, Key, Field)`、`maptab_lookup(Table, Key, Field, Default)` のルールSQL関数により、長大な `CASE ... WHEN ... THEN` 連鎖を単一のテーブルルックアップに置き換えられます。ルックアップしたフィールドは組み込みの `subbits` 関数を直接駆動し、バイナリペイロードのデコードにも利用可能です。

  テーブルは `emqx ctl maptabs` CLI で管理可能。1ノードでのロードや削除はクラスター全ノードに複製され、更新時にダウンしていたノードは再参加時に自動追従します。

  プラグイン設定で安全制限を提供：`max_tables`（デフォルト100）、`max_rows_per_table`（デフォルト10000）、`max_table_file_bytes`（デフォルト10000000）。

- [#18037](https://github.com/emqx/emqx/pull/18037) Enterprise Linux 10（Red Hat Enterprise Linux 10、Rocky Linux 10、互換ディストリビューション向け）パッケージを追加しました。
- [#18127](https://github.com/emqx/emqx/pull/18127) macOS 26（Tahoe）パッケージのリリースを開始しました。

#### パフォーマンス

- [#18185](https://github.com/emqx/emqx/pull/18185) サブスクリプション HTTP API の深いページングクエリを改善しました。各ターゲットノードでメモリ内にサブスクリプション行を蓄積し、ページネーションバッチごとに RPC を発行するのを回避します。
- [#18229](https://github.com/emqx/emqx/pull/18229) データ統合の送信パスにおける CPU オーバーヘッドを削減しました。アクションやソースでないリソース（例：クラスターリンクのメッセージ転送）を経由するメッセージごとにフォーマット済みエラー文字列を生成しなくなり、高負荷時の長スケジューラー警告を回避します。

### バグ修正

#### コア MQTT 機能

- [#17895](https://github.com/emqx/emqx/pull/17895) TLS/WSSリスナーを管理証明書バンドルからファイルベース証明書に切り替える際、参照していたバンドルが既に削除されていても成功するように修正しました。Dashboard が `managed_certs` を `null` でクリアする場合も含みます。
- [#17911](https://github.com/emqx/emqx/pull/17911) Erlang/OTP の `ssl` アプリケーションが対応している場合、DTLSリスナーで `ECDHE-PSK-CHACHA20-POLY1305` 暗号スイートの検証を許可しました。
- [#18102](https://github.com/emqx/emqx/pull/18102) 配信レート制限が有効な場合に MQTT クライアントが QoS 1 および QoS 2 メッセージを順不同で受信する問題を修正しました。EMQX は遅延したメッセージの送信が可能になるまで後続メッセージをキューに保持します。

  影響バージョン：6.1.2、6.1.3、6.2.0～6.2.2。`delivery_messages_rate` または `delivery_bytes_rate` が設定されたセッションのみ影響。デフォルトでは配信レート制限は設定されていません。

- [#18108](https://github.com/emqx/emqx/pull/18108) まだ参照されている管理証明書バンドル（またはその中の単一ファイル）を削除しようとすると、参照元設定を明示した明確なエラーで常に失敗するようになりました。`force_delete` クエリパラメータはこのチェックをバイパスしなくなり、APIスキーマからも削除されました。

  さらに、リスナーがディスク上に存在しない証明書バンドルを参照している場合でも、Prometheus 統計エンドポイントが完全に失敗しなくなりました。該当リスナーは証明書有効期限メトリクスから除外され、警告ログが出力されます。

- [#18111](https://github.com/emqx/emqx/pull/18111) `mqtt.strict_mode` 有効時、MQTT v3.1 の CONNECT パケットでパスワードフラグがセットされユーザ名フラグがセットされていない場合は拒否するようにしました。これは MQTT v3.1.1 の既存動作と一致します。MQTT v3.1 仕様ではユーザ名なしでパスワードを送ることは無効です。

  さらに接続ログの可読性を向上しました。CONNECT パケットのトレースではパスワード未指定時に `Password=undefined` と表示し、空パスワードとの区別を可能にしました。ログの `peername` フィールドは常に `10.0.0.1:54123` のようなプレーン文字列で表示されます。

- [#18181](https://github.com/emqx/emqx/pull/18181) バースト値が `0` に設定されたレートリミッターが余分なバーストを許可してしまう問題を修正しました。これにより MQTT 配信メッセージレート制限などが設定より緩くなっていました。
- [#18236](https://github.com/emqx/emqx/pull/18236) ソケットバックの TCP リスナーを使用するクライアントが高負荷時に予期せず切断される問題を修正しました。準備完了信号がまだ準備できていないソケットに届くケースが原因でした。

  ```
  [error] crasher: initial call: emqx_socket_connection:init/4, ..., error: {{case_clause,{select,{select_info,recv,#Ref<...>}}},[{emqx_socket_connection,handle_msg,2,[{file,"emqx_socket_connection.erl"},{line,827}]}, ...
  ```

- [#18293](https://github.com/emqx/emqx/pull/18293) QUIC スタックを quicer-0.4.8（msquic 2.5.7）にアップグレードしました。
- [#18357](https://github.com/emqx/emqx/pull/18357) [#18375](https://github.com/emqx/emqx/pull/18375) ノードの起動完了まで MQTT 接続を拒否するようにしました。これにより、認証、認可、プラグインフックが有効になる前にリスナーがトラフィックを処理することがなくなります。

  `GET /status` API は起動完了まで HTTP 503 を返すようになり、ロードバランサーは新規接続をクラスター内の他ノードにルーティング可能です。

  起動完了前のノードへのクラスター参加要求は「後で再試行してください」というメッセージで拒否されます。

#### ルールエンジン

- [#17957](https://github.com/emqx/emqx/pull/17957) `rule_engine.limit_selects_in_namespace = true` 設定時に、複数のルールイベント（例：`$events/client/connack`）がグローバルネームスペースのルールをトリガーしない問題を修正しました。
- [#18049](https://github.com/emqx/emqx/pull/18049) `rule_engine.limit_selects_in_namespace = true` 設定時に、アラームの有効化／無効化でトリガーされるグローバルルールが発火しない問題を修正しました。
- [#18388](https://github.com/emqx/emqx/pull/18388) ネームスペースに属するルールの `republish` アクションを修正しました。`rule_engine.limit_selects_in_namespace` が有効（デフォルト）の場合、再パブリッシュメッセージはルールのネームスペース（`<namespace>/<topic>`）でパブリッシュされます。これにより、`republish` アクションはルールのネームスペース境界に従います。すでに `<namespace>/` で始まるレンダリング済みトピックは変更されず、プレフィックスを追加するテンプレートはそのまま動作します。`rule_engine.limit_selects_in_namespace = false` に設定すると従来の動作を維持します。

#### データ統合

- [#17859](https://github.com/emqx/emqx/pull/17859) MQTT コネクターが IPv6 ブローカーに接続できるように修正しました。

  以前は、IPv6 リテラル（例：`[::1]:1883`）が保存時に `bad_host_port` バリデーションエラーで拒否され、IPv6 のみ解決されるホスト名は IPv4 で接続しようとして「ホスト解決できない」エラーになっていました。

  サーバーアドレスパーサーは角括弧付き IPv6 リテラル（例：`[::1]`、`[::1]:1883`、`mqtt://[::1]:1883`）を受け入れるようになり、MQTT コネクターは接続時に IPv6 プローブを有効化し、IPv6 のみのブローカーに到達可能です。

  MQTT コネクターとクラスターリンクの `server` アドレスは公式 MQTT URI スキーム `mqtt`（平文TCP）および `mqtts`（TLS）を受け入れます。例：`mqtt://broker:1883`、`mqtts://broker:8883`。スキームなしの `host:port` も引き続き受け入れます。その他のスキームは `unsupported_scheme` バリデーションエラーで拒否されます。

- [#17947](https://github.com/emqx/emqx/pull/17947) HTTP コネクターの更新後にアクションバッファワーカーがブロックされ、メッセージが次のリトライ間隔までキューに残る問題を修正しました。
- [#17955](https://github.com/emqx/emqx/pull/17955) GreptimeDB の非同期バッチが低書き込みレート時にヘルスチェック後もフラッシュされない問題を修正しました。
- [#17961](https://github.com/emqx/emqx/pull/17961) Kafka または Pulsar コネクターがヘルスチェックタイムアウトで `disconnected` 状態に遷移し、内部キューを再生成する問題を修正しました。これらはタイムアウト時に `connecting` に遷移します。
- [#17970](https://github.com/emqx/emqx/pull/17970) SSRF 保護有効時に、既存の接続先がポリシーでブロックされているコネクターが存在しても、コネクター管理操作が妨げられないようにしました。

  以前は SSRF 保護有効化や拒否リスト拡張後に、関係ないコネクター操作が内部エラーで失敗し、影響を受けたコネクターの削除がアクションやルール削除後も残存する問題がありました。

  SSRF 保護は HTTP および MQTT コネクターに適用され、作成・更新時にブロックされたアドレスのコネクターは拒否されます。有効化・無効化・削除はブロックされず、他のコネクター種別はポリシー対象外です。

- [#17973](https://github.com/emqx/emqx/pull/17973) Kafka プロデューサーアクションのリトライメトリクスを修正しました。`retried`、`retried.success`、`retried.failed` カウンターは、ブローカー再接続後に内部バッファが再送したメッセージを反映し、リトライメッセージの最終成功・失敗を判別可能です。従来は内部リトライ数に関わらず常に `0` でした。`success` と `failed` カウンターは影響を受けず二重カウントされません。
- [#17982](https://github.com/emqx/emqx/pull/17982) GCP Pub/Sub コンシューマーが HTTP/2 を使用し、タイムアウト時にプルリクエストをキャンセルするようになりました。これにより GCP サーバーに対しメッセージのリースを新しいプルリクエストに割り当て可能であることを明確に通知し、テールレイテンシを削減します。
- [#18055](https://github.com/emqx/emqx/pull/18055) クラスター内の異なるノードで Snowflake Streaming アクションが以下のエラーで失敗する問題を修正しました。

  ```
  {unrecoverable_error,#{body => <<"{\"code\":\"STALE_CONTINUATION_TOKEN_SEQUENCER\",\"message\":\"Channel sequencer in the continuation token is stale. Please reopen the channel\"}">>,...
  ```

- [#18110](https://github.com/emqx/emqx/pull/18110) スキーマレジストリで draft-06 JSON Schema の `examples` 注釈を使用した際に有効なデータが無効と判定される問題を修正しました。

## 6.2.2

*リリース日: 2026-07-02*

EMQX 6.2.2 へのアップグレード前に、破壊的変更および既知の問題を必ずご確認ください。

### 強化点

#### クラスター

- [#17530](https://github.com/emqx/emqx/pull/17530) クラスターリンクは非コミュニティライセンスが必要になりました。デフォルトのコミュニティライセンスでは設定済みリンクは非アクティブ（メッセージ転送やルート複製なし）となり、REST API は非コミュニティライセンスをロードするよう明示的なヒントを返してリンク有効化を拒否します。リンクの無効化・削除は引き続き可能で、レガシー設定の整理に利用できます。ライセンスアップグレード後はダッシュボードや REST API からノード再起動なしでリンクを有効化可能です。
- [#17549](https://github.com/emqx/emqx/pull/17549) EMQX Backup Sync プラグインを追加しました。Data Backup API を用いてプライマリクラスターからセカンダリクラスターへ選択した設定を定期的に同期します。HTTPS 通信に対する TLS オプションの設定をサポートします。
- [#17620](https://github.com/emqx/emqx/pull/17620) ルーティングテーブルの検査・調整用のオペレーター向け診断モジュール `emqx_router_tool` を追加しました。`emqx ctl eval` 経由で実行し、以下のヘルパーを提供します：

  - `cluster_schema_view/0`：各クラスター ノードで稼働中のルートストレージスキーマを報告。
  - `scan_missing_routes/0,1`：ローカルのサブスクリプションテーブルをストリームし、このノードにルートエントリが欠落しているトピックを報告。スキャンは2パスで実行され、スロットリングされ、同時のサブスクライブ・アンサブスクライブを許容。
  - `reconcile_missing_routes/0,1`：既存の `emqx_router:add_route/2` API を使い欠落ルートを再追加。

  このモジュールはスキーマ非依存でライブクラスター上で安全に実行可能です。

#### マルチテナンシー

- [#17665](https://github.com/emqx/emqx/pull/17665) マルチテナンシーアプリにテナント別のドロップメッセージ数とドロップ配信数のカウンターを追加しました。これらは既存のテナント別メトリクスとともに `/api/v5/prometheus/namespaced_stats` で `namespace` ラベル付きで公開されます。オペレーターは Prometheus からテナントごとのドロップ率をログ調査なしに診断可能です。

  既知の制限：QoS 2 PUBREL の待機タイムアウトによるドロップはまだテナント別帰属されません。該当経路はグローバルカウンターをインクリメントし、`message.dropped` フックは発火しません。

- [#17711](https://github.com/emqx/emqx/pull/17711) ビルトインデータベース認証ユーザー HTTP API でネームスペース選択を一貫化し、削除済みネームスペースに残ったレコードのクリーンアップを可能にしました。

- [#17497](https://github.com/emqx/emqx/pull/17497) 非バッチモード（`batch_size = 1`）でアクション設定された場合に `actions.executed` メトリクスが `actions.messages` を過小計測する問題を修正しました。

  以前はバッファワーカのテレメトリフラッシュごとに `actions.executed` をインクリメントしていたため、複数の個別完了を1イベントに集約し、`actions.executed` が `actions.messages` に追いつかないことがありました。

  2つのメトリクスは独立した呼び出し箇所でインクリメントされます：`actions.executed` はアクションコールバック呼び出しごと（バッチモードはバッチ単位、単一モードはメッセージ単位）、`actions.messages` は処理したメッセージごとです。

- [#17513](https://github.com/emqx/emqx/pull/17513) Prometheus のマッチした認可の許可・拒否メトリクスが実際の認可判定を反映するよう修正しました。
