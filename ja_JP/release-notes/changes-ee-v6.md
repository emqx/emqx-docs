# EMQX Enterprise Version 6

## 6.1.4

*リリース日: 2026-08-03*

EMQX 6.1.4 へのアップグレード前に、破壊的変更および既知の問題を必ずご確認ください。

### 強化点

#### マルチテナンシー

- [#17732](https://github.com/emqx/emqx/pull/17732) APIキー作成および更新エンドポイントに `namespace` フィールドを追加しました。オペレーターはもはや `role` 文字列に namespace をエンコードする必要がありません。`ns:<namespace>::<role>` 形式は引き続きサポートされます。両方の形式が提供された場合、その namespace 値は一致している必要があります。
- [#17855](https://github.com/emqx/emqx/pull/17855) namespace スコープの EMQX ダッシュボード管理者が、自身の namespace 内で API キーの作成、一覧表示、読み取り、更新、削除を行えるようになりました。グローバル API キーや他の namespace のキーは作成できません。自身の namespace 外の API キーは表示されません。

#### アクセス制御

- [#17813](https://github.com/emqx/emqx/pull/17813) ダッシュボードのユーザーおよび API キーエンドポイントに、管理者相当のスコープ（EMQX バリデーションメッセージで `privilege scopes` と呼ばれる）である `system`、`user_management`、`api_key_management`、`sso_management` と他のスコープを混在させたスコープリストを拒否するバリデーションを追加しました。これらのスコープは管理者相当の権限を付与するため、他のスコープを追加しても権限は制限されません。必要な権限に応じて、管理者相当のスコープのみ、またはその他のスコープのみを使用してください。

  既存のレコードは混在スコープでも引き続き動作します。更新時に明示的なスコープリストが送信された場合は、管理者相当のスコープのみかその他のスコープのみを含む必要があります。namespace スコープのダッシュボード管理者はこの相互排他ルールの対象外で、namespace RBAC に従います。

#### データ統合

- [#17933](https://github.com/emqx/emqx/pull/17933) RabbitMQ コネクターで複数ノードの `servers` リスト（例：`rmq1:5672,rmq2:5672`）をサポートしました。コネクターは接続時のフェイルオーバーと接続プールの開始オフセットのローテーションを提供します。`server` と `port` 設定は `servers` 未設定時に引き続きサポートされます。

- [#17944](https://github.com/emqx/emqx/pull/17944) HTTP コネクターおよび HTTP ベースの認証・認可に OAuth2 クライアントクレデンシャル認証を追加しました。有効化すると、EMQX は設定されたトークンエンドポイントからアクセストークンを取得・更新し、送信リクエストに Bearer 認証ヘッダーとして追加します。

  トークン取得に失敗するとコネクターのヘルスチェックは `disconnected` を報告します。OAuth2 を有効にしつつ `Authorization` ヘッダーを設定した構成は拒否されます。

  クライアントIDとクライアントシークレットはトークンリクエストのフォームフィールドとして送信され、HTTP Basic `Authorization` ヘッダーでの送信はサポートされません。

- [#18014](https://github.com/emqx/emqx/pull/18014) Datalayers Arrow Flight コネクターに自動プリペアドステートメント再構築を追加しました。サーバーがプリペアドステートメントを失った場合（再起動後など）、クライアントは自動的にステートメントを再作成し、書き込み操作をリトライします。これにより、ステートメント欠如による書き込み失敗を回避します。

- [#18042](https://github.com/emqx/emqx/pull/18042) DynamoDB コネクターに AWS IAM ロール認証情報サポートを追加しました。

  アクセスキーIDとシークレットアクセスキーが省略された場合、EMQX は ECS タスクロールまたは EC2 インスタンスメタデータから一時的な認証情報を取得し、有効期限前に更新します。

- [#18081](https://github.com/emqx/emqx/pull/18081) Snowflake Streaming アクションのレジリエンスを向上しました。チャネルの内部状態が同期外れになった場合、エラーを回復可能とみなし、失敗した行をリトライし、手動介入なしにチャネルを再オープンしようとします。

- [#18085](https://github.com/emqx/emqx/pull/18085) Kafka、Confluent、Azure Event Hubs プロデューサーに以下の設定オプションを追加しました：

  - `max_batch_age`（アクション）：メッセージがプロデューサーバッファに留まる最大時間。超過したメッセージは破棄され、`dropped` と `dropped.expired` メトリクスがインクリメントされます。期限切れメッセージは `failed` や `success` としてカウントされません。デフォルトは `infinity`（バッファ内で期限切れなし）。
  - `max_retries`（アクション）：メッセージバッチの Kafka 再試行許容回数。設定回数を超えるとバッチは破棄され、影響を受けたメッセージは `failed` としてカウントされます。再試行カウンターは Kafka がエラーコードを返した場合のみ増加し、接続喪失後の再送はカウントされません。デフォルトは `infinity`（無限再試行）。
  - `reconnect_delay`（アクション）：接続喪失後の再接続までの遅延。デフォルトは以前ハードコードされていた `2s`。
  - `request_timeout`（コネクター）：Kafka 応答待ち時間。タイムアウトすると接続を再確立します。デフォルトは `30s`。

  Kafka クライアントライブラリを `wolff` 4.2.1 にアップグレードし、メモリモードバッファの `max_linger_time` サポートを復活させました。小さいバッチは `max_linger_time` まで追加メッセージを待ち、送信リクエスト頻度を減らします。満杯バッチは遅延なしで送信されます。

- [#18110](https://github.com/emqx/emqx/pull/18110) スキーマレジストリで JSON Schema ドラフト 2019-09 および 2020-12 をサポートしました。

- [#18137](https://github.com/emqx/emqx/pull/18137) GCP Pub/Sub プロデューサーおよびコンシューマーで、トピック設定に完全修飾トピックパス（`projects/<project-id>/topics/<topic-name>`）を受け入れるようになりました。これにより、サービスアカウントのプロジェクトとは異なる GCP プロジェクトのトピックにパブリッシュやコンシュームが可能です。トピック名のみの場合は従来通りサービスアカウントのプロジェクトに解決されます。コンシューマーはサブスクリプションをサービスアカウントのプロジェクトに作成し、トピック参照のみ別プロジェクトを指せます。

#### プラグイン

- [#18012](https://github.com/emqx/emqx/pull/18012) EMQX REST API を介した同期 MQTT リクエスト/レスポンスフロー用の `emqx_sync_request` プラグインを追加しました。ノードローカル CLI 診断でリクエストカウンターや現在の保留状態も提供します。

#### パッケージング

- [#18037](https://github.com/emqx/emqx/pull/18037) Red Hat Enterprise Linux 10、Rocky Linux 10、互換ディストリビューション向けの Enterprise Linux 10 (EL10) パッケージを追加しました。
- [#18127](https://github.com/emqx/emqx/pull/18127) macOS 26 (Tahoe) 向けパッケージのリリースを開始しました。

### バグ修正

#### コア MQTT 機能

- [#17911](https://github.com/emqx/emqx/pull/17911) Erlang/OTP の `ssl` アプリケーションがサポートする場合、DTLS リスナーで `ECDHE-PSK-CHACHA20-POLY1305` 暗号スイートの検証をサポートしました。
- [#18062](https://github.com/emqx/emqx/pull/18062) TLS/WSS リスナーを管理証明書バンドルからファイルベース証明書に切り替える際、Dashboard が `managed_certs` を `null` でクリアするリクエストを送信しても成功するように修正しました。バンドルが既に削除されていても問題ありません。
- [#18102](https://github.com/emqx/emqx/pull/18102) EMQX 6.1.2 および 6.2.0 で導入された問題を修正しました。配信レート制限が設定されている場合に MQTT クライアントが QoS 1 および QoS 2 メッセージを順不同で受信することがありました。EMQX はレート制限されたメッセージが送信可能になるまで後続メッセージをキューに保持します。
- [#18108](https://github.com/emqx/emqx/pull/18108) まだ参照されている管理証明書バンドル（またはそのファイル）を削除しようとすると、参照元設定を明示的に列挙したエラーで常に失敗するようにしました。`force_delete` クエリパラメータはチェックをバイパスしなくなり、API スキーマから削除されました。

  また、Prometheus 統計エンドポイントは、ディスク上に存在しない証明書バンドルを参照するリスナーがあっても完全に失敗しなくなりました。該当リスナーは証明書有効期限メトリクスから除外され、警告ログが出力されます。

- [#18111](https://github.com/emqx/emqx/pull/18111) `mqtt.strict_mode` バリデーションを MQTT v3.1 の CONNECT パケットにも拡張しました。EMQX はユーザ名フラグなしでパスワードフラグが設定されたパケットを拒否します。これは MQTT v3.1.1 の動作と一致します。MQTT v3.1 仕様ではユーザ名なしのパスワードは許可されていません。

  接続ログの可読性も向上しました。CONNECT パケットのトレースではパスワードが存在しない場合に `Password=undefined` と表示し、空パスワードと区別します。ログは `peername` フィールドを `10.0.0.1:54123` のようなプレーン文字列で表示します。

#### ルールエンジン

- [#17957](https://github.com/emqx/emqx/pull/17957) `rule_engine.limit_selects_in_namespace = true` 設定時に、複数のルールイベント（例：`$events/client/connack`）がグローバル namespace でトリガーされない問題を修正しました。
- [#18049](https://github.com/emqx/emqx/pull/18049) `rule_engine.limit_selects_in_namespace = true` が設定されていると、アラームの有効化・無効化イベントでトリガーされるグローバルルールが発火しない問題を修正しました。

#### データ統合

- [#17859](https://github.com/emqx/emqx/pull/17859) MQTT コネクターが IPv6 ブローカーに接続できるよう修正しました。

  以前は、IPv6 リテラル（例：`[::1]:1883`）が保存時に `bad_host_port` バリデーションエラーで拒否され、IPv6 のみを解決するホスト名は IPv4 で接続しようとして「ホスト解決不可」エラーになっていました。

  サーバーアドレスパーサーは角括弧付き IPv6 リテラル（例：`[::1]`、`[::1]:1883`、`mqtt://[::1]:1883`）を受け入れ、MQTT コネクターは接続時に IPv6 プロービングを有効にして、IPv6 専用ブローカーに接続可能にしました。

  MQTT コネクターとクラスターリンクの `server` アドレスは、公式の MQTT URI スキーム `mqtt`（プレーン TCP）と `mqtts`（TLS）を受け入れます。例：`mqtt://broker:1883`、`mqtts://broker:8883`。スキームなしの `host:port` も引き続き受け入れます。その他のスキームは `unsupported_scheme` バリデーションエラーで拒否されます。

- [#17947](https://github.com/emqx/emqx/pull/17947) HTTP コネクターの更新後にアクションバッファワーカーがブロックされ、メッセージがリトライ間隔までキューに残る問題を修正しました。
- [#17955](https://github.com/emqx/emqx/pull/17955) 低書き込みレート時に GreptimeDB 非同期バッチがフラッシュされない問題を修正しました。
- [#17961](https://github.com/emqx/emqx/pull/17961) Kafka または Pulsar コネクターがヘルスチェックタイムアウト後に `disconnected` 状態に遷移し、内部キューが再作成される問題を修正しました。Kafka と Pulsar コネクターはタイムアウト後に `connecting` 状態に遷移します。
- [#17970](https://github.com/emqx/emqx/pull/17970) SSRF 保護が有効な場合、ポリシーでブロックされたアドレスを持つ既存コネクターがあっても、コネクター管理操作が妨げられなくなりました。

  以前は、SSRF 保護有効化後に既存コネクターのアドレスがブロックされると、関連しないコネクター操作が内部エラーで失敗し、該当コネクター削除後もアクションやルール削除後に残留することがありました。

  SSRF 保護は HTTP および MQTT コネクターに適用され、作成・更新時にブロックされたアドレスは拒否されます。作成・無効化・削除は常に許可され、他のコネクタータイプはポリシー対象外です。

- [#17973](https://github.com/emqx/emqx/pull/17973) Kafka プロデューサーアクションのリトライメトリクスを修正しました。アクションの `retried`、`retried.success`、`retried.failed` カウンターは、ブローカー再接続後に内部バッファが再送したメッセージを反映し、オペレーターがリトライメッセージの最終結果を把握できるようになりました。従来は内部リトライ数に関わらずこれらのカウンターは常に `0` でした。`success` と `failed` カウンターは影響を受けず二重計上されません。
- [#17982](https://github.com/emqx/emqx/pull/17982) GCP Pub/Sub コンシューマーを HTTP/2 に更新し、タイムアウト時にアクティブなプルリクエストをキャンセルするようにしました。HTTP/2 ストリームのキャンセルにより GCP サーバーはリクエスト終了を明確に認識し、メッセージを次のプルリクエストにリースできる可能性があり、テールレイテンシを低減します。
- [#18055](https://github.com/emqx/emqx/pull/18055) Snowflake Streaming アクションが異なるクラスター ノードで以下のエラーで失敗する問題を修正しました。

  ```text
  {unrecoverable_error,#{body => <<"{\"code\":\"STALE_CONTINUATION_TOKEN_SEQUENCER\",\"message\":\"Channel sequencer in the continuation token is stale. Please reopen the channel\"}">>,...
  ```

- [#18110](https://github.com/emqx/emqx/pull/18110) スキーマレジストリの draft-06 JSON Schema で `examples` アノテーションを使用すると有効なデータが無効として拒否される問題を修正しました。

#### クラスター

- [#17995](https://github.com/emqx/emqx/pull/17995) 永続化された `mqtt.max_packet_size` がローカル設定と異なるクラスターにノードが参加するとノードが終了する問題を修正しました。EMQX はリスナー起動前にリスナー更新の副作用をスキップし、EMQX アプリケーション起動時に同期済み設定からリスナーを作成します。
- [#17999](https://github.com/emqx/emqx/pull/17999) コミュニティ（シングルノード）ライセンスのノードがクラスタリング可能なライセンスを持つクラスターに参加すると起動クラッシュループする問題を修正しました。ノードはクラスタリングライセンスの同期を有界の猶予期間待機し、その後起動します。猶予期間内にクラスタリングライセンスが同期されない場合は拒否されます。
- [#18077](https://github.com/emqx/emqx/pull/18077) ノードが完全起動前に `cluster join` リクエスト（CLI または API）を受け取るとクラッシュする問題を修正しました。起動中の内部データベース再起動によるノードダウンを防ぐため、完全起動前のリクエストは明確なエラーメッセージで拒否されます。ノード起動後に再試行してください。

#### アクセス制御

- [#17806](https://github.com/emqx/emqx/pull/17806) データバックアップのインポート・エクスポートエンドポイントを最小権限の原則に合わせました。`user_management` と `api_key_management` の両方を含まないスコープセットのダッシュボードユーザーは、`dashboard_users` および `api_keys` テーブルセットを含むアーカイブのインポート・エクスポートができなくなりました。グローバル管理者と必要なスコープを持つ API キー呼び出しは影響を受けません。
- [#17853](https://github.com/emqx/emqx/pull/17853) コネクターデバッグログの HTTP リクエストヘッダーの秘匿処理を改善しました。`x-api-key`、`x-auth-token`、`api-key`、`cookie` ヘッダーは `Authorization` と `Proxy-Authorization` と同様にコネクター状態で秘密として保存され、トレースまたはデバッグレベルのログ出力時に値が省略されます。

  共通のヘッダー秘匿ヘルパーは、コネクターのテンプレートパーサーが生成する iolist 形式のヘッダー名も認識します。

- [#17871](https://github.com/emqx/emqx/pull/17871) 非グローバル namespace でスーパーユーザーを作成しようとすると、組み込みデータベースユーザーの一括インポートやブートストラップファイル経由でも拒否されるようになりました。該当行は失敗として報告され、保存されません。
- [#17974](https://github.com/emqx/emqx/pull/17974) 接続ログでの生の MQTT パケットデータはデフォルトで秘匿されるようになりました。診断用に信頼済みクライアント IP アドレスはリスナーごとに許可リスト化できます。
- [#18005](https://github.com/emqx/emqx/pull/18005) CLI 監査ログに機密コマンド引数が保存される問題を修正しました。
- [#18009](https://github.com/emqx/emqx/pull/18009) 管理者および API キーレコードのロールの暗黙的なデフォルトスコープ（`unset` 表示）に対するスコープ処理を一貫化しました。読み書き操作は `unset` 相当のスコープリストを受け入れます。これらのレコードは明示的なスコープリストではなく将来互換の暗黙的スコープを保持し、後続リリースで追加されたスコープが自動的に有効になります。

  - `PUT /api/v5/users/{username}` がデフォルト管理者のノート（説明）のみを更新するリクエストを拒否する問題を修正しました。EMQX はこのようなリクエストに含まれるデフォルトスコープリストを明示的な割当てとみなしません。送信値が `unset` または管理者ロールの完全なデフォルトスコープセットと一致する場合は「明示的スコープなし」とみなしてノート更新を許可します。
  - [#18196](https://github.com/emqx/emqx/pull/18196) API キー作成・更新時に `unset` またはロールのデフォルトスコープと一致するリストを「明示的スコープなし」とみなすようにしました。これにより、API キー取得時に返される `scopes` 値を変更せずに再送信してもリクエスト失敗になりません。
  - [#18221](https://github.com/emqx/emqx/pull/18221) 起動時にデフォルト管理者を明示的スコープリスト付きで作成しなくなりました。起動時に明示的リストを持つデフォルト管理者レコードは暗黙的形式に更新されます。

#### マルチテナンシー

- [#17807](https://github.com/emqx/emqx/pull/17807) namespace スコープの管理者向けに分離されたバックアップ領域を追加しました。データバックアップエンドポイント（`/data/export`、`/data/import`、`/data/files`、`/data/files/:filename`）を通じたエクスポート、アップロード、一覧表示、ダウンロード、インポート、削除操作は自身の namespace のバックアップにのみ作用します。namespace スコープ管理者はグローバルバックアップや他の namespace のバックアップを閲覧・ダウンロード・削除できません。

  グローバル管理者は引き続きデフォルトでグローバルバックアップを管理でき、変更前に作成されたバックアップも含みます。`GET /data/files`、`DELETE /data/files`、`GET /data/files/:filename` に `namespace` クエリパラメータを渡して特定 namespace のバックアップを検査・削除できます。

- [#17975](https://github.com/emqx/emqx/pull/17975) namespace スコープの呼び出し元が `PUT /api/v5/tracing` を通じてグローバルトレーシング設定を更新できないようにしました。namespace スコープのダッシュボードユーザーおよび API キーは HTTP ステータスコード `403` を受け取ります。グローバルダッシュボード管理者は引き続きアクセス可能です。
- [#18008](https://github.com/emqx/emqx/pull/18008) グローバル管理者がバックアップのインポート・アップロード時にオプションの `namespace` クエリパラメータを渡せるようにしました。パラメータが省略された場合はグローバルバックアップスコープが使用されます。

  namespace スコープ管理者の場合、`namespace` クエリパラメータは無視され、呼び出し元の namespace に操作が制限されます。これはバックアップの一覧表示やダウンロード操作と一貫しています。

- [#18117](https://github.com/emqx/emqx/pull/18117) namespace 削除時に、その namespace の組み込みデータベース認証ユーザー（パスワードベースおよび SCRAM）と認可ルールも削除されるようになりました。以前はこれらのレコードが namespace 削除後も残り、同名の namespace を再作成すると再出現していました。

  さらに、新しい CLI コマンド `emqx ctl mt purge_ns <namespace>` を追加しました。namespace を削除し、その namespace に属するすべてのデータをパージします。コマンドは冪等で、namespace の存在を要求しないため、途中で削除が中断された場合の残留データの最終手段として使用できます。

## 6.1.3

*リリース日: 2026-07-01*

EMQX 6.1.3 へのアップグレード前に、破壊的変更および既知の問題を必ずご確認ください。

### 強化点

#### クラスター

- [#17530](https://github.com/emqx/emqx/pull/17530) クラスターリンクは非コミュニティライセンスを必要とするようになりました。デフォルトのコミュニティライセンスでは、設定されたリンクは非アクティブ（メッセージ転送やルート複製なし）で、REST API は非コミュニティライセンスのロードを促す明確なヒント付きでリンク有効化を拒否します。リンクの無効化と削除は引き続き可能で、レガシー設定の整理に使えます。ライセンスアップグレード後は、ノード再起動なしにダッシュボードや REST API からリンクを有効化できます。
- [#17549](https://github.com/emqx/emqx/pull/17549) EMQX Backup Sync プラグインを追加しました。Data Backup API を使い、プライマリクラスターからセカンダリクラスターへ選択された設定を定期同期します。HTTPS 通信に TLS オプションの設定をサポートします。
- [#17620](https://github.com/emqx/emqx/pull/17620) オペレーター向け診断モジュール `emqx_router_tool` を追加しました。`emqx ctl eval` で実行し、ルーティングテーブルの検査と調整を支援します。以下のヘルパーを提供します：

  - `cluster_schema_view/0`：各クラスター ノードが使用するルートストレージスキーマを報告。
  - `scan_missing_routes/0,1`：ローカルのサブスクリプションテーブルをストリームし、このノードにルートエントリがないトピックを報告。2パスでスロットルされ、同時のサブスクライブ・アンサブスクライブを許容。
  - `reconcile_missing_routes/0,1`：既存の `emqx_router:add_route/2` API を使い欠落ルートを再追加。

  スキーマ非依存でライブクラスター上で安全に実行可能です。

#### マルチテナンシー

- [#17711](https://github.com/emqx/emqx/pull/17711) 組み込みデータベース認証ユーザーの HTTP API で namespace 選択を一貫化し、削除済み namespace から残ったレコードのクリーンアップを可能にしました。

  以前はユーザー作成のみリクエストボディに `namespace` フィールドを受け入れ、更新・削除は `ns` クエリパラメータのみでした。更新・削除エンドポイントもリクエストボディの `namespace` を受け入れ、両方指定時は `ns` クエリパラメータが優先されます。ユーザー一覧は引き続き `ns` クエリパラメータを使用します。

- [#17665](https://github.com/emqx/emqx/pull/17665) マルチテナンシーアプリで namespace ごとのドロップメッセージ数とドロップ配信数のカウンターを追加しました。これらは `/api/v5/prometheus/namespaced_stats` で `namespace` ラベル付きで公開され、既存の namespace ごとのメトリクスファミリーと並びます。オペレーターは Prometheus からテナントごとのドロップ率をログ調査なしに診断可能です。

  既知の制限：QoS 2 PUBREL の待機タイムアウトドロップはまだ namespace ごとの帰属がありません。該当ドロップパスはグローバルカウンターを増加させるのみで `message.dropped` フックは発火しません。

#### データ統合

- [#17481](https://github.com/emqx/emqx/pull/17481) MQTT ブリッジのイングレス（ソース）サブスクリプションに `retain_as_published` オプションを追加しました。ブリッジが MQTT 5.0 でリモートブローカーに接続し、`retain_as_published = true` の場合、転送されるメッセージの元の `retain` フラグを保持し、クリアしません。これにより上流の保持メッセージを忠実に再パブリッシュできます。デフォルトは `false` で既存動作を維持します。`proto_ver` が `v3` または `v4` の場合は効果がありません。

  また、`bridge_mode = true` と `proto_ver = v5` の組み合わせはレガシーブリッジモードフラグが MQTT 5.0 で無効なため警告ログを出すようにしました。代わりに個別サブスクリプションで `retain_as_published` を設定してください。

- [#17508](https://github.com/emqx/emqx/pull/17508) PostgreSQL および TimescaleDB コネクター接続で `application_name` スタートアップパラメータを `emqx` に設定しました。これにより PostgreSQL ログや `pg_stat_activity` ビューで EMQX データベースセッションを識別しやすくなります。
- [#17576](https://github.com/emqx/emqx/pull/17576) GreptimeDB コネクターで TLS 暗号スイート設定を `ssl.ciphers` フィールドでサポートしました。指定された暗号リストに限定して TLS ネゴシエーションを行います。サポートされない暗号はコネクター起動時に拒否されます。
- [#17594](https://github.com/emqx/emqx/pull/17594) Google Cloud Pub/Sub および BigQuery コネクターで `service_account_json` に `file://` 秘密ファイルを指定可能にし、外部ファイルからサービスアカウント認証情報を注入できるようにしました。
- [#17717](https://github.com/emqx/emqx/pull/17717) Confluent Producer コネクターで TLS ピア検証を有効にするオプションを追加しました。
- [#17718](https://github.com/emqx/emqx/pull/17718) GCP PubSub Producer/Consumer および BigQuery コネクターで TLS ピア検証を有効にするオプションを追加しました。

#### 可観測性

- [#17712](https://github.com/emqx/emqx/pull/17712) オペレーターがリモートコンソールから呼び出せる診断モジュール `emqx_session_tool` を追加しました。多数の接続があるクラスターで、`emqx_session_tool:top_by(mqueue_len)` を使いゲージやカウンター値で上位 K セッションを見つけられます。`mqueue_dropped` や `inflight_cnt` など他のセッションメトリクスもサポートします。クライアント一覧を手動でページングせずに最も負荷の高いセッションを特定できます。

  スキャンはチャネルレジストリをストリームし、上位 K 結果のみ保持し、接続プロセスにメッセージを送らずキャッシュ済みメトリクスを読み取ります。`emqx_session_tool:cluster_top_by/1` はクラスター全ノードで集約します。

- [#17558](https://github.com/emqx/emqx/pull/17558) `GET /monitor_current` HTTP API に新たに `rules_matched` と `actions_executed` のメトリクスと対応するレートを追加しました。これらはそれぞれマッチしたルール数とアクション実行率（成功＋失敗）を追跡します。

  また、バッチモードでない場合（`batch_size = 1`）に `actions.executed` がアクション呼び出しを過小計上していた問題を修正しました。カウンターはバッファワーカのテレメトリフラッシュウィンドウに依存せず、アクションコールバック呼び出しごとに 1 ずつ増加します。

#### コア MQTT 機能

- [#17529](https://github.com/emqx/emqx/pull/17529) QoS 0 メッセージを Message Queue サブスクリプション経由で配信した際、内部的にアックされず、キューサブスクライバーがローカルのインフライト制限に達した後にメッセージ受信を停止する問題を修正しました。
- [#17540](https://github.com/emqx/emqx/pull/17540) SSL リスナーで `password = "file://..."` を設定し、キーファイルが暗号化されている場合に設定検証が `bad_password_or_invalid_keyfile` で失敗する問題を修正しました。`file://` 参照はランタイムだけでなく検証時にも解決されます。
- [#17569](https://github.com/emqx/emqx/pull/17569) MQTT v5 のユーザープロパティ解析コストを二次関数から線形に削減しました。

  以前は多数のユーザープロパティを含む CONNECT、PUBLISH、SUBSCRIBE パケットが所有コネクションプロセスのスケジューラ時間を超線形に増加させていました。各プロパティがリスト末尾に追加されていたためです。解析はエントリ数に線形スケールしつつワイヤ順序を保持するようになりました。

- [#17731](https://github.com/emqx/emqx/pull/17731) WS または WSS リスナーのオプション更新時（例：TLS 証明書ローテーション）に発生していた一時的な「address already in use」エラーを修正しました。リスナー更新はポートの再バインドを伴い、OS が古いソケットを解放していない場合があるため、EMQX は再バインドを短時間リトライします。
- [#17798](https://github.com/emqx/emqx/pull/17798) 保持メッセージがワイルドカードサブスクリプションの QoS 制限ではなく、元のパブリッシュ QoS で配信される問題を修正しました。
- [#17801](https://github.com/emqx/emqx/pull/17801) `ssl_opts.ciphers` バリデータが OpenSSL または IANA/RFC 命名の暗号名を受け入れるようにしました。以前は OpenSSL 形式のみ認識し、TLS 1.2 の有効な IANA 名（例：`TLS_ECDHE_ECDSA_WITH_AES_256_GCM_SHA384`）を `bad_ciphers` として拒否していました。TLS 1.3 暗号は IANA と OpenSSL 名が同一のため影響ありません。

#### ルールエンジン

- [#17725](https://github.com/emqx/emqx/pull/17725) 6.0.3、6.1.2、6.2.1 で導入されたバグを修正しました。グローバルルールがテナント namespace（`client_attrs.tns`）を持つパブリッシュクライアントのメッセージに対して `FROM` トピックでマッチしなくなる問題です。

  - 以前はレプリカノードに接続していたクライアントの一部がグローバルレジストリから失われ、テイクオーバー時の不整合やダッシュボードの誤情報表示を引き起こしていました。本修正ではネットワーク分断回復時に既存クライアントを再登録するバックグラウンドプロセスを追加し、「ネットワーク分断後にブローカーが回復中」アラームを追加しました。
  - 重複するネットワーク分断を自動回復する新しいクラスター自動修復アルゴリズムを導入しました。

- [#17342](https://github.com/emqx/emqx/pull/17342) エクスポートされた `cluster.hocon` に部分的な `node` セクションが含まれている場合、クラスター設定インポートが `required_field: node.cookie` スキーマチェックエラーで失敗する問題を修正しました。読み取り専用ルート（`node`、`rpc`）はデータインポート対象外のため、インポート前に除外し、検証に実行中ノードの値を使用します。
- [#17348](https://github.com/emqx/emqx/pull/17348) クラスター ノード間で有効なチェック済み設定は同一でも生の設定表現が異なる場合に `emqx ctl conf cluster_sync status` の診断が騒がしく誤解を招く問題を修正しました。チェック済み設定に対応しない生の差異は抑制し、チェック済み設定が不整合な場合のみ警告を出します。生の設定キーが片方にのみ存在する場合のクラッシュも回避します。

  また、アクション、ソース、ブリッジ、ルールメタデータの `created_at` と `last_modified_at` のタイムスタンプのみの差異は無視します。データインポートや起動時設定読み込みで生成されたタイムスタンプは一部ノードのみ更新されることがありますが、実効設定は同一です。

- [#17349](https://github.com/emqx/emqx/pull/17349) 応答しないターゲットクラスターへの接続でルート複製が停滞したクラスターリンクの応答性を改善しました。該当クラスターリンクの削除が若干早く完了します。
- [#17382](https://github.com/emqx/emqx/pull/17382) ネットワーク分断時に発生するグローバルチャネルレジストリの破損を修正しました。
- [#17424](https://github.com/emqx/emqx/pull/17424) ネットワーク分断後の Mnesia 自動修復で同一クライアント ID の重複または古いグローバルセッションレジストリエントリが残るリークを修正しました。

  廃棄およびテイクオーバーキック RPC ハンドラーは対象プロセスが生存しない場合にレジストリ行を削除し、接続パスの登録スロットルはトゥームストーン行（ローカルチャネル状態なし）を認識して新規接続を無期限にブロックする代わりに収集します。

- [#17432](https://github.com/emqx/emqx/pull/17432) 同時実行のクラスターリンク API リクエストが成功または未検出ではなく一般エラー応答を返す問題を修正しました。
- [#17469](https://github.com/emqx/emqx/pull/17469) アクティブなクラスターリンクの有効化・無効化時に以下のような警告が出る問題を修正しました。

- [#17586](https://github.com/emqx/emqx/pull/17586) グローバルセッションレジストリの古いエントリを定期的にパージするようにしました。以前はセッションの所有プロセスがクリーンな登録解除なしに終了すると（例：ネットワーク分断で登録解除が複製されなかった、コアノードのコンセンサスチェックがダウンイベントクリーンアップ中にタイムアウトした場合など）、同一クライアント ID が再接続されない限りレジストリエントリが永続化していました。

#### アクセス制御

- [#16692](https://github.com/emqx/emqx/pull/16692) CRL キャッシュの回帰を修正しました。`emqx_crl_cache:evict/1` が内部の URL 状態を完全にクリアしていませんでした。削除後、同じ CRL URL は次回使用時に正しく再登録され、リフレッシュタイマーが復元され、接続ごとの HTTP フェッチが繰り返されることを防止します。
- [#16780](https://github.com/emqx/emqx/pull/16780) `type` フィールドが欠落した認可ソースのバリデーションで内部エラーが発生する問題を修正しました。EMQX はこのケースで明確な `BAD_REQUEST` バリデーションエラーを返します。
- [#16805](https://github.com/emqx/emqx/pull/16805) 動的 ACL 判定のために認可フック結果が認可キャッシュ保存をオプトアウトできるようにしました。
- [#16865](https://github.com/emqx/emqx/pull/16865) `mqtt.client_attrs_init` 式に `cert_common_name` と `cert_subject` のエイリアスを追加しました。既存の `cn` と `dn` 変数に加わります。
- [#16868](https://github.com/emqx/emqx/pull/16868) REST API 認証エラーメッセージを改善し、プログラムクライアントがベアラートークンの繰り返しログインではなく API キー（Basic 認証）を使うよう誘導します。エラー応答に `api_key.bootstrap_file` 設定と永続的 API キー作成用の `POST /api_key` エンドポイントを記載しました。
- [#16939](https://github.com/emqx/emqx/pull/16939) 組み込みデータベース認証器が、デフォルトのブートストラップファイルパスが設定されているがファイルが存在しない場合に警告を出さないように修正しました。
- [#17045](https://github.com/emqx/emqx/pull/17045) パスワードなしの CONNECT パケットでパスワードベース認証バックエンドが認証チェーンを中断する問題を修正しました。パスワードなし接続時に最初のパスワードベース認証器がエラーを返し、後続認証器が試行されない問題でした。
- [#17100](https://github.com/emqx/emqx/pull/17100) ID プロバイダーが `+json` 構造化シンタックスサフィックス（例：`application/jwk-set+json; charset=utf-8`）を持つ JWKS レスポンスを返すと OIDC SSO ログインが `provider_not_ready` で失敗する問題を修正しました。これらのレスポンスは有効な JWKS として受け入れられます。
- [#17122](https://github.com/emqx/emqx/pull/17122) URL エンコードされたユーザー名（例：メールアドレス）を持つ SSO ユーザーのダッシュボード RBAC チェックを修正し、`force_mfa` 無効時にビューアーのセルフサービス MFA 無効化リクエストが正しく動作するようにしました。
- [#17140](https://github.com/emqx/emqx/pull/17140) PEM ではなく DER エンコードされた CRL ボディ（`Content-Type: application/pkix-crl`）を HTTP 経由で取得した際に EMQX がサイレントに失敗する問題を修正しました。EMQX は PEM と DER の両方をデコードし、どちらでもない場合は URL と共に警告をログに出します。
- [#17171](https://github.com/emqx/emqx/pull/17171) namespace スコープのダッシュボード管理者が自身の MFA を有効化・無効化できない RBAC 問題を修正しました。namespace 管理者は他のダッシュボードユーザーの MFA 設定管理は引き続き制限されます。
- [#17177](https://github.com/emqx/emqx/pull/17177) ダッシュボードで作成された REST API キーは名前由来ではなくランダムに生成されるようになりました。
- [#17223](https://github.com/emqx/emqx/pull/17223) TCP パススループロキシ（例：GCP TCP Proxy NLB、AWS NLB）を SSL リスナーの前に置いた場合にクライアント証明書が欠落する問題を修正しました。TLS ハンドシェイクは成功し証明書は存在していましたが、認証やルールイベントに露出していませんでした。CN、Subject、完全 PEM に依存する関数、ACL ルール、認証バックエンドはこの形態でも正しく動作します。
- [#17428](https://github.com/emqx/emqx/pull/17428) プロバイダーの `.well-known/openid-configuration` レスポンスに `Cache-Control: max-age=0` のようなヘッダーが含まれるとダッシュボード OIDC SSO がクラッシュし、EMQX が OpenID プロバイダー検出を完了できない問題を修正しました。クラッシュにより OIDC スーパーバイザーが単一失敗後に再起動予算を使い果たし、設定再保存なしに SSO が回復不能になっていました。キャッシュコントロールパーサーはこれらの値に寛容になり、ワーカーは不正な有効期限でハードクラッシュせず、OIDC スーパーバイザーは 1 分以内に複数回の再起動を許可し、一時的失敗をクリーンにリトライします。

#### ゲートウェイ

- [#17141](https://github.com/emqx/emqx/pull/17141) CoAP 接続モードのトークンテイクオーバーを修正しました。再接続する UDP/DTLS クライアントは有効なトークンで再開でき、無効なトークン/クライアントID 組み合わせは拒否されます。CoAP テイクオーバー接続フック実行前に必要な接続情報フィールドが存在することを保証しました。

- [#17287](https://github.com/emqx/emqx/pull/17287) MQTT-SN クライアントが予期しない接続状態や Will 状態でパケットを受信してクラッシュする問題を修正しました。`DISCONNECT` が接続セットアップ中に、`REGISTER` が Will ハンドシェイク完了前に、`WILLMSGUPD` が Will トピック存在前に受信された場合が該当します。

#### 可観測性

- [#17497](https://github.com/emqx/emqx/pull/17497) `batch_size = 1` の非バッチモードで設定されたアクションの `actions.executed` メトリクスが `actions.messages` を過小計上していた問題を修正しました。

  以前はバッファワーカのテレメトリフラッシュごとに `actions.executed` を 1 増やしており、多数の個別完了を 1 イベントに集約していたため、バッチなしでも `actions.executed` が `actions.messages` に追従できていませんでした。

  2 つのメトリクスは独立した呼び出し箇所でインクリメントされます：`actions.executed` はアクションコールバック呼び出しごと（バッチモードではバッチごと、シングルモードではメッセージごと）、`actions.messages` は処理したメッセージごと。

- [#17513](https://github.com/emqx/emqx/pull/17513) Prometheus のマッチした認可の許可/拒否メトリクスが実際の認可判定を反映するよう修正しました。

- [#17536](https://github.com/emqx/emqx/pull/17536) ダッシュボードの SSL リスナー `password` およびその他の秘密型設定フィールド（MQTT ブリッジパスワード、クラスターリンクパスワード、ダッシュボード OIDC クライアントシークレット、S3 シークレットアクセスキー、AI Completion API キー、Pulsar/RocketMQ 認証情報など）のツールチップに `file://` オプションをドキュメント化しました。ジェネリックな秘密型説明では既に言及されていましたが、フィールド固有の説明が上書きしていたため、ユーザーはリテラル値のみ受け入れると思い込んでいました。

- [#17708](https://github.com/emqx/emqx/pull/17708) ロガーの JSON フォーマッタークラッシュを修正しました。これにより一部のデバッグレベルトレースイベントが `FORMATTER CRASH` 行に置き換わる問題が解消されました。
