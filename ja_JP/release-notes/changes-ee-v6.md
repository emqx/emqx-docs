# EMQX Enterprise Version 6

## 6.0.4

*リリース日: 2026-09-24*

EMQX 6.0.4 にアップグレードする前に、破壊的変更および既知の問題を必ずご確認ください。

### 強化点

#### コア MQTT 機能

- [#18974](https://github.com/emqx/emqx/pull/18974) `mqtt.max_connect_user_properties` を追加しました。これは MQTT v5 の CONNECT プロパティおよび Will プロパティで受け入れる User Property ペアの数を個別に制限します。デフォルトは 100 で、`infinity` に設定すると制限を無効化します。

- [#19096](https://github.com/emqx/emqx/pull/19096) `mqtt.max_connect_packet_size` 設定を追加しました。これは `mqtt.max_packet_size` に加えて CONNECT パケットのサイズを制限します。CONNECT パケットがこの制限を超えると EMQX はクライアントの接続を切断し、リスナーのシャットダウンカウンター `connect_packet_too_large` をインクリメントします。デフォルトは `1MB` で、`mqtt.max_packet_size` のデフォルトと同じため、この設定を下げるまでは動作に変更はありません。

- [#19126](https://github.com/emqx/emqx/pull/19126) パブリッシュフックでメッセージのパーシステンス成功を報告できるようになりました。プラグインがパーシステンスを報告した場合、HTTP パブリッシュ API はサブスクリプションが一致しなくてもメッセージ ID とともに HTTP 200 を返します。

#### アクセス制御

- [#17732](https://github.com/emqx/emqx/pull/17732) API キー作成および更新エンドポイントに `namespace` フィールドを追加しました。これにより、オペレーターは `role` 文字列内にネームスペースをエンコードする必要がなくなりました（既存の `ns:<namespace>::<role>` 形式は引き続き動作します）。両方の形式が指定された場合は一致している必要があります。

- [#17813](https://github.com/emqx/emqx/pull/17813) ダッシュボードのユーザーおよび API キーエンドポイントで、特権スコープ（`system`、`user_management`、`api_key_management`、`sso_management`）とその他のスコープが混在するスコープリストを拒否するようになりました。これらの特権スコープは管理者相当の権限を持つため、制限付きスコープと組み合わせても意味のある制限にはなりません。アカウントに管理者相当の権限を持たせるかどうかに応じて、特権のみのスコープリストか非特権のみのスコープリストを使用してください。混在したスコープセットを持つ既存のレコードは次回更新まで動作を継続しますが、次回更新時には分割が必要です。

- [#17855](https://github.com/emqx/emqx/pull/17855) ネームスペーススコープのダッシュボード管理者は、自分のネームスペース内で API キーの作成、一覧表示、読み取り、更新、削除が可能になりました。グローバル API キーや他のネームスペースのキーは作成できず、ネームスペース外の API キーは表示されません。

#### データ統合

- [#17933](https://github.com/emqx/emqx/pull/17933) RabbitMQ コネクターがマルチノードの `servers` リスト（例: `rmq1:5672,rmq2:5672`）をサポートし、接続時のフェイルオーバーとプール開始オフセットのローテーションに対応しました。`servers` 未設定時は既存の `server` と `port` 設定が引き続きサポートされます。

- [#17944](https://github.com/emqx/emqx/pull/17944) HTTP コネクターおよび HTTP 認証・認可に OAuth2 クライアントクレデンシャル認証を追加しました。有効化すると、EMQX は設定されたトークンエンドポイントからアクセストークンを取得・更新し、アウトバウンドリクエストに Bearer 認可ヘッダーとして追加します。

  トークン取得に失敗するとコネクターのヘルスチェックは `disconnected` を報告します。OAuth2 を有効にしつつ `Authorization` ヘッダーを指定した設定は拒否されます。

  トークンリクエストボディにはクライアント ID とクライアントシークレットをフォームフィールドとして送信します。HTTP Basic `Authorization` ヘッダーでの送信はサポートされません。

- [#18014](https://github.com/emqx/emqx/pull/18014) Datalayers Arrow Flight コネクターが準備済みステートメントの自動再構築に対応しました。サーバーが再起動などで準備済みステートメントを失った場合、クライアントは再作成して書き込み操作をリトライし、書き込み失敗を回避します。

- [#18042](https://github.com/emqx/emqx/pull/18042) DynamoDB コネクターに AWS IAM ロール認証を追加しました。

  アクセスキー ID とシークレットアクセスキーが省略された場合、EMQX は ECS タスクロールまたは EC2 インスタンスメタデータから一時的な認証情報を取得し、有効期限前に更新します。

- [#18081](https://github.com/emqx/emqx/pull/18081) Snowflake Streaming アクションのレジリエンスを向上しました。チャネルの内部状態が同期外れになった場合でも、失敗した行をリトライし、手動介入なしにチャネルを再オープンしようとします。

- [#18085](https://github.com/emqx/emqx/pull/18085) Kafka、Confluent、Azure Event Hubs プロデューサーに以下の新設定を追加しました：

  - `max_batch_age`（アクション）：プロデューサーバッファ内でこの期間を超えて滞留したメッセージを送信せず破棄。`dropped.expired` メトリックでカウント。デフォルトは `infinity`（破棄しない）。
  - `max_retries`（アクション）：リトライ失敗回数がこの値を超えたメッセージバッチを破棄。`failed` メトリックでカウント。リトライカウンターは Kafka が明示的にエラーコードを返した場合のみ増加し、接続切断後の再送はカウントしません。デフォルトは `infinity`（無限リトライ）。
  - `reconnect_delay`（アクション）：接続切断後の再接続遅延。デフォルトは `2s`（従来はハードコード）。
  - `request_timeout`（コネクター）：Kafka からの応答待ち時間。超過すると接続を再確立。デフォルトは `30s`。

  また、Kafka クライアントライブラリのアップグレード（wolff 4.2.1）により、メモリモードバッファの `max_linger_time` サポートが復活。小規模バッチは最大 `max_linger_time` 待機してメッセージを集約し、送信リクエスト頻度を低減。満杯バッチは遅延なしで送信されます。

- [#18110](https://github.com/emqx/emqx/pull/18110) スキーマレジストリで JSON Schema draft 2019-09 および 2020-12 をサポートしました。

- [#18137](https://github.com/emqx/emqx/pull/18137) GCP Pub/Sub プロデューサーおよびコンシューマーがトピック設定に完全修飾トピックパス（`projects/<project-id>/topics/<topic-name>`）を受け入れるようになりました。これにより、サービスアカウントのプロジェクト外のトピックにパブリッシュまたはサブスクライブ可能です。トピック名のみの場合は従来通りサービスアカウントのプロジェクトに解決されます。コンシューマーはサブスクリプションをサービスアカウントのプロジェクトに作成し、トピック参照のみ別プロジェクトを指すことが可能です。

- [#18515](https://github.com/emqx/emqx/pull/18515) Azure Blob Storage アクションの `blob` テンプレートフィールドが、Aggregated S3 アクションの `key` フィールドと同じスキーマ検証を使うようになり、許可されたバインディングのみが使用されるようになりました。

- [#18926](https://github.com/emqx/emqx/pull/18926) Kafka、Confluent、Azure Event Hubs コネクターに IPv6 サポートを追加しました。

  - `bootstrap_hosts` に括弧付き IPv6 アドレス（例: `[::1]:9092`、`[fd00::5]:9092,host2:9093`）を指定可能。
  - IPv6 のみ解決されるホスト名や IPv6 アドレスを広告するブローカーに接続可能。
  - 新しい `socket_opts.ip_family` オプションで IP アドレスファミリを指定可能。デフォルトの `auto` は IPv4 を優先し、次に IPv6 を試行。`ipv6` に設定すると IPv6 のみ、`ipv4` に設定すると IPv4 のみ接続。

  アップグレードされた Kafka クライアントライブラリは SASL 再認証中に発生していた同期プロデュースのタイムアウトも修正しています。

#### プラグイン

- [#18012](https://github.com/emqx/emqx/pull/18012) EMQX REST API 経由の同期 MQTT リクエスト/レスポンスフローを提供する `emqx_sync_request` プラグインを追加しました。ノードローカルの CLI 診断機能も提供し、リクエストカウンターや現在の保留状態を確認できます。

#### オブザーバビリティ

- [#17712](https://github.com/emqx/emqx/pull/17712) オペレーター向けの診断モジュール `emqx_session_tool` を追加しました。リモートコンソールから呼び出せます。`emqx_session_tool:top_by(mqueue_len)`（または `mqueue_dropped`、`inflight_cnt` など任意のセッションメトリック）で多数の接続があるクラスターでトップKセッションを効率的に検索可能です。チャネルレジストリをストリーム処理し、トップK結果のみ保持し、接続プロセスにメッセージを送らずにキャッシュ済みメトリックを読み取ります。`emqx_session_tool:cluster_top_by/1` は全クラスターのノード結果を集約します。

- [#18528](https://github.com/emqx/emqx/pull/18528) OpenTelemetry 統合のエクスポーターエンドポイントは、スキームと明示的なポートを含む有効な URL でなければならなくなりました。サポートされるスキームは `http` と `https` です。

#### パフォーマンス

- [#18185](https://github.com/emqx/emqx/pull/18185) サブスクリプション HTTP API の深いページングクエリを改善しました。各ターゲットノードでメモリ内にサブスクリプション行を蓄積し、ページネーションごとに RPC を発生させることを回避しています。

- [#18229](https://github.com/emqx/emqx/pull/18229) データ統合の送信パスにおける CPU オーバーヘッドを削減しました。アクションやソース以外のリソース（例: クラスターリンクのメッセージ転送）を経由するメッセージごとにフォーマット済みエラーストリングを生成しなくなり、高負荷時の長スケジューラー警告を抑制します。

#### デプロイメント

- [#18037](https://github.com/emqx/emqx/pull/18037) Red Hat Enterprise Linux 10、Rocky Linux 10、互換ディストリビューション向けに Enterprise Linux 10 (EL10) パッケージを追加しました。

- [#18127](https://github.com/emqx/emqx/pull/18127) macOS 26 (Tahoe) パッケージのリリースを開始しました。

### バグ修正

#### セキュリティ

- [#16389](https://github.com/emqx/emqx/pull/16389) OAuth2 の `client_secret` が認証、認可、ゲートウェイ、HTTP コネクターの設定読み取り API で平文で返されていた問題を修正しました。API レスポンスではマスクされ、マスクされた値を再送信しても保存済みのシークレットは変更されません。

- [#17644](https://github.com/emqx/emqx/pull/17644) `plain` パスワードハッシュアルゴリズムが大文字小文字のみ異なるパスワードを認証で受け入れていた問題を修正しました。

- [#17653](https://github.com/emqx/emqx/pull/17653) Prometheus 設定 API がプッシュゲートウェイヘッダーに保存済みの `Authorization` ヘッダー値を返していたセキュリティ問題を修正しました。API はこれらの値をレスポンスでマスクします。

- [#17654](https://github.com/emqx/emqx/pull/17654) `POST /authentication` で認証プロバイダーのシークレット（JWT HMAC シークレット、HTTP `Authorization` ヘッダー、リクエストボディのパスワードなど）がマスクされずに返されていた問題を修正しました。作成レスポンスは一覧・取得エンドポイントと同様にマスクされます。

- [#17657](https://github.com/emqx/emqx/pull/17657) プラグイン API コールバックに生の `authorization` および `cookie` ヘッダーが転送されていたセキュリティ問題を修正しました。これらの認証情報を含むヘッダーはプラグインコードに届く前にマスクされます。

- [#17739](https://github.com/emqx/emqx/pull/17739) ログ、トレース、監査レコード内の機密データのマスクを改善しました。

- [#17765](https://github.com/emqx/emqx/pull/17765) 複数のゲートウェイブローカー経路で認可チェックが欠落していた問題を修正しました。

  MQTT-SN メッセージパブリッシュ、JT808 上流パブリッシュと自動ダウンリンクサブスクライブ、GBT32960 上流パブリッシュと自動ダウンリンクサブスクライブ、OCPP 上流パブリッシュと自動ダウンリンクサブスクライブは、パブリッシュやサブスクライブの前に認可をチェックします。

- [#17787](https://github.com/emqx/emqx/pull/17787) HTTP コネクターの `ehttpc` ワーカーがリクエスト中に強制終了された際、リクエストヘッダーがエラーログに含まれていた問題を修正しました。

  リクエスト中に `ehttpc` ワーカーが削除されると、`gen_server:call` の引数（リクエストヘッダーを含む）が EXIT 理由に含まれ、エラーログにそのまま書き込まれていました。ログ出力前に引数は破棄されます。

- [#17790](https://github.com/emqx/emqx/pull/17790) TOTP 共有シークレットが `dashboard_login_failed` サーバーログに書き込まれていた問題を修正しました。初回 MFA 設定時に含まれていました。

- [#17791](https://github.com/emqx/emqx/pull/17791) JWT HMAC キーのバイト列が設定更新時の `cluster_rpc_apply_result` および `cluster_rpc_apply_ok` デバッグログに表示されていた問題を修正しました。

  内部の JWK レコード構造を認識し、ログ出力前にプレースホルダーに置換します。`jwk` フィールドも機密として扱います。

- [#17853](https://github.com/emqx/emqx/pull/17853) コネクターのデバッグログにおける機密 HTTP リクエストヘッダーのマスクを改善しました。`x-api-key`、`x-auth-token`、`api-key`、`cookie` ヘッダーはコネクター状態でシークレットとして保持され、トレース/デバッグレベルでの出力時に値が表示されません。共通のヘッダーマスクヘルパーは、コネクターのテンプレートパーサーが生成する iolist 形式のヘッダー名も認識するようになりました。

- [#17888](https://github.com/emqx/emqx/pull/17888) LwM2M ゲートウェイが登録/更新 MQTT レポートに `password`、`secret`、`private_key`、`access_token` などの機密 REGISTER クエリフィールドを含めていた問題を修正しました。

- [#17974](https://github.com/emqx/emqx/pull/17974) 接続ログで生の MQTT パケットデータをデフォルトでマスクするようになりました。診断用に信頼済みクライアント IP をリスナーごとに許可リスト化可能です。

- [#18005](https://github.com/emqx/emqx/pull/18005) CLI 監査ログに機密コマンド引数が記録される問題を修正しました。

- [#18051](https://github.com/emqx/emqx/pull/18051) CoAP デバッグログで機密 URI クエリ値が漏洩していた問題を修正しました。

- [#18146](https://github.com/emqx/emqx/pull/18146) ダッシュボードおよび管理 API のスコープベース認可を強化し、同等のリクエストパスで一貫してアクセス制御チェックを適用するようにしました。

- [#18293](https://github.com/emqx/emqx/pull/18293) QUIC スタックを quicer-0.4.8 (msquic 2.5.7) にアップグレードしました。CVE-2026-32179 のセキュリティ更新を含みます。

- [#18302](https://github.com/emqx/emqx/pull/18302) Elasticsearch アクションの `index` と `id` 値をリクエストパス作成時に URL エンコードするようにしました。`#` や `/` などの文字がパスセグメント内のリテラルとして扱われ、リクエストターゲットを変更しなくなります。JSON リクエストボディは影響を受けません。

- [#18314](https://github.com/emqx/emqx/pull/18314) GCP Pub/Sub プロデューサー、GCP Pub/Sub コンシューマー、BigQuery コネクターの JSON サービスアカウント認証設定の読み取り時に、サービスアカウント JSON 値をマスクするように HTTP API を修正しました。

- [#18330](https://github.com/emqx/emqx/pull/18330) 読み取り専用 REST エンドポイントがシークレットを平文で返さなくなりました：

  - `GET /listeners` と `GET /listeners/{id}` はリスナーの `ssl_options.password` を `******` と表示。
  - `GET /exhooks` と `GET /exhooks/{name}` は gRPC クライアントの `ssl.password` を `******` と表示。
  - `POST /license` の監査ログエントリはリクエストボディを `******` と記録し、ライセンスキーが `GET /audit` に表示されないように。

  `******` プレースホルダーを含むリクエストボディでリスナーや exhook サーバーを更新しても保存済みシークレットは変更されません。

- [#18344](https://github.com/emqx/emqx/pull/18344) HOCON を 0.46.3 にアップグレードしました。配列型設定フィールド内の機密値を `******` と表示し、設定検証エラーログに機密値を出力しなくなりました。

- [#18391](https://github.com/emqx/emqx/pull/18391) 認証キャッシュキーの衝突を修正しました。異なる認証情報が同じバイト列に連結される場合、キャッシュエントリを共有し、クライアントが他のクライアントの認証結果を受け取る可能性がありました。

- [#18580](https://github.com/emqx/emqx/pull/18580) `bin/node_dump` スクリプトが生成する `conf.hocon` ファイル内の機密設定値をマスクしました。

  設定スキーマで機密とマークされた値（例: `dashboard.default_password`、`license.key`）は `******` と書き込まれます。修正前は固定のキー名リストのみマスクされており、これらは平文で書き込まれていました。

- [#18708](https://github.com/emqx/emqx/pull/18708) デバッグモード有効時に Erlang cookie とライセンスキーがシェルトレース出力に表示されるのを防止しました。

  `bin/emqx` コマンドを `DEBUG=1` または `DEBUG=2` で実行しても、Erlang cookie やライセンスキーはシェルトレースに表示されません。

- [#18836](https://github.com/emqx/emqx/pull/18836) クラスター設定同期のデバッグログに成功した設定変更の結果を含めなくなりました。

  結果に HTTP 認証ヘッダーテンプレートなどのコンパイル済みランタイム状態が含まれ、ログマスクが適用されていませんでした。

- [#18853](https://github.com/emqx/emqx/pull/18853) 監査ログで SSO MFA 設定および検証の認証情報がマスクされずに保存されていた問題を修正しました。

  SSO MFA リクエストボディは監査記録に `username` と `backend` のみを保持し、一時トークン、TOTP コード、未知の認証情報フィールドは監査ファイルや監査データベースに書き込む前にマスクされます。

- [#18855](https://github.com/emqx/emqx/pull/18855) クライアント証明書で認証された DTLS クライアントの MQTT-SN セッションウェイクアップ認可を修正しました。証明書に紐づくセッションは同一のピア証明書を提示した場合のみ新しい関連付けから再開可能です。証明書なし、異なる証明書、再発行証明書によるウェイクアップは拒否されます。

  クライアント証明書なしの平文 UDP および DTLS クライアントは従来の ClientId のみの PINGREQ ウェイクアップ動作を維持します。

  フレームおよびハートビートで CRLF (`\r\n`) 行末を受け入れるようになりました。修正前は CRLF 行末のクライアントは接続できませんでした。

### 強化点

#### セキュリティ強化

- [#17040](https://github.com/emqx/emqx/pull/17040) API キーによるダッシュボードユーザーアカウント管理エンドポイントへのアクセスを制限しました。

  以前は `administrator` ロールの API キーが HTTP Basic 認証でダッシュボードユーザー管理エンドポイント（`POST/DELETE /users/:username/mfa`、`POST /users/:username/change_pwd`）を呼び出せました。これにより API キーが他ユーザーの MFA リセットや無効化、パスワード変更を行え、人間のダッシュボードセッションと機械の API キーの分離を回避していました。

  これらのエンドポイントは API キー経由のアクセスで `401 API_KEY_NOT_ALLOW` を返すようになりました。既存の `/users`、`/users/:username`、`/logout`、`/api_key` への API キーアクセス拒否ポリシーと整合します。ダッシュボードユーザーはダッシュボード UI からベアラートークン（JWT）セッションで自身の MFA とパスワードを管理可能です。

- [#17065](https://github.com/emqx/emqx/pull/17065) ルールエンジンで到達可能なコネクターおよびブリッジ設定に対する SSRF 保護を追加しました。

#### クラスタリング

- [#17076](https://github.com/emqx/emqx/pull/17076) 新しいルーティングテーブル同期機構を導入しました。ルーティングテーブルスキーマバージョンは `v3` にステップアップし、`v2` との後方互換性を提供します。

  スキーマ v3 では、各ノード（コアまたはレプリカント）が自身に向けられたルーティングテーブルエントリの完全な所有権を持ち、ピアノードは読み取り専用アクセスのみとなります。これにより、パーティション耐性が向上し、パーティション化されたクラスターでピアノードが他ノードのルーティングテーブルを変更できなくなります。また、レプリカントノードの SUBACK レイテンシも改善されます。

  **後方互換性:** v3 対応ノードが v2 のみ対応クラスターに参加すると互換性のため v2 を使用し続けます。クラスターを v3 に切り替えるにはアップグレード後に全ノードを再起動してください。自動切り替えを防ぐには `broker.routing.storage_schema` を `v2` に設定します。

  **ダウングレード注意:** クラスターが v3 に切り替わるとローリングダウングレードは不可能です。

  ノードの現在のルーティングスキーマバージョンを確認するには：

  ```
  emqx eval 'emqx_router:get_schema_vsn()'
  ```

  API キーはオプションの `scopes` フィールドを持ち、設定時はロールチェックに加えて管理スコープカタログで認可されます。`publisher` API キーロールは `publish` スコープのみ許可されます。

  新カタログエンドポイント `GET /api_key_scopes` と `GET /user_scopes` はベアラー認証呼び出し元にスコープ語彙を公開します。`GET /users`、`POST /users`、`PUT /users/:username` はレスポンスにスコープを含み、明示的に設定されていない場合はロールデフォルトスコープを表示します。

  新スコープモデルに伴う動作変更：

  - `dashboard.default_username` ユーザーは保護されたブレークグラスアカウントとなり、削除、管理者降格、スコープ割当はできず、説明のみ変更可能です。既存の最後の管理者チェックは他の管理者に適用されます。
  - セルフサービス更新はスコープを尊重し、パスワード変更と MFA セルフエンドポイントは例外です。例: `user_management` なしのビューアーは自身のパスワード変更と MFA 管理は可能ですが、他ユーザーの編集はできません。
  - `PUT /users/:username` と `PUT /api_key/:name` はスコープ省略時に永続化済みスコープと照合し、互換性のない降格やロール変更を拒否します。
  - API キーブートストラップファイルはオプションのスコープ列（`key:secret:role:scopes`）を受け入れ、不明またはロール非互換スコープは警告付きで破棄され、既存の 3 列ファイルは読み込み可能です。
  - SAML SP メタデータエンドポイント（`GET /sso/saml/metadata`）は認証不要となり、`/sso/saml/acs` と一致します。

- [#16943](https://github.com/emqx/emqx/pull/16943)、[#17361](https://github.com/emqx/emqx/pull/17361) SSO（LDAP、OIDC、SAML）でバックエンドごとの `force_mfa` 強制を追加しました。

- [#16675](https://github.com/emqx/emqx/pull/16675) セッション引き継ぎや破棄シナリオで `disconnected_at` が `connected_at` より遅く記録されるタイムスタンプ順序問題を修正しました。
