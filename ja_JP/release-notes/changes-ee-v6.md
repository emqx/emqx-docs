# EMQX Enterprise Version 6

## 6.2.3

*リリース日: 2026-08-21*

EMQX 6.2.3 へのアップグレード前に、破壊的変更および既知の問題を必ずご確認ください。

### 強化点

#### アクセス制御

- [#17813](https://github.com/emqx/emqx/pull/17813) ダッシュボードのユーザーおよび API キーのエンドポイントは、特権スコープ（`system`、`user_management`、`api_key_management`、`sso_management`）とその他のスコープが混在するスコープリストを拒否するようになりました。これら4つの特権スコープは管理者相当の権限を持つため、制限付きスコープリストと組み合わせてもアカウントを意味のある形で制限できません。アカウントに管理者相当の権限を持たせるかどうかに応じて、特権スコープのみのリストか、非特権スコープのみのリストを使用してください。既存の混在したスコープセットを持つレコードは次回の更新まで機能し続けますが、次回の更新ではリストを分割する必要があります。
- [#17980](https://github.com/emqx/emqx/pull/17980) 強化されたセキュリティプロファイルにおいて、EMQX はサーバー起動によるサブスクライブに対してトピック検証、認可、MQTT 機能チェック、およびクライアントサブスクライブフックを適用するようになりました。
- [#18002](https://github.com/emqx/emqx/pull/18002) 強化されたセキュリティプロファイルで、SAML レスポンスおよびアサーション署名の検証をデフォルトで有効化しました。
- [#18296](https://github.com/emqx/emqx/pull/18296) 認証器の `precondition` 式（および Variform 式が許容される任意の場所）で使用可能な新しい関数 `is_jwt(value)` を追加しました。これは値が構造的に JWT（JWS コンパクト形式）である場合のみ true を返し、署名検証は行いません。これにより、JWT でないパスワードを提示するクライアントに対して JWT 認証器をスキップでき、特に強化されたセキュリティプロファイル下で非 JWT 認証情報が JWT 認証器により拒否される問題を回避できます。

#### マルチテナンシー

- [#17732](https://github.com/emqx/emqx/pull/17732) API キー作成および更新エンドポイントに `namespace` フィールドを追加しました。これにより、オペレーターは `role` 文字列内にネームスペースをエンコードする必要がなくなりました（既存の `ns:<namespace>::<role>` 形式は引き続き有効です）。両形式が指定された場合は一致する必要があります。
- [#17855](https://github.com/emqx/emqx/pull/17855) ネームスペーススコープのダッシュボード管理者は、自身のネームスペース内で API キーの作成、一覧表示、読み取り、更新、削除が可能になりました。グローバル API キーや他のネームスペースのキーは作成できず、他ネームスペースの API キーは非表示となります。

#### データ統合

- [#17933](https://github.com/emqx/emqx/pull/17933) RabbitMQ コネクターがマルチノードの `servers` リスト（例：`rmq1:5672,rmq2:5672`）をサポートし、接続時フェイルオーバーおよびプール開始オフセットのローテーションを提供します。`servers` 未設定時は従来の `server`/`port` 設定が有効です。
- [#17944](https://github.com/emqx/emqx/pull/17944) HTTP コネクターおよび HTTP 認証・認可に OAuth2 クライアントクレデンシャル認証を追加しました。有効化時、EMQX は設定されたトークンエンドポイントからアクセストークンを取得・更新し、送信リクエストに Bearer 認可ヘッダーとして付加します。

  トークン取得に失敗するとコネクターのヘルスチェックは `disconnected` を報告します。OAuth2 と同時に `Authorization` ヘッダーを指定した設定は拒否されます。

  クライアント ID とクライアントシークレットはトークンリクエストボディのフォームフィールドとして送信され、HTTP Basic `Authorization` ヘッダーでの送信はサポートされません。

- [#18014](https://github.com/emqx/emqx/pull/18014) Datalayers Arrow Flight コネクターが準備済みステートメントの自動再構築を有効化しました。サーバーが準備済みステートメントを失った場合（例：再起動後）、クライアントは自動的に再作成し、書き込み操作を再試行するため、書き込み失敗を回避します。
- [#18042](https://github.com/emqx/emqx/pull/18042) DynamoDB コネクターに AWS IAM ロールクレデンシャルを追加しました。アクセスキー ID とシークレットアクセスキーが省略された場合、EMQX は ECS タスクロールまたは EC2 インスタンスメタデータから一時的なクレデンシャルを取得し、有効期限前に更新します。
- [#18081](https://github.com/emqx/emqx/pull/18081) Snowflake Streaming アクションのレジリエンスを改善しました。チャネルの内部状態が同期外れになる特定のエラー時に、失敗した行を再試行し、手動介入なしでチャネルの再オープンを試みます。
- [#18085](https://github.com/emqx/emqx/pull/18085) Kafka、Confluent、Azure Event Hubs プロデューサーに以下の新設定を追加しました：

  - `max_batch_age`（アクション）：プロデューサーバッファ内でこの期間を超えたメッセージを送信せず破棄し、`dropped.expired` メトリクスにカウントします。デフォルトは `infinity`（破棄なし）。
  - `max_retries`（アクション）：この回数の再試行失敗後にメッセージバッチを破棄し、`failed` メトリクスにカウントします。再試行カウンターは Kafka が明示的にエラーコードを返した場合のみ増加し、接続喪失後の再送は増加しません。デフォルトは `infinity`（無限再試行）。
  - `reconnect_delay`（アクション）：接続喪失後の再接続遅延。デフォルトは `2s`（従来は固定値）。
  - `request_timeout`（コネクター）：Kafka からの応答待ち時間。これを超えると接続が古くなったとみなし再確立します。デフォルトは `30s`。

  Kafka クライアントライブラリ（wolff 4.2.1）をアップグレードし、メモリモードバッファの `max_linger_time` サポートを復活。小規模バッチは最大 `max_linger_time` まで待機し、送信要求頻度を低減。満杯バッチは遅延なく送信されます。

- [#18110](https://github.com/emqx/emqx/pull/18110) スキーマレジストリで JSON Schema draft 2019-09 および 2020-12 をサポートしました。
- [#18137](https://github.com/emqx/emqx/pull/18137) GCP Pub/Sub プロデューサーおよびコンシューマーが、トピック設定に完全修飾トピックパス（`projects/<project-id>/topics/<topic-name>`）を受け入れるようになりました。これにより、サービスアカウントのプロジェクトとは異なる GCP プロジェクトのトピックへのパブリッシュやコンシュームが可能です。ベアトピック名は従来通りサービスアカウントのプロジェクトに解決されます。コンシューマーは依然としてサービスアカウントのプロジェクト内にサブスクリプションを作成し、トピック参照のみ別プロジェクトを指せます。

#### ルールエンジン

- [#18253](https://github.com/emqx/emqx/pull/18253) ルールエンジン SQL 関数 `map_to_range(value, min, max)` と `hash_to_range(value, min, max)` を追加しました。値（またはそのハッシュ）を包含的な整数範囲にマッピングし、シャーディングやバケット分割に便利です。例：トピックセグメントからシャードインデックスを導出して複数ルールにデバイス群を分散する場合、`hash_to_range(nth(2, tokens(topic, '/')), 0, 3)` のように使用します。
- [#18306](https://github.com/emqx/emqx/pull/18306) LZ4 Frame 圧縮・解凍用のルール関数 `lz4_compress` と `lz4_uncompress` を追加しました。

#### プラグイン

- [#18012](https://github.com/emqx/emqx/pull/18012) EMQX REST API 経由の同期 MQTT リクエスト/レスポンスフローを提供する `emqx_sync_request` プラグインを追加しました。ノードローカル CLI 診断用にリクエストカウンターと現在の保留状態も提供します。
- [#18353](https://github.com/emqx/emqx/pull/18353) ルール SQL 用の名前付きマッピングテーブルを提供する新プラグイン `emqx_maptabs` を追加しました。

  テーブルは JSON ファイルからシードされ、メモリ上に保持されてルールエンジンのホットパスから高速に参照可能です。新しいルール SQL 関数 `maptab_lookup(Table, Key)`、`maptab_lookup(Table, Key, Field)`、`maptab_lookup(Table, Key, Field, Default)` は長い `CASE ... WHEN ... THEN` ラダーを単一のテーブルルックアップに置き換え、ルックアップしたフィールドは組み込みの `subbits` 関数を直接駆動してバイナリペイロードをデコードできます。

  テーブルは `emqx ctl maptabs` CLI で管理され、1ノードでのロードや削除はクラスター内全ノードに複製され、更新時にダウンしていたノードは再参加時に自動追従します。

  プラグイン設定で安全制限を提供します：`max_tables`（デフォルト100）、`max_rows_per_table`（デフォルト10000）、`max_table_file_bytes`（デフォルト10000000）。

#### パッケージング

- [#18037](https://github.com/emqx/emqx/pull/18037) Red Hat Enterprise Linux 10、Rocky Linux 10、および互換ディストリビューション向けに Enterprise Linux 10 (EL10) パッケージを追加しました。
- [#18127](https://github.com/emqx/emqx/pull/18127) macOS 26 (Tahoe) パッケージのリリースを開始しました。

#### パフォーマンス

- [#18185](https://github.com/emqx/emqx/pull/18185) サブスクリプション HTTP API の深いページングクエリを改善しました。各ターゲットノードでメモリ内にサブスクリプション行を蓄積し、ページネーションバッチごとに RPC を発行するのを回避します。
- [#18229](https://github.com/emqx/emqx/pull/18229) データ統合の送信パスにおける CPU オーバーヘッドを削減しました。アクションやソースでないリソース（例：クラスターリンクのメッセージ転送）を経由するすべてのメッセージに対してフォーマット済みエラー文字列を生成しなくなり、高負荷時の長スケジューラ警告を回避します。

### バグ修正

#### コア MQTT 機能

- [#17895](https://github.com/emqx/emqx/pull/17895) TLS/WSS リスナーを管理証明書バンドルからファイルベース証明書に切り替える際、参照していたバンドルが既に削除されていても成功するように修正しました。Dashboard が `managed_certs` を `null` でクリアする場合も含みます。
- [#17911](https://github.com/emqx/emqx/pull/17911) Erlang/OTP の ssl アプリケーションが対応している場合、DTLS リスナーで `ECDHE-PSK-CHACHA20-POLY1305` 暗号スイートの検証を可能にしました。
- [#18102](https://github.com/emqx/emqx/pull/18102) 配信レート制限が有効な場合に MQTT クライアントが QoS 1 および QoS 2 メッセージを順不同で受信する問題を修正しました。EMQX はブロックされたメッセージが送信可能になるまで後続メッセージをキューに保持します。

  影響バージョン：6.1.2、6.1.3、および 6.2.0～6.2.2。配信レート制限が設定されたセッションのみが影響を受けます。デフォルトでは制限は設定されていません。

- [#18108](https://github.com/emqx/emqx/pull/18108) まだ参照されている管理証明書バンドル（またはその中の単一ファイル）を削除しようとすると、参照元の設定を明示したエラーで常に失敗するようになりました。`force_delete` クエリパラメータはこのチェックをバイパスしなくなり、API スキーマから削除されました。

  さらに、リスナーがディスク上に存在しない証明書バンドルを参照している場合でも、Prometheus 統計エンドポイントが完全に失敗しなくなりました。該当リスナーは証明書有効期限メトリクスから除外され、警告がログに記録されます。

- [#18111](https://github.com/emqx/emqx/pull/18111) `mqtt.strict_mode` 有効時、MQTT v3.1 の CONNECT パケットでユーザー名フラグなしにパスワードフラグがセットされている場合は拒否されるようになりました。これは MQTT v3.1.1 の既存動作と一致します。MQTT v3.1 仕様ではユーザー名なしでパスワードを提供することは無効です。

  接続ログの可読性も向上しました。CONNECT パケットのトレースではパスワード未提供時に `Password=undefined` と表示し、空パスワードとの区別を可能にしました。またログの `peername` フィールドは常に `10.0.0.1:54123` のようなプレーン文字列で表示されます。

- [#18181](https://github.com/emqx/emqx/pull/18181) バースト値を `0` に設定したレートリミッターが追加のバーストを許可してしまう問題を修正しました。これにより MQTT 配信メッセージレート制限などが設定より緩くなる場合がありました。
- [#18236](https://github.com/emqx/emqx/pull/18236) ソケットバックド TCP リスナーを使用するクライアントが高負荷時に予期せず切断される問題を修正しました。これは準備完了信号がまだ準備できていないソケットに届くことが原因でした。

  ```
  [error] crasher: initial call: emqx_socket_connection:init/4, ..., error: {{case_clause,{select,{select_info,recv,#Ref<...>}}},[{emqx_socket_connection,handle_msg,2,[{file,"emqx_socket_connection.erl"},{line,827}]}, ...
  ```

- [#18293](https://github.com/emqx/emqx/pull/18293) QUIC スタックを quicer-0.4.8（msquic 2.5.7）にアップグレードしました。CVE-2026-32179 のセキュリティ更新を含みます。
- [#18357](https://github.com/emqx/emqx/pull/18357) [#18375](https://github.com/emqx/emqx/pull/18375) ノードの起動完了まで MQTT 接続を拒否するようになりました。これにより、認証、認可、プラグインフックが有効になる前にリスナーがトラフィックを処理しなくなります。

  `GET /status` API は起動完了まで HTTP 503 を返すため、ロードバランサーは新規接続をクラスター内の他ノードにルーティングできます。

  起動完了前のノードへのクラスター参加要求は、後で再試行するよう促すメッセージで拒否されます。

#### 永続ストレージ

- [#18143](https://github.com/emqx/emqx/pull/18143) 永続共有サブスクリプションで、サブスクライバーが異なるノードに接続している場合に共有サブスクリプションリーダーとの通信が失敗する問題を修正しました。これにより CPU 使用率の異常な急増が発生していました。

#### ルールエンジン

- [#17957](https://github.com/emqx/emqx/pull/17957) `rule_engine.limit_selects_in_namespace = true` 設定時に、複数のルールイベント（例：`$events/client/connack`）がグローバルネームスペースのルールをトリガーしない問題を修正しました。
- [#18049](https://github.com/emqx/emqx/pull/18049) `rule_engine.limit_selects_in_namespace = true` 設定時に、アラームの有効化/無効化トリガーによるグローバルルールが発火しない問題を修正しました。
- [#18388](https://github.com/emqx/emqx/pull/18388) ネームスペースに属するルールの `republish` アクションを修正しました。`rule_engine.limit_selects_in_namespace` が有効（デフォルト）な場合、再パブリッシュされたメッセージはルールのネームスペース（`<namespace>/<topic>`）の下でパブリッシュされます。これにより、`republish` アクションはルール自身のネームスペース境界に従います。すでに `<namespace>/` で始まるレンダリング済みトピックは変更されず、プレフィックスを自分で追加するテンプレートはそのまま動作します。`rule_engine.limit_selects_in_namespace = false` に設定すると従来の動作を維持します。

#### データ統合

- [#17859](https://github.com/emqx/emqx/pull/17859) MQTT コネクターが IPv6 ブローカーに接続できるよう修正しました。

  以前は、IPv6 リテラル（例：`[::1]:1883`）が保存時に `bad_host_port` バリデーションエラーで拒否され、IPv6 のみ解決するホスト名は IPv4 接続を試みて「ホスト解決不可」エラーとなっていました。

  サーバーアドレスパーサーは括弧付き IPv6 リテラル（例：`[::1]`、`[::1]:1883`、`mqtt://[::1]:1883`）を受け入れ、MQTT コネクターは接続時に IPv6 プローブを有効化し、IPv6 専用ブローカーにも到達可能です。

  MQTT コネクターおよびクラスターリンクの `server` アドレスは、公式 MQTT URI スキーム `mqtt`（プレーン TCP）および `mqtts`（TLS）を受け入れます。例：`mqtt://broker:1883`、`mqtts://broker:8883`。スキームなしの `host:port` も引き続き受け入れます。その他のスキームは `unsupported_scheme` バリデーションエラーで拒否されます。

- [#17947](https://github.com/emqx/emqx/pull/17947) HTTP コネクターの更新時に、コネクター再作成後にアクションバッファワーカーがブロックされ、メッセージが次の再試行間隔までキューに残る問題を修正しました。
- [#17955](https://github.com/emqx/emqx/pull/17955) GreptimeDB の非同期バッチが低書き込みレート時にヘルスチェック後もフラッシュされず残る問題を修正しました。
- [#17961](https://github.com/emqx/emqx/pull/17961) Kafka または Pulsar コネクターがヘルスチェックタイムアウトで `disconnected` 状態に遷移し、内部キューを再作成する問題を修正しました。現在は `connecting` に遷移します。
- [#17970](https://github.com/emqx/emqx/pull/17970) SSRF 保護が有効な場合、ポリシーでブロックされる既存コネクターのアドレスによりコネクター管理操作が妨げられないようにしました。

  以前は SSRF 保護有効化または拒否リスト拡張後に、無関係なコネクター操作が内部エラーで失敗し、影響を受けたコネクター削除後もアクションやルールは削除済みなのにコネクターが残ることがありました。

  SSRF 保護は HTTP および MQTT コネクターに適用され、作成・更新時にブロックされます。無効化・削除はブロックされず、他のコネクター種別は対象外です。

- [#17973](https://github.com/emqx/emqx/pull/17973) Kafka プロデューサーアクションの再試行メトリクスを修正しました。アクションの `retried`、`retried.success`、`retried.failed` カウンターは、ブローカー再接続後に内部バッファが再送したメッセージを反映し、再試行メッセージが最終的に成功したか失敗したかをオペレーターが判別可能になりました。従来は内部再試行数に関わらず常に `0` でした。`success` および `failed` カウンターは影響を受けず二重計上されません。
- [#17982](https://github.com/emqx/emqx/pull/17982) GCP PubSub コンシューマーが HTTP/2 を使用し、タイムアウト時にプルリクエストをキャンセルするようになりました。これにより GCP サーバーにリクエスト終了をより明確に通知し、メッセージを新しいプルリクエストにリース可能にしてテールレイテンシを削減します。
- [#18055](https://github.com/emqx/emqx/pull/18055) クラスター内の異なるノードで Snowflake Streaming アクションが以下のエラーで失敗し始める問題を修正しました。

  ```
  {unrecoverable_error,#{body => <<"{\"code\":\"STALE_CONTINUATION_TOKEN_SEQUENCER\",\"message\":\"Channel sequencer in the continuation token is stale. Please reopen the channel\"}">>,...
  ```

- [#18110](https://github.com/emqx/emqx/pull/18110) スキーマレジストリの draft-06 JSON Schema で `examples` 注釈を使用すると有効なデータが無効として拒否される問題を修正しました。

#### クラスター

- [#17995](https://github.com/emqx/emqx/pull/17995) 永続化された `mqtt.max_packet_size` がローカル設定と異なるクラスターにノードが参加する際にノードが終了する問題を修正しました。EMQX はリスナー起動前にリスナー更新の副作用をスキップし、EMQX アプリケーション起動時に同期済み設定からリスナーを作成します。

#### マルチテナンシー

- [#17807](https://github.com/emqx/emqx/pull/17807) ネームスペーススコープの管理者に対して、分離されたデータバックアップ領域を追加しました。データバックアップエンドポイント（`/data/export`、`/data/import`、`/data/files`、`/data/files/:filename`）を介したエクスポート、アップロード、一覧表示、ダウンロード、インポート、削除は常に自身のネームスペースのバックアップにのみ作用します。ネームスペーススコープの管理者はグローバルバックアップや他ネームスペースのバックアップを参照・ダウンロード・削除できません。

- [#17975](https://github.com/emqx/emqx/pull/17975) `/tracing` 設定エンドポイント（`PUT /api/v5/tracing`）はグローバル管理者に制限されました。ネームスペーススコープのダッシュボード管理者および API キーはグローバル `[trace]` 設定を変更できず、HTTP 403 で拒否されます。
- [#18008](https://github.com/emqx/emqx/pull/18008) データバックアップ：グローバル管理者は `namespace` クエリパラメータを渡すことでネームスペーススコープのバックアップをインポートまたはアップロードできるようになりました。これは一覧表示やダウンロードと一貫しています。以前はネームスペーススコープのバックアップを直接インポートすると失敗し、アップロード時はグローバルスコープに移動して成功していました。両操作は同じ挙動になります。ネームスペーススコープの管理者はすべての操作で自身のネームスペースに制限されます。
- [#18117](https://github.com/emqx/emqx/pull/18117) ネームスペース削除時に、そのネームスペースの組み込みデータベース認証ユーザー（パスワードベースおよび SCRAM）と認可ルールも削除されるようになりました。以前はこれらレコードがネームスペース削除後も残存し、同名ネームスペース作成時に再出現していました。

  さらに、新しい CLI コマンド `emqx ctl mt purge_ns <namespace>` を追加し、ネームスペースを削除し関連データを完全にパージ可能にしました。このコマンドは冪等で、ネームスペースの存在を要求しません。以前の削除が中断された場合の残留データの最終手段として利用できます。

- [#18164](https://github.com/emqx/emqx/pull/18164) ネームスペース内でのバックアップインポート時のフィードバックを改善しました。対象ネームスペースに属さないアーカイブ（別ネームスペースやグローバルバックアップなど）をインポートすると、何もインポートされず成功したように見える代わりに明確なエラーを返します。グローバル管理者は `namespace` クエリパラメータを使って特定ネームスペースのバックアップを復元可能です。

  グローバルバックアップは完全なクラスターのスナップショットとなりました。グローバルエクスポートはすべてのネームスペースの設定も含み、グローバルインポートは各ネームスペースの設定をそれぞれのネームスペースに復元します。ネームスペースなしクラスターは従来通りのアーカイブを生成・読み込みします。

- [#18222](https://github.com/emqx/emqx/pull/18222) ネームスペーススコープの管理者 API キーはネームスペーススコープのダッシュボードユーザーと同じデフォルトスコープリストを取得するようになりました。特に、`publish` スコープはデフォルトに含まれなくなりました。これは誤解を招くためで、パブリッシュ API はグローバル専用であり、ネームスペース API キーでは使用できません。`publish` を含む明示的スコープリストで新規ネームスペース API キーを作成したり、既存のスコープリストに `publish` を含めて変更すると検証エラーになります。既存の API キーは影響を受けません。以前保存されたスコープリスト（`publish` を含むものも含む）はそのまま保持され、従来通り動作します。
- [#18227](https://github.com/emqx/emqx/pull/18227) 削除された管理ネームスペースのクライアントが非同期クライアントキック中に一時的にネームスペースレート制限なしでパブリッシュできる問題を修正しました。

## 6.2.2

*リリース日: 2026-07-02*

### 強化点

#### クラスター

- [#17530](https://github.com/emqx/emqx/pull/17530) クラスターリンクは非コミュニティライセンスを必要とするようになりました。デフォルトのコミュニティライセンス下では、設定済みリンクは非アクティブ（メッセージ転送やルート複製なし）となり、REST API はリンク有効化試行を拒否し、非コミュニティライセンスのロードを促す明示的なヒントを返します。リンクの無効化および削除は引き続き可能で、レガシー設定の整理に利用できます。ライセンスアップグレード後は、ノード再起動なしでダッシュボードや REST API からリンクを有効化可能です。
- [#17549](https://github.com/emqx/emqx/pull/17549) EMQX Backup Sync プラグインを追加し、データバックアップ API を用いてプライマリクラスターからセカンダリクラスターへ選択設定を定期同期可能にしました。プラグインはプライマリクラスターへの HTTPS 通信に TLS オプションを設定可能です。
- [#17620](https://github.com/emqx/emqx/pull/17620) ルーティングテーブルの検査・調整用のオペレーター向け診断モジュール `emqx_router_tool` を追加しました。`emqx ctl eval` 経由で実行し、以下のヘルパーを提供します：

  - `cluster_schema_view/0`：各クラスター ノードが使用するルートストレージスキーマを報告。
  - `scan_missing_routes/0,1`：ローカルのサブスクリプションテーブルをストリームし、このノードにルートエントリが存在しないトピックを報告。スキャンは2パスで実行され、スロットル制御され、同時のサブスクライブ・アンサブスクライブを許容。
  - `reconcile_missing_routes/0,1`：既存の `emqx_router:add_route/2` API を用いて欠落ルートを再追加。

  モジュールはスキーマ非依存でライブクラスター上で安全に実行可能です。

#### マルチテナンシー

- [#17665](https://github.com/emqx/emqx/pull/17665) マルチテナンシーアプリにテナントごとのドロップメッセージ・ドロップ配信カウンターを追加しました。これらは既存のネームスペース別メトリクスとともに `/api/v5/prometheus/namespaced_stats` で `namespace` ラベル付きで公開されます。オペレーターは Prometheus からテナントごとのドロップ率をログ調査なしに診断可能です。

  既知の制限：QoS 2 PUBREL 待機タイムアウトによるドロップは、グローバルカウンターのみ増加し `message.dropped` フックは発火しないため、ネームスペース別帰属はまだありません。

- [#17711](https://github.com/emqx/emqx/pull/17711) 組み込みデータベース認証ユーザーの HTTP API でネームスペース選択を一貫化し、削除済みネームスペースに残ったレコードのクリーンアップを可能にしました。

  以前はユーザー作成のみリクエストボディに `namespace` フィールドを受け入れ、更新・削除は `ns` クエリパラメータのみ受け入れていました。更新・削除エンドポイントもリクエストボディの `namespace` を受け入れ、両方指定時は `ns` が優先されます。ユーザー一覧は引き続き `ns` クエリパラメータを使用します。

#### アクセス制御

- [#17564](https://github.com/emqx/emqx/pull/17564) 強化されたセキュリティプロファイルで認可バックエンド障害時にフェイルクローズ動作を追加しました。強化モードではバックエンド障害や不正なバックエンド応答はアクセス拒否とし、従来のレガシーモードは無視・フォールバック動作を維持します。
- [#17589](https://github.com/emqx/emqx/pull/17589) 強化されたセキュリティプロファイルでアクセス制御フックコールバック障害時にフェイルクローズ動作を追加しました。認証または認可フックコールバックのクラッシュは無視せずアクセス拒否とします。
- [#17674](https://github.com/emqx/emqx/pull/17674) 強化されたセキュリティプロファイルで認証バックエンド障害や不正応答時にフェイルクローズ動作を追加しました。従来動作は `authentication_settings.ignore_backend_failures` で維持可能です。
- [#17696](https://github.com/emqx/emqx/pull/17696) 強化されたセキュリティプロファイルで JWKS エンドポイントの TLS 証明書検証をデフォルトで有効化し、JWKS キーが利用不可時に提示された JWT を拒否し、JWT 資格情報が欠落した場合は拒否します。
  
#### データ統合

- [#17481](https://github.com/emqx/emqx/pull/17481) MQTT ブリッジのイングレス（ソース）サブスクリプションに `retain_as_published` オプションを追加しました。ブリッジが MQTT 5.0 でリモートブローカーに接続し、`retain_as_published = true` の場合、転送メッセージの元の `retain` フラグを保持し、上流の保持メッセージを忠実に再パブリッシュします。デフォルトは `false` で既存動作を維持します。`proto_ver` が `v3` または `v4` の場合は影響ありません。

  また、`bridge_mode = true` と `proto_ver = v5` の組み合わせはレガシーブリッジモードフラグが MQTT 5.0 で無効なため警告ログを出すようにしました。代わりに個別サブスクリプションで `retain_as_published` を設定してください。

- [#17508](https://github.com/emqx/emqx/pull/17508) PostgreSQL および TimescaleDB コネクター接続で `application_name` スタートアップパラメータを `emqx` に設定しました。これにより PostgreSQL のログや `pg_stat_activity` などで EMQX のデータベースセッションを識別しやすくなります。
- [#17576](https://github.com/emqx/emqx/pull/17576) GreptimeDB コネクターで既存の `ssl.ciphers` フィールドを使った TLS 暗号スイート設定をサポートしました。暗号リスト指定時は TLS ネゴシエーションをそのスイートに制限し、サポートされない暗号は起動時に拒否されます。
- [#17594](https://github.com/emqx/emqx/pull/17594) Google Cloud Pub/Sub および BigQuery コネクターの `service_account_json` 値を `file://` 秘密ファイルで設定可能にしました。これによりサービスアカウント認証情報を外部ファイルから注入できます。

#### オブザーバビリティ

- [#17558](https://github.com/emqx/emqx/pull/17558) `GET /monitor_current` HTTP API に新たに `rules_matched` と `actions_executed` の2つのメトリクスと対応するレートを追加しました。これらはマッチしたルール数とアクション実行率（成功＋失敗）を追跡します。

## 6.2.1

*リリース日: 2026-06-11*

EMQX 6.2.1 へのアップグレード前に、破壊的変更および既知の問題を必ずご確認ください。

### 強化点

#### セキュリティ強化

- [#17040](https://github.com/emqx/emqx/pull/17040) API キーによるダッシュボードユーザーアカウント管理エンドポイントへのアクセスを制限しました。

  以前は `administrator` ロールの API キーが HTTP Basic 認証でダッシュボードのユーザー管理エンドポイント（`POST/DELETE /users/:username/mfa`、`POST /users/:username/change_pwd`）を呼び出せました。これにより、API キーが他のダッシュボードユーザーの MFA をリセットまたは無効化したり、パスワードを変更したりでき、ヒューマンダッシュボードセッションと機械的 API キーの分離を回避していました。

  これらのエンドポイントは API キー経由アクセス時に `401 API_KEY_NOT_ALLOW` を返すようになり、既存の `/users`、`/users/:username`、`/logout`、`/api_key` への API キーアクセス拒否ポリシーと整合します。ダッシュボードユーザーはベアラートークン（JWT）セッションを使ってダッシュボード UI から自身の MFA とパスワードを管理可能です。

- [#17065](https://github.com/emqx/emqx/pull/17065) ルールエンジンから到達可能なコネクターおよびブリッジ設定に対する SSRF 保護を追加しました。

  `rule_engine.ssrf.enable` を `true` に設定すると、EMQX はコネクター、ブリッジ、アクション設定にアウトバウンド SSRF ポリシーを適用します。ポリシーは対象を評価し、`rule_engine.ssrf.deny_hosts` の完全一致は即時拒否、解決済み IP は `rule_engine.ssrf.allow_cidrs` と `rule_engine.ssrf.deny_cidrs` でチェックされます。デフォルト拒否範囲はループバック、リンクローカル（クラウドインスタンスメタデータエンドポイント含む）、RFC 1918、ULA、未指定、マルチキャスト範囲です。チェックは設定更新時に実行され、HTTP の `url` フィールドやすべてのコネクター系の `server`、`servers`、`bootstrap_hosts` フィールドを対象とします。

  この機能はデフォルト無効で、内部サービスを指す正当なコネクターがあるデプロイとの互換性を保ちます。マルチテナントや外部公開環境のオペレーターはネットワーク層のイグレスファイアウォールと併用して有効化を推奨します。

- [#17173](https://github.com/emqx/emqx/pull/17173) API キーによるダッシュボードアカウントおよび API キーのエクスポート・インポートを制限しました。

  API キーで呼び出された `POST /data/export` は生成されるアーカイブから `dashboard_users` と `api_keys` の mnesia テーブルセットを静かに省略します。API キーで呼び出された `POST /data/import` はアップロードされたバックアップにこれらテーブルセットが含まれる場合に `403 FORBIDDEN` を返します。

  ダッシュボードのベアラートークン（ログイン）呼び出しは影響を受けず、ダッシュボードユーザーおよび API キーを含む完全なデータベースのバックアップと復元が可能です。

  これは特権昇格のギャップを閉じます。既存の `/users` と `/api_key` エンドポイントは API キーによるダッシュボードログイン資格情報および API キー記録へのアクセスを拒否しますが、API キー保持者はデータバックアップエンドポイント経由でこれら制限を回避できていました。

- [#17187](https://github.com/emqx/emqx/pull/17187) 未認証の `GET /status?format=json` 応答から EMQX リリースバージョン（`rel_vsn`）を削除しました。バージョンは認証済みノード情報 API で引き続き取得可能です。
- [#17201](https://github.com/emqx/emqx/pull/17201) アップロードされた tarball のパストラバーサルに対するプラグインインストールエンドポイントを強化し、許可リストを厳格化しました。

  - インストールパスは、プラグインインストールディレクトリ外に解決される tarball エントリを拒否します。
  - `emqx ctl plugins allow <name-vsn>` エントリは発行から5分後に期限切れとなり、`emqx ctl plugins allow <name-vsn> sha256:<HEX>` でパッケージの SHA-256 ハッシュに固定可能です。固定ハッシュと一致しないアップロードは `403 Forbidden` で拒否されます。`sha256:` 引数を省略すると従来の `<name-vsn>.tar.gz` 名のペイロードを受け入れる動作を維持します。
  - HTTP プラグインインストールエンドポイント（およびそれをラップするダッシュボードアップロード）で成功したインストールは直ちにクラスター全体で許可エントリを取り消し、異なる tarball での再利用を防ぎます。

- [#17252](https://github.com/emqx/emqx/pull/17252) 公式ダウンロードサイトでプラグインパッケージの `.sha256` チェックサムサイドカーを公開し、ダウンロードしたプラグインアーカイブの整合性検証を可能にしました。
- [#17271](https://github.com/emqx/emqx/pull/17271) 公式 EMQX Docker イメージを強化し、イメージスキャナの検出事項を解消しました。

  - ランタイムイメージビルド時に Debian セキュリティアップグレードを適用し、最新のパッチ済み `libssl3t64` を取り込みました。
  - 未使用の `libgnutls30t64` パッケージを削除しました。EMQX は Erlang/OTP 経由で OpenSSL を使用し GnuTLS はリンクしないため、`curl` の推移的依存としてのみ存在していました。
  - Debian の `curl` パッケージを [stunnel/static-curl](https://github.com/stunnel/static-curl) の静的リンク済みバイナリ（OpenSSL、HTTP/2、HTTP/3 対応、RTMP・GnuTLS 非対応）に置き換えました。Debian パッケージは `librtmp1` 経由で `libgnutls30t64` を再導入するため、静的バイナリによりこれを回避しつつ、コンテナのヘルスチェックで `curl` を呼ぶ動作は変更しません。

- [#17309](https://github.com/emqx/emqx/pull/17309) PROXY-Protocol v2 の SSL Common Name および Subject フィールドに制御文字が紛れ込むのを防ぐためにサニタイズしました。

  `proxy_protocol = true` 設定のリスナーは、PROXY-Protocol SSL TLV バイト列に ASCII 制御文字が含まれる接続を拒否します（これは MQTT で取り込まれる `clientid`、`username`、`password` と同じバイトクラスです）。これにより攻撃者制御のバイトが `${cert_common_name}` や `${cert_subject}` テンプレート経由で HTTP 認証・認可やルールエンジンヘッダー値に到達するのを防ぎます。

  HTTP 認証・認可クライアントも、レンダリングされたヘッダー名や値に CR、LF、NUL バイトが含まれる場合はリクエスト送信を拒否します。

- [#17315](https://github.com/emqx/emqx/pull/17315) MQTT の `clientid`、`username`、`password` に適用されるバイトクラスチェックを、`ClientInfo` と HTTP リクエストテンプレートに供給される他のフィールドにも拡張しました。

  - `peersni`（TLS Server Name Indication、PROXY-Protocol v2 の `authority` TLV 由来も含む）は接続取り込み境界で検証されます。制御文字があると接続は拒否され警告ログが記録されます。
  - `mqtt.client_attrs_init` の Variform 式で生成されるクライアント属性値は制御文字を含む場合に破棄され（警告付き）、`${client_attrs.tns}` のようなテンプレートが注入バイトを下流に運ぶのを防ぎます。
  - HTTP アクションおよびブリッジコネクターのヘッダー描画は、レンダリングされた名前または値に NUL、CR、LF が含まれるヘッダーを破棄します。

- [#17440](https://github.com/emqx/emqx/pull/17440) バックアップファイルダウンロード（`GET /api/v5/data/files/<filename>`）をグローバルダッシュボード管理者に制限しました。バックアップアーカイブにはダッシュボードアカウント（パスワードハッシュや MFA/TOTP 状態含む）および API キー記録が含まれるため、API キー呼び出し、ダッシュボード閲覧者、ネームスペーススコープ管理者はダウンロードできなくなりました。バックアップディレクトリ一覧（`GET /api/v5/data/files`）は従来通り全ロールで利用可能です。
- [#17491](https://github.com/emqx/emqx/pull/17491) ゲートウェイ認証 API、エラーパス、デバッグログでパスワードやシークレットが露出する問題を修正しました。ゲートウェイ認証 API 応答は秘密を秘匿しつつ生の設定構造を保持します。以下のログパスは生パスワード・シークレットを出力しなくなりました：ゲートウェイ認証失敗、リスナー起動エラー、ExProto 認証ログ、CoAP トークン必須ログ、LwM2M 無効登録ログ。
- [#17501](https://github.com/emqx/emqx/pull/17501) ネームスペース間で MQTT メッセージ内容を読み取れないようネームスペーススコープのダッシュボードユーザーを制限しました。

  - 以下のエンドポイントは非グローバル呼び出し元に対し `403 FORBIDDEN` を返します。これらは呼び出し元のネームスペース外の MQTT ペイロードを露出する可能性があるためです。以前はネームスペースユーザーが他ネームスペースのメッセージを読み取り・削除できていました。

    - `GET /clients/:clientid/mqueue_messages`
    - `GET /clients/:clientid/inflight_messages`
    - `GET|DELETE /mqtt/retainer/messages`
    - `GET|DELETE /mqtt/retainer/message/:topic`
    - `GET /mqtt/delayed/messages`
    - `GET|DELETE /mqtt/delayed/messages/:node/:msgid`
    - `DELETE /mqtt/delayed/messages/:topic`

  - トレース API はネームスペーススコープ化されました。`GET /trace` は呼び出し元のネームスペースが作成したトレースのみを一覧表示し、個別トレースエンドポイント（`/trace/:name`、`/trace/:name/download`、`/trace/:name/log`、`/trace/:name/log_detail`、`/trace/:name/stop`）は他ネームスペースのトレースに対して `404` を返し、他ネームスペースのトレース存在を検出できないようにします。`DELETE /trace` の一括削除はグローバル管理者専用で、ネームスペーススコープの呼び出しは `403` となります。ネームスペース管理者は自身のトレースに対して作成、一覧、ダウンロード、ストリーミング、停止、削除を引き続き完全に実行可能です。

#### クラスター

- [#17076](https://github.com/emqx/emqx/pull/17076) 新しいルーティングテーブル同期機構を導入しました。ルーティングテーブルスキーマバージョンは `v3` にステップアップし、`v2` との後方互換性を提供します。

  スキーマ v3 では、各ノード（コアまたはレプリカント）が自身に向かうルーティングテーブルエントリの完全な所有権を持ち、ピアノードはこれらエントリに対して読み取り専用アクセスのみを持ちます。これにより、分断クラスターでピアノードが他ノードの代理でルーティングテーブルを変更できず、パーティション耐性が向上します。また、レプリカントノードの `SUBACK` レイテンシも改善します。

  **後方互換性**：v3 対応ノードが v2 のみ対応ノード群のクラスターに参加すると互換性のため v2 を使用し続けます。クラスターを v3 に切り替えるにはアップグレード後にクラスター全体を再起動してください。自動切り替えを防ぐには `broker.routing.storage_schema` を `v2` に設定します。

  **ダウングレード注意**：クラスターが v3 に切り替わるとローリングダウングレードは不可能です。

  ノードの現在のルーティングスキーマバージョンを確認するには：

  ```
  emqx eval 'emqx_router:get_schema_vsn()'
  ```

- [#17152](https://github.com/emqx/emqx/pull/17152) Erlang inet ポートオプション（接続およびリッスン）を分散ポート用に設定可能にしました。デフォルトのバッファサイズは 1 MB です。

  以前は Erlang 分散ポートのデフォルトバッファが非常に小さく（1460 バイト、一部プラットフォームで約9 KB）、分散ポートバッファ（`+zdbbl`）を 32 MB など大きく設定してもボトルネックとなっていました。これによりクラスター通信の信頼性が低下し、`erpc timeout` エラー、Mnesia トランザクション輻輳、多コアノードサポートの劣化が発生していました。

#### オブザーバビリティ

#### アクセス制御

- [#16942](https://github.com/emqx/emqx/pull/16942) [#17235](https://github.com/emqx/emqx/pull/17235) API キーおよびダッシュボードログインユーザーの詳細なスコープベースアクセス制御を導入しました。

  API キーは OpenAPI タグ由来の管理スコープカタログに基づき、特定 API パスカテゴリへのアクセスを制限可能になりました。スコープなしのキーは従来通り全アクセス可能です。空スコープリストはすべてのスコープ付き API パスを拒否します。`publisher` API キーロールは `[publish]` のみ許可されます。

  ダッシュボードログインユーザーも任意の `scopes` フィールドを持ち、設定時は API キーと同じパス・スコープカタログに対して認可され、既存の役割ベースチェックに重ねて適用されます。4つの新スコープ（`user_management`、`mfa_management`、`sso_management`、`api_key_management`）はダッシュボード専用エンドポイントをカバーし、`mfa_management` を除き管理者のみが持てます。API キーはこれらログイン専用スコープを持てません。両者のチェックは HTTP API とブートストラップファイル読み込みに適用され、互換性のないスコープは警告付きで破棄されます。

  新しい公開カタログエンドポイント `GET /api_key_scopes` と `GET /user_scopes` はベアラー認証呼び出し元にスコープ語彙を公開します。`GET /users`、`POST /users`、`PUT /users/:username` の応答にも `scopes` フィールドが含まれ、明示的に設定されていない場合は役割のデフォルトスコープリストを返します。

  新スコープモデルに伴う動作変更：

  - `dashboard.default_username` ユーザーはブレークグラスアカウントとして保護されます。削除、管理者からの降格、`scopes` フィールド設定はできず、`description` のみ変更可能です。これにより他管理者がスコープを失った場合でもオペレーターが管理権限を保持できます。
  - 自身のレコードに対するセルフサービスはスコープを尊重します。パスワード変更と MFA セルフエンドポイントのみスコープチェックをバイパスし、`PUT /users/:self` などはスコープチェック対象です。
  - `PUT /users/:username` と `PUT /api_key/:name` はリクエストボディに `scopes` がない場合、永続化済みスコープに対して役割変更を検証し、互換性のない降格や役割変更を拒否します。
  - API キーブートストラップファイルはスコープ列（`key:secret:role:scopes`）をオプションで受け入れます。未知または役割に適合しないスコープは警告付きで破棄され、既存の3列ファイルは読み込み可能です。
  - SAML SP メタデータエンドポイント（`GET /sso/saml/metadata`）は認証不要でアクセス可能になり、`/sso/saml/acs` と整合します。

- [#16943](https://github.com/emqx/emqx/pull/16943) SSO（OIDC/SAML/LDAP）バックエンドごとに `force_mfa` オプションを追加しました。

  有効化時、SSO ユーザーは IDP 側 MFA 設定に関わらず、ダッシュボードトークン取得前に TOTP MFA 設定または検証を完了する必要があります。3つの MFA 状態をサポートします：`not_configured`（設定強制）、`enabled`（検証必須）、`admin_disabled`（MFA スキップ）。新 API エンドポイント `POST /sso/mfa/setup` と `POST /sso/mfa/verify` が MFA フローを処理します。

  既存ユーザーは管理者が `/users/:username/mfa` の DELETE/POST で個別に免除または必須化でき、この決定は管理者変更までライブバックエンドポリシーをオーバーライドします。`force_mfa = true` バックエンドの SSO ユーザーが自身で MFA を無効化すると、次回ログイン時に再設定が必須です。管理者による無効化のみが免除となります。

- [#17178](https://github.com/emqx/emqx/pull/17178) `emqx ctl api_keys add` CLI コマンドが REST API と同様に `--scopes <scope1,scope2,...>` オプションを受け入れるようになりました。
- [#17218](https://github.com/emqx/emqx/pull/17218) ACME クライアントプラグイン `emqx_acme` を追加しました。RFC 8555 ACME CA（例：Let's Encrypt）から TLS 証明書を発行・更新し、EMQX 管理証明書バンドルに格納し、SSL/WSS およびダッシュボード HTTPS リスナー設定をバンドル使用に書き換えます。

#### マルチテナンシー

- [#17053](https://github.com/emqx/emqx/pull/17053) 新しいマルチテナンシー設定オプション `multi_tenancy.post_auth_tns_expression` を追加しました。

  設定時、この式は認証チェーン完了後に評価され、その結果が `client_attrs.tns` に書き込まれます。`client_attrs.tns` はマルチテナンシーのクォータやルーティングで使用されるテナントネームスペースキーです。

  これにより、オペレーターは認証応答属性（例：HTTP 認証バックエンドが返す `tag` フィールド）からテナントネームスペースを導出可能となり、事前認証の `mqtt.client_attrs_init` に依存しなくなります。例：`client_attrs.tag`、またはフォールバック付き `coalesce(client_attrs.tag, username)`。

  式が空（デフォルト）の場合は動作変更ありません。

- [#17078](https://github.com/emqx/emqx/pull/17078) 各管理ネームスペースの設定（セッション・リミッター）を `GET /api/v5/mt/managed_ns_list_details` の応答にインライン化し、管理 UI がネームスペースごとの設定を一括で取得可能にしました。これによりネームスペースごとに追加呼び出しを行う必要がなくなります。

- [#17104](https://github.com/emqx/emqx/pull/17104) 集約アップロードアクション（Azure Blob Storage、Amazon S3、GCS、Snowflake、S3 Tables）の BLOB 名テンプレートに日付パーツプレースホルダーを追加しました。プレースホルダーは集約開始時刻に対してレンダリングされ、UTC がデフォルトです。これにより Spark、Databricks、Synapse で直接利用可能な Hive パーティションオブジェクトレイアウト（例：`year=2025/month=04/day=22/hour=07/...`）を実現します。

  サポートプレースホルダー：

  - `${datetime.YYYY}`
  - `${datetime.MM}`
  - `${datetime.DD}`
  - `${datetime.hh}`
  - `${datetime.mm}`
  - `${datetime.ss}`
  - `${datetime.DOY}`（年内日）

  各プレースホルダーは明示的タイムゾーンをプレフィックス可能：

  - `utc`（デフォルト）：例 `${datetime.utc.YYYY}`
  - `local`（EMQX ノードのシステムタイムゾーン）：例 `${datetime.local.YYYY}`

- [#17165](https://github.com/emqx/emqx/pull/17165) アクションに `resource_opts.dispatch_strategy` オプションを追加しました。

  新オプションのデフォルトは `per_clientid` で、従来のバッファワーカーディスパッチ動作を維持します。`random` に設定すると、明示的な `pick_key` がないクエリはランダムなディスパッチキーを使用し、少数クライアントが大量メッセージをパブリッシュする際に複数バッファワーカーにトラフィックを分散します。

- [#17170](https://github.com/emqx/emqx/pull/17170) [#17282](https://github.com/emqx/emqx/pull/17282) [#17297](https://github.com/emqx/emqx/pull/17297) MQTT ブリッジコネクターおよびクラスターリンク設定に `tcp_opts`（`nodelay`、`sndbuf`、`recbuf`、`buffer`、`keepalive`、`delay_send`、`active_n`）を追加しました。これによりアウトバウンド MQTT クライアント TCP ソケットを接続ごとに調整可能です。未設定フィールドは OS / `gen_tcp` のデフォルトを維持します。`delay_send`（デフォルトオフ）は小さな書き込みをまとめてスループットを向上させる代わりにわずかなレイテンシ増加を伴います。
