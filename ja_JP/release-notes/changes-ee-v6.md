# EMQX Enterprise Version 6

## 6.2.3

*リリース日: 2026-08-21*

EMQX 6.2.3 へのアップグレード前に、破壊的変更および既知の問題を必ずご確認ください。

### 強化点

#### アクセス制御

- [#17813](https://github.com/emqx/emqx/pull/17813) DashboardユーザーおよびAPIキーのエンドポイントで、特権スコープ（`system`、`user_management`、`api_key_management`、`sso_management`）とその他のスコープが混在するスコープリストを拒否するようになりました。これら4つの特権スコープは管理者相当の権限を持つため、制限付きスコープと組み合わせてもアカウントを意味のある形で制限できません。アカウントに管理者相当の権限を持たせるかどうかに応じて、特権スコープのみのリストか、非特権スコープのみのリストを使用してください。既存の混在したスコープセットを持つレコードは次回更新まで機能し続けます。次回更新時にはリストを分割する必要があります。
- [#17980](https://github.com/emqx/emqx/pull/17980) 強化されたセキュリティプロファイルで、EMQXはサーバー起動によるサブスクライブに対してトピック検証、認可、MQTT機能チェック、およびクライアントサブスクライブフックを適用するようになりました。
- [#18002](https://github.com/emqx/emqx/pull/18002) 強化されたセキュリティプロファイルで、SAMLレスポンスおよびアサーション署名検証がデフォルトで有効になりました。
- [#18296](https://github.com/emqx/emqx/pull/18296) 認証器の `precondition` 式（およびVariform式が許される任意の場所）で使用可能な新しい関数 `is_jwt(value)` を追加しました。これは値が構造的にJWT（JWSコンパクト形式）である場合のみtrueを返し、署名検証は行いません。これにより、JWT認証器が非JWTパスワードを提示するクライアントに対してクリーンにスキップされます。特に、強化されたセキュリティプロファイル下で非JWT資格情報がJWT認証器により拒否される場合に有用です。

#### マルチテナンシー

- [#17732](https://github.com/emqx/emqx/pull/17732) APIキー作成および更新エンドポイントに `namespace` フィールドを追加しました。これにより、オペレーターは `role` 文字列内にネームスペースをエンコードする必要がなくなりました（既存の `ns:<namespace>::<role>` 形式は引き続き有効です）。両方の形式が提供された場合は一致している必要があります。
- [#17855](https://github.com/emqx/emqx/pull/17855) ネームスペーススコープ付きのDashboard管理者は、自身のネームスペース内でAPIキーの作成、一覧表示、読み取り、更新、削除が可能になりました。グローバルAPIキーや他のネームスペースのキーは作成できず、他のネームスペースのAPIキーは表示されません。

#### データ統合

- [#17933](https://github.com/emqx/emqx/pull/17933) RabbitMQコネクターでマルチノードの `servers` リスト（例：`rmq1:5672,rmq2:5672`）をサポートし、接続時のフェイルオーバーおよびプール開始オフセットのローテーションを実装しました。`servers` が未設定の場合は従来の `server`/`port` が有効です。
- [#17944](https://github.com/emqx/emqx/pull/17944) HTTPコネクターおよびHTTP認証・認可にOAuth2クライアントクレデンシャル認証を追加しました。有効化すると、EMQXは設定されたトークンエンドポイントからアクセストークンを取得・更新し、アウトバウンドリクエストにBearer認証ヘッダーとして付加します。

  トークン取得に失敗するとコネクターのヘルスチェックは `disconnected` を報告します。OAuth2を有効にしつつ `Authorization` ヘッダーを設定した構成は拒否されます。

  クライアントIDとクライアントシークレットはトークンリクエストボディのフォームフィールドとして送信され、HTTP Basic認証ヘッダーでの送信はサポートされません。

- [#18014](https://github.com/emqx/emqx/pull/18014) Datalayers Arrow Flightコネクターで準備済みステートメントの自動再構築を有効化しました。サーバーが準備済みステートメントを失った場合（例：再起動後）、クライアントは自動的に再作成し、書き込み操作を再試行して書き込み失敗を回避します。
- [#18042](https://github.com/emqx/emqx/pull/18042) DynamoDBコネクターにAWS IAMロール認証情報サポートを追加しました。

  アクセスキーIDとシークレットアクセスキーが両方省略された場合、EMQXはECSタスクロールまたはEC2インスタンスメタデータから一時的な認証情報を取得し、有効期限前に更新します。

- [#18081](https://github.com/emqx/emqx/pull/18081) Snowflake Streamingアクションのレジリエンスを向上させました。チャネルの内部状態が同期外になる特定のエラー時に、失敗した行を再試行し、手動介入なしでチャネルの再オープンを試みます。
- [#18085](https://github.com/emqx/emqx/pull/18085) Kafka、Confluent、Azure Event Hubsのプロデューサーに以下の新しい設定オプションを追加しました：

  - `max_batch_age`（アクション）：プロデューサーバッファに一定時間以上滞留したメッセージを送信せず破棄し、`dropped.expired` メトリクスでカウント。デフォルトは `infinity`（破棄しない）。
  - `max_retries`（アクション）：指定回数の再試行失敗後にメッセージバッチを破棄し、`failed` メトリクスでカウント。Kafkaが明示的にエラーコードを返した場合のみカウントし、接続喪失後の再送はカウントしません。デフォルトは `infinity`（無限再試行）。
  - `reconnect_delay`（アクション）：接続喪失後の再接続までの遅延。デフォルトは `2s`（従来は固定値）。
  - `request_timeout`（コネクター）：Kafkaからの応答待ち時間。超過すると接続を再確立。デフォルトは `30s`。

  Kafkaクライアントライブラリ（wolff 4.2.1）をアップグレードし、メモリモードバッファの `max_linger_time` サポートを復活。小規模バッチは最大 `max_linger_time` 待機し、送信リクエスト頻度を低減。満杯バッチは遅延なく送信されます。

- [#18110](https://github.com/emqx/emqx/pull/18110) スキーマレジストリでJSON Schemaドラフト2019-09および2020-12をサポートしました。
- [#18137](https://github.com/emqx/emqx/pull/18137) GCP Pub/Subのプロデューサーとコンシューマーがトピック設定で完全修飾トピックパス（`projects/<project-id>/topics/<topic-name>`）を受け入れるようになりました。これにより、サービスアカウントのプロジェクトとは異なるGCPプロジェクトのトピックにパブリッシュまたはコンシューム可能です。素のトピック名は従来通りサービスアカウントのプロジェクトに解決されます。コンシューマーはサブスクリプションをサービスアカウントのプロジェクトに作成し、トピック参照のみ別プロジェクトを指せます。

#### ルールエンジン

- [#18253](https://github.com/emqx/emqx/pull/18253) ルールエンジンSQL関数 `map_to_range(value, min, max)` と `hash_to_range(value, min, max)` を追加しました。値（またはそのハッシュ）を指定範囲内の整数にマッピングし、シャーディングやバケット分割に有用です。例：トピックのセグメントからシャードインデックスを導出し、大規模デバイス群を複数ルールに分散可能です：`hash_to_range(nth(2, tokens(topic, '/')), 0, 3)`。
- [#18306](https://github.com/emqx/emqx/pull/18306) LZ4 Frame圧縮・解凍のためのルール関数 `lz4_compress` と `lz4_uncompress` を追加しました。

#### プラグイン

- [#18012](https://github.com/emqx/emqx/pull/18012) EMQX REST API経由の同期MQTTリクエスト/レスポンスフローを提供する `emqx_sync_request` プラグインを追加しました。ノードローカルCLI診断でリクエストカウンターや現在の保留状態を確認可能です。
- [#18353](https://github.com/emqx/emqx/pull/18353) ルールSQL用の名前付きマッピングテーブルを提供する新プラグイン `emqx_maptabs` を追加しました。

  テーブルはJSONファイルから初期化され、メモリ上に保持されて高速なルックアップを実現します。新しいルールSQL関数 `maptab_lookup(Table, Key)`、`maptab_lookup(Table, Key, Field)`、`maptab_lookup(Table, Key, Field, Default)` は長い `CASE ... WHEN ... THEN` を単一のテーブルルックアップに置き換え、ルックアップしたフィールドは組み込みの `subbits` 関数を直接駆動してバイナリペイロードをデコード可能です。

  テーブルは `emqx ctl maptabs` CLIで管理され、1ノードでのロードや削除はクラスタ内全ノードにレプリケートされます。更新時にオフラインだったノードは再参加時に自動的に追いつきます。

  プラグイン設定には安全制限があり、`max_tables`（デフォルト100）、`max_rows_per_table`（デフォルト10000）、`max_table_file_bytes`（デフォルト10000000）があります。

- [#18229](https://github.com/emqx/emqx/pull/18229) データ統合の送信パスにおけるCPUオーバーヘッドを削減しました。アクションやソースでないリソース（例：クラスターリンクのメッセージ転送）を経由するメッセージごとにフォーマット済みエラー文字列を生成しなくなり、高負荷時の長スケジューラー警告を回避します。

### バグ修正

#### コアMQTT機能

- [#17895](https://github.com/emqx/emqx/pull/17895) TLS/WSSリスナーを管理証明書バンドルからファイルベース証明書へ切り替える際、参照されているバンドルが既に削除されていても成功するように修正しました。Dashboardが `managed_certs` を `null` に設定してクリアする場合も含みます。
- [#17911](https://github.com/emqx/emqx/pull/17911) Erlang/OTPの `ssl` アプリケーションが対応している場合、DTLSリスナーで `ECDHE-PSK-CHACHA20-POLY1305` 暗号スイートの検証を許可しました。
- [#18102](https://github.com/emqx/emqx/pull/18102) 配信レート制限が有効な場合にMQTTクライアントがQoS 1およびQoS 2メッセージを順不同で受信する問題を修正しました。EMQXはブロックされたメッセージが送信可能になるまで後続メッセージをキューイングします。

  影響バージョン: 6.1.2、6.1.3、および6.2.0～6.2.2。配信レート制限が設定されたセッションのみ影響を受けます。デフォルトでは設定されていません。

- [#18108](https://github.com/emqx/emqx/pull/18108) まだ参照されている管理証明書バンドル（またはその中の単一ファイル）を削除しようとすると、参照元設定を明示したエラーで必ず失敗するようになりました。`force_delete` クエリパラメータはチェックをバイパスしなくなり、APIスキーマから削除されました。

  さらに、リスナーがディスク上に存在しない証明書バンドルを参照している場合でも、Prometheus統計エンドポイントが完全に失敗しなくなりました。該当リスナーは証明書有効期限メトリクスから除外され、警告ログが出力されます。

- [#18111](https://github.com/emqx/emqx/pull/18111) `mqtt.strict_mode` 有効時に、MQTT v3.1のCONNECTパケットでユーザー名フラグなしにパスワードフラグが設定されている場合は拒否するように修正しました。これはMQTT v3.1.1の既存動作と一致します。MQTT v3.1仕様ではユーザー名なしでパスワードを提供することは無効です。

  接続ログの可読性も改善され、パスワード未提供時は `Password=undefined` と表示されるようになりました（従来は空パスワードと区別できませんでした）。ログの `peername` フィールドは常に `10.0.0.1:54123` のようなプレーン文字列で表示されます。

- [#18181](https://github.com/emqx/emqx/pull/18181) バースト値が `0` に設定されたレートリミッターが追加のバーストを許可してしまう問題を修正しました。これにより、MQTT配信メッセージレート制限などが設定より緩くなることがありました。
- [#18236](https://github.com/emqx/emqx/pull/18236) ソケットベースのTCPリスナーを使用するクライアントが高負荷時に予期せず切断される問題を修正しました。準備完了していないソケットに対して準備完了シグナルが届くことが原因でした。

  ```
  [error] crasher: initial call: emqx_socket_connection:init/4, ..., error: {{case_clause,{select,{select_info,recv,#Ref<...>}}},[{emqx_socket_connection,handle_msg,2,[{file,"emqx_socket_connection.erl"},{line,827}]}, ...
  ```

- [#18293](https://github.com/emqx/emqx/pull/18293) QUICスタックを quicer-0.4.8（msquic 2.5.7）にアップグレードしました。
- [#18357](https://github.com/emqx/emqx/pull/18357) [#18375](https://github.com/emqx/emqx/pull/18375) ノード起動完了までMQTT接続を拒否するようにしました。これにより、認証・認可・プラグインフックが有効になる前にリスナーがトラフィックを処理しなくなります。

  `GET /status` APIは起動完了までHTTP 503を返すようになり、ロードバランサーはクラスタ内の他ノードへ新規接続をルーティング可能です。

  起動完了していないノードへのクラスタ参加要求は「後で再試行してください」というメッセージで拒否されます。

- [#18049](https://github.com/emqx/emqx/pull/18049) `rule_engine.limit_selects_in_namespace = true` 設定時に、アラームの有効化/無効化トリガーによるグローバルルールが発火しない問題を修正しました。
- [#18388](https://github.com/emqx/emqx/pull/18388) ネームスペースに属するルールの `republish` アクションを修正しました。`rule_engine.limit_selects_in_namespace` が有効（デフォルト）な場合、再パブリッシュされたメッセージはルールのネームスペースプレフィックス付きトピック（`<namespace>/<topic>`）でパブリッシュされます。これにより、`republish` アクションはルールのネームスペース境界を遵守します。既に `<namespace>/` で始まるレンダリング済みトピックは変更されません。`rule_engine.limit_selects_in_namespace = false` に設定すると従来の動作が維持されます。

#### データ統合

- [#17859](https://github.com/emqx/emqx/pull/17859) MQTTコネクターがIPv6ブローカーに接続できるよう修正しました。

  以前はIPv6リテラル（例：`[::1]:1883`）が保存時に `bad_host_port` バリデーションエラーで拒否され、IPv6のみ解決されるホスト名はIPv4接続を試みて「ホスト解決不可」エラーとなっていました。

  サーバーアドレスパーサーは角括弧付きIPv6リテラル（例：`[::1]`、`[::1]:1883`、`mqtt://[::1]:1883`）を受け入れ、MQTTコネクターは接続時にIPv6プローブを有効化し、IPv6専用ブローカーに到達可能にしました。

  MQTTコネクターとクラスターリンクの `server` アドレスは公式MQTT URIスキーム `mqtt`（平文TCP）と `mqtts`（TLS）を受け入れます。例：`mqtt://broker:1883`、`mqtts://broker:8883`。スキームなしの `host:port` も引き続き受け入れます。その他のスキームは `unsupported_scheme` バリデーションエラーで拒否されます。

- [#17947](https://github.com/emqx/emqx/pull/17947) HTTPコネクターの更新時に、アクションバッファワーカーがブロックされてメッセージが次の再試行間隔までキューに残る問題を修正しました。
- [#17955](https://github.com/emqx/emqx/pull/17955) GreptimeDBの非同期バッチが低書き込みレート時にヘルスチェック後もフラッシュされない問題を修正しました。
- [#17961](https://github.com/emqx/emqx/pull/17961) KafkaまたはPulsarコネクターがヘルスチェックタイムアウトで `disconnected` 状態に遷移し、内部キューが再作成される問題を修正しました。これらはタイムアウト後に `connecting` 状態に遷移します。
- [#17970](https://github.com/emqx/emqx/pull/17970) SSRF保護有効時に、ポリシーでブロックされた既存コネクターの影響でコネクター管理操作が妨害される問題を修正しました。

  以前は、SSRF保護有効化（または拒否リスト拡張）後に作成済みコネクターがあると、無関係なコネクター操作が内部エラーで失敗し、影響を受けたコネクターの削除がアクションやルール削除後も残存することがありました。

  SSRF保護はHTTPおよびMQTTコネクターに適用され、作成・更新時にブロックされたアドレスを拒否します。コネクターの有効化・無効化・削除はブロックされず、他のコネクター種別はポリシー対象外です。

- [#17973](https://github.com/emqx/emqx/pull/17973) Kafkaプロデューサーアクションの再試行メトリクスを修正しました。アクションの `retried`、`retried.success`、`retried.failed` カウンターは、ブローカー再接続後に内部バッファが再送したメッセージを反映し、オペレーターが再試行メッセージの最終成功・失敗を判別可能になりました。従来は内部再試行数に関わらずこれらのカウンターは常に0でした。`success` と `failed` カウンターは影響を受けず重複カウントされません。
- [#17982](https://github.com/emqx/emqx/pull/17982) GCP Pub/SubコンシューマーがHTTP/2を使用し、タイムアウト時にプルリクエストをキャンセルするようになりました。これによりGCPサーバーにリクエスト終了が明確に伝わり、メッセージのリースが次のプルリクエストに割り当てられやすくなり、テールレイテンシが低減します。
- [#18055](https://github.com/emqx/emqx/pull/18055) クラスター内の異なるノードでSnowflake Streamingアクションが以下のエラーで失敗する問題を修正しました。

  ```
  {unrecoverable_error,#{body => <<"{\"code\":\"STALE_CONTINUATION_TOKEN_SEQUENCER\",\"message\":\"Channel sequencer in the continuation token is stale. Please reopen the channel\"}">>,...
  ```

- [#18110](https://github.com/emqx/emqx/pull/18110) スキーマレジストリでdraft-06 JSON Schemaの `examples` 注釈を使用した際に有効なデータが無効と判定される問題を修正しました。

- [#17530](https://github.com/emqx/emqx/pull/17530) クラスターリンクは非コミュニティライセンスが必要になりました。デフォルトのコミュニティライセンス下では、設定済みリンクは非アクティブ（メッセージ転送やルート複製なし）となり、REST APIは非コミュニティライセンス読み込みを促す明確なヒント付きでリンク有効化を拒否します。リンクの無効化および削除は引き続き可能で、レガシー設定の整理に利用できます。ライセンスアップグレード後はDashboardまたはREST APIからノード再起動なしでリンクを有効化可能です。
- [#17549](https://github.com/emqx/emqx/pull/17549) EMQX Backup Syncプラグインを追加し、Data Backup APIを使ってプライマリクラスタからセカンダリクラスタへ選択設定を定期同期可能にしました。HTTPSコールのTLSオプション設定をサポートします。
- [#17620](https://github.com/emqx/emqx/pull/17620) オペレーター向け診断モジュール `emqx_router_tool` を追加しました。`emqx ctl eval` で実行し、以下のヘルパーを提供します：

  - `cluster_schema_view/0`：各クラスタノードが使用するルートストレージスキーマを報告。
  - `scan_missing_routes/0,1`：ローカルサブスクリプションテーブルをストリームし、このノードにルートエントリがないトピックを報告。2パスで実行、スロットリングされ、同時サブスクライブ・アンサブスクライブを許容。
  - `reconcile_missing_routes/0,1`：既存の `emqx_router:add_route/2` APIを使い欠落ルートを再追加。

  スキーマ非依存でライブクラスタ上で安全に実行可能です。

#### マルチテナンシー

- [#17665](https://github.com/emqx/emqx/pull/17665) マルチテナンシーアプリにネームスペース別の破棄メッセージ・配信破棄カウンターを追加しました。これらは既存のネームスペース別メトリクスと共に `/api/v5/prometheus/namespaced_stats` で `namespace` ラベル付きで公開されます。オペレーターはログ調査なしにPrometheusからテナント別の破棄率を診断可能です。

  既知制限：QoS 2 PUBRELの待機タイムアウト破棄はまだネームスペース別帰属されません。該当経路はグローバルカウンターをインクリメントし、`message.dropped` フックは発火しません。

- [#17711](https://github.com/emqx/emqx/pull/17711) 組み込みデータベース認証ユーザーHTTP APIでネームスペース選択を一貫化し、削除済みネームスペースの残存レコードのクリーンアップを可能にしました。

  以前はユーザー作成のみリクエストボディに `namespace` フィールドを受け入れていましたが、更新・削除は `ns` クエリパラメータのみ受け入れていました。更新・削除もリクエストボディの `namespace` を受け入れ、両方指定時は `ns` が優先されます。ユーザー一覧は引き続き `ns` クエリパラメータを使用します。

#### アクセス制御

- [#17564](https://github.com/emqx/emqx/pull/17564) 強化されたセキュリティプロファイルで認可バックエンド障害時にフェイルクローズ動作を追加しました。強化モードではバックエンド障害や不正レスポンスでアクセス拒否し、従来モードは既存の無視・フォールバック動作を維持します。
- [#17589](https://github.com/emqx/emqx/pull/17589) 強化されたセキュリティプロファイルでアクセス制御フックコールバック障害時にフェイルクローズ動作を追加しました。認証・認可フックコールバックのクラッシュは無視されずアクセス拒否となります。
- [#17674](https://github.com/emqx/emqx/pull/17674) 強化されたセキュリティプロファイルで認証バックエンド障害や不正レスポンス時にフェイルクローズ動作を追加しました。従来動作は `authentication_settings.ignore_backend_failures` で維持可能です。
- [#17696](https://github.com/emqx/emqx/pull/17696) 強化されたセキュリティプロファイルでJWKSエンドポイントTLS証明書検証をデフォルトで有効化し、JWKS鍵が利用不可の場合JWTを拒否、JWT資格情報が欠如した場合に拒否するようにしました。

#### データ統合

- [#17481](https://github.com/emqx/emqx/pull/17481) MQTTブリッジのイングレス（ソース）サブスクリプションに `retain_as_published` オプションを追加しました。ブリッジがMQTT 5.0でリモートブローカーに接続し、`retain_as_published = true` の場合、転送メッセージの元の `retain` フラグを保持し、アップストリームの保持メッセージを忠実に再パブリッシュします。デフォルトは既存動作維持のため `false` です。`proto_ver` が `v3` または `v4` の場合は効果がありません。

  また、`bridge_mode = true` と `proto_ver = v5` の同時設定時に警告ログを出力します。MQTT 5.0では従来のブリッジモードフラグは無効であり、個別サブスクリプションで `retain_as_published` を設定してください。

- [#17508](https://github.com/emqx/emqx/pull/17508) PostgreSQLおよびTimescaleDBコネクター接続で、`application_name` スタートアップパラメータを `emqx` に設定しました。これにより、PostgreSQLログや `pg_stat_activity` などでEMQXのデータベースセッションが識別しやすくなります。
- [#17576](https://github.com/emqx/emqx/pull/17576) GreptimeDBコネクターでTLS暗号スイート設定を既存の `ssl.ciphers` フィールドでサポートしました。暗号リスト指定時はTLSネゴシエーションがそれらに制限され、サポート外の暗号はコネクター起動時に拒否されます。
- [#17594](https://github.com/emqx/emqx/pull/17594) Google Cloud Pub/SubおよびBigQueryコネクターの `service_account_json` 値に `file://` 秘密ファイルを指定可能にし、外部ファイルからサービスアカウント認証情報を注入可能にしました。

#### 可観測性

- [#17558](https://github.com/emqx/emqx/pull/17558) `GET /monitor_current` HTTP APIに新たに `rules_matched` と `actions_executed` メトリクスおよび対応レートを追加しました。これらはマッチしたルール数とアクション実行率（成功＋失敗）を追跡します。

  また、非バッチモード（`batch_size = 1`）での `actions.executed` の過小計測を修正しました。カウンターはバッファワーカーテレメトリーフラッシュに依存せず、アクションコールバック呼び出しごとに1回インクリメントされます。

## 6.2.1

*リリース日: 2026-06-11*

EMQX 6.2.1 へのアップグレード前に、破壊的変更および既知の問題を必ずご確認ください。

### 強化点

#### セキュリティ強化

- [#17040](https://github.com/emqx/emqx/pull/17040) APIキーによるDashboardユーザーアカウント管理エンドポイントへのアクセスを制限しました。

  以前は `administrator` ロールのAPIキーがHTTP Basic認証でDashboardユーザー管理の `POST/DELETE /users/:username/mfa` および `POST /users/:username/change_pwd` を呼び出せました。これによりAPIキーが他のDashboardユーザーのMFAリセットや無効化、パスワード変更を行え、人間のDashboardセッションと機械APIキーの分離が破られていました。

  これらのエンドポイントはAPIキー経由アクセス時に `401 API_KEY_NOT_ALLOW` を返すようになり、既存の `/users`、`/users/:username`、`/logout`、`/api_key` へのAPIキーアクセス拒否ポリシーと整合します。DashboardユーザーはBearerトークン（JWT）セッションでDashboard UIから自身のMFA・パスワードを管理可能です。

- [#17065](https://github.com/emqx/emqx/pull/17065) ルールエンジンから到達可能なコネクターおよびブリッジ設定に対するSSRF保護を追加しました。

  `rule_engine.ssrf.enable` が `true` の場合、EMQXはコネクター、ブリッジ、アクション設定にアウトバウンドSSRFポリシーを適用します。ポリシーは各ターゲットを評価し、`rule_engine.ssrf.deny_hosts` の完全一致は即時拒否、解決済みIPは `rule_engine.ssrf.allow_cidrs` と `rule_engine.ssrf.deny_cidrs` でチェックされます。デフォルト拒否範囲はループバック、リンクローカル（クラウドインスタンスメタデータエンドポイント含む）、RFC 1918、ULA、未指定、マルチキャストです。チェックは設定更新時に実行され、HTTPの `url` フィールドや全コネクター種別の `server`、`servers`、`bootstrap_hosts` フィールドを対象とします。

  この機能はデフォルト無効で、内部サービスを指す正当なコネクターがあるデプロイとの互換性を維持します。マルチテナントや外部公開環境のオペレーターはネットワーク層のイグレスファイアウォールと併せて有効化を推奨します。

- [#17173](https://github.com/emqx/emqx/pull/17173) APIキーによるDashboardアカウントおよびAPIキーのエクスポート・インポートを制限しました。

  APIキーで呼び出された `POST /data/export` はアーカイブから `dashboard_users` と `api_keys` のmnesiaテーブルセットを静かに除外し、`POST /data/import` はこれらのテーブルセットを含むアップロード時に `403 FORBIDDEN` を返します。

  DashboardのBearerトークン（ログイン）呼び出しは影響を受けず、DashboardユーザーおよびAPIキーを含む完全なデータベースのバックアップ・復元が可能です。

  これは権限昇格のギャップを解消します。既存の `/users` および `/api_key` エンドポイントはAPIキーのDashboardログイン資格情報およびAPIキーレコードへのアクセスを拒否しますが、APIキー保持者はデータバックアップエンドポイント経由でこれらの制限を回避できていました。

- [#17187](https://github.com/emqx/emqx/pull/17187) 認証なしの `GET /status?format=json` レスポンスからEMQXリリースバージョン（`rel_vsn`）を削除しました。バージョン情報は認証済みノード情報APIで引き続き取得可能です。
- [#17201](https://github.com/emqx/emqx/pull/17201) アップロードされたtarballのパス・トラバーサルに対するプラグインインストールエンドポイントを強化し、許可リストを厳格化しました。

  - インストールパスはプラグインインストールディレクトリ外に解決されるtarballの展開を拒否します。
  - `emqx ctl plugins allow <name-vsn>` エントリーは発行後5分で期限切れとなり、SHA-256ハッシュを指定してパッケージの整合性を検証可能です。ハッシュ不一致のアップロードは `403 Forbidden` で拒否されます。`sha256:` 引数省略時は従来通り `<name-vsn>.tar.gz` という名前のペイロードを受け入れます。
  - HTTPプラグインインストールエンドポイント（およびDashboardアップロード）で成功したインストールはクラスタ全体で許可エントリーを即時取り消し、異なるtarballでの再利用を防止します。

- [#17252](https://github.com/emqx/emqx/pull/17252) 公式ダウンロードサイトでプラグインパッケージに `.sha256` チェックサムサイドカーを公開し、ダウンロードしたプラグインアーカイブの整合性検証を可能にしました。
- [#17271](https://github.com/emqx/emqx/pull/17271) 公式EMQX Dockerイメージのイメージスキャナー検出結果を解消しました。

  - ランタイムイメージビルド時にDebianのセキュリティアップグレードを適用し、最新のパッチ済み `libssl3t64` を取り込みました。
  - 未使用の `libgnutls30t64` パッケージを削除しました。EMQXはErlang/OTP経由でOpenSSLを使用しGnuTLSはリンクしないため、`curl` の推移的依存としてのみ存在していました。
  - Debianの `curl` パッケージを [stunnel/static-curl](https://github.com/stunnel/static-curl) の静的リンク済みバイナリ（OpenSSL、HTTP/2、HTTP/3対応、RTMP・GnuTLS非対応）に置き換えました。Debianパッケージは `librtmp1` 経由で `libgnutls30t64` を再導入していましたが、静的バイナリはこれを回避しつつコンテナのヘルスチェックでの `curl` 呼び出しを維持します。

- [#17309](https://github.com/emqx/emqx/pull/17309) PROXY-Protocol v2のSSL共通名およびSubjectフィールドに制御文字が混入しクライアント識別に悪用される問題を修正しました。

  `proxy_protocol = true` 設定のリスナーは、PROXY-Protocol SSL TLVバイト列にASCII制御文字が含まれる接続を拒否します（MQTTの `clientid`、`username`、`password` で既に拒否されているバイトクラスと同様）。これにより、攻撃者制御のバイト列が `${cert_common_name}` や `${cert_subject}` テンプレート経由でHTTP認証・認可・ルールエンジンのヘッダー値に到達するのを防ぎます。

  HTTP認証・認可クライアントも、レンダリングされたヘッダー名や値にCR、LF、NULバイトが含まれる場合はリクエスト送信を拒否します。

- [#17315](https://github.com/emqx/emqx/pull/17315) MQTTの `clientid`、`username`、`password` に適用されるバイトクラスチェックを `ClientInfo` およびHTTPリクエストテンプレートの他フィールドに拡張しました。

  - `peersni`（TLSサーバー名表示、PROXY-Protocol v2の `authority` TLV由来も含む）を接続受信境界で検証し、制御文字がある場合は接続拒否し警告ログを出力します。
  - `mqtt.client_attrs_init` のVariform式で生成されるクライアント属性値は制御文字を含む場合に破棄され（警告付き）、`${client_attrs.tns}` のようなテンプレートでのバイト注入を防止します。
  - HTTPアクション・ブリッジコネクターヘッダーのレンダリングは、名前または値にNUL、CR、LFを含むヘッダーを破棄します。

- [#17440](https://github.com/emqx/emqx/pull/17440) バックアップファイルダウンロード（`GET /api/v5/data/files/<filename>`）をグローバルDashboard管理者のみに制限しました。バックアップアーカイブにはDashboardアカウント（パスワードハッシュ、MFA/TOTP状態含む）やAPIキーが含まれるため、APIキー呼び出し、Dashboard閲覧者、ネームスペース管理者はダウンロードできません。バックアップディレクトリ一覧（`GET /api/v5/data/files`）は従来通り全権限ロールが利用可能です。
- [#17491](https://github.com/emqx/emqx/pull/17491) ゲートウェイ認証API、エラー経路、デバッグログでパスワードや秘密情報が露出する問題を修正しました。ゲートウェイ認証APIレスポンスは秘密情報を秘匿しつつ生設定構造を保持します。以下のログ経路は生パスワード・秘密を出力しません：ゲートウェイ認証失敗、リスナー起動エラー、ExProto認証ログ、CoAPトークン必須ログ、LwM2M無効登録ログ。
- [#17501](https://github.com/emqx/emqx/pull/17501) ネームスペーススコープ付きDashboardユーザーがネームスペース境界を越えてMQTTメッセージ内容を読み取れないようにしました。

  - 以下のエンドポイントは非グローバル呼び出し元に対し `403 FORBIDDEN` を返します。これらは呼び出し元のネームスペース外のMQTTペイロードを露出する可能性があるためです。以前はネームスペースユーザーが他ネームスペースのメッセージを読み取り・削除可能でした。

    - `GET /clients/:clientid/mqueue_messages`
    - `GET /clients/:clientid/inflight_messages`
    - `GET|DELETE /mqtt/retainer/messages`
    - `GET|DELETE /mqtt/retainer/message/:topic`
    - `GET /mqtt/delayed/messages`
    - `GET|DELETE /mqtt/delayed/messages/:node/:msgid`
    - `DELETE /mqtt/delayed/messages/:topic`

  - トレースAPIはネームスペーススコープ化されました。`GET /trace` は呼び出し元のネームスペースで作成されたトレースのみを一覧表示し、個別トレースエンドポイント（`/trace/:name`、`/trace/:name/download`、`/trace/:name/log`、`/trace/:name/log_detail`、`/trace/:name/stop`）は異なるネームスペースのトレースに対して404を返し、他ネームスペースのトレース存在を発見できないようにします。バルク削除 `DELETE /trace` はグローバル管理者専用で、ネームスペース呼び出し元は403を受けます。ネームスペース管理者は自身のトレースに対して作成、一覧、ダウンロード、ストリーミング、停止、削除が可能です。
