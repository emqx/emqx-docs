# EMQX Enterprise Version 6

## 6.2.3

*リリース日: 2026-08-21*

EMQX 6.2.3 へアップグレードする前に、破壊的変更点および既知の問題を必ずご確認ください。

### 強化点

#### アクセス制御

- [#17813](https://github.com/emqx/emqx/pull/17813) ダッシュボードユーザーおよび API キーのエンドポイントで、特権スコープ（`system`、`user_management`、`api_key_management`、`sso_management`）とその他のスコープが混在したスコープリストを拒否するようになりました。これら4つの特権スコープは管理者相当の権限を持つため、これらと制限されたスコープリストを組み合わせてもアカウントを意味のある形で制限できません。アカウントに管理者相当の権限を持たせるかどうかに応じて、特権スコープのみのリストか非特権スコープのみのリストを使用してください。既存の混在したスコープセットを持つレコードは次回更新まで動作を継続します。次回更新時にはリストを分割する必要があります。
- [#17980](https://github.com/emqx/emqx/pull/17980) 強化されたセキュリティプロファイルにおいて、EMQX はサーバー発行のサブスクライブに対してもトピック検証、認可、MQTT 機能チェック、クライアントサブスクライブフックを適用するようになりました。
- [#18002](https://github.com/emqx/emqx/pull/18002) 強化されたセキュリティプロファイルで、SAML レスポンスおよびアサーションの署名検証をデフォルトで有効化しました。
- [#18296](https://github.com/emqx/emqx/pull/18296) 認証器の `precondition` 式（および Variform 式が許される任意の場所）で使用可能な新関数 `is_jwt(value)` を追加しました。これは値が構造的に JWT（JWS コンパクト形式）である場合にのみ true を返し、署名検証は行いません。これにより、非 JWT パスワードを提示するクライアントに対して JWT 認証器をスキップでき、特に強化されたセキュリティプロファイル下で非 JWT 資格情報が JWT 認証器により拒否される状況で有用です。

#### マルチテナンシー

- [#17732](https://github.com/emqx/emqx/pull/17732) API キー作成および更新エンドポイントに `namespace` フィールドを追加しました。これにより、オペレーターは `role` 文字列内にネームスペースをエンコードする必要がなくなりました（既存の `ns:<namespace>::<role>` 形式は引き続き有効です）。両方の形式が指定された場合は一致している必要があります。
- [#17855](https://github.com/emqx/emqx/pull/17855) ネームスペーススコープのダッシュボード管理者は、自身のネームスペース内の API キーを作成、一覧表示、読み取り、更新、削除できるようになりました。グローバル API キーや他のネームスペースのキーは作成できず、また自身のネームスペース外の API キーは非表示となります。

#### データ統合

- [#17933](https://github.com/emqx/emqx/pull/17933) RabbitMQ コネクターでマルチノードの `servers` リスト（例：`rmq1:5672,rmq2:5672`）をサポートしました。接続時のフェイルオーバーとプール開始オフセットのローテーションを提供します。`servers` が未設定の場合は従来の `server` と `port` 設定を使用します。
- [#17944](https://github.com/emqx/emqx/pull/17944) HTTP コネクターおよび HTTP 認証・認可に OAuth2 クライアントクレデンシャル認証を追加しました。有効化すると、EMQX は設定されたトークンエンドポイントからアクセストークンを取得・更新し、アウトバウンドリクエストに Bearer 認証ヘッダーとして追加します。

  トークン取得に失敗した場合、コネクターのヘルスチェックは `disconnected` を報告します。OAuth2 を有効にしつつ `Authorization` ヘッダーを提供する設定は拒否されます。

  クライアントIDとクライアントシークレットはトークンリクエストボディのフォームフィールドとして送信され、HTTP Basic 認証ヘッダーでの送信はサポートされません。

- [#18014](https://github.com/emqx/emqx/pull/18014) Datalayers Arrow Flight コネクターで準備済みステートメントの自動再構築を有効化しました。サーバーが準備済みステートメントを失った場合（例：再起動後）、クライアントは自動的に再作成し、書き込み操作を再試行して書き込み失敗を回避します。
- [#18042](https://github.com/emqx/emqx/pull/18042) DynamoDB コネクターに AWS IAM ロール認証情報サポートを追加しました。アクセスキーIDとシークレットアクセスキーが省略された場合、EMQX は ECS タスクロールまたは EC2 インスタンスメタデータから一時的な認証情報を取得し、有効期限前に更新します。
- [#18081](https://github.com/emqx/emqx/pull/18081) Snowflake Streaming アクションのレジリエンスを改善しました。チャネルの内部状態が同期外になる特定のエラー時に、失敗した行を再試行し、手動介入なしにチャネルを再オープンしようとします。
- [#18085](https://github.com/emqx/emqx/pull/18085) Kafka、Confluent、Azure Event Hubs のプロデューサーに以下の新設定を追加しました：

  - `max_batch_age`（アクション）：プロデューサーバッファ内でこの期間を超えて滞留したメッセージを破棄し、`dropped.expired` メトリクスにカウントします。デフォルトは `infinity`（破棄しない）。
  - `max_retries`（アクション）：失敗したリトライ回数がこの値を超えたメッセージバッチを破棄し、`failed` メトリクスにカウントします。リトライカウンターは Kafka が明示的にエラーコードを返した場合のみ増加し、接続喪失後の再送はカウントしません。デフォルトは `infinity`（無限リトライ）。
  - `reconnect_delay`（アクション）：接続喪失後の再接続遅延。デフォルトは `2s`（従来はハードコード）。
  - `request_timeout`（コネクター）：Kafka からの応答待ち時間。これを超えると接続は古くなったと見なされ再確立されます。デフォルトは `30s`。

  また、Kafka クライアントライブラリ（wolff 4.2.1）をアップグレードし、メモリモードバッファの `max_linger_time` サポートを復活させました。小規模バッチは `max_linger_time` まで待機してメッセージを集約し、送信リクエスト頻度を低減します。満杯バッチは遅延なく送信されます。

- [#18110](https://github.com/emqx/emqx/pull/18110) スキーマレジストリで JSON Schema draft 2019-09 および 2020-12 をサポートしました。
- [#18137](https://github.com/emqx/emqx/pull/18137) GCP Pub/Sub プロデューサーとコンシューマーで、トピック設定に完全修飾トピックパス（`projects/<project-id>/topics/<topic-name>`）を受け入れるようになりました。これにより、サービスアカウントのプロジェクトとは異なる GCP プロジェクトのトピックにパブリッシュまたはサブスクライブ可能です。ベアトピック名は従来通りサービスアカウントのプロジェクトに解決されます。コンシューマーの場合、サブスクリプションはサービスアカウントのプロジェクトに作成され、トピック参照のみ別プロジェクトを指すことができます。

#### ルールエンジン

- [#18253](https://github.com/emqx/emqx/pull/18253) ルールエンジン SQL 関数 `map_to_range(value, min, max)` と `hash_to_range(value, min, max)` を追加しました。値（またはそのハッシュ）を包含的な整数範囲にマップします。シャーディングやバケット分割に便利です。例：トピックのセグメントからシャードインデックスを導出して複数ルールにデバイス群を分散する場合 `hash_to_range(nth(2, tokens(topic, '/')), 0, 3)`。
- [#18306](https://github.com/emqx/emqx/pull/18306) LZ4 Frame 圧縮・解凍のルール関数 `lz4_compress` と `lz4_uncompress` を追加しました。

#### プラグイン

- [#18012](https://github.com/emqx/emqx/pull/18012) EMQX REST API 経由の同期 MQTT リクエスト/レスポンスフロー用プラグイン `emqx_sync_request` を追加しました。ノードローカル CLI 診断でリクエストカウンターや現在の保留状態を確認可能です。
- [#18353](https://github.com/emqx/emqx/pull/18353) ルール SQL 用の名前付きマッピングテーブルを提供する新プラグイン `emqx_maptabs` を追加しました。

  テーブルは JSON ファイルから初期化され、ルールエンジンのホットパスで高速なメモリ内ルックアップに利用されます。`maptab_lookup(Table, Key)`、`maptab_lookup(Table, Key, Field)`、`maptab_lookup(Table, Key, Field, Default)` のルール SQL 関数は長大な `CASE ... WHEN ... THEN` 構造を単一のテーブルルックアップに置き換え、ルックアップしたフィールドは組み込みの `subbits` 関数を直接駆動してバイナリペイロードをデコード可能です。

  テーブルは `emqx ctl maptabs` CLI で管理します。1ノードでのテーブルのロードや削除はクラスター全ノードに複製され、更新時にダウンしていたノードも再参加時に自動追従します。

  プラグイン設定で安全限界を指定可能です：`max_tables`（デフォルト100）、`max_rows_per_table`（デフォルト10000）、`max_table_file_bytes`（デフォルト10000000）。

#### パッケージング

- [#18037](https://github.com/emqx/emqx/pull/18037) Enterprise Linux 10（EL10）パッケージを追加しました。Red Hat Enterprise Linux 10、Rocky Linux 10、互換ディストリビューション向けです。
- [#18127](https://github.com/emqx/emqx/pull/18127) macOS 26（Tahoe）パッケージのリリースを開始しました。

#### パフォーマンス

- [#18185](https://github.com/emqx/emqx/pull/18185) サブスクリプション HTTP API の深いページングクエリを改善しました。各ターゲットノードでメモリ内にサブスクリプション行を蓄積し、ページネーションごとに RPC を1回に削減します。
- [#18229](https://github.com/emqx/emqx/pull/18229) データ統合送信パスの CPU オーバーヘッドを削減しました。アクションやソースでないリソース（例：クラスターリンクのメッセージ転送）を経由するメッセージごとにフォーマット済みエラー文字列を生成しなくなり、高メッセージボリューム時の長スケジューラ警告を回避します。

### バグ修正

#### コア MQTT 機能

- [#17895](https://github.com/emqx/emqx/pull/17895) TLS/WSS リスナーを管理証明書バンドルからファイルベース証明書に切り替える際、参照されているバンドルが既に削除されていても成功するようになりました。Dashboard が `managed_certs` を `null` でクリアする場合も含みます。
- [#17911](https://github.com/emqx/emqx/pull/17911) Erlang/OTP の `ssl` アプリケーションがサポートしている場合、DTLS リスナーで `ECDHE-PSK-CHACHA20-POLY1305` 暗号スイートの検証を許可しました。
- [#18102](https://github.com/emqx/emqx/pull/18102) 配信レート制限が有効な場合に MQTT クライアントが QoS 1 および QoS 2 メッセージを順不同で受信する問題を修正しました。EMQX はブロックされたメッセージが送信可能になるまで後続メッセージをキューイングします。

  影響バージョン: 6.1.2、6.1.3、6.2.0～6.2.2。`delivery_messages_rate` または `delivery_bytes_rate` が設定されたセッションのみ影響。デフォルトではレート制限は設定されていません。

- [#18108](https://github.com/emqx/emqx/pull/18108) まだ参照されている管理証明書バンドル（またはその中の単一ファイル）を削除しようとすると、参照元設定を明示したエラーで常に失敗するようになりました。`force_delete` クエリパラメータはこのチェックをバイパスしなくなり、API スキーマから削除されました。

  さらに、リスナーがディスク上に存在しない証明書バンドルを参照している場合、Prometheus ステータスエンドポイントが完全に失敗しなくなりました。該当リスナーは証明書有効期限メトリクスから除外され、警告がログに記録されます。

- [#18111](https://github.com/emqx/emqx/pull/18111) `mqtt.strict_mode` 有効時、MQTT v3.1 の CONNECT パケットでパスワードフラグがセットされているがユーザー名フラグがセットされていない場合は拒否するようになりました。これは MQTT v3.1.1 の既存動作と一致します。MQTT v3.1 仕様ではユーザー名なしでパスワードを送ることは無効とされています。

  さらに接続ログの可読性を向上しました。CONNECT パケットのトレースでパスワード未指定時は `Password=undefined` と表示し、空パスワードと区別可能にしました。ログの `peername` フィールドは常に `10.0.0.1:54123` のようなプレーン文字列で表示されます。

- [#18181](https://github.com/emqx/emqx/pull/18181) バースト値 `0` で設定されたレートリミッターが追加のバーストを許可してしまう問題を修正しました。これにより MQTT 配信メッセージレート制限などが設定より緩くなることがありました。
- [#18236](https://github.com/emqx/emqx/pull/18236) ソケットベースの TCP リスナーを使用するクライアントが高負荷時に予期せず切断される問題を修正しました。準備完了信号がまだ準備できていないソケットに届くことが原因でした。

  ```
  [error] crasher: initial call: emqx_socket_connection:init/4, ..., error: {{case_clause,{select,{select_info,recv,#Ref<...>}}},[{emqx_socket_connection,handle_msg,2,[{file,"emqx_socket_connection.erl"},{line,827}]}, ...
  ```

- [#18293](https://github.com/emqx/emqx/pull/18293) QUIC スタックを quicer-0.4.8（msquic 2.5.7）にアップグレードしました。CVE-2026-32179 のセキュリティアップデートを含みます。
- [#18357](https://github.com/emqx/emqx/pull/18357) [#18375](https://github.com/emqx/emqx/pull/18375) ノードの起動完了まで MQTT 接続を拒否するようになりました。これにより認証、認可、プラグインフックが有効になる前にリスナーがトラフィックを処理しなくなります。

  `GET /status` API は起動完了まで HTTP 503 を返し、ロードバランサーが新規接続を他ノードにルーティング可能にします。

  起動完了していないノードへのクラスタ参加要求は「後で再試行してください」というメッセージで拒否されます。

#### 永続ストレージ

- [#18143](https://github.com/emqx/emqx/pull/18143) 永続共有サブスクリプションで、サブスクライバーが別ノードに接続している場合に共有サブスクリプションリーダーとの通信が失敗し、CPU 使用率が異常に上昇する問題を修正しました。

#### ルールエンジン

- [#17957](https://github.com/emqx/emqx/pull/17957) `rule_engine.limit_selects_in_namespace = true` 設定時に複数のルールイベント（例：`$events/client/connack`）がグローバルネームスペースでルールをトリガーしない問題を修正しました。
- [#18049](https://github.com/emqx/emqx/pull/18049) `rule_engine.limit_selects_in_namespace = true` 設定時にアラームの有効化/無効化トリガーによるグローバルルールが発火しない問題を修正しました。
- [#18388](https://github.com/emqx/emqx/pull/18388) ネームスペースに属するルールの `republish` アクションを修正しました。`rule_engine.limit_selects_in_namespace` が有効な場合（デフォルト）、再パブリッシュされたメッセージはルールのネームスペース（`<namespace>/<topic>`）下でパブリッシュされます。これにより `republish` アクションがルールと同じネームスペース境界を遵守します。すでに `<namespace>/` で始まるレンダリング済みトピックは変更されません。`rule_engine.limit_selects_in_namespace = false` に設定すると従来の動作を維持します。

#### データ統合

- [#17859](https://github.com/emqx/emqx/pull/17859) MQTT コネクターで IPv6 ブローカーへの接続を修正しました。

  以前は IPv6 リテラル（例：`[::1]:1883`）が保存時に `bad_host_port` バリデーションエラーで拒否され、IPv6 のみ解決するホスト名は IPv4 で接続しようとして「ホスト解決不可」エラーになっていました。

  サーバーアドレスパーサーはブラケット付き IPv6 リテラル（例：`[::1]`、`[::1]:1883`、`mqtt://[::1]:1883`）を受け入れ、MQTT コネクターは接続時に IPv6 プロービングを有効にして IPv6 専用ブローカーに到達可能にしました。

  MQTT コネクターとクラスターリンクの `server` アドレスは公式 MQTT URI スキーム `mqtt`（平文 TCP）と `mqtts`（TLS）を受け入れます（例：`mqtt://broker:1883`、`mqtts://broker:8883`）。スキームなしの `host:port` も引き続き受け入れます。その他のスキームは `unsupported_scheme` バリデーションエラーで拒否されます。

- [#17947](https://github.com/emqx/emqx/pull/17947) HTTP コネクターの更新後にアクションバッファワーカーがブロックされ、メッセージが次のリトライ間隔までキューに残る問題を修正しました。
- [#17955](https://github.com/emqx/emqx/pull/17955) GreptimeDB 非同期バッチが低書き込みレート時にヘルスチェック後もフラッシュされない問題を修正しました。
- [#17961](https://github.com/emqx/emqx/pull/17961) Kafka または Pulsar コネクターがヘルスチェックタイムアウト時に `disconnected` 状態に遷移し、内部キューを再生成する問題を修正しました。現在は `connecting` 状態に遷移します。
- [#17970](https://github.com/emqx/emqx/pull/17970) SSRF 保護有効時に、ポリシーでブロックされたアドレスを持つ既存コネクターが原因でコネクター管理操作が妨害される問題を修正しました。

  以前は SSRF 保護有効化（または拒否リスト拡張）後に既存コネクターが存在すると、無関係なコネクター操作が内部エラーで失敗し、影響を受けたコネクターの削除時にアクションやルールは削除済みでもコネクターが残ることがありました。

  SSRF 保護は HTTP と MQTT コネクターに適用され、作成・更新時にブロックされたアドレスは拒否されます。コネクターの有効化・無効化・削除はブロックされず、他のコネクター種別は対象外です。

- [#17973](https://github.com/emqx/emqx/pull/17973) Kafka プロデューサーアクションのリトライメトリクスを修正しました。アクションの `retried`、`retried.success`、`retried.failed` カウンターは、ブローカー再接続後に内部バッファが再送したメッセージを反映し、オペレーターがリトライメッセージの最終結果を判別可能になりました。以前は内部リトライ回数に関わらずこれらのカウンターは常に `0` でした。`success` と `failed` カウンターは影響を受けず二重計上されません。
- [#17982](https://github.com/emqx/emqx/pull/17982) GCP PubSub コンシューマーが HTTP/2 を使用し、タイムアウト時にプルリクエストをキャンセルするようになりました。これにより GCP サーバーにリクエスト終了が明確に通知され、メッセージのリースが新しいプルリクエストに移譲されやすくなり、テールレイテンシが低減します。
- [#18055](https://github.com/emqx/emqx/pull/18055) クラスター内の異なるノードで Snowflake Streaming アクションが以下のエラーで失敗し始める問題を修正しました。

  ```
  {unrecoverable_error,#{body => <<"{\"code\":\"STALE_CONTINUATION_TOKEN_SEQUENCER\",\"message\":\"Channel sequencer in the continuation token is stale. Please reopen the channel\"}">>,...
  ```

- [#18110](https://github.com/emqx/emqx/pull/18110) スキーマレジストリで draft-06 JSON Schema の `examples` アノテーションを使用すると有効なデータが無効と判定される問題を修正しました。

### 強化点

#### クラスター

- [#17530](https://github.com/emqx/emqx/pull/17530) クラスターリンクは非コミュニティライセンスが必要になりました。デフォルトのコミュニティライセンス下では設定済みリンクは非アクティブ（メッセージ転送やルート複製なし）となり、REST API は非コミュニティライセンスのロードを促す明確なヒント付きでリンク有効化を拒否します。リンクの無効化・削除は引き続き可能で、レガシー設定の整理に利用できます。ライセンスアップグレード後はダッシュボードや REST API からノード再起動不要でリンクを有効化可能です。
- [#17549](https://github.com/emqx/emqx/pull/17549) EMQX Backup Sync プラグインを追加しました。データバックアップ API を使い、プライマリクラスターからセカンダリクラスターへ選択した設定を定期的に同期します。プラグインはプライマリクラスターへの HTTPS 呼び出しに TLS オプションを設定可能です。
- [#17620](https://github.com/emqx/emqx/pull/17620) ルーティングテーブルの検査・調整用オペレーター向け診断モジュール `emqx_router_tool` を追加しました。`emqx ctl eval` で実行します。以下のヘルパーを提供します：

  - `cluster_schema_view/0`：各クラスター ノードが使用するルートストレージスキーマを報告。
  - `scan_missing_routes/0,1`：ローカルサブスクリプションテーブルをストリームし、このノードにルートエントリが存在しないトピックを報告。2パスで実行し、スロットリングされ、同時のサブスクライブ・アンサブスクライブを許容。
  - `reconcile_missing_routes/0,1`：既存の `emqx_router:add_route/2` API を使い欠落ルートを再追加。

  スキーマ非依存でライブクラスター上で安全に実行可能です。

#### マルチテナンシー

- [#17665](https://github.com/emqx/emqx/pull/17665) マルチテナンシーアプリにネームスペースごとのドロップメッセージ数・ドロップ配信数カウンターを追加しました。これらは既存のネームスペース別メトリクスとともに `/api/v5/prometheus/namespaced_stats` で `namespace` ラベル付きで公開されます。オペレーターはログ調査なしに Prometheus からテナントごとのドロップ率を診断可能です。

  既知の制限：QoS 2 PUBREL 待機タイムアウトドロップはまだネームスペース別帰属されません。これはドロップパスがグローバルカウンターを増加させるのみで `message.dropped` フックを発火しないためです。

- [#17711](https://github.com/emqx/emqx/pull/17711) ビルトインデータベース認証ユーザー HTTP API でネームスペース選択を一貫化し、削除済みネームスペースに残ったレコードのクリーンアップを可能にしました。

  以前はユーザー作成時のみリクエストボディで `namespace` フィールドを受け入れ、更新・削除は `ns` クエリパラメータのみ受け入れていました。更新・削除エンドポイントもリクエストボディの `namespace` を受け入れるようになり、両方指定時は `ns` クエリパラメータが優先されます。ユーザー一覧は引き続き `ns` クエリパラメータを使用します。

#### アクセス制御

- [#17564](https://github.com/emqx/emqx/pull/17564) 強化されたセキュリティプロファイルで認可バックエンド障害時にフェイルクローズ動作を追加しました。強化モードではバックエンド障害や不正な応答はアクセス拒否となり、従来モードは既存の無視およびフォールバック動作を維持します。
- [#17589](https://github.com/emqx/emqx/pull/17589) 強化されたセキュリティプロファイルでアクセス制御フックコールバック障害時にフェイルクローズ動作を追加しました。認証・認可フックコールバックのクラッシュは無視されずアクセス拒否となります。
- [#17674](https://github.com/emqx/emqx/pull/17674) 強化されたセキュリティプロファイルで認証バックエンド障害や不正応答時にフェイルクローズ動作を追加しました。従来動作は `authentication_settings.ignore_backend_failures` で維持可能です。
- [#17696](https://github.com/emqx/emqx/pull/17696) 強化されたセキュリティプロファイルで JWKS エンドポイントの TLS 証明書検証をデフォルトで有効化し、JWKS キーが利用不可の場合は提示された JWT を拒否し、JWT 資格情報が欠如した場合は拒否するようにしました。

#### データ統合

- [#17481](https://github.com/emqx/emqx/pull/17481) MQTT ブリッジのイングレス（ソース）サブスクリプションに `retain_as_published` オプションを追加しました。ブリッジが MQTT 5.0 でリモートブローカーに接続し、`retain_as_published = true` の場合、転送メッセージの元の `retain` フラグを保持し、上流の保持メッセージを忠実に再パブリッシュします。デフォルトは `false` で既存動作を維持します。`proto_ver` が `v3` または `v4` の場合は無効です。

  また、`bridge_mode = true` と `proto_ver = v5` の同時設定時に警告ログを出すようにしました。MQTT 5.0 では従来のブリッジモードフラグは無効であり、個別サブスクリプションで `retain_as_published` を設定してください。

- [#17508](https://github.com/emqx/emqx/pull/17508) PostgreSQL および TimescaleDB コネクター接続時に `application_name` スタートアップパラメータを `emqx` に設定しました。

  これにより PostgreSQL のログや `pg_stat_activity` などで EMQX のデータベースセッションを識別しやすくなります。

- [#17576](https://github.com/emqx/emqx/pull/17576) GreptimeDB コネクターで既存の `ssl.ciphers` フィールドを通じた TLS 暗号スイート設定をサポートしました。暗号リスト指定時はそのスイートに限定され、サポート外の暗号はコネクター起動時に拒否されます。

- [#17594](https://github.com/emqx/emqx/pull/17594) Google Cloud Pub/Sub および BigQuery コネクターの `service_account_json` 値に `file://` シークレットファイルを指定可能にし、外部ファイルからサービスアカウント認証情報を注入できるようにしました。

- [#17717](https://github.com/emqx/emqx/pull/17717) Confluent Producer コネクターで TLS ピア検証を有効化するオプションを追加しました。
- [#17718](https://github.com/emqx/emqx/pull/17718) GCP PubSub Producer/Consumer および BigQuery コネクターで TLS ピア検証を有効化するオプションを追加しました。

#### 可観測性

- [#17558](https://github.com/emqx/emqx/pull/17558) `GET /monitor_current` HTTP API に新たに `rules_matched` と `actions_executed` のメトリクスおよびレートを追加しました。これらはマッチしたルール数とアクション実行率（成功＋失敗）を追跡します。

  また、非バッチモード（`batch_size = 1`）での `actions.executed` の過小計測を修正しました。カウンターはバッファワーカーテレメトリのフラッシュウィンドウに依存せず、アクションコールバック呼び出しごとに1回インクリメントされます。

- [#17712](https://github.com/emqx/emqx/pull/17712) オペレーターがリモートコンソールから呼び出せる診断モジュール `emqx_session_tool` を追加しました。`emqx_session_tool:top_by(mqueue_len)` などで多接続クラスターのセッションをゲージやカウンター値でトップK抽出可能です。チャネルレジストリをストリームし、上限付きトップK結果のみ保持し、接続プロセスにメッセージを送らずにセッションメトリクスをキャッシュから読み取ります。`emqx_session_tool:cluster_top_by/1` はクラスター全ノードで集約します。

#### パフォーマンス

- [#17530](https://github.com/emqx/emqx/pull/17530) クラスターリンクは非コミュニティライセンスが必要になりました。デフォルトのコミュニティライセンス下では設定済みリンクは非アクティブ（メッセージ転送やルート複製なし）となり、REST API は非コミュニティライセンスのロードを促す明確なヒント付きでリンク有効化を拒否します。リンクの無効化・削除は引き続き可能で、レガシー設定の整理に利用できます。ライセンスアップグレード後はダッシュボードや REST API からノード再起動不要でリンクを有効化可能です。

### バグ修正

#### コア MQTT 機能

- [#17540](https://github.com/emqx/emqx/pull/17540) SSL リスナーで `password = "file://..."` を設定し、キーファイルが暗号化されている場合に設定検証が `bad_password_or_invalid_keyfile` で失敗する問題を修正しました。`file://` 参照は実行時だけでなく検証時にも解決されるようになりました。
- [#17569](https://github.com/emqx/emqx/pull/17569) MQTT v5 のユーザープロパティ解析コストを二次関数的から線形に削減しました。

  以前は多数のユーザープロパティを含む CONNECT、PUBLISH、SUBSCRIBE パケットで、各プロパティをリスト末尾に追加するため所有接続プロセスのスケジューラ時間が超線形に増加していました。解析はエントリ数に対して線形にスケールし、ワイヤ順序は保持されます。

- [#17731](https://github.com/emqx/emqx/pull/17731) WS/WSS リスナーのオプション更新時に一時的な「アドレス使用中」エラーが発生する問題を修正しました。TLS 証明書のローテーションなどでリスナーを更新するとポート再バインドが発生し、OS が古いソケットを解放していない場合がありました。EMQX は再バインドを短時間リトライし、更新失敗を回避します。
- [#17798](https://github.com/emqx/emqx/pull/17798) 保持メッセージがワイルドカードサブスクリプションの QoS 制限ではなく元のパブリッシュ QoS で配信される問題を修正しました。
- [#17801](https://github.com/emqx/emqx/pull/17801) `ssl_opts.ciphers` バリデーターが OpenSSL または IANA/RFC 命名の暗号名を受け入れるようになりました。以前は OpenSSL 形式のみ認識し、IANA 名（例：`TLS_ECDHE_ECDSA_WITH_AES_256_GCM_SHA384`）は `bad_ciphers` として拒否されていました。TLS 1.3 暗号は IANA と OpenSSL 名が同一のため影響ありません。

#### ルールエンジン

- [#17725](https://github.com/emqx/emqx/pull/17725) 6.0.3、6.1.2、6.2.1 で導入されたバグを修正しました。パブリッシュクライアントがテナントネームスペース（`client_attrs.tns`）を持つ場合、グローバルルールが `FROM` トピックでメッセージにマッチしなくなる問題です。

#### クラスター

- [#17586](https://github.com/emqx/emqx/pull/17586) グローバルセッションレジストリから古いエントリを定期的に削除する機能を追加しました。

  セッションの所有プロセスがクリーンな登録解除なしに死んだ場合、同一クライアント ID が再接続しなければレジストリ行が永続的に残ることがありました。これはネットワーク分断やコアノードのコンセンサスチェックタイムアウト時に発生します。

#### マルチテナンシー

- [#17715](https://github.com/emqx/emqx/pull/17715) `multi_tenancy.post_auth_tns_expression` が空文字列またはエラーを返した場合にネームスペースゲート（`allow_only_managed_namespaces` 適用、セッションクォータなど）がスキップされてクライアントが通過する問題を修正しました。

  空文字列およびエラー結果は「ネームスペース未割当」とみなされ、認証前にネームスペースを指定しなかったクライアントと同じゲートを通過します。`allow_only_managed_namespaces = true` なら拒否され、`false` ならネームスペースなしで受け入れられます。この場合、認証前に `client_attrs.tns` に含まれていたネームスペース値もクリアされ、式が割当を拒否した場合に保持されません。

- [#17757](https://github.com/emqx/emqx/pull/17757) `/prometheus/namespaced_stats` でネームスペース管理者・API キーが自身のネームスペースのデータのみ閲覧可能になりました。グローバル管理者・API キーは引き続き全ネームスペースのデータを閲覧可能です。

#### 可観測性

- [#17497](https://github.com/emqx/emqx/pull/17497) 非バッチモード（`batch_size = 1`）で設定されたアクションの `actions.executed` メトリクスが `actions.messages` を過小計測する問題を修正しました。

  以前はバッファワーカーテレメトリフラッシュごとに `actions.executed` を1回インクリメントしていたため、多数の個別完了を1イベントに集約し、バッチなしでも `actions.executed` が `actions.messages` に追いつきませんでした。

  2つのメトリクスは独立した呼び出し位置でインクリメントされます：`actions.executed` はアクションコールバック呼び出しごと（バッチモードはバッチごと、単一モードはメッセージごと）、`actions.messages` は処理したメッセージごとです。
