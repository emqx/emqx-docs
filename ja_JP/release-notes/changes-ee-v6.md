# EMQX Enterprise Version 6

## 6.0.4

*リリース日: 2026-09-30*

EMQX 6.0.4 にアップグレードする前に、破壊的変更と既知の問題を必ずご確認ください。

### 強化点

#### コア MQTT 機能

- [#18974](https://github.com/emqx/emqx/pull/18974) `mqtt.max_connect_user_properties` を追加しました。これは MQTT v5 の CONNECT プロパティおよび Will プロパティで受け入れるユーザープロパティペアの数を個別に制限します。デフォルトは 100 で、制限を無効にするには `infinity` に設定してください。

- [#19096](https://github.com/emqx/emqx/pull/19096) `mqtt.max_connect_packet_size` 設定を追加しました。これは `mqtt.max_packet_size` に加えて CONNECT パケットのサイズを制限します。CONNECT パケットがこの制限を超えると EMQX はクライアント接続を切断し、リスナーのシャットダウンカウンター `connect_packet_too_large` を増加させます。デフォルトは `1MB` で、`mqtt.max_packet_size` のデフォルトと同じため、設定を下げるまでは動作に変更はありません。

- [#19126](https://github.com/emqx/emqx/pull/19126) パブリッシュフックでメッセージのパーシステンス成功を報告する機能を追加しました。プラグインがパーシステンスを報告すると、HTTP パブリッシュ API はサブスクリプションが一致しなくてもメッセージ ID とともに HTTP 200 を返します。

#### アクセス制御

- [#17732](https://github.com/emqx/emqx/pull/17732) API キー作成および更新エンドポイントに `namespace` フィールドを追加しました。これにより、オペレーターはもはや `role` 文字列内にネームスペースをエンコードする必要がなくなりました（既存の `ns:<namespace>::<role>` 形式は引き続き動作します）。両方の形式が指定された場合は一致している必要があります。

- [#17813](https://github.com/emqx/emqx/pull/17813) ダッシュボードのユーザーおよび API キーエンドポイントは、特権スコープ（`system`、`user_management`、`api_key_management`、`sso_management`）とその他のスコープを混在させたスコープリストを拒否するようになりました。これらの特権スコープはいずれも管理者相当の権限を持つため、制限付きスコープリストと組み合わせても意味のある制限になりません。アカウントが管理者相当の権限を持つかどうかに応じて、特権のみのスコープリストか非特権のみのスコープリストを使用してください。混在したスコープセットを持つ既存のレコードは次回の更新まで動作しますが、次回の更新ではリストを分割する必要があります。

- [#17855](https://github.com/emqx/emqx/pull/17855) ネームスペーススコープ付きダッシュボード管理者は、自分のネームスペース内で API キーの作成、一覧表示、読み取り、更新、削除が可能になりました。グローバル API キーや他のネームスペースのキーは作成できず、ネームスペース外の API キーは非表示になります。

#### データ統合

- [#17933](https://github.com/emqx/emqx/pull/17933) RabbitMQ コネクターがマルチノードの `servers` リスト（例：`rmq1:5672,rmq2:5672`）をサポートし、接続時のフェイルオーバーとプール開始オフセットのローテーションを実装しました。`servers` が未設定の場合は従来の `server` と `port` 設定が引き続きサポートされます。

- [#17944](https://github.com/emqx/emqx/pull/17944) HTTP コネクターおよび HTTP 認証・認可に OAuth2 クライアントクレデンシャル認証を追加しました。有効化すると、EMQX は設定されたトークンエンドポイントからアクセストークンを取得・更新し、アウトバウンドリクエストに Bearer 認証ヘッダーとして追加します。

  コネクターのヘルスチェックはトークン取得失敗時に `disconnected` を報告します。OAuth2 を有効にしつつ `Authorization` ヘッダーを提供する設定は拒否されます。

  トークンリクエストボディにはクライアント ID とクライアントシークレットをフォームフィールドとして送信し、HTTP Basic 認証ヘッダーでの送信はサポートしません。

- [#18014](https://github.com/emqx/emqx/pull/18014) Datalayers Arrow Flight コネクターが準備済みステートメントを自動的に再構築するようになりました。サーバーが再起動などで準備済みステートメントを失った場合、クライアントが再作成して書き込み操作をリトライし、書き込み失敗を回避します。

- [#18042](https://github.com/emqx/emqx/pull/18042) DynamoDB コネクターに AWS IAM ロール認証情報サポートを追加しました。アクセスキー ID とシークレットアクセスキーが省略された場合、EMQX は ECS タスクロールまたは EC2 インスタンスメタデータから一時的な認証情報を取得し、有効期限前に更新します。

- [#18081](https://github.com/emqx/emqx/pull/18081) Snowflake Streaming アクションのレジリエンスを向上させました。チャネルの内部状態が同期外になった場合でも、失敗した行をリトライし、手動介入なしでチャネルを再オープンしようとします。

- [#18085](https://github.com/emqx/emqx/pull/18085) Kafka、Confluent、Azure Event Hubs プロデューサーに新しい設定オプションを追加しました：

  - `max_batch_age`（アクション）：プロデューサーバッファにこの期間以上滞留したメッセージを送信せず破棄。`dropped.expired` メトリクスにカウント。デフォルトは `infinity`（破棄しない）。
  - `max_retries`（アクション）：この回数のリトライ失敗後にメッセージバッチを破棄。`failed` メトリクスにカウント。リトライカウンターは Kafka が明示的にエラーコードを返した場合のみ増加し、接続ロス後の再送はカウントしません。デフォルトは `infinity`（無限リトライ）。
  - `reconnect_delay`（アクション）：接続ロス後の再接続までの遅延。デフォルトは `2s`（従来はハードコード）。
  - `request_timeout`（コネクター）：Kafka からの応答待ち時間。デフォルトは `30s`。

  さらに Kafka クライアントライブラリのアップグレード（wolff 4.2.1）により、メモリモードバッファの `max_linger_time` サポートが復活。小さいバッチは `max_linger_time` まで待機し、送信リクエスト頻度を削減。満杯バッチは遅延なく送信されます。

- [#18110](https://github.com/emqx/emqx/pull/18110) スキーマレジストリで JSON Schema draft 2019-09 と 2020-12 をサポートしました。

- [#18137](https://github.com/emqx/emqx/pull/18137) GCP Pub/Sub プロデューサーとコンシューマーがトピック設定に完全修飾トピックパス（`projects/<project-id>/topics/<topic-name>`）を受け入れるようになりました。これにより、サービスアカウントのプロジェクトとは異なる GCP プロジェクトのトピックにパブリッシュまたはサブスクライブ可能です。トピック名のみの場合は従来通りサービスアカウントのプロジェクトに解決されます。コンシューマーの場合、サブスクリプションはサービスアカウントのプロジェクトに作成され、トピック参照のみ別プロジェクトを指せます。

- [#18515](https://github.com/emqx/emqx/pull/18515) Azure Blob Storage アクションの `blob` テンプレートフィールドが、Aggregated S3 アクションの `key` フィールドと同じスキーマ検証を使うようになり、許可されたバインディングのみが使用されるようになりました。

- [#18926](https://github.com/emqx/emqx/pull/18926) Kafka、Confluent、Azure Event Hubs コネクターに IPv6 サポートを追加しました。

  - `bootstrap_hosts` に角括弧付き IPv6 アドレス（例：`[::1]:9092`、`[fd00::5]:9092,host2:9093`）を指定可能。
  - IPv6 のみ解決されるホスト名や IPv6 アドレスを広告するブローカーにも接続可能。
  - 新しい `socket_opts.ip_family` オプションで IP アドレスファミリを選択可能。デフォルトの `auto` は IPv4 を優先し IPv6 を試行。`ipv6` は IPv6 のみ、`ipv4` は IPv4 のみ。

  Kafka クライアントライブラリのアップグレードにより、SASL 再認証中にリクエストが保留中の場合に発生していた同期送信タイムアウトも修正されました。

#### プラグイン

- [#18012](https://github.com/emqx/emqx/pull/18012) EMQX REST API を介した同期 MQTT リクエスト/レスポンスフロー用の `emqx_sync_request` プラグインを追加しました。ノードローカルの CLI 診断機能も提供し、リクエストカウンターや現在の保留状態を確認できます。

#### 可観測性

- [#17712](https://github.com/emqx/emqx/pull/17712) オペレーター向け診断モジュール `emqx_session_tool` を追加しました。リモートコンソールから呼び出せます。`emqx_session_tool:top_by(mqueue_len)`（または `mqueue_dropped`、`inflight_cnt` など任意のセッションメトリクス）で、多数の接続があるクラスターでクライアントリストを手動でページングせずにトップ K セッションを見つけられます。スキャンはチャネルレジストリをストリームし、上位 K 結果のみ保持し、接続プロセスにメッセージを送らずにキャッシュ済みセッションメトリクスを読み取ります。`emqx_session_tool:cluster_top_by/1` は全クラスターのノードで集約します。

- [#18528](https://github.com/emqx/emqx/pull/18528) OpenTelemetry 統合エクスポーターのエンドポイントは、スキームと明示的なポートを含む有効な URL でなければならなくなりました。サポートされるスキームは `http` と `https` です。

#### パフォーマンス

- [#18185](https://github.com/emqx/emqx/pull/18185) サブスクリプション HTTP API の深いページクエリを改善しました。ターゲットノードごとにメモリ内でサブスクリプション行を集約し、ページネーションごとに RPC を発生させるのを回避しました。

- [#18229](https://github.com/emqx/emqx/pull/18229) データ統合の送信パスにおける CPU オーバーヘッドを削減しました。アクションやソースでないリソース（例：クラスターリンクのメッセージ転送）を経由するメッセージごとにフォーマット済みエラーストリングを生成しなくなり、高負荷時の長スケジューラー警告を防止します。

- [#19240](https://github.com/emqx/emqx/pull/19240) MQTT PUBLISH メッセージ受信時の一時的なメモリ割り当てを削減しました。パケット検証の動作は変更ありません。

#### デプロイ

- [#18037](https://github.com/emqx/emqx/pull/18037) Red Hat Enterprise Linux 10、Rocky Linux 10、および互換ディストリビューション向けの Enterprise Linux 10 (EL10) パッケージを追加しました。

- [#18127](https://github.com/emqx/emqx/pull/18127) macOS 26 (Tahoe) パッケージのリリースを開始しました。

### バグ修正

#### セキュリティ

- [#16389](https://github.com/emqx/emqx/pull/16389) OAuth2 の `client_secret` が認証、認可、ゲートウェイ、HTTP コネクターの設定読み取り API で平文で返されていた問題を修正しました。API レスポンスではマスクされ、マスクされた値を再送信しても保存済みの秘密は変更されません。

- [#17644](https://github.com/emqx/emqx/pull/17644) `plain` パスワードハッシュアルゴリズムが認証時に大文字小文字のみ違うパスワードを受け入れていた問題を修正しました。

- [#17653](https://github.com/emqx/emqx/pull/17653) Prometheus 設定 API がプッシュゲートウェイのヘッダーに保存済みの `Authorization` ヘッダー値を返していたセキュリティ問題を修正しました。API はレスポンスでこれらの値を編集します。

- [#17654](https://github.com/emqx/emqx/pull/17654) `POST /authentication` で認証器を作成すると、JWT HMAC シークレット、HTTP `Authorization` ヘッダー、リクエストボディのパスワードなどのプロバイダー秘密がマスクされずに返されていた問題を修正しました。作成レスポンスはリストおよび取得エンドポイントと同様の編集を適用します。

- [#17657](https://github.com/emqx/emqx/pull/17657) 生の `authorization` および `cookie` ヘッダーがプラグイン API コールバックに転送されていたセキュリティ問題を修正しました。これらの認証情報を含むヘッダーはプラグインコードに届く前に編集されます。

- [#17739](https://github.com/emqx/emqx/pull/17739) ログ、トレース、監査レコードの機密データ編集を改善しました。

- [#17765](https://github.com/emqx/emqx/pull/17765) 複数のゲートウェイブローカー経路で認可チェックが欠落していた問題を修正しました。

  MQTT-SN メッセージパブリッシュ、JT808 上流パブリッシュおよび自動ダウンリンクサブスクライブ、GBT32960 上流パブリッシュおよび自動ダウンリンクサブスクライブ、OCPP 上流パブリッシュおよび自動ダウンリンクサブスクライブは、パブリッシュやサブスクライブの前に認可をチェックします。

- [#17787](https://github.com/emqx/emqx/pull/17787) HTTP コネクターの `ehttpc` ワーカーがリクエスト中に強制終了された際に、リクエストヘッダーがエラーログに含まれていた問題を修正しました。

  `ehttpc` ワーカーがリクエスト中に削除された場合、`gen_server:call` の引数（リクエストヘッダー含む）が EXIT 理由に含まれ、エラーログにそのまま書き込まれていました。ログ出力前に呼び出し引数は破棄されます。

- [#17790](https://github.com/emqx/emqx/pull/17790) TOTP 共有シークレットが `dashboard_login_failed` サーバーログに書き込まれていた問題を修正しました。これは MFA 初回セットアップ時に含まれていました。

- [#17791](https://github.com/emqx/emqx/pull/17791) JWT HMAC キーのバイト列が設定更新時の `cluster_rpc_apply_result` および `cluster_rpc_apply_ok` デバッグログに表示されていた問題を修正しました。

  編集機能は内部の JWK レコード形状を認識し、ログ出力前にプレースホルダーに置換します。`jwk` フィールドも機密情報として扱います。

- [#17853](https://github.com/emqx/emqx/pull/17853) コネクターのデバッグログで機密 HTTP リクエストヘッダーの編集を改善しました。`x-api-key`、`x-auth-token`、`api-key`、`cookie` ヘッダーはコネクター状態で秘密として保存され、トレース／デバッグレベルで状態が出力されても値は表示されません。共通のヘッダー編集ヘルパーは、テンプレートパーサーが生成する iolist 形式のヘッダー名も認識するようになりました。

- [#17888](https://github.com/emqx/emqx/pull/17888) LwM2M ゲートウェイが登録／更新 MQTT レポートに `password`、`secret`、`private_key`、`access_token` などの機密 REGISTER クエリフィールドを含めていた問題を修正しました。

- [#17974](https://github.com/emqx/emqx/pull/17974) 接続ログで生の MQTT パケットデータがデフォルトで編集されるようになりました。診断用に信頼済みクライアント IP アドレスをリスナーごとに許可リスト化可能です。

- [#18005](https://github.com/emqx/emqx/pull/18005) CLI 監査ログに機密コマンド引数が保存されていた問題を修正しました。

- [#18051](https://github.com/emqx/emqx/pull/18051) CoAP デバッグログで機密 URI クエリ値が漏洩していた問題を修正しました。

- [#18146](https://github.com/emqx/emqx/pull/18146) ダッシュボードおよび管理 API のスコープベース認可を強化し、同等のリクエストパスでアクセス制御チェックが一貫して適用されるようにしました。

- [#18293](https://github.com/emqx/emqx/pull/18293) QUIC スタックを quicer-0.4.8（msquic 2.5.7）にアップグレードしました。CVE-2026-32179 のセキュリティアップデートが含まれます。

- [#18302](https://github.com/emqx/emqx/pull/18302) Elasticsearch アクションの `index` と `id` 値をリクエストパス作成時に URL エンコードするようにしました。`#` や `/` などの文字がパスセグメント内のリテラルとして扱われ、リクエストターゲットを変更しなくなります。JSON リクエストボディは影響を受けません。

- [#18314](https://github.com/emqx/emqx/pull/18314) GCP Pub/Sub プロデューサー、GCP Pub/Sub コンシューマー、BigQuery コネクターの JSON サービスアカウント認証設定読み取り時に、HTTP API がサービスアカウント JSON 値を編集するようになりました。

- [#18330](https://github.com/emqx/emqx/pull/18330) 読み取り専用 REST エンドポイントで秘密情報が平文で返されなくなりました：

  - `GET /listeners` と `GET /listeners/{id}` はリスナーの `ssl_options.password` を `******` と表示。
  - `GET /exhooks` と `GET /exhooks/{name}` は gRPC クライアントの `ssl.password` を `******` と表示。
  - `POST /license` の監査ログエントリはリクエストボディを `******` と記録し、ライセンスキーが `GET /audit` に表示されません。

  `******` プレースホルダーを含むボディでリスナーや exhook サーバーを更新しても保存済みの秘密は変更されません。

- [#18344](https://github.com/emqx/emqx/pull/18344) HOCON を 0.46.3 にアップグレードしました。このリリースでは配列型設定フィールド内の機密値を `******` と表示し、設定検証エラーログに機密値を出力しなくなりました。

- [#18391](https://github.com/emqx/emqx/pull/18391) 認証キャッシュキーの衝突を修正しました。異なる認証情報が同じバイト列に連結されると、キャッシュエントリーを共有し、キャッシュ TTL 内に別のクライアントが他のクライアントの認証結果を受け取る可能性がありました。

- [#18580](https://github.com/emqx/emqx/pull/18580) `bin/node_dump` スクリプトが生成する `conf.hocon` ファイルの機密設定値を編集しました。

  設定スキーマで機密とマークされた値（例：`dashboard.default_password`、`license.key`）は `******` として書き込まれます。修正前は固定のキー名リストのみ編集されていたため、これらは平文で書き込まれていました。

- [#18708](https://github.com/emqx/emqx/pull/18708) デバッグモード有効時に Erlang クッキーとライセンスキーがシェルトレース出力に表示されるのを防止しました。

  `bin/emqx` コマンドを `DEBUG=1` または `DEBUG=2` で実行しても、Erlang クッキーやライセンスキーはシェルトレースに表示されません。

- [#18836](https://github.com/emqx/emqx/pull/18836) クラスター設定同期デバッグログに成功した設定変更の結果を含めなくなりました。

  結果には HTTP 認証ヘッダーテンプレートなどのコンパイル済みランタイム状態が含まれ、ログ編集が適用されませんでした。

- [#18853](https://github.com/emqx/emqx/pull/18853) SSO MFA 設定および検証の認証情報が監査ログに編集されずに保存されていた問題を修正しました。

  SSO MFA リクエストボディは監査記録に `username` と `backend` のみを保持し、一時トークン、TOTP コード、未知の認証情報フィールドは監査ファイルや監査データベースに書き込む前に編集されます。

- [#18855](https://github.com/emqx/emqx/pull/18855) 検証済みクライアント証明書で認証された DTLS クライアントの MQTT-SN セッションウェイクアップ認可を修正しました。証明書に紐づくセッションは同一のピア証明書を提示した場合のみ新しい関連付けから再開可能です。クライアント証明書なし、または異なる証明書や再発行証明書の場合は拒否されます。

  MySQL は `ON DUPLICATE KEY UPDATE` をサポートし、ClickHouse は `FORMAT Values` と `FORMAT JSONCompactEachRow` をサポートし、TDengine は `INSERT ... USING ... TAGS` とテーブル識別子補間をサポートします。

  MySQL テンプレートの一貫したレンダリングのため、MySQL ブリッジはすべての接続で `ANSI_QUOTES` と `NO_BACKSLASH_ESCAPES` モードを無条件に無効化し、それに応じて文を扱います。

  ClickHouse ブリッジは SQL テンプレートからバッチ値区切り文字を推論し、設定された `batch_value_separator` 値を無視します。

#### ゲートウェイ

- [#17805](https://github.com/emqx/emqx/pull/17805) ゲートウェイの再ロードが途中で失敗した場合（例：無効設定やポート競合）に `already_started` エラーで失敗する問題を修正しました。失敗時のロッカープロセスを自動回収し、次回ロードやオペレーターの再試行はクリーンな状態から開始されます。

- [#17815](https://github.com/emqx/emqx/pull/17815) MQTT-SN UDP セッションルーティングを修正しました。UDP ソースタプルが変わるか再利用される場合、`esockd_udp_proxy` を介してパケットをパースした ClientId でルーティングします。これによりスリープ中のセッションが異なる UDP ソースタプルから再開可能になり、再利用された UDP ソースタプルが別 ClientId のパケットを古いセッションに届けるのを防止します。

- [#18504](https://github.com/emqx/emqx/pull/18504) STOMP フレームのエスケープされたヘッダー文字と CRLF 行末の解析を修正しました。

  STOMP ゲートウェイは STOMP 1.2 に従い、ヘッダー名と値内のエスケープシーケンス `\c`、`\r`、`\n`、`\\` をデコードします。CONNECT と CONNECTED フレームは STOMP 1.0 との後方互換のためヘッダーエスケープ対象外で、パスワードにコロンやバックスラッシュが含まれていても変更されません。未定義のエスケープシーケンスはフレームエラーとして拒否されます。

  ゲートウェイはフレームとハートビートで CRLF (`\r\n`) 行末を受け入れます。修正前は CRLF 行末を使うクライアントが接続できませんでした。

- [#18776](https://github.com/emqx/emqx/pull/18776) MQTT-SN はスリープ中のクライアントがスリープ時間を超過した場合に設定された Will メッセージをパブリッシュし、クライアントが正常切断した場合は Will メッセージをパブリッシュしなくなりました。

- [#18842](https://github.com/emqx/emqx/pull/18842) ゲートウェイ接続は認証バックエンドが返す `clientid_override` 値を無視するようになりました。ゲートウェイプロトコルは対応していません。発生時に警告をログに出します。

  ゲートウェイ接続のマウントポイントテンプレートは認証結果マージ後の共有ゲートウェイ認証フローで評価されます。

## 6.0.3

*リリース日: 2026-06-17*

EMQX 6.0.3 にアップグレードする前に、破壊的変更と既知の問題を必ずご確認ください。

### 強化点

#### セキュリティ強化

- [#17040](https://github.com/emqx/emqx/pull/17040) API キーのダッシュボードユーザーアカウント管理エンドポイントアクセスを制限しました。

  以前は `administrator` ロールの API キーが HTTP Basic 認証でダッシュボードユーザー管理エンドポイント（`POST/DELETE /users/:username/mfa`、`POST /users/:username/change_pwd`）を呼び出せました。これにより API キーが他ユーザーの MFA リセットや無効化、パスワード変更を行え、人間のダッシュボードセッションと機械の API キーの分離を回避していました。

  これらのエンドポイントは API キー経由アクセス時に `401 API_KEY_NOT_ALLOW` を返し、既存の `/users`、`/users/:username`、`/logout`、`/api_key` への API キーアクセス拒否ポリシーと整合します。ダッシュボードユーザーはダッシュボード UI からベアラートークン（JWT）セッションで自分の MFA とパスワードを管理可能です。

- [#17065](https://github.com/emqx/emqx/pull/17065) ルールエンジンで到達可能なコネクターとブリッジ設定に対する SSRF 保護を追加しました。

  `rule_engine.ssrf.enable` を `true` に設定すると、EMQX はコネクター、ブリッジ、アクション設定に対してアウトバウンド SSRF ポリシーを適用します。ポリシーは `rule_engine.ssrf.deny_hosts` の完全一致を即時拒否し、解決済みターゲット IP を `rule_engine.ssrf.allow_cidrs` と `rule_engine.ssrf.deny_cidrs` でチェックします。デフォルトの拒否範囲はループバック、リンクローカル（クラウドインスタンスメタデータエンドポイント含む）、RFC 1918、ULA、未指定、マルチキャスト範囲をカバーします。チェックは設定更新時に実行され、HTTP の `url` フィールドやすべてのコネクターの `server`、`servers`、`bootstrap_hosts` フィールドを対象とします。

  この機能はデフォルトで無効で、内部サービスを指す正当なコネクター設定との互換性を維持します。マルチテナントや外部公開環境のオペレーターはネットワークレイヤーのイグレスファイアウォールと合わせて有効化を推奨します。

- [#17173](https://github.com/emqx/emqx/pull/17173) API キーによるダッシュボードアカウントと API キーのデータバックアップインポート・エクスポートを制限しました。

  API キーで呼び出した `POST /data/export` は生成されるアーカイブから `dashboard_users` と `api_keys` の mnesia テーブルセットを静かに省略します。API キーで呼び出した `POST /data/import` はアップロードされたバックアップにこれらのテーブルセットが含まれると `403 FORBIDDEN` を返します。

  ダッシュボードのベアラートークン（ログイン）呼び出しは影響を受けず、ダッシュボードユーザーと API キーを含む完全なデータベースのバックアップと復元を継続して行えます。

  これは特権昇格のギャップを解消します。既存の `/users` と `/api_key` エンドポイントは API キーのダッシュボードログイン資格情報と API キーレコードへのアクセスを拒否しますが、API キー保持者はデータバックアップ経由でこれらの制限を回避できていました。

- [#17187](https://github.com/emqx/emqx/pull/17187) 認証されていない `GET /status?format=json` レスポンスから EMQX リリースバージョン（`rel_vsn`）を削除しました。バージョンは認証済みノード情報 API で利用可能です。

- [#17201](https://github.com/emqx/emqx/pull/17201) アップロードされた tarball のパス・トラバーサルに対するプラグインインストールエンドポイントを強化し、インストール許可リストを厳格化しました。

  - インストールパスはプラグインインストールディレクトリ外に展開される tarball を拒否します。
  - `emqx ctl plugins allow <name-vsn>` エントリーは発行後 5 分で期限切れになり、SHA-256 ハッシュでパッケージを固定可能です。ハッシュが一致しないアップロードは `403 Forbidden` で拒否されます。`sha256:` 引数省略時は `<name-vsn>.tar.gz` という名前の任意のペイロードを受け入れます。
  - HTTP プラグインインストールエンドポイント（およびそれをラップするダッシュボードアップロード）は成功時に許可エントリーをクラスター全体で即時取り消し、同じ許可を別の tarball に再利用できなくします。

- [#17309](https://github.com/emqx/emqx/pull/17309) PROXY-Protocol v2 SSL Common Name と Subject フィールドの制御文字をサニタイズし、クライアント識別に制御文字が混入するのを防止しました。

  `proxy_protocol = true` のリスナーは PROXY-Protocol SSL TLV バイトに ASCII 制御文字が含まれる接続を拒否し、警告ログを出します。これは `${cert_common_name}` と `${cert_subject}` テンプレートを介して HTTP 認証・認可やルールエンジンヘッダー値に攻撃者制御バイトが届くのを防ぎます。

  HTTP 認証・認可クライアントはレンダリング済みヘッダー名や値に CR、LF、NUL バイトが含まれる場合はリクエスト送信を拒否します。

- [#17315](https://github.com/emqx/emqx/pull/17315) MQTT クライアント ID / ユーザー名 / パスワードに適用されるバイトクラスチェックを、`ClientInfo` と HTTP リクエストテンプレートに供給される他のフィールドにも拡張しました。

  - `peersni`（TLS Server Name Indication、PROXY-Protocol v2 の `authority` TLV からも受け入れ）は接続取り込み境界で検証され、制御文字があると接続拒否し警告をログに出します。
  - `mqtt.client_attrs_init` の Variform 式で生成されるクライアント属性値は制御文字を含むと破棄され（警告付き）、`${client_attrs.tns}` のようなテンプレートで注入バイトが下流に伝播しません。
  - HTTP アクション／ブリッジコネクタのヘッダー描画は、レンダリング済みの名前や値に NUL、CR、LF が含まれるヘッダーを破棄します。

- [#17330](https://github.com/emqx/emqx/pull/17330) `proxy_protocol` 有効な TCP と SSL リスナーの PROXY Protocol v2 TLV パーサーを強化しました。以前は宣言長がバッファを超過する TLV でストリームが静かに切り詰められていました。現在は厳格に解析し、不正な TLV ストリームは接続拒否し警告ログを出します。

- [#17440](https://github.com/emqx/emqx/pull/17440) バックアップファイルダウンロード（`GET /api/v5/data/files/<filename>`）をグローバルダッシュボード管理者に制限しました。バックアップアーカイブにはダッシュボードアカウント（パスワードハッシュ、MFA/TOTP 状態含む）と API キーレコードが含まれるため、API キー呼び出し、ダッシュボード閲覧者、ネームスペース管理者はダウンロード不可です。バックアップディレクトリ一覧（`GET /api/v5/data/files`）は従来通りすべての権限で利用可能です。

- [#17491](https://github.com/emqx/emqx/pull/17491) ゲートウェイ認証 API、エラーパス、デバッグログでパスワードや秘密が露出していた問題を修正しました。ゲートウェイ認証 API レスポンスは秘密を編集しつつ生の設定構造を保持します。以下のログパスは生のパスワードや秘密を出力しません：ゲートウェイ認証失敗、リスナー起動エラー、ExProto 認証ログ、CoAP トークン必須ログ、LwM2M 無効登録ログ。

- [#17501](https://github.com/emqx/emqx/pull/17501) ネームスペース付きダッシュボードユーザーがネームスペース境界を越えて MQTT メッセージ内容を読み取れないようにしました。

  - 以下のエンドポイントはグローバル以外の呼び出し元に `403 FORBIDDEN` を返します。これらは呼び出し元のネームスペース外の MQTT ペイロードを公開する可能性があるためです。以前はネームスペースユーザーが他ネームスペースのメッセージを読み取り・削除できました。

    - `GET /clients/:clientid/mqueue_messages`
    - `GET /clients/:clientid/inflight_messages`
    - `GET|DELETE /mqtt/retainer/messages`
    - `GET|DELETE /mqtt/retainer/message/:topic`
    - `GET /mqtt/delayed/messages`
    - `GET|DELETE /mqtt/delayed/messages/:node/:msgid`
    - `DELETE /mqtt/delayed/messages/:topic`

  - トレース API はネームスペーススコープ化されました。`GET /trace` は呼び出し元のネームスペースで作成されたトレースのみを一覧表示します。トレース個別エンドポイント（`/trace/:name`、`/trace/:name/download`、`/trace/:name/log`、`/trace/:name/log_detail`、`/trace/:name/stop`）は他ネームスペースのトレースに対して `404` を返し、他ネームスペースのトレースの存在を隠します。バルク削除 `DELETE /trace` はグローバル管理者専用で、ネームスペース呼び出し元は `403` を受けます。ネームスペース管理者は自ネームスペースのトレースの作成、一覧、ダウンロード、ストリーミング、停止、削除が可能です。

#### クラスタリング

- [#17076](https://github.com/emqx/emqx/pull/17076) 新しいルーティングテーブル同期機構を導入しました。ルーティングテーブルスキーマバージョンは `v3` に上げられ、`v2` との下位互換性も提供されます。

  スキーマ v3 では各ノード（コアまたはレプリカント）が自身に向けられたルーティングテーブルエントリーの完全な所有権を持ち、ピアノードは読み取り専用アクセスのみとなります。これによりパーティション耐性が向上し、パーティション分割されたクラスターのピアノードが他ノードの代わりにルーティングテーブルを変更できなくなります。またレプリカントノードの `SUBACK` レイテンシも改善されます。

  **下位互換性:** v3 対応ノードが v2 のみ対応クラスターに参加すると互換のため v2 を使い続けます。クラスターを v3 に切り替えるにはアップグレード後にクラスター全体を再起動してください。自動切り替えを防ぐには `broker.routing.storage_schema` を `v2` に設定します。

  **ダウングレード注意:** クラスターが v3 に切り替わるとローリングダウングレードは不可能です。

  ノードの現在のルーティングスキーマバージョンを確認するには：

  ```
  emqx eval 'emqx_router:get_schema_vsn()'
  ```

- [#17152](https://github.com/emqx/emqx/pull/17152)、[#17181](https://github.com/emqx/emqx/pull/17181) Erlang inet ポートオプション（接続とリッスン両方）を分散ポート用に設定可能にし、デフォルトのバッファサイズを 1 MB にしました。

  以前は Erlang 分散ポートは非常に小さいデフォルトバッファ（1460 バイト、プラットフォームによっては約 9 KB）を使い、分散ポートバッファ（`+zdbbl`）を大きく設定しても性能ボトルネックとなっていました。これによりクラスター通信の信頼性が低下し、`erpc timeout` エラー、Mnesia トランザクション渋滞、多コアノードの性能低下が発生していました。

- [#17221](https://github.com/emqx/emqx/pull/17221) MQTT メッセージ転送のクラスターリンク診断を改善しました。

  メッセージ転送接続に接続問題がある場合、リンクリソースの状態と対応するアラームに切断理由が含まれるようになり、設定問題の特定が容易になりました。

- [#17530](https://github.com/emqx/emqx/pull/17530) クラスターリンクは非コミュニティライセンスが必要になりました。デフォルトのコミュニティライセンスでは設定済みリンクは非アクティブ（メッセージ転送やルート複製なし）で、REST API はリンク有効化を拒否し非コミュニティライセンスのロードを促す明確なヒントを返します。リンクの無効化と削除は可能で、レガシー設定の整理が可能です。ライセンスアップグレード後はダッシュボードや REST API からリンクを有効化でき、ノード再起動は不要です。

- [#17329](https://github.com/emqx/emqx/pull/17329) `/api/v5/prometheus/stats` エンドポイントにノード全体のゲージメトリクスを追加しました：

- [#16942](https://github.com/emqx/emqx/pull/16942)、[#17235](https://github.com/emqx/emqx/pull/17235) API キーとダッシュボードログインユーザーの詳細なスコープベースアクセス制御を導入しました。

  API キーはオプションの `scopes` フィールドをサポートし、設定時はロールチェックに加えて管理スコープカタログに対して認可されます。`publisher` API キーロールは `publish` スコープのみに制限されます。

  ダッシュボードログインユーザーもロールベースチェックに加えて `scopes` をサポートします。4 つのログイン専用スコープ（`user_management`、`mfa_management`、`sso_management`、`api_key_management`）はダッシュボード専用エンドポイントをカバーします。`user_management`、`sso_management`、`api_key_management` は管理者専用で、`mfa_management` は強制 MFA からの自己免除に任意のロールが持てます。API キーはこれらログイン専用スコープを使えません。

  新しいカタログエンドポイント `GET /api_key_scopes` と `GET /user_scopes` はベアラ認証呼び出し元にスコープ語彙を公開します。`GET /users`、`POST /users`、`PUT /users/:username` はレスポンスに `scopes` を含み、明示的に設定されていない場合はロールデフォルトスコープを表示します。

  新スコープモデルに伴う動作変更：

  - `dashboard.default_username` ユーザーは保護されたブレークグラスアカウントになりました。削除、管理者からの降格、スコープ割当はできず、説明のみ変更可能です。既存の最後の管理者チェックは他の管理者に適用されます。
  - 自己サービス更新はスコープを尊重しますが、パスワード変更と MFA 自己エンドポイントは例外です。例：`user_management` なしの閲覧者は自分のパスワード変更と MFA 管理は可能ですが、他のプロフィール編集はできません。
  - `PUT /users/:username` と `PUT /api_key/:name` はリクエストに `scopes` がない場合、永続化されたスコープに対してロール変更を検証し、不整合な降格やロール変更を拒否します。
  - API キーブートストラップファイルはオプションのスコープ列（`key:secret:role:scopes`）を受け入れます。不明またはロール非互換のスコープは警告付きで破棄され、既存の 3 列ファイルは引き続きロード可能です。
  - SAML SP メタデータエンドポイント（`GET /sso/saml/metadata`）は認証不要でアクセス可能になり、`/sso/saml/acs` と一致します。
