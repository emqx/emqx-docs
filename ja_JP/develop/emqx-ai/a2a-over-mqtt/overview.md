# A2A over MQTT

A2A over MQTTは、[Agent-to-Agent (A2A) プロトコル](https://a2a-protocol.org/latest/)をMQTTに対応させるブローカーに依存しないトランスポートプロファイルです。標準化されたトピック規約、MQTT v5プロパティのマッピング、およびディスカバリ動作を定義しており、異なるフレームワークで構築されたAIエージェントが、相互にポイントツーポイントの統合を必要とせずにMQTTブローカーを介して登録、発見、連携できるようにします。

EMQXは、**A2A Registry**という組み込み機能を通じてA2A over MQTTを実装しています。これは、ディスカバリトピックにパブリッシュされたAgent Cardをインデックス化し、エージェントの生存状態を追跡し、オペレーター向けの管理インターフェースを提供します。

::: warning 多くのリスナーマウントポイントとは非互換
A2A Registryは、[マウントポイント](../../../guides/configuration/listener.md#mountpoint)が設定されたリスナー経由で接続されたエージェントには対応していません。唯一の例外は、`acme/`のようにトピックレベルがちょうど1つのマウントポイントであり、EMQXがこれを`$a2a`トピックのネームスペースプレフィックスとして解析する場合です。それ以外のマウントポイントの場合、マウントされたトピックは`$a2a/v1/`規約に合致しなくなり、Agent Cardはインデックス化、検証、生存状態の注釈なしに通常のリテインドメッセージとして保存されます。クライアントにエラーは報告されません。
:::

## なぜMQTTでA2Aか

標準のA2AプロトコルはトランスポートにHTTPを使用しています。これはクラウド環境では有効ですが、分散型、IoT、エッジコンピューティング環境では制約が多く、エージェントがリソース制限のあるデバイス上で動作したり、NATの背後にあったり、持続的なHTTP接続が困難な環境では不向きです。

MQTTはこれらの制約に直接対応しています：

- **軽量かつ効率的**：最小限のプロトコルオーバーヘッドで、低帯域幅かつ信頼性の低いネットワークに適しています。
- **ブローカー経由のルーティング**：エージェント同士が互いのアドレスを知る必要がなく、ブローカーがルーティングを担当します。
- **ディスカバリのためのリテインドメッセージ**：エージェントはAgent Cardをリテインドメッセージとしてパブリッシュし、専用のレジストリサービスなしでサブスクライバーに即座に提供されます。
- **ネイティブなプレゼンス検出**：MQTTのLast Will and Testament (LWT)により、エージェントが予期せず切断された際に自動的にオフラインを通知します。
- **集中認証**：EMQXの既存の認証および認可がすべてのエージェントトラフィックに一貫して適用されます。

## 主な機能

- 標準化された`$a2a/v1/discovery/`トピック上のリテインドメッセージによるエージェント登録とディスカバリ。
- Agent Cardの閲覧、登録、管理を対話的に行うためのダッシュボードUI。
- `emqx ctl a2a-registry`コマンドによるCLI管理。
- Agent Card登録時のA2Aスキーマ検証（オプション）。
- ブローカー管理の生存監視：EMQXはエージェント接続状態を反映した`a2a-status` MQTTユーザープロパティを付与。
- MQTT v5のリクエスト／リプライ：エージェント間のタスク委譲のための標準化された`Response Topic`と`Correlation Data`規約。
