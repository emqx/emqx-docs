# X.509証明書認証

X.509は、安全なインターネット通信で広く使用されている標準的な公開鍵証明書フォーマットです。EMQXはTLS/SSL接続およびX.509証明書を用いたクライアント／サーバー間の相互認証をサポートしており、高いレベルのセキュリティを提供します。

## 特徴と利点

- **セキュリティ**：X.509はデジタル証明書と公開鍵暗号を用いた安全で信頼性の高い認証機構を提供し、通信の機密性、完全性、認証を保証します。不正なデバイスのネットワークアクセスや悪意ある操作を防止します。
- **相互運用性**：X.509は広くサポートされている普遍的な標準で、多くのIoTデバイスがX.509証明書をサポートしているため、デバイス間の認証と安全な通信がより簡単かつ信頼性の高いものになります。
- **スケーラビリティ**：X.509は大規模なIoT展開に対応可能です。柔軟な証明書チェーンと管理機構を備え、複雑なIoT環境に適応し、多数のデバイスやエンティティの認証をサポートします。
- **信頼できる第三者検証**：X.509証明書は通常、厳格なセキュリティ審査と検証を経た信頼された認証局（CA）によって発行されます。デバイスは信頼されたCA発行の証明書を使用して自身の身元と証明書の正当性を保証できます。
- **強力な暗号アルゴリズムのサポート**：X.509は共通の対称・非対称暗号アルゴリズムを含む幅広い暗号アルゴリズムと鍵長をサポートし、IoTデバイスが強力な暗号化アルゴリズムを用いて通信の安全性を確保できます。
- **柔軟な証明書設定と管理**：X.509は柔軟な証明書設定と管理オプションを備えています。デバイスは用途に応じて適切な証明書属性や拡張フィールドを選択でき、特定のIoTアプリケーション要件を満たせます。さらに、証明書の失効や更新は証明書管理機構により効果的に管理可能です。

## X.509証明書認証の有効化

X.509証明書認証は基本的にTLS/SSLの相互認証です。設定方法は[SSL/TLSの相互認証を有効化する](../../network/emqx-mqtt-tls.md#enable-ssl-tls-with-two-way-authentication)を参照してください。

::: tip

X.509証明書認証はパスワード認証やJWT認証よりも先に実行されます。

:::

## 証明書情報のマッピング

EMQXはX.509証明書情報をユーザー名またはクライアントIDとしてマッピングし、証明書とクライアントのバインドを実現できます。Dashboardまたは設定ファイルで設定可能です。

::: warning mTLSによる証明書フィールドマッピングの必須条件

`peer_cert_as_username` または `peer_cert_as_clientid` を `disabled` 以外に設定する場合、SSLリスナーは相互TLSを強制する必要があります。

- `verify = verify_peer`
- `fail_if_no_peer_cert = true`
<<<<<<< HEAD
- `cacertfile` は管理下のCAバンドルに設定（任意の名前で証明書を発行可能な公開CAは信用しないでください）

:::

mTLSがない場合、クライアントは証明書を提示せずに接続したり、任意のCN/DNを持つ自己署名証明書を提示できます。EMQXはそれを検証せず、CN/DNを直接ユーザー名またはクライアントIDにマッピングします。攻撃者が選んだCN/DNにより、任意の身元を偽装可能です。空のCN/DNはHTTP認証などの下流認証機構で予期しない動作を引き起こすこともあります。mTLSを強制すると、マッピング適用前にEMQXがハンドシェイクを拒否します。

::: tip 注意

空のユーザー名ケースへの追加の安全策として、`listeners.{type}.{name}.enable_authn = quick_deny_anonymous` を設定し、派生ユーザー名が空のクライアントを認証チェーンに入らず即座に拒否することが推奨されます。これはmTLSを補完するものであり、代替ではありません。偽造CN/DNに対する防御にはなりません。

:::

CN、DN、証明書全体の内容など、ピア証明書のフィールドをユーザー名として使用可能です。現在サポートされている証明書情報の解釈は以下の通りです。

クライアントはピア証明書のフィールド（CN、DN、証明書全体の内容など）をユーザー名として使用できます。現在サポートされている証明書情報の解釈は以下の通りです。
>>>>>>> origin/release-5.10

- `cn`：証明書のCNフィールド
- `dn`：証明書のDN情報（`CN=xxx,OU=xxx,O=xxx,L=xxx,ST=xxx,C=xxx`形式）
- `crt`：証明書のDER形式の内容
- `pem`：DER証明書をPEM形式に変換した内容
- `md5`：DERまたはPEM証明書内容のMD5値
