# トピック書き換え

多くのIoTデバイスは再設定やアップグレードに対応していないため、サブスクライブしているトピックを変更することが困難です。この問題を解決するために、EMQXはトピック書き換え機能を導入しました。関連するルールを設定することで、EMQXは新しいメッセージを送信するクライアントや新しいトピックをサブスクライブするクライアントのサブスクライブトピックを自動的に書き換えます。

このトピック書き換え機能は、[保持メッセージ](./mqtt-retained-message.md)や[遅延パブリッシュ](./mqtt-delayed-publish.md)機能と組み合わせて使用できます。例えば、遅延パブリッシュを利用したい場合、トピック書き換えを使ってメッセージを必要なトピックにリダイレクトできます。

::: tip
トピック書き換えは、書き換え前に認可チェックが実行されます。
:::

::: tip

トピック書き換えは、共有サブスクライブトピックに関してはクライアントのサブスクライブ／サブスクライブ解除時に実際のトピックにのみ適用されます。つまり、共有サブスクライブトピックのプレフィックス `$share/<group-name>/` を除いた部分にのみ影響します。

例えば、クライアントが `$share/group/t/1` のような共有サブスクライブトピックフィルターをサブスクライブ／サブスクライブ解除する場合、EMQXは `$share/group/` を無視して `t/1` の部分だけをマッチングおよび書き換えの対象とします。

共有サブスクライブの詳細については、[共有サブスクライブ](./mqtt-shared-subscription.md)を参照してください。

:::

## トピック書き換えルールの設定

EMQXのトピック書き換えルールは設定が必要です。複数のトピック書き換えルールを追加できます。ルール数に制限はありませんが、トピックを持つMQTTメッセージはすべて再度書き換えルールにマッチングされるため、高スループット環境ではルール数に比例してパフォーマンスオーバーヘッドが増加します。そのため、この機能は注意して使用してください。

各トピックの書き換えルールのフォーマットは以下の通りです。

```bash
rewrite = [
  {
    action:       "all"
    source_topic: "x/#"
    dest_topic:   "x/y/z/$1"
    re:           "^x/y/(.+)$"
  }
]
```

各書き換えルールはフィルターと正規表現で構成されます。

書き換えルールは `publish`、`subscribe`、`all` の3種類に分かれています。`publish` ルールはPUBLISHメッセージのトピックにマッチし、`subscribe` ルールはSUBSCRIBEおよびUNSUBSCRIBEメッセージのトピックにマッチします。`all` ルールはPUBLISH、SUBSCRIBE、UNSUBSCRIBEのすべてのメッセージに対して有効です。

トピック書き換えが有効な状態で、PUBLISHメッセージなどのMQTTパケットを受信すると、EMQXはパケット内のトピックを使って設定ファイル内のルールのトピックフィルター部分と順にマッチングを行います。マッチングに成功すると、正規表現を使ってトピック内の情報を抽出し、元のトピックを置換して新しいトピックを生成します。

置換後のトピック（ターゲット式）では、正規表現で抽出した要素を `$N` の形式で参照できます。ここで `$N` は正規表現で抽出したN番目の要素を意味し、例えば `$1` は最初の抽出要素です。

また、ターゲット式は `${clientid}` でクライアントIDを、`${username}` でクライアントのユーザー名を表すこともできます。

なお、EMQXは設定ファイルのルールを上から順に読み込みます。トピックが複数の書き換えルールのトピックフィルターに同時にマッチする場合、最初にマッチしたルールでトピックを書き換えます。

ルール内の正規表現がMQTTパケットのトピックにマッチしなかった場合は書き換えに失敗し、他のルールによる書き換えは行われません。そのため、MQTTパケットのトピックとトピック書き換えルールは慎重に設計する必要があります。

## 例

以下のトピック書き換えルールが設定ファイルに追加されているとします。

```bash
rewrite = [
  {
    action:       "all"
    source_topic: "y/+/z/#"
    dest_topic:   "y/z/$2"
    re:           "^y/(.+)/z/(.+)$"
  }
  {
    action:       "all"
    source_topic: "x/#"
    dest_topic:   "z/y/x/$1"
    re:           "^x/y/(.+)$"
  }
  {
    action:       "all"
    source_topic: "x/y/+"
    dest_topic:   "z/y/$1"
    re:           "^x/y/(\d+)$"
  }
]
```

このとき、以下の5つのトピックをサブスクライブしたとします：`y/a/z/b`、`y/def`、`x/1/2`、`x/y/2`、`x/y/z`。

+ `y/def` はどのトピックフィルターにもマッチしないため、トピック書き換えは行われず、そのまま `y/def` トピックをサブスクライブします。
+ `y/a/z/b` は `y/+/z/#` トピックフィルターにマッチするため、EMQXは最初のルールを適用し、正規表現で `[a、b]` を抽出します。抽出した2番目の要素を `y/z/$2` に代入し、実際には `y/z/b` トピックをサブスクライブします。
+ `x/1/2` は `x/#` トピックフィルターにマッチし、EMQXは2番目のルールを適用しますが、正規表現にマッチしないためトピック書き換えは行われず、そのまま `x/1/2` トピックをサブスクライブします。
+ `x/y/2` は `x/#` と `x/y/+` の2つのトピックフィルターに同時にマッチします。EMQXは設定ファイルを上から順に読み込むため、3番目のルールを優先的に適用し、正規表現で置換して実際には `z/y/2` トピックをサブスクライブします。
+ `x/y/z` も `x/#` と `x/y/+` の2つのトピックフィルターに同時にマッチしますが、3番目のルールの正規表現にマッチしないためトピック書き換えは行われず、そのまま `x/y/z` トピックをサブスクライブします。なお、3番目のルールの正規表現マッチが失敗しても、2番目のルールには再度マッチしません。
