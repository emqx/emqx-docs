# EMQX バージョンライフサイクルとサポート終了（EOL）日

EMQX は、迅速に進化する SaaS プラットフォームから大規模なエンタープライズ展開まで、幅広いユーザーに対応しています。これら多様なニーズに応えるため、EMQX はイノベーション、安定性、長期メンテナンスのバランスを取った多層的なリリースおよびサポートポリシーを採用しています。

本ライフサイクルポリシーの目的は以下の通りです：

- [EMQX Cloud](../faq/concept.md#which-products-do-we-offer) における頻繁な内部アップデートによる迅速なイノベーションの支援
- オンプレミスユーザーに対し、予測可能な四半期ごとのスケジュールで新機能を提供
- エンタープライズ顧客に対して、指定された **Long-Term Support (LTS)** バージョンを通じた長期的な安定性の提供
- バージョンのサポート期間および **サポート終了（EOL）** の明確かつ予測可能なタイムラインの確保

3つの異なるリリース層（Internal、Feature、LTS）を提供することで、EMQX はユーザーが最新機能への迅速なアクセスを重視するか、長期的なプラットフォームの安定性を重視するかに応じて、最適なバージョンのリリース頻度を選択できるようにしています。

## リリース層とリリース頻度

迅速なイノベーションとエンタープライズグレードの安定性のバランスを取るため、EMQX は以下の3層リリースモデルを採用しています：

### Internal リリース

*   **頻度:** 月次
*   **対象:** EMQX 内部チーム、EMQX Cloud、見込み顧客
*   **目的:** EMQX が管理する環境（例：EMQX Cloud、内部テスト、限定的な公開ステージング）で新機能を迅速に提供・検証。Internal リリースは選定された顧客への早期アクセスも提供し、将来の公開 Feature リリースの基盤となります。
*   **品質保証:** 公開ダウンロードはできませんが、EMQX Cloud を支えるために完全なQAを経ており、本番環境対応可能な品質です。実験的・不安定なものではありません。
*   **サポート:** EMQX チームが Cloud 環境向けに直接メンテナンスを行います。オンプレミス顧客向けの直接利用は想定していません。

### Feature リリース（公開）

*   **頻度:** 四半期ごと（通常3月、6月、9月、12月）
*   **対象:** 最新の安定機能にタイムリーにアクセスしたいオンプレミスユーザー
*   **目的:** 最近の Internal リリースで検証済みの機能をパッケージ化し、一般的なオンプレミス利用向けに提供
*   **サポート期間:** 初回リリース日から18ヶ月間

### Long-Term Support (LTS) リリース（公開）

*   **頻度:** 年次（通常6月の Feature リリースが LTS 指定される）
*   **対象:** ミッションクリティカルな展開で最大の安定性と長期計画を必要とするエンタープライズユーザー
*   **目的:** 高度に安定し、広範に検証されたバージョンを長期サポート付きで提供
*   **サポート期間:** 初回リリースから3年間（特例として 4.4.x は5年間サポート）

この多層リリースモデルにより、機能は内部検証を経て成熟し、オンプレミス展開における安定性と品質が向上します。

*   **5.8.x**（初回リリース日：2024年8月28日、EOL日：2027年8月27日）

## バージョン番号と命名規則

EMQX は Semantic Versioning（`MAJOR.MINOR.PATCH`、例：`5.8.1`）を基盤とし、リリース層ごとに特定の命名規則を設けています。

### メジャーリリース（例：`4.0.0`、`5.0.0`、`6.0.0`）

*   後方互換性のない変更を含む可能性のある大幅な更新を導入
*   メジャーバージョン間の直接インプレースアップグレードは原則サポートされません。通常は新規デプロイを構築し、設定やデータを手動で移行します。詳細は各メジャーバージョンの移行ガイドを参照してください。

### Internal リリース（例：`5.9.0-M3.202506`）

*   **形式:** `X.Y.Z-M[1-3].YYYYMM`（例：`5.9.0-M2.202505`、`5.9.1-M3.202506`）
*   `X.Y` は開発中の次期または現行の公開 Feature リリースのマイナーバージョンに対応
*   `Z` は内部反復に応じて増分。臨時修正が適用されることもあります

### Feature リリース（例：`5.7.0`、`5.9.0`、`5.10.0`）

*   新機能、改善、バグ修正を四半期ごとに提供する公開マイナーリリース
*   同一メジャーバージョン内の過去マイナーリリース（例：`5.x`）と後方互換性があり、クラスタのローリングアップグレードをサポート
*   **形式:** `X.Y.0`
*   `Y`（マイナーバージョン）は四半期ごとに増分
*   **命名:** `EMQX Enterprise X.Y.0`

### LTS リリース（例：`5.8.0`）

*   年次の Feature リリースのうち、長期サポート対象として指定されたもの
*   初回 LTS リリース (`X.Y.0`) はリリース時点での最新かつ安定した完全検証済み機能セットを含む
*   **形式:** `X.Y.0`
*   **命名:** `EMQX Enterprise X.Y.0`
*   LTS ステータスはドキュメントおよび公式ダウンロードページで明示されます

### パッチリリース（例：`5.8.1`、`5.9.2`）

*   重要なバグ修正およびセキュリティパッチのみを含む
*   新機能や破壊的変更は含まれない
*   発行対象：
    *   **Feature リリース:** 初回リリース（`X.Y.0`）から18ヶ月のサポート期間内の Feature マイナーリリースライン（例：`5.9.x`）に対し、そのリリースラインに適用可能な重要なバグ修正・セキュリティパッチを提供
    *   **LTS リリース:** 3年間のサポート期間中、対象の LTS リリースラインに適用可能な重要なバグ修正・セキュリティパッチを提供

## メンテナンスポリシー

EMQX のリリースは種類とライフサイクル段階に応じて異なるメンテナンスが行われます：

*   **Internal リリース:**
    *   EMQX チームが管理。発見されたバグは通常、次の内部反復や Cloud 環境内のホットフィックスで対応され、これらの修正は将来の公開リリースに向けて dev ブランチに統合されます。
*   **Feature リリース（公開）:**
    *   新機能や改善は四半期ごとの Feature マイナーリリース（例：5.9.0、5.10.0）で提供されます。18ヶ月のライフサイクル期間中、各 Feature リリースライン（例：5.9.x）は、そのリリースラインに適用可能な重要なバグ修正やセキュリティパッチをパッチリリース（例：5.9.1、5.9.2）で受け取ります。
    *   対象ユーザーは、新機能への迅速なアクセスを望み、短期間のサポートサイクルを受け入れられる方です。
*   **Long-Term Support (LTS) リリース（公開）:**
    *   **初回 LTS リリース（例：5.8.0）:** 最新の安定機能セットを含んでリリース
    *   **以降の LTS パッチリリース（例：5.8.1、5.8.2）:** 3年間のライフサイクル期間中、以下の更新をパッチリリースで提供
        *   重要なバグ修正
        *   セキュリティ脆弱性の修正
        *   **重要:** LTS のパッチリリース（X.Y.Z）は新機能を導入しません。最大限の安定性を維持するためです。
    *   対象ユーザーは、システムの安定性、予測可能性、長期サポートを厳格に求めるエンタープライズ顧客や、デプロイ後の変更を最小限に抑えたいケースです。
*   **パッチリリース:**
    *   例：5.10.1、5.10.2 はバグ修正とセキュリティパッチのみを含み、新機能は含みません。
    *   まれに、メンテナンスチームの裁量で、メンテナンスモードのバージョンに対し、移行を支援するための最小限かつ非破壊的な変更が加えられることがあります。

## アップグレードパスの推奨

最新機能、パフォーマンス向上、セキュリティ更新へのアクセスを確保するため、展開タイプに応じて以下の定期的なアップグレード戦略を推奨します：

*   **EMQX Cloud:** EMQX チームが完全に管理し、ユーザーは月次アップデートをシームレスに享受可能
*   **オンプレミス Feature リリース:** 四半期ごとの Feature リリース間でアップグレードし、新機能を利用可能。18ヶ月のサポート期間内の Feature リリースを利用し続けることを推奨
*   **オンプレミス LTS リリース:** エンタープライズユーザーは現在の LTS バージョンから次の LTS バージョンへの移行を計画し、長期サポートの途切れを防ぐために十分な重複期間を設けることが可能。Feature リリースから LTS へのアップグレードもサポート

各リリースには詳細なアップグレードガイドと互換性に関する注意事項が含まれており、計画と実行を支援します。
