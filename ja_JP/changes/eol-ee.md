# EMQX バージョンライフサイクルとサポート終了（EOL）日

EMQX は、迅速に進化する SaaS プラットフォームから大規模なエンタープライズ展開まで、幅広いユーザーに対応しています。これら多様なニーズに応えるため、EMQX はイノベーション、安定性、長期メンテナンスのバランスを取った多層的なリリースおよびサポートポリシーを採用しています。

本ライフサイクルポリシーは以下を目的としています：

- [EMQX Cloud](../faq/concept.md#which-products-do-we-offer) における頻繁な内部アップデートによる迅速なイノベーションの支援
- オンプレミスユーザーへ予測可能な四半期ごとのスケジュールで新機能を提供
- 指定された **Long-Term Support (LTS)** バージョンによるエンタープライズ顧客への長期安定性の提供
- バージョンのサポート期間および **サポート終了（EOL）** の明確かつ予測可能なスケジュールの保証

3つの異なるリリース階層（Internal、Feature、LTS）を提供することで、EMQX はユーザーが最新機能への迅速なアクセスを重視するか、長期的なプラットフォームの安定性を重視するかに応じて最適なバージョンの選択を可能にしています。

## リリース階層とリリース頻度

迅速なイノベーションとエンタープライズ品質の安定性を両立するため、EMQX は以下の3層リリースモデルを採用しています。

### Internal リリース

*   **頻度:** 月次
*   **対象:** EMQX 内部チーム、EMQX Cloud、見込み顧客
*   **目的:** EMQX が管理する環境（例：EMQX Cloud、内部テスト、限定的な公開ステージング）で新機能を迅速に提供・検証。Internal リリースは選定された顧客への早期アクセスも提供し、将来の公開 Feature リリースの基盤となる。
*   **品質保証:** 公開ダウンロードは不可だが、EMQX Cloud を支えるために完全なQAを経ており、実運用に耐える安定版である。実験的・不安定なものではない。
*   **サポート:** EMQX チームが Cloud 環境向けに直接メンテナンス。オンプレミス顧客向けではない。

### Feature リリース（公開）

*   **頻度:** 四半期ごと（通常3月、6月、9月、12月）
*   **対象:** 最新の安定機能をタイムリーに利用したいオンプレミスユーザー
*   **目的:** 最近の Internal リリースで検証された機能をパッケージ化し、一般のオンプレミス環境向けに提供
*   **サポート期間:** 初回リリース日から18ヶ月間

### Long-Term Support (LTS) リリース（公開）

*   **頻度:** 年次（通常は6月の Feature リリースが LTS 指定される）
*   **対象:** ミッションクリティカルな展開で最大限の安定性と長期計画を必要とするエンタープライズユーザー
*   **目的:** 非常に安定し、広範に検証されたバージョンを長期サポート付きで提供
*   **サポート期間:** 初回リリースから3年間（4.4.x は特例で5年間サポート）

この階層的リリースモデルにより、機能は内部検証を経て成熟し、オンプレミス展開においてより高い安定性と品質を保証します。

## バージョン番号と命名規則

EMQX はセマンティックバージョニング（`MAJOR.MINOR.PATCH`、例：`5.8.1`）を基本に、リリース階層ごとに特定の命名規則を設けています。

### メジャーリリース（例：`4.0.0`、`5.0.0`、`6.0.0`）

*   後方互換性のない変更を含む大幅な更新を導入
*   メジャーバージョン間の直接アップグレードは基本的にサポートされず、新規デプロイを構築し設定やデータを手動で移行する必要があります。詳細は各メジャーバージョンの移行ガイドを参照してください。

### Internal リリース（例：`5.9.0-M3.202506`）

*   **形式:** `X.Y.Z-M[1-3].YYYYMM`（例：`5.9.0-M2.202505`、`5.9.1-M3.202506`）
*   `X.Y` は開発中の次期または現行の公開 Feature リリースのマイナーバージョンに対応
*   `Z` は内部反復で増分されることがあり、臨時修正が適用される場合もある

### Feature リリース（例：`5.7.0`、`5.9.0`、`5.10.0`）

*   新機能、改善、バグ修正を四半期ごとに提供する公開マイナーリリース
*   同一メジャーバージョン内の過去マイナーリリース（例：`5.x`）との後方互換性（API・機能）を保持し、クラスターのローリングアップグレードをサポート
*   **形式:** `X.Y.0`
*   `Y`（マイナーバージョン）は四半期ごとに増分
*   **命名:** EMQX Enterprise X.Y.0

### LTS リリース（例：`5.8.0`）

*   年次の Feature リリースのうち、Long-Term Support 指定されたもの
*   初回 LTS リリース（`X.Y.0`）は、その時点での最新かつ安定した完全検証済みの機能セットを含む
*   **形式:** `X.Y.0`
*   **命名:** `EMQX Enterprise X.Y.0`
*   LTS ステータスはドキュメントおよび公式ダウンロードページで明示される

### パッチリリース（例：`5.8.1`、`5.9.2`）

*   重要なバグ修正およびセキュリティパッチのみを含む
*   新機能や破壊的変更は含まれない
*   発行対象：
    *   **Feature リリース:** 初回リリース（`X.Y.0`）から18ヶ月のサポート期間内の各 Feature マイナーリリースライン（例：`5.9.x`）に対し、そのリリースラインに影響する重要なバグ修正・セキュリティパッチを提供
    *   **LTS リリース:** 3年間のサポート期間中、該当 LTS リリースラインに影響する重要なバグ修正・セキュリティパッチを提供

## メンテナンスポリシー

EMQX のリリースは種類とライフサイクル段階に応じて異なるメンテナンスが行われます。

*   **Internal リリース:**
    *   EMQX チームがメンテナンスを担当。発見されたバグは通常、次回の内部反復や Cloud 環境内のホットフィックスで対応。これらの修正は dev ブランチに統合され、将来の公開リリースに反映される。
*   **Feature リリース（公開）:**
    *   新機能や改善は四半期ごとの Feature マイナーリリース（例：5.9.0、5.10.0）で提供。
    *   18ヶ月のサポート期間中は、各 Feature リリースライン（例：5.9.x）に対し、該当する重要なバグ修正・セキュリティパッチをパッチリリース（例：5.9.1、5.9.2）で提供。
    *   対象ユーザーは、新機能への迅速なアクセスを求め、短期間のサポートサイクルを許容できる方。
*   **Long-Term Support (LTS) リリース（公開）:**
    *   **初回 LTS リリース（例：5.8.0）:** 最新の安定機能セットを含む形でリリース。
    *   **以降の LTS パッチリリース（例：5.8.1、5.8.2）:** 3年間のライフサイクル中、以下の更新を提供：
        *   重要なバグ修正
        *   セキュリティ脆弱性パッチ
        *   **重要:** LTS のパッチリリース（X.Y.Z）では新機能は一切追加されない。
    *   対象ユーザーは、システムの安定性、予測可能性、長期サポートを厳格に求めるエンタープライズ顧客や、展開後の変更を最小限に抑えたいケース。
*   **パッチリリース:**
    *   例：5.10.1、5.10.2 はバグ修正とセキュリティパッチのみを含み、新機能は含まれない。
    *   まれに、メンテナンスチームの判断で、メンテナンスモードのバージョンに対し、移行を支援するための最小限かつ非破壊的な変更を加える場合がある。

## アップグレードパスの推奨

最新機能、性能向上、セキュリティアップデートを確実に利用するため、展開形態に応じて以下のアップグレード戦略を推奨します。

*   **EMQX Cloud:** EMQX チームが完全に管理しており、ユーザーは月次の更新をシームレスに享受可能。
*   **オンプレミス Feature リリース:** 四半期ごとの Feature リリース間でアップグレードし、新機能を利用可能。サポート期間内（18ヶ月以内）の Feature リリースを利用し続けることを推奨。
*   **オンプレミス LTS リリース:** エンタープライズユーザーは現在の LTS バージョンから次の LTS バージョンへの移行を計画し、長期サポートを途切れなく受けられるように重複期間を設けることが可能。Feature リリースから LTS リリースへのアップグレードもサポートされている。

各リリースには詳細なアップグレードガイドと互換性に関する注意事項が付属し、計画と実行を支援します。
