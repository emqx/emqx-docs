# EMQX バージョンライフサイクルとサポート終了（EOL）日

EMQX は、迅速に進化する SaaS プラットフォームから大規模なエンタープライズ展開まで、幅広いユーザーに対応しています。これら多様なニーズに応えるため、EMQX はイノベーション、安定性、長期保守のバランスを取った多層的なリリースおよびサポートポリシーを採用しています。

本ライフサイクルポリシーは以下を目的としています：

- [EMQX Cloud](../faq/concept.md#which-products-do-we-offer) における頻繁な内部アップデートによる迅速なイノベーションの支援。
- オンプレミスユーザーに対し、予測可能な四半期スケジュールでの新機能提供。
- エンタープライズ顧客に対して、指定された **Long-Term Support（LTS）** バージョンによる長期安定性の提供。
- バージョンのサポート期間および **サポート終了（EOL）** の明確かつ予測可能なスケジュールの確保。

3つの異なるリリース階層（Internal、Feature、LTS）を提供することで、EMQX はユーザーが最新機能への迅速なアクセスを重視するか、長期的なプラットフォームの安定性を重視するかに応じて最適なバージョン選択を可能にしています。

## リリース階層とリリース頻度

迅速なイノベーションとエンタープライズレベルの安定性のバランスを取るため、EMQX は以下の3層リリースモデルを採用しています。

### Internal リリース

*   **頻度:** 月次。
*   **対象:** EMQX 内部チーム、EMQX Cloud、および見込み顧客。
*   **目的:** EMQX が管理する環境（例：EMQX Cloud、内部テスト、限定的なパブリックステージング）で新機能を迅速に提供・検証。Internal リリースは選定された顧客への早期アクセスも提供し、将来の公開 Feature リリースの基盤となります。
*   **品質保証:** 公開ダウンロードはできませんが、EMQX Cloud を支えるためにフルQAを実施し、本番環境対応可能な品質を保証しています。実験的・不安定なものではありません。
*   **サポート:** EMQX チームが Cloud 環境向けに直接メンテナンス。オンプレミスの顧客向けではありません。

### Feature リリース（公開）

*   **頻度:** 四半期ごと（通常3月、6月、9月、12月）。
*   **対象:** 最新の安定機能をタイムリーに利用したいオンプレミスユーザー。
*   **目的:** 最近の Internal リリースで検証済みの機能をパッケージ化し、一般のオンプレミス利用者に提供。
*   **サポート期間:** 初回リリース日から18か月。

### Long-Term Support（LTS）リリース（公開）

*   **頻度:** 年次（通常6月の Feature リリースが LTS 指定）。
*   **対象:** ミッションクリティカルな展開で最大の安定性と長期計画が必要なエンタープライズユーザー。
*   **目的:** 高度に安定化・検証されたバージョンを長期サポート付きで提供。
*   **サポート期間:** 初回リリースから3年（4.4.x は特例で5年サポート）。

この階層的リリースモデルにより、機能は内部検証を経て成熟し、オンプレミス展開においてより高い安定性と品質を実現します。

## バージョン番号および命名規則

EMQX は Semantic Versioning（`MAJOR.MINOR.PATCH`、例：`5.8.1`）を基盤とし、リリース階層ごとに特定の命名規則を設けています。

### メジャーリリース（例：`4.0.0`、`5.0.0`、`6.0.0`）

*   後方互換性のない変更を含む可能性のある大幅な更新を導入。
*   メジャーバージョン間の直接的なインプレースアップグレードは一般的にサポートされません。通常は新規デプロイを構築し設定やデータを手動で移行します。詳細は各メジャーバージョンのマイグレーションガイドを参照してください。

### Internal リリース（例：`5.9.0-M3.202506`）

*   **形式:** `X.Y.Z-M[1-3].YYYYMM`（例：`5.9.0-M2.202505`、`5.9.1-M3.202506`）。
*   `X.Y` は開発中の次期または現行の公開 Feature リリースのマイナーバージョンに対応。
*   `Z` は内部反復で増分。アドホックな修正が適用されることもあります。

### Feature リリース（例：`5.7.0`、`5.9.0`、`5.10.0`）

*   新機能、改善、バグ修正を四半期ごとに提供する公開マイナーリリース。
*   同一メジャーバージョン内の過去のマイナーリリース（例：`5.x`）と後方互換性（APIおよび機能）を保ち、ローリングクラスタアップグレードをサポート。
*   **形式:** `X.Y.0`。
*   `Y`（マイナーバージョン）は四半期ごとに増加。
*   **命名:** `EMQX Enterprise X.Y.0`。

### LTS リリース（例：`5.8.0`）

*   年次の Feature リリースのうち、Long-Term Support に昇格したもの。初回 LTS リリース（`X.Y.0`）はリリース時点での最新かつ安定した機能セットを含みます。
*   **形式:** `X.Y.0`。
*   **命名:** `EMQX Enterprise X.Y.0`。
*   LTS ステータスはドキュメントおよび公式ダウンロードページで明示されます。

### パッチリリース（例：`5.8.1`、`5.9.2`）

*   重要なバグ修正およびセキュリティパッチのみを含む。
*   新機能や破壊的変更は含みません。
*   発行対象：
    *   **Feature リリース:** 初回リリース（`X.Y.0`）から18か月のサポート期間内の各 Feature マイナーリリースライン（例：`5.9.x`）に対し、そのラインに影響する重大なバグ修正やセキュリティ脆弱性のパッチを提供。
    *   **LTS リリース:** 3年間のサポート期間中、該当 LTS ラインに影響する重大なバグ修正やセキュリティパッチを提供。

## メンテナンスポリシー

EMQX のリリースは種類とライフサイクル段階に応じて異なるメンテナンスが行われます。

*   **Internal リリース:**
    *   EMQX チームが対応。発見されたバグは通常、次回の内部反復や Cloud 環境でのホットフィックスで修正され、これらの修正は開発ブランチにマージされ将来の公開リリースに反映されます。
*   **Feature リリース（公開）:**
    *   新機能や改善は四半期ごとの Feature マイナーリリース（例：5.9.0、5.10.0）で提供。
    *   18か月のライフサイクル期間中、各 Feature リリースライン（例：5.9.x）は、そのラインに該当する重大なバグ修正およびセキュリティパッチをパッチリリース（例：5.9.1、5.9.2）で受け取ります。
    *   対象ユーザーは、新機能への迅速なアクセスを望み、短期間のサポートサイクルを受け入れられるユーザーです。
*   **Long-Term Support（LTS）リリース（公開）:**
    *   **初回 LTS リリース（例：5.8.0）:** 最新の安定機能セットを含む形でリリース。
    *   **以降の LTS パッチリリース（例：5.8.1、5.8.2）:** 3年間のライフサイクル期間中、以下の更新をパッチリリースで提供：
        *   重大なバグ修正
        *   セキュリティ脆弱性パッチ
        *   **重要:** 最大の安定性を確保するため、LTS バージョンのパッチリリース（X.Y.Z）は新機能を導入しません。
    *   対象ユーザーは、システムの安定性、予測可能性、長期サポートを厳格に求めるエンタープライズ顧客や、デプロイ後の変更を最小限に抑えたいシナリオです。
*   **パッチリリース:**
    *   例：5.10.1、5.10.2。バグ修正とセキュリティパッチのみを含み、新機能は含みません。
    *   まれに、メンテナンスチームの裁量で、メンテナンスモードのバージョンに対し、移行支援のための最小限かつ影響の少ない変更を加えることがあります。

## アップグレードパスの推奨

最新機能、パフォーマンス向上、セキュリティアップデートを確実に利用するため、展開形態に応じて以下の定期的なアップグレード戦略を推奨します。

*   **EMQX Cloud:** EMQX チームが完全管理し、ユーザーは月次アップデートをシームレスに享受可能。
*   **オンプレミス Feature リリース:** 四半期ごとの Feature リリース間でアップグレードし、新機能を利用可能。サポート期間内（18か月以内）の Feature リリースを利用し続けることを推奨。
*   **オンプレミス LTS リリース:** エンタープライズユーザーは現在の LTS バージョンから次の LTS バージョンへの移行を計画的に実施し、長期サポートの継続を確保。Feature リリースから LTS リリースへのアップグレードもサポート。

各リリースには詳細なアップグレードガイドと互換性に関する注意事項が含まれており、計画と実行を支援します。
