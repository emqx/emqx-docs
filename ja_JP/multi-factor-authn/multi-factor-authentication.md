# 多要素認証（MFA）

EMQX 5.9.0 では、EMQX ダッシュボードのセキュリティ強化のために多要素認証（MFA）機能が導入されました。この機能により、ユーザーはログイン時に2段階の認証プロセスを完了する必要があります。このプロセスは、パスワードと時間ベースのワンタイムパスワード（TOTP）を用いてユーザーの本人確認を行い、不正アクセスを防止するための追加のセキュリティ層を提供します。

## 主要な概念

- **MFA**：ユーザーのパスワードと、認証アプリによって生成されるTOTPなどの第二の認証要素の2種類の本人確認を必要とするセキュリティ機能です。
- **TOTP**：Google AuthenticatorやAuthyなどの認証アプリが、サーバーと共有された秘密情報に基づいて生成する一時的なコードです。
- **QRコード**：認証アプリでのセットアップを簡単にするために、共有秘密情報をグラフィカルに表現したコードです。

## SSO ユーザーに対する強制 MFA

EMQX 5.10 以降、SSO ユーザーに対しても MFA を強制できます。  
[シングルサインオン（SSO）](../dashboard/sso.md)（SAML、OIDC、LDAP）を有効化後、各バックエンドごとに `force_mfa` スイッチをオンにすることで、そのバックエンドからのすべてのユーザーに対し、IdP 認証に加えて TOTP の第二要素認証を必須にできます。

これは特にパブリックネットワークに公開された EMQX 環境において重要です。上流の IdP で認証情報が漏洩しても、攻撃者はユーザーの認証デバイスを持っていなければダッシュボードにアクセスできません。

`force_mfa` は各 SSO バックエンド（`saml`、`oidc`、`ldap`）ごとに独立して設定されます。ローカルアカウントには影響しません。各 SSO ユーザーの TOTP 秘密鍵はローカルユーザーとは別に管理されます。管理者は任意の SSO ユーザーに対して MFA の有効化・無効化・リセットを行えます。MFA が無効化されたユーザーは、バックエンドで `force_mfa = true` が設定されていても TOTP 認証が免除されます。これは緊急管理者アカウントの運用に便利です。

### SSO バックエンドで強制 MFA を有効化する

`base.hocon` にて、MFA を必須にしたい各バックエンドに `force_mfa = true` を追加します。ダッシュボードの SSO 設定 UI からも設定可能です。詳細は [LDAP SSO の設定](../dashboard/sso-ldap.md)、[SAML SSO の設定](../dashboard/sso-saml.md)、[OIDC SSO の設定](../dashboard/sso-oidc.md)を参照してください。

設定例：

```hocon
dashboard {
  sso {
    saml {
      enable = true
      force_mfa = true          # すべての SAML ユーザーにログイン時の TOTP を必須化
      # ... その他の SAML 設定
    }
    oidc {
      enable = true
      force_mfa = false         # 強制しない。ユーザー単位で有効化可能
      # ... その他の OIDC 設定
    }
    ldap {
      enable = true
      force_mfa = true
      # ... その他の LDAP 設定
    }
  }
}
```

`force_mfa` のデフォルト値は `false` であり、5.10 より前の動作を維持します。

::: tip
`force_mfa` をオンにしても既存のセッションは無効化されません。次回の新規ログイン時に適用されます。
:::

### 個別の SSO ユーザーの MFA 管理

ダッシュボードの **System** -> **Users** にて、SSO ユーザーはバックエンド名とともに一覧表示されます。**Actions** 列の **MFA Settings** ボタンから以下の操作が可能です。

- **MFA 有効化**：該当ユーザーに次回ログイン時の TOTP セットアップと使用を強制します。バックエンドの `force_mfa` がオフでも有効です。
- **MFA 無効化**：該当ユーザーを免除します。バックエンドで MFA が必須でも TOTP 認証をスキップします。緊急管理者アカウントに便利です。
- **TOTP 秘密鍵リセット**：現在の秘密鍵をクリアし、次回ログイン時にセットアップを再度行います。認証デバイスを紛失した場合に使用します。

### MFA を伴う SSO ログインフロー

MFA 強制は SSO のログイン体験を変えません。

1. 通常通り「SSO でログイン」ボタンをクリックします。
2. IdP で認証を行います。
3. ダッシュボードに戻った後、MFA 対象ユーザーは TOTP コードの入力を求められます。
4. `force_mfa` が有効な初回ログイン時は、QRコードスキャンやキー入力による一度限りの TOTP セットアップが案内されてからダッシュボードにアクセスします。

::: tip セキュリティ注意事項
設計上、TOTP 認証成功前にダッシュボードアクセス用の認証情報は発行されません。  
SSO コールバックリンクを傍受しても MFA を回避できません。
:::

### FAQ

**Q: `force_mfa` を有効にしたら、すでにログイン中の SSO ユーザーは強制ログアウトされますか？**  
A: いいえ。`force_mfa` は新規ログイン時のみ適用されます。既存のセッションは有効なままです。

**Q: 緊急管理者アカウントの MFA を一時的に無効化するには？**  
A: **System** -> **Users** で該当ユーザーを選び、**MFA Settings** から **Disable MFA** をクリックしてください。次回ログイン時から TOTP 認証がスキップされます。再度有効化またはリセットも可能です。

**Q: SSO バックエンド全体ではなく、一部のユーザーだけに MFA を要求できますか？**  
A: はい。`force_mfa` を `false` のままにしておき、対象ユーザーのみ **Users** ページから個別に MFA を有効化してください。
