# In-flight とメッセージキュー

## はじめに

メッセージのスループットを向上させ、ネットワークの変動による影響を軽減するために、EMQX は複数の未アック済みの QoS 1 および QoS 2 メッセージを同時に In-flight 状態で保持できます。送信済みで未確認のメッセージは、アックが完了するまで Inflight Window に格納されます。

Inflight Window の最大数（`max_inflight` を参照）に達した場合、新たに到着したメッセージは即座に転送されず、一時的にメッセージキューに格納されます。

配信が再開されると、トピック優先度が無効の場合は EMQX は FIFO 順でメッセージをデキューします。トピック優先度が有効な場合は、EMQX はトピック優先度に従ってメッセージをスケジューリングし、各優先度内では FIFO 順を維持します。配信された QoS 1 および QoS 2 メッセージは Inflight Window に追加されますが、配信された QoS 0 メッセージは Inflight Window に入りません。

QoS 0 メッセージは通常 Inflight Window をバイパスして即座に転送されます。インメモリセッションの場合、接続の送信キューが混雑すると、その後続の QoS 0 メッセージはメッセージキューに格納されます。Inflight Window が満杯で `mqueue_store_qos0` が有効な場合も、EMQX は QoS 0 メッセージをキューに格納し、通常のキュースケジューリングに従わせます。接続が回復するか Inflight Window に空きができると、EMQX はキュー内の配信を再開します。

トピック優先度ごとのメッセージキューが長さ制限に達すると、EMQX はまずその優先度の最も古い QoS 0 メッセージを削除します。もしその優先度に QoS 0 メッセージが存在しなければ、残りの最も古いメッセージを削除します。トピック優先度が無効の場合は、全メッセージが同じ優先度を共有します。このポリシーにより、QoS 0 のバースト中でも QoS 1 および QoS 2 メッセージが進行しやすくなります。したがって、適切なメッセージキュー長さ制限の設定が重要です。`max_mqueue_len` を参照してください。

メッセージキューは、サブスクライバーがオフラインであってもセッションが維持されている間に到着したメッセージも保存します。EMQX は次回サブスクライバーがオンラインになった際にこれらのメッセージを送信します。`mqueue_store_qos0` オプションは、サブスクライバーがオフライン時、インメモリ接続の送信キューが混雑している時、または Inflight Window が満杯の時に、EMQX が QoS 0 メッセージをメッセージキューに保存するかどうかを制御します。このオプションが無効の場合、サブスクライバーがオフラインまたは送信キューが混雑している間に到着した QoS 0 メッセージは破棄されます。Inflight Window のみが満杯の場合は、EMQX は QoS 0 メッセージの即時配信を継続します。

なお、Inflight Window とメッセージキューはグローバルではなく、EMQX は各クライアント接続ごとに個別の Inflight Window とメッセージキューを割り当てます。

## Inflight Window と Receive Maximum

MQTT v5 プロトコルは CONNECT パケットに `Receive Maximum` 属性を追加し、その公式説明は以下の通りです。

> クライアントは、この値を使用して、同時に処理可能な QoS 1 および QoS 2 のパブリッシュメッセージの最大数を制限します。サーバーが送信しようとする QoS 0 のパブリッシュメッセージを制限する仕組みはありません。

つまり、サーバーはアックを待つ間に異なるメッセージ識別子を持つ複数の PUBLISH パケットをクライアントに送信できますが、未アック済みメッセージ数が `Receive Maximum` の制限に達するとそれ以上送信しません。

このことから、`Receive Maximum` は実質的に EMQX の Inflight Window 機構と同じであることがわかります。ただし、EMQX は MQTT v5.0 プロトコルがリリースされる前からこの機能を MQTT クライアントに提供していました。現在は MQTT v5.0 プロトコルを使用するクライアントは、Receive Maximum の仕様に従って Inflight Window の最大長を設定し、以前のバージョンの MQTT プロトコルを使用するクライアントは設定に従って設定されます。

ただし、EMQX は CONNECT パケットで要求された `Receive Maximum` 値を必ずしも許可しません。代わりに、CONNACK パケットで許可される `Receive Maximum` は `mqtt.max_inflight` 設定によって上限が決まります。

## 設定項目

| 設定項目               | 型       | オプション値       | デフォルト値 | 説明                                                                                  |
| ---------------------- | -------- | ------------------ | ------------ | ------------------------------------------------------------------------------------- |
| mqtt.max_inflight      | integer  | (0, 65536)         | 32           | Inflight Window の長さ制限。0 は制限なしを意味します。                              |
| mqtt.max_mqueue_len    | integer  | [0, ∞)             | 1000         | メッセージキューの長さ制限。`0` は制限なしを意味します。                           |
| mqtt.mqueue_store_qos0 | enum     | `true`, `false`    | true         | クライアントがオフライン、インメモリ接続の送信キューが混雑、または Inflight Window が満杯の際に、EMQX が QoS 0 メッセージをメッセージキューに保存するかどうかを制御します。 |
