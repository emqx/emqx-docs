# Known Issues in EMQX 5.9

## e5.9.3

| Since version | Issue                                                        | Workaround                                                   | Status                    |
| ------------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------- |
| 5.9.3 | **Memory Growth in Kafka and Confluent Producer Actions When Acknowledgments Are Disabled**<br />When `parameters.required_acks = none`, the producer's memory usage increases with each Kafka produce request, and the accumulated memory is not released after the buffer is drained. | Wait until all buffered messages have been sent, then set the action's `parameters.required_acks` to `leader_only` or `all_isr`. Changing this setting recreates the producer and releases the accumulated memory. | Fixed in EMQX 5.9.4. See [emqx/emqx#19994](https://github.com/emqx/emqx/pull/19994). |

| 5.0.0         | **Route and Session Registry Can Become Inconsistent in Clusters**<br />Several related issues can leave stale or missing entries in the route table and the global session (channel) registry after cluster events such as a network partition heal, an abrupt node shutdown, or an RPC timeout during cleanup. Concrete symptoms:<br />- Routes for subscribers on a replicant node may not fully resynchronize after a network partition heals, so some subscriptions silently stop receiving messages until the affected node restarts.<br />- Channels owned by replicant nodes can be dropped from the global registry after a partition heal, leading to incorrect session takeover (a reconnecting client may not displace its old session) and misleading client counts in the Dashboard.<br />- Global session registry rows can leak indefinitely when a session's owner process dies without a clean unregister (for example after a brief network split that prevents the unregister from replicating, or when a core's consensus check times out during down-event cleanup) and the same client ID never reconnects. Over time these dead rows accumulate.<br />These fixes are landed in newer release lines but will not be backported to 5.9. See emqx/emqx PRs [#17076](https://github.com/emqx/emqx/pull/17076), [#17257](https://github.com/emqx/emqx/pull/17257), and [#17522](https://github.com/emqx/emqx/pull/17522). | -                                                            | Upgrade to 5.10.4+, 6.1.2+, or 6.2.1+ |
| 5.0.0         | **Node Crash if Linux monotonic clock steps backward**<br />In certain virtual Linux environments, the operating system is unable to keep the clocks monotonic, which may cause Erlang VM to exit with the message `OS monotonic time stepped backwards!`. | For such environments, you may set the `+c` flag to `false` in `etc/vm.args`. |                           |
| 5.3.0         | **Limitation in SAML-Based SSO**<br />EMQX Dashboard supports Single Sign-On based on the Security Assertion Markup Language (SAML) 2.0 standard and integrates with Okta and OneLogin as identity providers. However, the SAML-based SSO currently does not support a certificate signature verification mechanism and is incompatible with Azure Entra ID due to its complexity. | -                                                            |                           |
| 5.9.0 | **Memory Growth in JWT Authentication Using JWKS and Other `httpc` Callers**<br />The bundled Erlang/OTP HTTP client (`httpc`) keeps about 100 bytes of process memory for each asynchronous request, and for each synchronous request that fails before it is sent. Garbage collection does not release it; it is released only when the process exits. For JWT authenticators that retrieve keys from a JWKS endpoint, the JWKS client pool accumulates memory with every key refresh. Affects EMQX 5.9.0–5.9.3. | Apply the [httpc hot patch](https://github.com/emqx/emqx-hot-patches/tree/main/261118-httpc-alias-leak) (5.9.2–5.9.3) to stop further memory growth. After loading the patch, release accumulated memory by restarting the JWT authenticator resource as described in [Release memory already leaked by JWKS clients](https://github.com/emqx/emqx-hot-patches/tree/main/261118-httpc-alias-leak#release-memory-already-leaked-by-jwks-clients), or by restarting the node. For 5.9.0 and 5.9.1, first upgrade to a release supported by the patch. | Fixed in EMQX 5.9.4. See [emqx/emqx#20124](https://github.com/emqx/emqx/pull/20124). |
