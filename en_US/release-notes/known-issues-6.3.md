# Known Issues in EMQX 6.3

## 6.3.1

| Since version | Issue                                                        | Workaround                                                   | Status |
| ------------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ------ |
| 6.0.0         | **Slow message intake on TCP listeners with `tcp_backend = socket` when `tcp_options.recbuf` or `sndbuf` is set**<br />On a TCP listener configured with `tcp_backend = socket`, the `tcp_options.recbuf` and `tcp_options.sndbuf` values are applied to each accepted connection after the TCP handshake, instead of to the listening socket as the `gen_tcp` backend does. On Linux, shrinking the receive buffer of an established connection below the segment size negotiated during the handshake makes the broker advertise a zero receive window, so a client can deliver only about `recbuf` bytes every 200 ms (on the sender's persist timer). With `recbuf = 4KB`, a 256 KB message takes about 9 seconds to arrive; the smaller the buffer, the slower the intake. Listeners with the default `tcp_backend = gen_tcp`, and `socket` listeners that leave `recbuf` and `sndbuf` unset (they have no default), are not affected. | Remove `tcp_options.recbuf` and `tcp_options.sndbuf` from listeners that use `tcp_backend = socket`, so the kernel sizes the buffers, or switch the listener to `tcp_backend = gen_tcp`. If a fixed buffer size is required, use `64KB` or more. | Fix scheduled for 6.3.2 ([emqx/emqx#19174](https://github.com/emqx/emqx/pull/19174)) |
